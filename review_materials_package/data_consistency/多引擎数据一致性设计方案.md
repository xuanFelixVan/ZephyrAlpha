# 多引擎数据一致性设计方案

> 基于Saga模式的跨引擎数据同步保障方案
>
> **核心挑战**：vn.py、RQAlpha、Backtrader、QMT、backtesting.py五个引擎间的持仓、资金、订单状态同步
> **技术方案**：Saga分布式事务模式 + PostgreSQL逻辑复制 + Redis Streams
> **设计目标**：强一致性保证、高可用性、低延迟（<50ms）、完整补偿机制

**版本**: v1.0
**更新**: 2026-04-02
**Layer**: Layer 4 (执行层) + Layer 1 (数据层)
**优先级**: P1 - 多引擎架构核心基础

## 1. 问题分析与挑战

### 1.1 多引擎数据同步问题

| 引擎 | 数据存储方式 | 数据格式 | 同步难点 |
|------|--------------|----------|----------|
| **vn.py** | MongoDB + SQLite | Python对象 + 关系表 | 实时交易数据量大，状态变更频繁 |
| **RQAlpha** | HDF5 + 内存对象 | 结构化数组 | 回测场景批量处理，数据版本多 |
| **Backtrader** | CSV + 内存对象 | Pandas DataFrame | 多时间框架，自定义数据源 |
| **QMT** | 券商数据库 + 本地缓存 | 专有二进制格式 | 券商接口限制，需模拟盘同步 |
| **backtesting.py** | Pandas DataFrame | 轻量级内存结构 | 快速回测，无持久化存储 |

### 1.2 关键数据同步需求

#### 1.2.1 持仓数据同步
- **同步实体**: 股票代码、持仓数量、成本价、浮动盈亏
- **同步时机**: 交易执行后实时同步、每日收盘后批量同步
- **一致性要求**: 强一致性（持仓数量必须精确一致）

#### 1.2.2 资金数据同步
- **同步实体**: 可用资金、冻结资金、总资产、当日盈亏
- **同步时机**: 交易前后实时同步、资金划转时同步
- **一致性要求**: 强一致性（资金总额必须精确一致）

#### 1.2.3 订单状态同步
- **同步实体**: 订单ID、状态（待成交/部分成交/完全成交/已取消）、成交数量、成交均价
- **同步时机**: 订单状态变更时实时同步
- **一致性要求**: 最终一致性（允许短暂延迟）

### 1.3 技术挑战评级

| 挑战 | 风险等级 | 影响 | 缓解措施 |
|------|----------|------|----------|
| **跨引擎事务原子性** | P0（高风险） | 数据不一致导致交易错误 | Saga模式 + 补偿事务 |
| **网络分区容忍** | P1（中风险） | 引擎间通信中断 | 重试机制 + 本地缓存 |
| **性能开销** | P1（中风险） | 同步延迟影响交易 | 异步处理 + 批量合并 |
| **补偿事务复杂性** | P1（中风险） | 回滚逻辑错误 | 状态机 + 幂等设计 |
| **数据格式转换** | P2（低风险） | 格式不一致 | 统一数据模型 + 适配器 |

## 2. 技术方案评估

### 2.1 备选方案对比

| 维度 | **Saga模式** (推荐) | **两阶段提交 (2PC)** | **事件溯源 (Event Sourcing)** |
|------|---------------------|---------------------|-----------------------------|
| **一致性模型** | 最终一致性 → 强一致性 | 强一致性 | 最终一致性 |
| **性能** | 高（异步执行） | 低（同步阻塞） | 中（事件重放） |
| **可用性** | 高（无单点故障） | 低（协调者单点） | 高（事件存储高可用） |
| **复杂度** | 中（需补偿逻辑） | 高（协调者复杂） | 高（事件模型设计） |
| **扩展性** | 高（新增引擎易） | 低（协议限制） | 中（事件存储扩展） |
| **适合场景** | 长事务、跨系统 | 短事务、强一致 | 审计追踪、状态重建 |
| **实现成本** | 中（3-5天） | 高（5-7天） | 高（7-10天） |

### 2.2 推荐方案：Saga模式 + PostgreSQL + Redis

#### 2.2.1 架构优势
1. **最终一致性可升级强一致性**: 通过补偿事务实现业务层面的强一致性
2. **无单点故障**: 无中心协调者，每个引擎独立处理自己的事务
3. **高性能**: 异步执行，支持批量操作，延迟<50ms
4. **易于扩展**: 新增引擎只需实现Saga参与接口
5. **容错能力强**: 补偿事务机制保证异常时数据安全

#### 2.2.2 技术栈选择
- **事务协调**: 自定义Saga协调器（Python）
- **状态存储**: PostgreSQL（强一致性保证）
- **事件驱动**: Redis Streams（低延迟消息）
- **监控告警**: Prometheus + Grafana（事务健康监控）

### 3.2 数据流设计

#### 3.2.1 正常执行流程（成功）
1. **事务启动**: 协调器创建Saga事务，分配唯一ID
2. **预检查阶段**: 各引擎检查资源可用性（资金、持仓）
3. **执行阶段**: 顺序执行各引擎的本地事务
4. **确认阶段**: 所有引擎执行成功后确认事务
5. **完成通知**: 发布事务完成事件，更新全局状态

#### 3.2.2 补偿执行流程（失败）
1. **失败检测**: 任何引擎本地事务失败
2. **停止执行**: 协调器停止后续引擎执行
3. **补偿触发**: 按逆序触发已执行引擎的补偿事务
4. **状态回滚**: 各引擎回滚到事务前状态
5. **失败通知**: 发布事务失败事件，记录错误日志

### 3.3 核心组件设计

#### 3.3.1 Saga协调器 (SagaCoordinator)
```python
class SagaCoordinator:
    """Saga模式协调器"""
    
    def __init__(self, postgres_client, redis_client):
        self.pg = postgres_client
        self.redis = redis_client
        self.participants = {}  # 引擎ID -> 参与方客户端
        
    async def execute_transaction(self, transaction: SagaTransaction) -> SagaResult:
        """执行Saga事务"""
        # 1. 创建事务记录
        tx_id = await self._create_transaction_record(transaction)
        
        # 2. 执行预检查
        precheck_results = await self._execute_precheck(tx_id, transaction)
        if not all(r.success for r in precheck_results):
            return SagaResult.failed("预检查失败", precheck_results)
            
        # 3. 顺序执行本地事务
        executed_participants = []
        for participant_id, command in transaction.commands.items():
            try:
                result = await self._execute_local_transaction(
                    participant_id, command, tx_id
                )
                if not result.success:
                    # 触发补偿
                    await self._trigger_compensation(
                        tx_id, executed_participants
                    )
                    return SagaResult.failed(f"参与者{participant_id}执行失败", result)
                    
                executed_participants.append(participant_id)
                
            except Exception as e:
                await self._trigger_compensation(tx_id, executed_participants)
                return SagaResult.failed(f"执行异常: {str(e)}")
                
        # 4. 确认事务完成
        await self._confirm_transaction(tx_id)
        return SagaResult.success(tx_id)
        
    async def _trigger_compensation(self, tx_id: str, participants: List[str]):
        """触发补偿事务"""
        # 按逆序触发补偿
        for participant_id in reversed(participants):
            await self._execute_compensation(participant_id, tx_id)
```

#### 3.3.2 Saga参与方 (SagaParticipant)
```python
class SagaParticipant:
    """Saga模式参与方（引擎适配器集成）"""
    
    def __init__(self, engine_adapter: BaseEngineAdapter):
        self.engine = engine_adapter
        self.local_tx_log = {}  # 本地事务日志
        
    async def execute_local_transaction(
        self, command: LocalCommand, tx_id: str
    ) -> ParticipantResult:
        """执行本地事务"""
        # 记录事务开始
        await self._log_transaction_start(tx_id, command)
        
        try:
            # 执行引擎特定操作
            if command.type == "position_transfer":
                result = await self._transfer_position(command)
            elif command.type == "capital_adjustment":
                result = await self._adjust_capital(command)
            elif command.type == "order_sync":
                result = await self._sync_order(command)
            else:
                raise ValueError(f"未知命令类型: {command.type}")
                
            # 记录事务成功
            await self._log_transaction_success(tx_id, result)
            return ParticipantResult.success(tx_id, result.data)
            
        except Exception as e:
            # 记录事务失败
            await self._log_transaction_failure(tx_id, str(e))
            return ParticipantResult.failed(tx_id, str(e))
            
    async def compensate_transaction(self, tx_id: str) -> CompensationResult:
        """补偿事务（回滚）"""
        tx_log = await self._get_transaction_log(tx_id)
        if not tx_log:
            return CompensationResult.skipped(f"事务{tx_id}不存在")
            
        try:
            # 执行补偿逻辑
            if tx_log.command.type == "position_transfer":
                # 反向转移持仓
                await self._reverse_position_transfer(tx_log)
            elif tx_log.command.type == "capital_adjustment":
                # 反向调整资金
                await self._reverse_capital_adjustment(tx_log)
            elif tx_log.command.type == "order_sync":
                # 订单同步无需补偿（只读）
                pass
                
            await self._log_compensation_success(tx_id)
            return CompensationResult.success(tx_id)
            
        except Exception as e:
            await self._log_compensation_failure(tx_id, str(e))
            return CompensationResult.failed(tx_id, str(e))
```

### 5.2 补偿事务设计原则

#### 5.2.1 幂等性设计
- **补偿命令幂等**: 同一事务的补偿命令可重复执行，结果一致
- **状态检查**: 补偿前检查当前状态，避免重复补偿
- **结果记录**: 记录补偿结果，后续补偿直接返回成功

#### 5.2.2 可重试性设计
- **最大重试次数**: 每个补偿操作最多重试3次
- **退避策略**: 指数退避重试（1s, 2s, 4s）
- **超时设置**: 单次补偿操作最长30秒

#### 5.2.3 业务语义补偿
- **持仓转移补偿**: 反向转移相同数量的持仓
- **资金调整补偿**: 反向调整相同金额的资金
- **订单同步补偿**: 无需补偿（只读操作）

### 5.3 关键算法实现

#### 5.3.1 预检查算法
```python
async def precheck_position_transfer(
    self, tx_id: str, transfer: PositionTransfer
) -> PrecheckResult:
    """持仓转移预检查"""
    checks = []
    
    # 检查源引擎持仓是否足够
    source_position = await self._get_position(
        transfer.source_engine, transfer.symbol
    )
    if source_position.available < transfer.quantity:
        checks.append(PrecheckItem(
            type="position_sufficiency",
            passed=False,
            message=f"源引擎持仓不足: {source_position.available} < {transfer.quantity}"
        ))
    else:
        checks.append(PrecheckItem(
            type="position_sufficiency",
            passed=True,
            message="持仓充足"
        ))
    
    # 检查目标引擎是否支持该股票
    target_supported = await self._check_symbol_support(
        transfer.target_engine, transfer.symbol
    )
    checks.append(PrecheckItem(
        type="symbol_support",
        passed=target_supported,
        message="目标引擎支持该股票" if target_supported else "目标引擎不支持该股票"
    ))
    
    # 检查是否在交易时间（避免非交易时间转移）
    in_trading_hours = await self._is_in_trading_hours()
    checks.append(PrecheckItem(
        type="trading_hours",
        passed=in_trading_hours,
        message="在交易时间内" if in_trading_hours else "非交易时间"
    ))
    
    all_passed = all(c.passed for c in checks)
    return PrecheckResult(
        tx_id=tx_id,
        passed=all_passed,
        checks=checks,
        timestamp=datetime.now()
    )
```

#### 5.3.2 补偿事务调度算法
```python
async def schedule_compensation(
    self, tx_id: str, failed_participant_id: str, executed_participants: List[str]
) -> CompensationSchedule:
    """调度补偿事务"""
    # 确定需要补偿的参与者（逆序）
    participants_to_compensate = []
    for participant_id in executed_participants:
        participants_to_compensate.append(participant_id)
        if participant_id == failed_participant_id:
            break
    
    # 逆序排列（后执行的先补偿）
    participants_to_compensate.reverse()
    
    # 创建补偿计划
    schedule = CompensationSchedule(
        tx_id=tx_id,
        participants=participants_to_compensate,
        current_index=0,
        max_retries=3,
        status="pending"
    )
    
    # 存储补偿计划
    await self._store_compensation_schedule(schedule)
    
    # 触发第一个补偿
    if participants_to_compensate:
        await self._trigger_participant_compensation(
            tx_id, participants_to_compensate[0]
        )
    
    return schedule
```

## 附录A：术语表

| 术语 | 定义 |
|------|------|
| **Saga模式** | 一种管理长时间运行事务的模式，将大事务拆分为多个本地事务，通过补偿机制保证一致性 |
| **补偿事务** | 用于撤销已执行本地事务的操作，保证事务失败时数据一致性 |
| **最终一致性** | 系统保证在没有新的更新的情况下，最终所有副本都会达到一致的状态 |
| **强一致性** | 任何读写操作都好像以某种顺序一次一个地执行，且每个读操作都返回最近一次写操作的结果 |
| **预检查** | 在执行事务前检查资源可用性和约束条件，避免无效事务执行 |
| **幂等性** | 同一操作执行一次或多次的效果相同，不会产生副作用 |
