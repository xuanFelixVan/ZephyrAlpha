## 📋 规范概述



本文档定义了清风量化系统文档版本号的命名规范，确保版本管理的标准化和一致性。



```---



## 🎯 版本号格式



### 标准格式



```

version: X.Y.Z

```



- **X (主版本号)**: 重大变更，不兼容的架构调整

- **Y (次版本号)**: 功能增加，向后兼容的改进

- **Z (修订号)**: Bug修复，文档错误修正



```---



## 📊 版本号升级规则



### 主版本号 (X) 升级条件



**何时升级**: 重大架构变更或根本性重写



**示例场景**:

- 从单体架构迁移到微服务架构

- 核心数据模型重构

- 主要技术栈更换

- 文档结构彻底重组



**示例**:

```yaml

version: 1.0.0  # 初始版本

version: 2.0.0  # 架构重大重构

version: 3.0.0  # 技术栈迁移

```



### 次版本号 (Y) 升级条件



**何时升级**: 功能增加或重要改进



**示例场景**:

- 新增模块或功能

- 扩展接口定义

- 增加新的配置选项

- 性能优化方案

- 文档内容扩充



**示例**:

```yaml

version: 1.0.0  # 初始版本

version: 1.1.0  # 新增功能模块

version: 1.2.0  # 扩展接口定义

version: 1.3.0  # 性能优化方案

```



### 修订号 (Z) 升级条件



**何时升级**: Bug修复或小改进



**示例场景**:

- 文档错误修正

- 链接修复

- 格式调整

- 拼写错误修正

- 示例代码更新



**示例**:

```yaml

version: 1.0.0  # 初始版本

version: 1.0.1  # 修正文档错误

version: 1.0.2  # 修复链接

version: 1.0.3  # 格式调整

```



```---



## 📁 文件名与版本号对应



### 文件名版本标识



**推荐格式**: `FILENAME_VX.md`



**示例**:

```

ARCHITECTURE_BLUEPRINT_V1.md     # version: 1.0.0

ARCHITECTURE_BLUEPRINT_V2.md     # version: 2.0.0

TRADING_SYSTEM_DESIGN_V1.2.md    # version: 1.2.0

```



### 版本号提取规则



从文件名提取版本号的优先级：



1. **文件名中的版本标识** (最高优先级)

   - `_V2` → `2.0.0`

   - `_V1.2` → `1.2.0`

   - `_v3` → `3.0.0`



2. **YAML头部版本号** (次优先级)

   ```yaml

   version: 1.5.0

   ```



3. **默认版本号** (最低优先级)

   - `1.0.0`



```---



## 🏷️ 特殊版本标识



### 预发布版本



**格式**: `X.Y.Z-alpha.N` 或 `X.Y.Z-beta.N`



**示例**:

```yaml

version: 2.0.0-alpha.1  # 内部测试版本

version: 2.0.0-beta.1   # 公开测试版本

version: 2.0.0          # 正式发布版本

```



### 归档版本



**格式**: `X.Y.Z-archived`



**示例**:

```yaml

version: 1.0.0-archived  # 已归档的旧版本

```



### 草稿版本



**格式**: `X.Y.Z-draft`



**示例**:

```yaml

version: 1.0.0-draft  # 草稿版本，未正式发布

```

## 📝 版本号管理流程



### 新文档创建



1. **初始版本**: 所有新文档从 `1.0.0` 开始

2. **YAML头部**: 必须包含版本号字段

3. **文件名**: 可选包含版本标识



**示例**:

```yaml

```---

version: 1.0.0


responsibility_boundary: 新模块蓝图设计

layer: Layer 8 (人机交互层)

```---

```



### 文档更新流程



1. **评估变更级别**:

   - 重大架构变更 → 升级主版本号

   - 功能增加 → 升级次版本号

   - 错误修正 → 升级修订号



2. **更新版本号**:

   - 修改YAML头部的version字段

   - 可选更新文件名版本标识



3. **记录变更历史**:

   - 在文档中添加变更记录章节

   - 说明版本升级原因



**变更记录示例**:

```markdown

## 变更历史



### v2.0.0 (2026-04-07)

- 重大架构重构：从单体架构迁移到微服务架构

- 新增服务发现机制

- 更新所有接口定义



### v1.5.0 (2026-03-15)

- 新增实时监控模块

- 扩展API接口



### v1.0.0 (2026-01-01)

- 初始版本发布

```

## 🎯 最佳实践



### 1. 保持版本号一致性



- YAML头部版本号与文件名版本标识保持一致

- 所有引用文档使用相同版本号



### 2. 及时更新版本号



- 每次重要修改后立即更新版本号

- 不要累积多个变更后再升级版本号



### 3. 记录变更历史



- 每次版本升级都要记录变更内容

- 变更记录要清晰、具体



### 4. 使用自动化工具



- 使用版本号验证脚本定期检查

- 在CI/CD流程中集成版本号检查
