# COINTEGRATION ANALYSIS BLUEPRINT



## 核心定位



负责协整分析模块设计，识别资产间长期均衡关系，支持统计套利和配对交易策略。



> **职责边界**: 

> - ✅ 本文档负责：协整分析、统计套利、配对交易

> - ❌ 本文档不负责：因子计算（由因子模块负责）



## 接口与契约（蓝图终稿）



- 全库 API 与事件约定真源：`API_Contract.md`。协整分析的输入（价格序列/标的池/窗口/显著性阈值）与输出（配对列表/价差序列/信号/置信度）若对外暴露，契约口径以该真源为准。



## 验收标准（可检查）



- 给定一组标的与时间窗口，能输出非空的候选配对列表，并包含可解释的统计量（例如 p-value、ADF 统计量、Johansen rank 等）。

- 能为至少 1 个配对生成交易信号（开仓/平仓条件），并能在回测框架中复现实验结果（可用最小样例验证）。

- 风险控制参数（止损/止盈/最大持仓/失效判定）有明确默认值或配置入口。

- 对外输出/事件若存在，应能在 `API_Contract.md` 中定位契约入口（或在“已知限制”列出未闭合项）。



## 已知限制



- 协整关系在市场结构变化下可能失效，需要漂移监控与再训练/再检验机制；本文不在蓝图阶段闭合全部监控与再训练策略。



## 设计目标



### 主要目标



1. **功能完整性**: 确保协整分析功能完整，满足业务需求

2. **性能优化**: 提升系统性能，降低资源消耗

3. **可维护性**: 提高代码质量，便于后续维护

4. **可扩展性**: 支持功能扩展，适应业务变化



### 质量目标



- 代码覆盖率: ≥80%

- 性能指标: 满足设计要求

- 文档完整性: 100%



## 核心功能



### 功能清单



1. **协整检验**: 实现Engle-Granger、Johansen等协整检验方法

2. **配对交易**: 基于协整关系识别配对交易机会

3. **统计套利**: 构建均值回归交易策略

4. **风险监控**: 监控协整关系稳定性



### 功能特性



- 多种协整检验方法支持

- 自动配对识别

- 实时信号生成

- 风险预警机制

## 接口与契约（蓝图终稿）



- 全库 API 与事件约定真源：`API_Contract.md`。协整检验输入数据口径、信号输出、下单建议与回测评估事件等对外约定需以该真源或其子契约为准。

- 邻层协同边界：与 **Layer 1（数据预处理）**、**Layer 5（策略/执行）**、**Layer 10（治理与合规）** 的交互以契约为准（避免信号口径漂移）。



## 验收标准（可检查）



- 能对给定资产对执行协整检验并输出可复核结果（统计量、显著性、窗口）。

- 能生成交易信号或建议（入场/出场/止损任一），并能解释触发条件。

- 能在回测中复现一次信号到交易的闭环（输入→输出→评估），并记录版本与参数。

- 在协整关系失效或数据异常时能触发告警并给出降级策略与留痕。



## 已知限制



- 信号字段字典、事件载荷与参数空间细化将在施工阶段固化到 `API_Contract.md` 子契约；本蓝图先确保边界、接口闭合点与验收闭环清晰。
