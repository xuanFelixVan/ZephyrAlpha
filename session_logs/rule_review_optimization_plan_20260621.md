## 一、核心原则

### 1.1 防幻觉优先
每次修改后，必须通过**新AI冷启动模拟测试**：
- 修改规则 → 模拟新AI只读此文件 → 能否正确理解？
  - YES → 修改有效，继续
  - NO → 回滚修改，噪音是必须的，保留

### 1.2 防幻觉验证4项检查
1. **关键约束清晰度**: 新AI能否识别规则的"禁止/必须"边界？
2. **触发条件明确性**: 新AI能否判断何时应用此规则？
3. **判定标准机械性**: 新AI能否机械判定规则是否被违反？
4. **跨规则一致性**: 修改是否破坏与其他规则的引用关系？

### 1.3 不拆分原则
- 能不拆分就绝对不拆分
- 阈值：3000行（约120KB）
- 拆分条件：文件超过3000行 + 用户同意 + 保证责任唯一/真源唯一
- 理由：防幻觉 > Token节省，AI理解规则需要完整上下文

## 三、噪音去除的防幻觉评估标准

| 噪音类型 | 删除条件 | 保留条件 |
|---------|---------|---------|
| "对标"段落 | 纯文化类比，无技术信息 | 包含技术映射关系 |
| "大白话"解释 | 规则本身已清晰 | 规则复杂，需要通俗解释 |
| "为什么"解释 | 规则的"是什么"已明确 | "为什么"影响规则执行 |
| ASCII图 | 信息已在表格中 | 图表信息比表格更清晰 |
| 修订记录 | git log已有 | 记录了关键决策原因 |
