## 4. 技术选型

| 组件 | 选择 | 理由 |
|------|------|------|
| **语言** | Python 3.10+ | 生态丰富 |
| **数据库** | SQLite (日常) + DuckDB (分析) | 零配置 |
| **配置** | YAML | 版本控制友好 |
| **调度** | APScheduler | 轻量级 |
| **回测** | 向量化 | 单机足够 |
| **API** | FastAPI (可选) | 轻量可扩展 |
| **日志** | loguru | 简单易用 |

## 5. 数据流设计

```
1. 数据采集 (data_collector)
   │
   ├─→ 原始数据 (data/raw/)
   │
   ▼
2. 数据清洗 (data_cleaner)
   │
   ├─→ 处理后数据 (data/processed/)
   │
   ▼
3. 因子计算 (factor_calculator)
   │
   ├─→ 因子数据 (data/factors/)
   │
   ▼
4. 策略执行 (strategy_engine)
   │
   ├─→ 信号数据 (data/signals/)
   │
   ▼
5. 风险校验 (risk_manager)
   │
   ├─→ 订单数据 (data/orders/)
   │
   ▼
6. 回测/执行 (backtest/trade_executor)
   │
   ├─→ 结果数据 (data/backtest_results/)
   │
   ▼
7. 绩效归因 (performance)
   │
   └─→ 报告 (reports/)
```

## 6. 关键设计决策

### 6.1 配置驱动开发
- 所有行为通过YAML配置控制
- 代码只是配置的执行器
- 配置变更无需修改代码

### 6.2 模块化设计
- 每个模块职责单一
- 模块间通过标准化接口通信
- 可独立测试和替换

### 6.3 渐进式复杂化
- 从简单开始，逐步添加功能
- 避免过度工程
- 先实现核心功能
