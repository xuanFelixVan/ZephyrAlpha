# 核心功能(F1-F37)依赖与调度设计

> 本文档是37个核心功能依赖关系和调度方式的**设计真源**。
> 全景图(depgraph.db)的依赖边修改必须以本文档为基准。
> 功能清单来源：[phase\_d\_ai\_prompts.md](file:///d:/ZephyrAlpha/docs/02_enterprise_architecture/phase_d_ai_prompts.md)

***

## 一、设计原则

|  #  | 原则          | 说明                                                                                                        |
| :-: | :---------- | :-------------------------------------------------------------------------------------------------------- |
|  1  | 单向分层依赖      | 禁止循环依赖。依赖方向只能从上层→下层。**同层间允许依赖，但禁止同层循环依赖**（MTH-009裁定，对标K8s/Conductor同层协作模式）                                |
|  2  | 依赖倒置(DIP)   | 编排器(F1)→下层**业务调度**依赖可使用抽象契约(contract类型)，不可使用具体实现(runtime类型)。基础设施健康检查（F1→F21）和同层协作（F1→F23）例外允许runtime。对标Kubernetes CRI/CSI、Netflix Conductor Worker API |
|  3  | 事件解耦        | 跨层调度通过事件总线(F22)，不建立直接依赖边。对标Citadel/Two Sigma事件驱动核心                                                        |
|  4  | 控制平面/数据平面分离 | 编排器(控制平面)与执行器(数据平面)逻辑分离。编排器依赖抽象接口，执行器通过标准协议对接。对标SDN/AWS Nitro/Google Tide                                 |
|  5  | 混合模式调度      | 调度采用事件驱动+队列轮询+声明式调和三模式混合，非单一模式。对标K8s声明式调和+Conductor Worker poll                                           |
|  6  | 基础设施下沉      | L0层(F22/F25/F26)出度0，被所有功能依赖但不依赖任何功能                                                                       |
|  7  | 应急层被动触发     | L6层不被其他层直接依赖（跨层入度=0），通过事件被触发而非直接依赖。L6内部允许依赖（如F5→F9委托触发回滚）                                                 |
|  8  | 职责单一        | 每个功能只做一件事，禁止功能边界重叠                                                                                        |
|  9  | F1总指挥       | F1(自动驾驶)在L2调度层，通过contract依赖F3抽象协议、通过event调度F14管线，出度最高                                                     |

### 1.1 依赖类型定义

|     类型     | 含义                      | 对标业界                             | 示例                                        |
| :--------: | :---------------------- | :------------------------------- | :---------------------------------------- |
| `contract` | 依赖抽象接口/Protocol，不依赖具体实现 | K8s CRI/CSI、Conductor Worker API | F1→F3（AutoPilot依赖TaskRepository Protocol） |
|   `event`  | 通过事件总线通信，无直接依赖          | Citadel Kafka事件核心、SDN控制平面        | F1→F14（F1发布pipeline\_start事件，F14订阅）       |
|  `runtime` | 直接运行时调用（同层或向下层）         | 传统同步调用                           | F1→F21（守护进程健康检查）                          |
|   `data`   | 数据依赖（读写共享数据）            | 数据库访问                            | F3→F25（任务卡持久化到数据库）                        |

## 二、七层架构分层

```
L0 基础设施层 │ F22 共享核心  F25 数据库集成层  F26 运行时集成
              │ (出度0，被所有功能依赖)
              │
L1 守护层     │ F21 IDE健康守护
              │ (冷启动STEP 0强制依赖，最先启动)
              │
L2 调度层     │ F1 自动驾驶/大脑  F23 Agent编排器
              │ (系统总指挥，调度L3/L4)
              │
L3 控制层     │ F2 门禁引擎  F4 预算执行器  F7 LLM安全网关  F8 RBAC权限
              │ F27 容量保障  F32 状态机引擎
              │ (安全防护，拦截校验)
              │
L4 执行层     │ F3 任务系统  F11 上下文引擎  F12 知识库  F13 MCP集群
              │ F14 管线编排  F24 Agent Spec/Skill  F33 本地模型
              │ (核心业务执行)
              │
L5 治理层     │ F6 漂移检测  F15 自动修复  F16 孤儿审判  F18 治理脚本
              │ F19 系统遥测  F20 监控统一  F28 资产盘点  F29 语义审计
              │ F30 红蓝对抗  F31 注册表治理  F34 代码去重
              │ F35 文件结构治理  F36 审计追踪链  F37 资源优化
              │ (监控审计修复)
              │
L6 应急层     │ F5 升级/A2A  F9 回滚系统  F10 模型考试
              │ (入度0，通过事件被触发)
              │
已完成(归档)  │ F17 交易骨架清理（一次性任务，已完成，保留蓝图）
```

**注**：F17为已完成的一次性清理任务，不参与依赖设计和调度，保留在文档中作为历史记录。

**依赖方向**：L6 → L5 → L4 → L3 → L2 → L1 → L0（上层依赖下层，单向，禁止逆向）
**DIP类型约束**：编排器(F1)可依赖下层抽象契约(contract类型)，不可依赖具体实现(runtime类型)

**事件方向**：L2/L3/L4/L5 ──发布事件──> 事件总线(F22) ──订阅──> L6(应急层)

## 九、启动顺序设计

### 9.1 启动波次（按依赖拓扑排序）

> 启动顺序按依赖拓扑排序，确保每个功能启动时其依赖已就绪。

|  波次 | 功能                                            | 说明                           |
| :-: | :-------------------------------------------- | :--------------------------- |
| 第0波 | F22, F25, F26                                 | L0基础设施层（boot），无依赖，最先启动       |
| 第1波 | F21, F4, F8, F32, F19, F30, F31, F36          | 仅依赖L0的功能（boot启动）             |

| 第5波 | F22, F25, F26                                 | L0基础设施层，最后关闭            |

| # | 约束 | 原因 |
