# 系统宪章 / System Charter

> **定位**：系统设计的最高层不变量定义——使命、能力边界、硬约束、安全控制。回答"这个系统到底能做什么、不能做什么、边界在哪"。
>
> **收录原则**：本文档只收录"不会变"的内容——规则、标准、界限、范围。会变的内容（开发进度、能力清单、优先级排序、资产覆盖、风险参数、能力-域映射矩阵、术语表等）不在本文档，见对应专题文档。

***

## §1 核心价值主张

### §1.1 一句话定位

> **这是一个由AI驱动的、能自我迭代升级的量化财富复利引擎（代码生成100% / 运维99% / 交易决策自主执行>90%，综合约99%由AI驱动）。**

> **"99% AI驱动"口径说明**：这是系统整体定性描述——代码生成100%由AI完成，日常运维99%由AI自治，交易决策中AI自主执行率目标>90%。人类角色为需求定义者、质量审核者和关键决策审批者。不同环节的AI参与度不同，但系统整体运行无需人工日常干预。

| 维度         | 内容                                                        |
| ---------- | --------------------------------------------------------- |
| 核心目标       | 资产长期复利增长                                                  |
| 核心差异化      | **99% AI驱动 + 自我迭代进化** — 它不仅自动交易，还会自我构建新模块、自我修复缺陷、自我淘汰过时策略 |
| 与其他量化系统的区别 | 量化系统的共同目标是资产复利增长。但本系统的构建者、维护者、迭代者都是AI，而非人类工程师              |
| 用户定位       | 单人使用 → 未来多账号（亲朋好友资金）                                      |
| 系统预期寿命     | 5-10年（在AI技术革命普及化之前保持竞争优势）                                 |

### §1.2 差异化详解与AI伦理

> **AI伦理声明**：本系统作为AI自治交易系统，声明以下价值观：①不参与市场操纵——所有交易决策基于公开信息和合法因子/信号，不利用技术优势进行幌骗（spoofing）或分层操纵（layering）；②不利用技术优势剥削弱势参与者——系统追求的是风险调整后的合理收益，而非通过高频或暗箱操作获利；③AI决策透明可解释——每笔自主决策都有完整的决策溯源链，拒绝"黑箱交易"；④遵守所在市场所有适用法规（§5法规合规映射）。

| 传统量化系统        | 本系统                                        |
| ------------- | ------------------------------------------ |
| 人类工程师写策略代码    | **AI生成策略代码**，人类做需求定义和质量审核                  |
| 人类发现bug→人工修复  | **AI自诊断堵塞→提出方案→改代码**                       |
| 人类决定什么时候加新策略  | **AI自动读论文/研报/论坛→主动创建新模块**                  |
| 人工执行模块生命周期    | **模块自动跑测试→上线→A/B对比→B胜出→A自动退役并清理**    |
| 架构升级需要人类架构师   | 架构层由人类主导设计，但**模块层和策略层全部AI自治**       |
| 人类监视+人工告警     | **AI自治运维：健康检查→异常诊断→自动修复→人类审批关键决策**         |
| 人类根据经验手动调风控参数 | **AI自适应风控：监控持仓集中度/波动率/相关性→自动调参→预判风险→提前对冲** |

### §1.3 五项从属能力

> 五项能力按"系统自身 vs 交易能力"和"进攻 vs 防御"两个维度组织。

|   维度   | 能力            | 一句话                                                                |
| :----: | ------------- | ------------------------------------------------------------------ |
| **系统进化** | ① AI自治进化与闭环优化 | AI全维度自我迭代：覆盖策略、因子、信号、仓位、风控等全部交易决策环节 |
| **系统运维** | ② AI自治运维      | 系统自监控→自诊断堵塞/瓶颈/衰退→自修复→保证不崩溃                                        |
| **交易运营** | ③ 多账户多策略      | 同一策略引擎管理多账户，按AUM动态调仓+微信实时通知                                        |
| **市场扩展** | ④ 渐进式全球扩展     | 从A股→港股/美股/期货→全球资产配置                                                |
| **风险控制** | ⑤ 自适应风控       | 风控规则随AUM/市场波动/策略变化自动调参，预判+对冲                                       |

## §2 硬边界约束（环境限制）

> 定义系统运行不可改变的客观限制，包括人力、硬件、资金与外部接口、交易规则与合规、运维与容灾、AI原生开发范式等维度。违反任何一条意味着系统设计前提被打破。

| 约束 | 核心限制 | 关键参数 |
|------|---------|---------|
| **约束一：人力** | 单人全栈开发+AI协作者，AI原生开发范式，99%AI自治运维 | 1人开发+AI；代码100%AI生成；运维99%AI自治 |
| **约束二：硬件** | 单台PC工作站，无集群/K8s | CPU i7-12700KF(12核20线程)；GPU RTX 3090 24GB（显存<90%=21.6GB硬上限）；RAM 64GB DDR4；存储D:731GB+E:931GB SSD；网络30Mbps |
| **约束三：资金与接口** | 个人资金，双账户（实盘+QMT模拟）；数据源免费/券商自带 | miniQMT下单10笔/秒、Tick=3秒；策略主方向多头（融券受限） |
| **约束四：交易规则** | T+1交割，涨跌停限制，融券受限 | 主板±10%/科创创业板±20%/ST±10%/北交所±30%；策略根频率=日频及以上；3秒Tick用于信号触发/风控/行为识别/状态判定/极端事件检测 |
| **约束五：运维容灾** | 单机部署，无热备，家用环境 | 交易时段RTO<5分钟；持仓RPO=0；断电断网→策略状态机断点恢复；Windows交易时段禁自动更新；D→F盘自动备份（代码镜像+数据库dump+增量备份，≥8小时间隔保护） |
| **约束六：AI原生范式** | AI生成代码不可完全信任 | 多AI交叉验证；依赖版本锁定；AI自治熔断（亏损超限/系统性风险/AI置信度低→降级为"仅建议"模式） |

## §3 方法论约束（投资哲学）

> 本节只保留不可妥协的计算规则和一致性铁律。具体策略目录、因子阈值、仓位算法、预测模型等设计选择见 `07_trading_decision_architecture/design_memos/`（00_index_trading_decision 讨论框架；遗留提案见 90_methodology_open_questions）。

**约束一：成本模型必须完整** — 回测成本=佣金+印花税+滑点+市场冲击+做T额外成本；回测必须包含全部成本类型，具体费率按实际账户配置（不硬编码）。

**约束二：统一框架派路线** — 不走多策略平台派（Citadel/Millennium 式独立 PM 并行），走统一框架派（Two Sigma/DE Shaw 式大模型+状态切换）。本质是"一个策略包含多个子策略，按市场状态切换权重"，而非养几十个互不相关的独立策略。理由：单人+AI+资金小的客观条件下，少而精是唯一可行路径，分散到几十策略既无研究带宽也无资金必要。

**约束三：Regime Detection 是生死线** — 统一框架成立的前提是准确识别当前市场状态（regime）。识别不准等于"用错误的状态切换错误的策略"，比单策略还糟。市场状态感知、体制转换检测、市场状态预测是本路线的命门环节，施工时享有最高优先级，不可降级处理。

**约束四：策略三维度解耦** — 策略 = 选股信号 × 组合权重 × 执行方式（what × how much × how）。三维度必须独立优化、不可耦合死：一个选股信号可配不同权重方案，一个权重方案可配不同执行方式。选股、仓位、执行三个环节必须分开实现，禁止为了"简单"把它们写成单一模块。

**约束五：少而精优于多而散** — 机构多策略是因钱多、人多必须分散，并非多策略更优。本系统资金小、人少，走少而精路线是适配规模的正确选择，非劣势。新增策略必须论证其与现有策略的差异性（信号源/持仓周期/市场状态适配），禁止通过堆砌相似策略制造"多策略"假象。

## §4 安全控制与范围边界

> 风控参数（杠杆、集中度等）由风险模型决定，不在此处硬编码；架构原则（风控引擎在关键路径）由系统设计保证。本节收录需要显式声明的安全控制、数据保护、运营原则和范围边界。

### §4.1 硬边界保护

|   编号  | 事项                        | 理由                                             | 执行机制                                            |
| :---: | --------------------------- | ---------------------------------------------- | ----------------------------------------------- |
| B-006 | **AI不可修改自身的硬边界约束**          | AI自治进化可以调整策略参数，但不可修改本节定义的硬边界本身 | 硬边界存储在独立配置文件中，AI只读；修改需要人工在配置文件中操作+重启确认          |

### §4.2 自迭代安全边界

|   编号  | 禁止事项                              | 理由                                      | 执行机制                            |
| :---: | --------------------------------- | --------------------------------------- | ------------------------------- |
| B-007 | **禁止AI在无人工审批的情况下进行实盘操作**（2026-08-27 Owner 终裁改写：原"上线新策略模块"收窄为"实盘操作"——回测/模拟盘/实验性训练/模块建设全部放开，唯真金白银的实盘操作须审批） | 唯实盘操作直接影响真金白银，必须人工确认；非实盘活动（回测/模拟/训练/研究）不产生影响资金的风险 | 实盘操作定义=实盘账户的下单/撤单/实盘部署启用/实盘参数生效；策略上线流程维持：回测通过→QMT模拟盘→实盘小资金→实盘部署，进入任一实盘阶段前人工审批 |
| B-009 | **禁止AI基于"过拟合模式"的参数调整生效到实盘**       | 在回测数据上反复调参必然找到一组"看起来很好"的参数，但实盘无效        | 回测必须包含样本外验证；监控回测-实盘偏差 |

> B-008（限制单次迭代变更范围）和 B-010（禁止退役策略换名复活）为工程实现细节，移至 90_methodology_open_questions #20，归入对应模块配置项。

### §4.3 数据与隐私边界

|    编号   | 禁止事项                                    | 理由                             | 执行机制                                                          |
| :-----: | --------------------------------------- | ------------------------------ | ------------------------------------------------------------- |
|  B-011  | **禁止AI将持仓/交易/策略数据发送到外部API（包括LLM API）**  | 实盘持仓和交易记录是最高级别敏感数据             | AI调用LLM时仅发送脱敏的策略描述/因子定义/回测统计量，禁止发送具体持仓/金额/交易记录                |
| B-013.5 | **禁止策略逻辑/因子公式/模型参数泄露到系统外部**             | 策略IP是系统的核心资产——策略逻辑泄露等同于Alpha泄露 | AI调用外部LLM时禁止发送完整策略代码/因子公式/模型权重；代码仓库本地托管，禁止推送到公开仓库；策略代码混淆或加密存储 |

### §4.4 运营原则

> 以下原则通过变更管理流程保证，适用于所有变更发起方（含AI自治运维）。

|   编号  | 原则                        | 内容                                      | 执行机制                                            |
| :---: | --------------------------- | ---------------------------------------------- | ----------------------------------------------- |
| B-014 | **交易时段变更冻结**          | 交易时段禁止任何生产变更（进程重启/依赖升级/配置推送），break-glass 审批除外 | 变更管理流程交易时段锁定；自治运维交易时段仅监控+告警，修复操作延至盘后 |
| B-016 | **审计日志留存** | 交易日志≥7年 / 决策日志≥3年 / 系统日志≥1年，清理需合规审批 | 日志归档策略强制执行；清理操作需人工审批 |

### §4.5 功能范围边界（本项目明确不做的事）

|   编号  | 不做的事            | 理由                                                                   | 替代方案/备注                                                  |
| :---: | --------------- | -------------------------------------------------------------------- | -------------------------------------------------------- |
| B-017 | **不做高频交易（HFT）** | miniQMT Tick=3秒+T+1制度→日内回转空间极小；RTX 3090单卡无法支撑微秒级推理                   | 策略根频率锁定在日频及以上，3秒Tick用于交易信号触发（买点时机）、风控、行为识别、市场状态判定、极端事件检测 |
| B-018 | **不做纯空头策略**     | A股融券受限（券源少/利率高/期限短），个人账户基本不可做空                                       | 空头信号仅用于风险规避（减仓/清仓），不构建纯空头策略                              |

## §5 法规合规映射

> "能不能做"不是由常识决定的，是由法规决定的。将边界规则映射到具体法规条文，确保能力边界的权威性。

| 编号 | 边界规则 | 适用法规 | 关键条款 | 对本系统的影响 |
|:----:|---------|---------|---------|--------------|
| L-001 | 集中度上限 | 《证券法》第86条/《上市公司收购管理办法》 | 持股超5%需举牌公告 | 当前AUM下不触发，架构预留集中度检查接口 |
| L-002 | B-017不做HFT | 证监会《证券公司程序化交易管理实施细则》(2025) | 程序化交易需报备；异常交易行为监控 | 本系统属程序化交易范畴需关注报备；下单10笔/秒远低于HFT阈值 |
| L-003 | 非交易时段禁下单 | 上交所/深交所《交易规则》 | 非交易时段订单为废单 | 执行层内置交易时段校验，合规与工程一致 |
| L-004 | B-011数据不外传 | 《个人信息保护法》/《数据安全法》 | 个人信息处理需告知同意；数据分类分级 | 主播监控涉及个人信息需评估合规；持仓/交易数据禁止跨境传输 |
| L-005 | 版权合规 | 《著作权法》第24条 | 个人研究属合理使用，商业用途需授权 | 策略工厂爬取内容仅用于个人研究，产出不含原始内容 |
| L-006 | AI生成策略合规 | 《生成式人工智能服务管理暂行办法》(2023) | AI生成内容需标识；提供者需备案 | 个人使用不对外服务，不触发备案；但AI决策需可解释 |
| L-007 | B-016审计日志留存 | 证监会《证券期货投资者适当性管理办法》/《证券法》 | 交易记录需留存备查 | 审计日志保留7年(交易≥7年/决策≥3年/系统≥1年) |
| L-008 | 适当性管理 | 《证券期货投资者适当性管理办法》 | 投资者分类、产品风险等级匹配 | 多账户扩展时每个账户需完成适当性评估 |

约束：涉及法规的边界规则必须有对应法规映射；新增边界规则时同步补充。

## §6 质量属性优先级与冲突取舍

> 当质量属性冲突时，此表决定取舍顺序。

**8项质量属性优先级**

| 属性 | 优先级 | 核心约束 |
|------|:------:|---------|
| 正确性 | P0 | 因子计算高准确率；数据无前视偏差 |
| 安全性 | P0 | 风控引擎在关键路径；敏感数据零外泄 |
| 合规性 | P0 | 审计日志完整覆盖；T+1/涨跌停规则严格遵守 |
| 延迟 | P0/P1 | 风控→执行低延迟；增量信号近实时；订单快速提交 |
| 可用性 | P0/P1 | 交易时段高可用 |
| 可扩展性 | P1 | 新增数据源快速接入；新策略类型不需改架构 |
| 可观测性 | P1 | 每笔订单有TraceID；决策溯源链完整覆盖 |
| 可维护性 | P1 | 因子/信号/策略均通过工厂模式管理(OCP) |

**11条冲突取舍决策**

| 冲突对 | 取舍规则 |
|--------|---------|
| 延迟 vs 正确性 | 正确性优先，宁可延迟下单也不下错单 |
| 可用性 vs 安全性 | 安全性优先，宁可停机也不违规交易 |
| 可扩展性 vs 延迟 | 延迟优先，新功能不得恶化关键路径延迟 |
| 可观测性 vs 延迟 | 可观测性不得引入显著延迟开销 |
| 成本效率 vs 正确性 | 正确性优先，不因节省算力而跳过验证 |
| 可维护性 vs 功能完整性 | 功能完整性优先，但新功能必须符合OCP |
| 自迭代速度 vs 过拟合风险 | 过拟合防护优先 |
| 自动化程度 vs 人类控制权 | 关键决策人类保留否决权 |
| 透明度 vs Alpha保护 | 合规可解释性优先，但策略IP不外泄（分层访问：风控见指标不见公式） |
| 数据新鲜度 vs 数据质量 | 质量优先，脏数据比晚数据更危险（数据质量门控阻断错误数据流入） |
| 回测速度 vs 回测精度 | 精度优先，快速筛选可近似但最终验证必须完整含全部成本和滑点 |
