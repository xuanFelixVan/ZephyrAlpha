## 0. 优先级排序原则（全文档统一的尺子）

1. **验证闭环优先**——回测-模拟盘对账不通，一切功能都是空中楼阁（先能信，再能多）。
2. **风险优先**——风控/资金/合规缺口永远排在增强功能前（project_memory 铁律）。
3. **真实缺口优先**——已实证断链/缺口的修复 > 新功能；候选池按触发条件晋升，不为凑数全做。
4. **省 token 治理件优先**——窗口期最贵的是 token，凡能降低未来每次任务 token 成本的（动态化/flake 治理/误报消除）提前做。
5. **数据依赖后置**——需要实盘数据积累才能验证的（ML 栈/参数校准/Phase 5）一律排到数据期，不抢跑。
6. **拒绝项防复提**——已裁定过度工程/拒绝的登记在案，未来不再消耗评审成本。
