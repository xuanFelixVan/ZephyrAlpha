# 前端仪表盘改版设计

## 1. 背景

### 1.1 现状

- 技术栈：Panel + HoloViews + Plotly（Streamlit 入口 v3.1.0 起弃用），主入口 `src/zephyr/frontend/dashboard/app_panel.py`（v3.4.0，#ARCH-047），端口 5006。
- 结构：11 个平级 Tab（5 治理类 + 6 交易/回测类），15 个组件文件，数据源依赖注入（TaskRepository/OLAPEngine/BacktestResult/MiniQMT 等，未注入时空状态）。

### 1.2 巡检结论（2026-08-20 浏览器实证）

| Tab | 数据 | 状态 |
|---|---|---|
| 任务进度 | 真实 | 可用；下半屏留白 |
| 知识库概览 | 空 | KB 系统 2026-07 已退役，死页面 |
| 门禁统计 | 空 | OLAPEngine 未配置；0 样本显示 Pass Rate 100% 误导 |
| Fitness | 真实 | 3 PASS/2 FAIL；指标卡名称折断 |
| OLAP 趋势 | 空 | 标题悬空无图 |
| 回测结果 | demo | 全站完成度最高（深色 5 子 Tab） |
| 实验历史 | mock | 未选中时右侧无内容 |
| Tick 回放 | 空 | 控件零数据时悬空未禁用 |
| 5档盘口 | 空 | 全站内容最少 |
| 持仓监控 | 零值 | 骨架合理，券商未接入 |
| 交易面板 | 真实表单 | 风控链路完整，除回测页外最可用 |

### 1.3 四大问题

1. **数据可用性**：11 Tab 仅 3 个有实质内容，过半导航项无信息价值
2. **空状态粗糙**：一条提示条 + 整页留白；OLAP 趋势标题悬空；门禁 0 样本显示 100% 误导
3. **主题割裂**：浅色（治理类）与深色（回测/交易）混排，切 Tab 刺眼
4. **导航无场景**：无"今天该看什么"的首页，退役模块仍占主导航

### 1.4 设计总纲（Owner 裁定 2026-08-20，最高原则）

> **前端 = Owner 与系统的交互界面，目的是消灭黑箱。**

- **核心功能只有一个：反馈。** 系统把全部分析/决策结果摆出来——AI 怎么想、得出了什么、实时结果、决策结果，全部可见。
- **验证是 Owner 侧行为，不是系统功能。** Owner 看反馈、用自己的主观交易去挑错；系统不建验证载体（不要逐日对照表之类的专门工具）。
- **页面内容必须来自项目真实模块**（全景扫描见 §10 附录），不拍脑袋设计呈现项。
- **盯盘按时间轴分两部分：盘中实时 + 盘后复盘。** 无独立"盘前"板块——盘前要看的"今日决策"就是前一日**盘后复盘的产出**（PLAN-01 明日预案引擎，生产态已落地）。

## 3. 考虑过的替代方案

## 4. 上限定义

- 本系统上限：**个人量化自用的监控+研究+治理工作台**，非多用户产品。
- 不做：权限系统、多用户、移动端适配、对外分享。
- 演进路径：web 优先，远期如需桌面化用 Tauri/Electron 包裹，不改前端本体。
