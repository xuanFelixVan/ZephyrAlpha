## 2. 议题一：打分标准/打分方式要不要升级？

当前输出 = 方向三标签（利好/利空/中性）+ 强度分。可升级点：

- **(a) 主体范围轴**（新增）：市场级 / 板块级 / 个股级。现状缺口——把"某公司中标"这种个股利好直接聚合成"当天市场情绪"，口径有污染；专业机构做市场级情绪时会先按主体范围过滤。
- **(b) 强度校准 calibration**（把模型自报分映射到可跨时间比较的经验分位）：现状 score 扎堆 0.8，聚合层用"计数+投票"规避了绝对值不可比问题；若未来要做连续型情绪因子才需要校准，暂不急。
- **(c) 微调轨**：见议题二。
- **(d) 输出多维化**：商业舆情 NLP（如 RavenPack，机构常用的机器读新闻服务）输出方向之外还有相关度/新颖度/事件类型等多字段——(a) 和议题三、四本质就是把其中我们最需要的两维先补出来。

**待决 Q1**：主体范围轴进 v3 prompt 吗？（成本=prompt 加一个字段+金标补标；收益=日级聚合口径干净）

## 3. 议题二：微调模型（LoRA）能不能再升级？

**澄清前提**：当前没有 LoRA 模型在打分，是原生 qwen3:8b + 提示词。升级路径 13 号设计备忘已排好序：

1. 零样本（当前，F1 0.787）——已完成
2. **监督微调 SFT**（用标注数据给模型"补课"）：需要**数千条**金标——现状只有 200 条金标，不够
3. **基于偏好的强化学习 RLSP**（让模型对齐"什么样的判断算好"）：更后段

数据从哪来：①用零样本跑完的 12 万条产物抽样人工复核成银标（模型初判+人工改错，标注效率高 5~10 倍）；②公开中文金融情感数据集做预训练打底。

**判断**：不抢跑。先把零样本 12 万条跑完、日级聚合进回测验证有效，微调才有验收基准——微调是 CAND 级候选，启动条件建议=金标/银标攒够 3000 条且零样本基线回测已验证。

## 4. 议题三：可预测性维度——可预期事件 vs 突发黑天鹅 ★

**Owner 洞察**：新闻分两类——**可提前预知的**（财报、解禁、政策会议、宏观数据发布、火箭发射窗口）和**不可预知的**（天灾、地缘突发等黑天鹅 black swan 事件=低概率高冲击的意外）。用法完全不同：可预期的要**提前埋伏**，突发的只能**落地后第一时间应对**。

**专业/量化社区做法**：

- **预定事件日历 scheduled events calendar**（机构把财报季、议息会、解禁日、指数调整日等结构化维护成日历，交易员提前布局）——项目已有 event_calendar 注册表（离散事件类型+时点纪律 PIT：只用当时能获得的信息，防未来函数）和 macro_indicator 注册表（宏观指标发布纪律），**机制在，缺的是"未来两个月可预见事件"的前瞻填充**。
- **突发新闻流 breaking news**：拼的是速度和第一反应规则（突发利空→风险节流直接降仓，对接 kill_switch 侧），而不是拼分析深度。
- 黑天鹅不可预测 ≠ 不可用：它的特征是瞬时冲击大、波动率飙升，正确的姿势是"事后快速识别+仓位应对"，而不是试图提前押注。

**落地选项**：

- **A（MVP）**：打分器输出加 `predictability` 字段（scheduled 日历内 / unscheduled 突发），成本=一个 prompt 字段。
- **B（正解）**：event_calendar 前瞻填充器——把未来财报/解禁/会议/行业事件结构化入库，新闻流入库时与日历自动 join 打标。

**待决 Q2**：先 A 还是直接 B？

## 5. 议题四：预期消化——"利好出尽是利空" ★

**Owner 经验**（商业航天火箭回收案例）：回收成功当天暴涨、次日暴跌=主力趁利好出货；所以看新闻要看**板块位置**——高位出利好=兑现点，底部出利好=启动点。"新闻反着看，别墅靠大海"。

**关键认知**：**新闻方向 ≠ 交易方向**，中间隔着"价格已经消化了多少预期"。这**不是打分器的错**（打分器判"利好"判得对），而是打分器下游缺一个"反应层"——与 Owner 的判断一致：分析本身没问题，缺的是分析之外的两个独立维度。

**专业/量化社区做法**：

- **事件研究 event study**（统计某类事件落地前后股票的异常收益 abnormal return=超出市场基准的那部分收益，及其累计值 CAR）：用历史数据回答"高位+大利好落地后，平均是涨还是跌"——先有实证再定规则，防拍脑袋。
- **一致预期差 consensus surprise**（实际值与卖方/市场一致预期的差距）：机构圈铁律——**消息本身不重要，和预期的差才重要**。CPI 增 3% 是利好还是利空，取决于预期是 2.5% 还是 3.5%。
- **买预期卖事实 buy the rumor sell the news**（提前炒预期、落地就兑现）：A股题材股的典型节奏，对应 Owner 的火箭案例。
- **新闻新鲜度 news novelty**（同一个故事第 N 次出现，影响力指数衰减）：商业舆情服务的核心字段——"火箭回收成功"第一次是新闻，第五次是例行公事。
- **事前漂移 pre-event drift**（事件落地前 5/10/20 日板块涨幅）：量化"资金抢跑了多少"。

**落地形态（分层，不动 L1 打分器）**：

- **L1 内容分析层**（已有）：这条新闻是好是坏？
- **L3 预期消化层**（新建）：输入 = 新闻方向 × 关联板块/个股事前涨幅 × 位置分位（距 250 日低点涨幅、动量阶段——项目技术指标体系已有基础）× 是否日历内事件 × 第几次出现；输出 = **预期消化度 priced-in score**（0~1，>0.7 视为高度消化→交易上按"利好出尽"处理）。
- **风险**：这层最容易过拟合（历史规律未必重演）。必须先做事件研究拿 A股实证分布，再定阈值规则。

**架构归属**：按"情绪周期=sleeve 内 alpha 择时 / regime=市场级风险节流"的分工，L3 消化层属**情绪周期侧**（决定买卖什么），regime 侧的市场级利空计数不受影响。

**待决 Q3**：L3 先做事件研究实证（慢但稳），还是直接规则 MVP（快但可能错）？

## 6. 议题五：获取时效性与数据准确性（前提层）

**Owner 判断**：分析本身没问题——新闻**数据的时效性和准确性**才是分析对不对的前提。拆解：

- **(a) 采集时效**：新闻从发布到入库延迟多少？盘中快讯的价值按分钟衰减。回测用的 ClickHouse 历史库里 `publish_time` 是**发布时间**还是**入库时间**？若混用，回测会隐性引入未来函数——需一次口径审计（时点纪律 PIT point-in-time 的合规检查）。
- **(b) 准确性**：多源交叉验证（vote_score 已有多源一致性投票）、纠错与撤稿处理机制。
- **(c) 前瞻获取**：议题三 B 项（两个月后事件的日历填充）解决"提前埋伏"的信息源问题。

**待决 Q4**：`publish_time` 口径审计排什么优先级？（建议：高——它是全量回测可信度的地基）

## 7. 讨论收敛方向：三层模型

```
L1 内容层：这条新闻是好是坏？          （已有，F1 0.787，v2 prompt）
L2 时间层：这事能不能提前知道？        （议题三：可预期日历 vs 突发）
L3 消化层：价格已经反映了多少？        （议题四：位置 × 事前涨幅 × 新鲜度）

交易动作 = f(L1, L2, L3)，而不是 f(L1)
"新闻反着看" = L3 高度消化时的反向规则
```

三层各自独立演进、互不污染：L1 打分器继续按金标评估集考核；L2 是数据工程（日历）；L3 是实证研究（事件研究）。
