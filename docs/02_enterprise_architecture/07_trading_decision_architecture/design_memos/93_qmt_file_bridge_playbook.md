# 大QMT文件桥双向通道操作手册（miniQMT 替代方案）

> ## 结案报告（2026-08-28 全量审查批，代码实证）
> **实际开发**：qmt_file_bridge_broker.py（E:\qmt_bridge 实盘/E:\qmt_bridge_sim 模拟双分区+orders/ack 回执文件对+隔 1~2 秒回执确认机制）；qmt_file_bridge_quote.py（行情出口读取，draft 成熟度）；蓝图 MOD-L06-001-QMTFB（哑执行器 v14+异步回填语义）；前端 qmt_bridge_health.py 健康面板（3 秒自刷）。

> **未做+原因**：①quote 侧 draft 成熟度（消费方驱动按需成熟）；②无独立计划任务脚本属设计内（导出=QMT 侧系统设置零代码，项目侧由持仓监控/对账消费方驱动）。

> 本备忘记录 miniQMT 清退后，项目与券商终端之间**唯一合规双向通道**的架构、实证证据与逐步打开方法。

## 1. 一句话结论

**miniQMT（迅投轻型直连接口，本地 Python 通过 xtquant 直连交易）死了，大QMT（迅投标准版客户端，策略运行在客户端沙箱内）活着。项目与沙箱之间的双向通道 = "项目写指令文件 → 沙箱内哑执行器读文件下单（进口）"+"官方自动导出与策略查询把资金/持仓/成交写成文件（出口）"。本系统这种"本地重型大脑"的个人开发者，这是唯一现实合规通道。**

## 3. 通道架构

```
ZephyrAlpha（大脑：因子/情绪/组合/风控，本机，零改动）
        │  每天产出指令文件 orders_YYYYMMDD.csv（GBK 或 ASCII）
        ▼
┌─ 大QMT 沙箱（XtItClient 内置 Python 3.6）─────────────────┐
│  哑执行器策略（纯 ASCII 源码，常驻模型交易）                │
│    读指令文件 → 校验（幂等/金额上限）→ passorder 下单       │
│    passorder＝大QMT 内置下单函数（事件驱动框架的官方委托口）  │
└──────────────────────────────────────────────┬───────────┘
        │ 出口双通道                             │ 报单进券商柜台
        ▼                                        ▼
① 官方自动导出（系统设置级，零代码）：          ② 策略内 get_trade_detail_data 查询
   Stock/PositionStatics.csv（持仓）              get_trade_detail_data＝大QMT 内置账户
   Stock/Account.csv（资金）                      查询函数（资金/持仓/委托/成交）
   Stock/Order.csv + Deal.csv（委托/成交）
   Message.csv（消息提示/废单原因）
        │
        ▼
E:\qmt_bridge\（桥接目录，GBK 编码文件）
        │
        ▼
ZephyrAlpha 读取 → 持仓监控/对账/风控闭环
```

- **进口（项目→QMT）**：指令文件 → 哑执行器 → passorder
- **出口（QMT→项目）**：官方自动导出（主）+ 策略内查询（辅）
- 全部交换文件为 **GBK 编码**（QMT 侧默认），项目侧读写按 GBK 处理

**⚠ 两个终端级铁律（2026-08-25 模拟终端实证踩出）**：
1. **导出设置按终端独立**——实盘/模拟/未来每个 QMT 终端各自持有一份设置，新终端必须各自配一遍（模拟终端委托/成交导出间隔默认 1.00 秒，与实盘 0.10 秒不同，注意核对）。
2. **覆盖陷阱：多终端禁止共用同一导出目录**——实盘与模拟都导 `E:\qmt_bridge` 会互相覆盖 `Stock\PositionStatics.csv` 等同名文件（实盘真持仓会被模拟假数据盖掉）。**分区约定**：实盘 = `E:\qmt_bridge\`，模拟 = `E:\qmt_bridge_sim\`；多账户再按 `acct_<资金账号>\` 二级分区（指令文件与回执同样按账号分区，连接器设计的一等公民）。

### B. 进口通道：策略创建与启动（三条铁律见 §6）

**B-1 写策略代码（铁律一：纯 ASCII 源码）**
- 源码只允许 ASCII 字符：注释用英文，中文路径用 `\uXXXX` 转义（例：`E:\国金证券QMT交易端` = `'E:\\u56fd\u91d1\u8bc1\u5238QMT\u4ea4\u6613\u7aef'`）
- 头部声明 `# -*- coding: utf-8 -*-`
- 原因：编辑器按 GBK 保存、引擎按 UTF-8 解码，任何中文字符 → SyntaxError → 秒起秒停无解释

**B-2 注册策略**：策略编辑器 →【新建策略文件】→ 粘贴 → 保存（命名，如 ZEPHYR_EXEC）→【编译】
- AI 直写磁盘文件（`E:\国金证券QMT交易端\python\<名>.py`）**不会**自动出现在模型交易列表——模型交易列表读注册表，必须在编辑器里保存过一次才算注册

**B-3 启动策略（铁律二：正确入口）**：大QMT【模型交易】面板 →【新建策略交易】：
- 策略类型=刚保存的策略；账号类型=**股票**；资金账号=`8887871993`
- 主图代码=`000300`（仅驱动 K 线的壳，逻辑不依赖）；运行周期=`1分钟`
- 运行模式：先**模拟**验证，稳定后切**实盘**
- 可选：勾【终端启动后自动运行】（QMT 一开策略自启，免每日手动）
- ⚠ **不要点编辑器里的【运行】**——那是指标试跑，不执行 init，纯假动作
- ⚠ **不要在编辑器里重新保存 AI 直写的 UTF-8 文件**——编辑器会把它覆盖回 GBK

**B-4 验收**：面板下方【策略日志】出现策略名前缀的打印（如 `INIT_OK_12345`）即通；引擎底层日志在 `E:\国金证券QMT交易端\userdata\log\XtClient_Formula_YYYYMMDD.log`（GBK）

### C. 正式执行器 v14（tick 级，实测通过版）

**文件位置**：
- 模拟终端：`E:\qmt_bridge_sim\ZEPHYR_EXEC_v14.txt` → 编辑器粘贴保存为 `ZEPHYR_EXEC`
- 实盘终端：`E:\qmt_bridge\ZEPHYR_EXEC_REAL.txt` → 编辑器粘贴保存为 `ZEPHYR_EXEC_REAL`

**核心机制**：
- **触发**：分笔线周期（逐笔/快照驱动，1~2 秒/次）
- **幂等**：两阶段文件状态机——裸行→`#SENDING`（passorder 前原子改名）→`#DONE`（柜台 remark 确认后）
- **容错**：`#SENDING` 超 30 tick（约 1 分钟）自动回滚重试，3 次失败转 `#FAIL` + ack 报警
- **撤单**：`action=cancel`，按目标订单 remark 定位 sysid，支持同批指令延迟处理

**指令文件格式**（`orders_sim.csv` / `orders_real.csv`）：
```csv
order_id,action,symbol,side,qty,pricetype,price
T2001,order,510300.SH,buy,100,latest,0
C2001,cancel,T2001,,,,,
```

**回执文件**（`ack_sim.csv` / `ack_real.csv`）：`oid,STATUS,detail`

### 11.6 备胎调研结论：迪雅数据（2026-08-26 网调）

**核心结论：迪雅数据是 REST 轮询 API（GET/POST + JSON），不是 WebSocket 推送**。官网"毫秒级推送"为营销话术，文档实证全部为请求-响应式端点（如 `GET https://api.cxdy.vip/api/scgl?apiKey=...`）。无 Key 时实时行情端点路径未公开（注册后可见），已知端点：沪深京列表 `/api/hslb`、市场概览 `/api/scgl`。

| 维度 | 迪雅数据 | QMT 反向行情桥（主源） | 新浪 Level-2 |
|---|---|---|---|
| 接入方式 | REST 轮询（apiKey） | 文件桥（免费） | 官方无 API；社区逆向 WebSocket（灰色） |
| 专业版价格 | ¥1099/年（10,000 次/天） | ¥0 | 标准版 ¥998/年（普及版 ¥298 接口不同） |
| 实时性 | 取决于轮询频率，3 秒轮询≈3 秒延迟 | tick 级（1~2 秒） | 逆向 WS 毫秒级，但 3~5 分钟强制断连重认证 |
| 5档盘口 | 有 | 有（get_full_tick） | 10 档 + 逐笔（标准版） |
| 调用预算测算 | 单标的 3 秒轮询：4h×3600s÷3s≈4,800 次/天，10,000 次额度可覆盖 2 只标的 | 无限制 | 无调用限制，但无 SLA、账号密码登录、有封禁风险 |

**新浪 Level-2 调查结论（2026-08-26 网调）**：官方定位是客户端/Web 看盘产品，**不公开开发者 API**；社区存在逆向接入方案（sinalv2 / SinaL2，机制：新浪账号登录→取 token→`ws://ff.sinajs.cn/wskt` WebSocket 推送 10 档+逐笔），但 token 与连接均 3~5 分钟过期需自动重连、属违反用户协议的灰色用法、无 SLA，**不能作为生产交易数据源**。

**裁定**：迪雅数据与新浪 Level-2 均降级为**纯备胎**——QMT 反向行情桥免费且更快（tick 级 vs 3 秒轮询），迪雅仅在"QMT 行情政策收紧/沙箱禁读行情"时启用（届时注册 5 天免费试用拿 apiToken，按 §11.3 同接口实现 DiyadataQuoteProvider：REST 轮询 + 本地缓存 + 调用预算守卫，工作量小，不在当前施工）；新浪仅在需要 10 档/逐笔且接受灰色风险时考虑。**Level-2 合规正解仍是等客户经理确认券商侧权限**（随 QMT 终端走，合规且稳定）。

### 13.3 三层长期预案（桥方案 ↔ 降级备胎 ↔ 大脑搬家的触发关系）

**核心认知**：保险备胎（沙箱内自算自下）= **阉割版策略**——沙箱只有行情类数据，**新闻/情绪/宽度等特色数据（ClickHouse 独有）沙箱拿不到**，新闻因子策略在备胎形态下停摆。备胎是"降级保命"（还有 K 线因子能交易），不是同等能力备份。

| 层 | 形态 | 桥传什么 | 策略能力 | 触发条件 |
|---|---|---|---|---|
| **L1 主用** | 桥方案（现状）：本地大脑→桥→沙箱哑执行器 | 每笔订单指令（高频） | **全量**（新闻因子等全数据） | 默认 |
| L2 临时 | 文件桥兜底 | 同 L1（慢，5.7s） | **全量**（数据在本地，只是传输慢） | QMT 重启/午休冻结/HTTP 偶发失败 |
| **L3 逃生** | **大脑搬家（部分）**：交易决策逻辑复制进沙箱，自算自下 | 仅参数（低频，周级搬运） | **降级**（K 线因子保命，新闻策略停摆） | **官方公告收紧沙箱文件 IO/Socket**（传闻级，未发生） |
| L4 终极 | GUI 自动化（EasyTrader 思路：pywinauto 模拟人工点击官方下单界面） | 无（界面即通道） | 全量信号本地算，人手节奏下单（2-5s/单） | L1-L3 全被封（沙箱对外通信全禁） |

**L4 不可封死的逻辑**：机器人点击与真人点击在界面层无法根忿区分——封 L4=宣布「客户端不许人用」=自废产品。但代价也最大：UI 变更即崩（EasyTrader 维护史=与客户端升级的赛跑）、合规定位最灰（UI 模拟违反用户协议）、单笔最慢。**只做预案不写代码**，L1-L3 全灭才启动。

**L3 演练纪律**：即使 L1 正常，每月一次「参数搬运演练」（当前实盘策略的参数文件人工粘贴进沙箱备用策略验证可运行）——保持逃生门熟练，真触发时切换成本=一次搬运。

**L3 触发的技术背景（Owner 质询定论 2026-09-04）**：「沙箱收紧文件 IO/Socket」技术上**封堵零难度**——券商控制解释器（patch builtins.open 限路径）/ OS ACL（用户账户写不进保护目录）/ 配置签名校验（改一字节即失效）/ 虚拟文件系统，四法任选其一即可，**是业务选择不是技术限制**。现阶段不封的理由：误伤存量合法策略+监管火力在 miniQMT 清退本身。故 L3 演练=对口子随时关闭的对冲，且盯 QMT 版本更新公告为收紧预警哨。

**L3 的两条保通路**（防"L3 期间连参数都传不进去"）：
1. 文件是官方认可的导出介质（券商自己用文件导出做数据交换）——被一刀切封掉概率低于 Socket
2. 备选通道：沙箱直读 ClickHouse HTTP 接口（VM 172.24.30.100:8123，需实测沙箱网络可达性）——参数/小数据可走数据库中转
