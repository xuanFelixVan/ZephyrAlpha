# 大QMT文件桥双向通道操作手册（miniQMT 替代方案）

> 本备忘记录 miniQMT 清退后，项目与券商终端之间**唯一合规双向通道**的架构、实证证据与逐步打开方法。
> 上游衔接：[40_execution_broker](40_execution_broker.md) 决策⑲（MiniQMT 政策关注）——2026-08-25 政策风险正式兑现，本备忘是兑现后的落地答案。
> 性质：永久态操作手册，全部步骤经 2026-08-25 实盘终端逐项实证，不是推测。

## 1. 一句话结论

**miniQMT（迅投轻型直连接口，本地 Python 通过 xtquant 直连交易）死了，大QMT（迅投标准版客户端，策略运行在客户端沙箱内）活着。项目与沙箱之间的双向通道 = "项目写指令文件 → 沙箱内哑执行器读文件下单（进口）"+"官方自动导出与策略查询把资金/持仓/成交写成文件（出口）"。本系统这种"本地重型大脑"的个人开发者，这是唯一现实合规通道。**

## 2. 背景与裁定

### 2.1 政策时间线（已核实）
- 2026-07-06：多家券商停止 miniQMT 新增开通（国金在列）
- 2026-08-21：国金证券向存量用户下发通知，**2026-09-18 miniQMT 全面清退**
- 监管逻辑：miniQMT 策略跑在券商视野外（"外接系统"），违反穿透式监管导向；大QMT 策略跑在客户端沙箱内，券商看得见、可风控、留痕可回溯，故保留

### 2.2 唯一性论证（为什么只剩这条路）
| 候选通道 | 判定 | 原因 |
|---|---|---|
| 换券商再开 miniQMT（财达/东北等） | ❌ | 监管统一清退，缓刑几个月且白压资金 |
| 大QMT 文件桥（本方案） | ✅ **唯一解** | 执行进沙箱（合规）+ 文件交换（官方认可介质）+ 本地大脑零改动 |
| PTrade（恒生云端托管终端，策略部署在券商服务器运行） | 备选备胎 | 装不下本项目（无本地文件、无 ClickHouse/Ollama、共享算力），适合轻策略 |
| 预埋单导入（QMT 交易面板从文本文件导入委托单一键发送） | 兜底 | 半自动（每天需人工点一次发送），进口通道的政策级后备 |
| 机构柜台 | ❌ | 300 万门槛，不适用 |

## 3. 通道架构

```
ZephyrAlpha（大脑：因子/情绪/组合/风控，本机，零改动）
        │  每天产出指令文件 orders_YYYYMMDD.csv（GBK 或 ASCII）
        ▼
┌─ 大QMT 沙箱（XtItClient 内置 Python 3.6）─────────────────┐
│  哑执行器策略（纯 ASCII 源码，常驻模型交易）                │
│    读指令文件 → 校验（幂等/金额上限）→ passorder 下单       │
│    passorder＝大QMT 内置下单函数（事件驱动框架的官方委托口）  │
└──────────────────────────────────────────────┬───────────┘
        │ 出口双通道                             │ 报单进券商柜台
        ▼                                        ▼
① 官方自动导出（系统设置级，零代码）：          ② 策略内 get_trade_detail_data 查询
   Stock/PositionStatics.csv（持仓）              get_trade_detail_data＝大QMT 内置账户
   Stock/Account.csv（资金）                      查询函数（资金/持仓/委托/成交）
   Stock/Order.csv + Deal.csv（委托/成交）
   Message.csv（消息提示/废单原因）
        │
        ▼
E:\qmt_bridge\（桥接目录，GBK 编码文件）
        │
        ▼
ZephyrAlpha 读取 → 持仓监控/对账/风控闭环
```

- **进口（项目→QMT）**：指令文件 → 哑执行器 → passorder
- **出口（QMT→项目）**：官方自动导出（主）+ 策略内查询（辅）
- 全部交换文件为 **GBK 编码**（QMT 侧默认），项目侧读写按 GBK 处理

## 5. 打开方法 SOP（标准作业程序，照做即可复现）

### A. 出口通道：官方自动导出（零代码，10 分钟）
路径：大QMT →【设置】→【系统设置】→【导出设置】

| 设置项 | 值 |
|---|---|
| 自动导出 | ✅ 勾 |
| 导出间隔 | 委托/成交 0.10 秒；资金/持仓/标的券/负债 10 秒 |
| 开始/结束时间 | 08:50:00 – 15:40:00 |
| 盘后导出 | ✅ 勾（收盘时间 15:20） |
| 导出文件以日期时间为后缀 | ❌ 不勾（保持固定文件名，程序好读） |
| 设置默认导出路径 | ✅ 勾，设为 `E:\qmt_bridge` |
| 导出历史数据天数 | 7 天 |
| 文本导出共享读模式 | ✅ 勾（允许外部边写边读，防文件占用冲突） |
| 股票交易→持仓/委托/成交/账号导出 | 列全选，路径在 `E:\qmt_bridge\Stock\` 下 |
| 全局信息→消息提示导出 | 列全选（日期/时间/账号/类别/级别/消息），路径 `E:\qmt_bridge\Message.csv` |

产出文件（GBK 编码）：`Stock/PositionStatics.csv`（持仓）、`Stock/Account.csv`（资金）、`Stock/Order.csv`（委托）、`Stock/Deal.csv`（成交）、`Message.csv`（废单原因等）。注意：导出只在时间窗（08:50-15:40）内刷新，盘后无新文件属正常。

### B. 进口通道：策略创建与启动（三条铁律见 §6）

**B-1 写策略代码（铁律一：纯 ASCII 源码）**
- 源码只允许 ASCII 字符：注释用英文，中文路径用 `\uXXXX` 转义（例：`E:\国金证券QMT交易端` = `'E:\\u56fd\u91d1\u8bc1\u5238QMT\u4ea4\u6613\u7aef'`）
- 头部声明 `# -*- coding: utf-8 -*-`
- 原因：编辑器按 GBK 保存、引擎按 UTF-8 解码，任何中文字符 → SyntaxError → 秒起秒停无解释

**B-2 注册策略**：策略编辑器 →【新建策略文件】→ 粘贴 → 保存（命名，如 ZEPHYR_EXEC）→【编译】
- AI 直写磁盘文件（`E:\国金证券QMT交易端\python\<名>.py`）**不会**自动出现在模型交易列表——模型交易列表读注册表，必须在编辑器里保存过一次才算注册

**B-3 启动策略（铁律二：正确入口）**：大QMT【模型交易】面板 →【新建策略交易】：
- 策略类型=刚保存的策略；账号类型=**股票**；资金账号=`8887871993`
- 主图代码=`000300`（仅驱动 K 线的壳，逻辑不依赖）；运行周期=`1分钟`
- 运行模式：先**模拟**验证，稳定后切**实盘**
- 可选：勾【终端启动后自动运行】（QMT 一开策略自启，免每日手动）
- ⚠ **不要点编辑器里的【运行】**——那是指标试跑，不执行 init，纯假动作
- ⚠ **不要在编辑器里重新保存 AI 直写的 UTF-8 文件**——编辑器会把它覆盖回 GBK

**B-4 验收**：面板下方【策略日志】出现策略名前缀的打印（如 `INIT_OK_12345`）即通；引擎底层日志在 `E:\国金证券QMT交易端\userdata\log\XtClient_Formula_YYYYMMDD.log`（GBK）

## 6. 三大坑排障表（2026-08-25 实测踩出，后来者可按症状直查）

| 症状 | 病根 | 修法 |
|---|---|---|
| 点编辑器【运行】，日志只有"开始运行/结束运行"，init 不执行 | 编辑器运行=指标试跑，不调用 init/handlebar（init/handlebar＝大QMT 策略框架的初始化/行情驱动两个入口函数） | 去【模型交易】面板新建策略交易并启动 |
| 模型交易里启动秒起秒停、策略日志空白、引擎日志无 subscribe | 该行"模型交易"配置损坏（账号/模式未配对），之后每次启动重复同一坏配置 | **删除该行，重新【新建策略交易】配好再启动**；对照法：同设置跑官方策略，官方能跑即证明是行坏不是环境坏 |
| 策略日志报 `SyntaxError: 'utf-8' codec can't decode byte 0xXX` | 源码含中文，编辑器 GBK 保存 vs 引擎 UTF-8 解码打架 | 源码改纯 ASCII（中文路径 `\u` 转义），头部 `coding: utf-8` |

## 7. 合规定位

- 报单发自券商沙箱内终端，券商看得见、可风控、留痕可回溯——满足穿透式监管核心诉求
- 指令文件是离散"交易指令单"（买什么/多少股/什么价），非实时交易行为外移；执行器保持"哑"（只翻译指令 + 终端侧保命校验：幂等去重、单笔金额上限、价格笼子检查），策略逻辑永不进桥
- 上线前按 40_execution_broker 决策⑱ 完成程序化交易报备（策略类型/服务器地址/风控参数）
- 项目为中低频（日/周级调仓），距高频认定线（每秒 15 笔/单日 2 万笔）数个数量级，无高频合规暴露
