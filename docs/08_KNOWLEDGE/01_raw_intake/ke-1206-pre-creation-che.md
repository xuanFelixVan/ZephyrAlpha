# DOC-005：创建前必查（Pre-Creation Check）

DOC-005：创建前必查（Pre-Creation Check）

AI 在创建任何文件或目录之前，必须执行"验架构 → 选位置 → 查重 → 融入或创建"工作流。创建新文件永远是最后选项，不是第一反应。

- **规则**：

  **前置步 —— 架构上下文自检（先看结构对不对）**
  - 执行 `../../meta/governance-methodology-standard.md`（PS-STD-011）MTH-002（架构上下文自检）的四步流程
  - 确认目标架构层完整——该层已有架构描述文件且已通过验证
  - 若该层架构不完整 → 优先补全架构文件，不得在不完整的架构层中创建孤立文件

  **Step 1 —— 精准定位（选对放的地方）**
  - 先查 `../../governance/document/trae_028_doc_structure_naming.yaml`（GOV-DOC-002）是否定义了该文件类型应放置的位置
  - 如果项目标准已定义 → 严格遵守
  - 如果项目标准未定义 → 参考 `../../meta/governance-methodology-standard.md`（PS-STD-011）中的 MTH-001 标准先行原则，参考专业机构做法（ITIL SACM / ISO 9001 §7.5）确定位置
  - 禁止凭直觉或习惯随手放置文件

  **Step 2 —— 查重扫描（有没有类似的）**
  - 在确定的目标位置及整个项目中搜索功能/主题相似的文件
  - 使用 glob + grep 搜索文件名、frontmatter summary、tags 字段
  - **操作定义**："内容接近" = 两个文件对同一架构事实（同一个规则、同一个实体、同一个流程）有定义或描述。针对不同事实的两个文件，即使用词相似，也不视为"内容接近"
  - 如果发现针对同一架构事实的相似文件 → 进入 Step 3
  - 如果未发现 → 直接创建，且仅创建一份（遵循 DOC-001 SSoT 唯一）

  **Step 3 —— 融入优先（不重复造轮子）**
  - 如果存在针对同一架构事实的相似文件：评估是否可以融入现有文件（扩展内容 / 补充章节）
  - 融入优于创建——优先修改现有文件，而非新建
  - 如果融入会导致文件职责不清 → 先按 DOC-002 重新划分责任边界，再决定是否需要新文件
  - 如果确认需要独立文件 → 必须在两个文件的 depends_on 中互相引用，明确管辖范围边界

- **违反后果**：目录结构混乱、同一内容分散在多个文件中、AI 在多个文件间不确定哪个是权威来源
- **验证方式**：每次文件创建操作后审查是否有功能重复的现有文件被遗漏
- **专业参考**：ITIL SACM → Golden Record / ISO 9001 §7.5 → Document Creation Review / Vibe Coding 社区 → creation-guard 技能

> **本原则与其他原则的关系**：DOC-005 的查重扫描（Step 2）是 DOC-001（SSoT 唯一）的执行保障——没有查重就不会发现重复。融入与独立文件的判断（Step 3）依赖 DOC-002（责任二选一）定义的责任边界。位置确定（Step 1）依赖 GOV-DOC-002 的目录结构规范。DOC-003（安全删除）与 DOC-005 互为反操作——删除前确认目标文件有内容（Step 1~3），创建前确认没有重复（Step 2~3）。
