# 2. 核心管道架构

2. 核心管道架构

```
规则文档入口
     │
     ▼
┌──────────────────────────────────────────────────────────────┐
│                     SemanticAuditPipeline                     │
│                                                              │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐  │
│  │ Stage 1  │──▶│ Stage 2  │──▶│ Stage 3  │──▶│ Stage 4  │  │
│  │ 引用提取 │   │ 触发检测 │   │ 安全过滤 │   │ 双向对齐 │  │
│  │ Extract  │   │ Trigger  │   │  Safety  │   │  Align   │  │
│  └──────────┘   └──────────┘   └──────────┘   └──────────┘  │
│       │              │              │              │         │
│       ▼              ▼              ▼              ▼         │
│  ┌──────────────────────────────────────────────────────┐   │
│  │              Stage 5: 问题聚合与去重                  │   │
│  └──────────────────────────────────────────────────────┘   │
│       │                                                      │
│       ▼                                                      │
│  ┌──────────┐                                                │
│  │ Stage 6  │  ← 仅对有修复建议的 RED 问题                    │
│  │ LLM 桥接 │     LLM 只生成修复文本——不做判断               │
│  └──────────┘                                                │
│       │                                                      │
│       ▼                                                      │
│  ┌──────────────────────────────────────┐                   │
│  │       SemanticAuditReport            │                   │
│  │  ┌────────┬────────┬──────────────┐  │                   │
│  │  │Issues  │Aligned │SafetyFiltered│  │                   │
│  │  └────────┴────────┴──────────────┘  │                   │
│  └──────────────────────────────────────┘                   │
└──────────────────────────────────────────────────────────────┘
```

| Stage | 输入 | 输出 | 是否调用 LLM |
|:---:|------|------|:---:|
| 1 | 规则文档 Markdown/文本 | 提取出的结构化引用清单（路径/ID/数字） | ❌ |
| 2 | 结构化引用清单 | 三类触发条件的命中结果 | ❌ |
| 3 | 触发命中结果 | 经过安全边界过滤的可操作问题 | ❌ |
| 4 | 注册表清单 + 磁盘清单 | 双向对齐差异报告 | ❌ |
| 5 | Stage 2 + 3 + 4 结果 | 去重聚合的问题清单 | ❌ |
| 6 | RED 问题 + 修复文本请求 | LLM 润色后的修复建议 | ✅（仅此处） |

> **关键设计**：Stage 1-5 全是机械操作——零 LLM、零随机性。只有 Stage 6 调用 LLM，且 LLM 的角色是**"翻译"已有修复建议为自然语言文本**，不做判断。
