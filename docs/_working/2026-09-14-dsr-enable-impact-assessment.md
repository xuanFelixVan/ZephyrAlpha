## 一、先纠正一个根本性误解：DSR 是概率，不是夏普

`src/zephyr/backtest/core/metrics.py:385`：`dsr = _norm_cdf(z)` —— **DSR ∈ [0, 1]，是"这个 Sharpe 超出运气成分的概率"**，不是调整后的夏普值。

源码注释（L389-390）给的两条线才是权威口径：

| 阈值 | 语义 | 出处 |
|---|---|---|
| **0.5** | `DSR_OVERFITTING_FLOOR`——**运气中值否决线**，低于此 = 无超出运气的证据 | metrics.py:391 `is_overfitting = dsr < 0.5` |
| **0.95** | **显著性放行线** | MOD-SIM-024 `is_significant`；`sharpe_calculator_fixer.py:168` `dsr_threshold: float = 0.95` |

**由此得出第一个坏消息**：`DecisionGate` 的测试里用的是 `DecisionGateConfig(dsr_threshold=0.5)`（`tests/backtest/test_decision_gate.py:264` 等 8 处）。若照抄这个数进生产，**等于"只要不比抛硬币差就放行"——这不是防过拟合，是发安慰剂。**

同时暴露同名不同义的隐患：`sharpe_calculator_fixer.dsr_threshold=0.95`（正确）与 `DecisionGateConfig.dsr_threshold`（tests 用 0.5）**两个同名配置、两套量纲理解**，必须统一。

## 四、三个必须同时修的坑

### 坑 1：`num_trials` 口径错（最严重）
`c4_deflated_sharpe_runner.py:117` 注释：「`num_trials: int  # 多重比较试次数（默认=变体数）`」，`_c4_engine.py:290` 同样是「num_trials=变体数口径」。

**每批只按本批变体数（35 / 51 / 374）算，而不是全厂累计试验数。** 这直接导致现有 133 条 DSR **系统性偏乐观**（metrics.py:306 早已警告："调用方 MUST 传入实际试错次数，若实际>10 而未显式传入，DSR 会偏乐观"）。

按累计 N=1102 重算，连唯一那条 0.9809 都掉到 0.5339。

### 坑 2：阈值口径错
见 §一。正确放行线 0.95，不是 0.5。

### 坑 3：fail-closed 会把"没考过"误杀成"不及格"
`decision_gate.py:683`：「DSR 判定器已启用但未注入 dsr，按不通过处理（fail-closed）」。

那 **51 条有 IS 但从未算过 DSR 的记录**，一旦开启开关会被判不通过。但它们的真实状态是**"没考过"，不是"没考好"**。把它们记成 rejected 会污染台账语义（distinguish：应记为 `not_tested` 而非 `rejected`）。

## 五、对我上一轮方案的诚实修正（重要）

我在《组合层穷尽网格立项稿》§五-3 写的是「**DSR 必须按批内总试验数 N 折减**」。实测数据打脸了：

网格 16.1 万条 → N=161000 → E[max(Z_N)] = 4.90；而 N=35 时 E[max(Z_N)] = 2.21。
**差 2.69 个 σ_SR。** 要过 0.95 线，策略 Sharpe 得比现在高出 2.69σ —— 数学上基本不可能。

**结论：穷尽法与 DSR 天然冲突。** 试得越多，门槛越高，这是 DSR 的设计本意，不是 bug。三个可选立场：

| 立场 | 含义 | 代价 |
|---|---|---|
| a. 硬刚 | 接受"工厂量产零幸存"，工厂价值全部落在**阴性库** | 心理上难接受，但最诚实 |
| b. 分层记账 N | 粗筛阶段不计数，只有进正考的几百条才计 N | 宽松口径，必须显式标注，否则自欺 |
| c. **改工厂目标**（推荐） | 不追求"挖出能上的策略"，追求"穷尽死路 + 对已有组合的增量 IC 贡献" | 与 AlphaGen 的"组合协同"思想一致，且 E5 增量 IC 本来就是这个口径 |

建议走 **c + a**：主目标改为增量 IC 与阴性库，DSR 只作为"万一出现真幸存者"时的确认工具，不作为工厂的产出 KPI。

## 六、建议：分三步，不要一步到位

1. **先修口径，不动开关**（零风险）
   - `num_trials` 改为累计试验数（新增一个全局累计计数器，真源入注册表）
   - 全量重算台账 133 条 DSR，回填 51 条缺口
   - 产出一份"真实底账"，看看在正确口径下还剩几条
2. **再定阈值**（需裁定）
   - ≥0.95 放行；<0.5 直接拒；中间区间 = 存疑，需补样本或降规模
   - 统一 `sharpe_calculator_fixer` 与 `DecisionGateConfig` 的同名配置
3. **最后开开关，且只对新批次生效**
   - 存量策略不追溯翻案（避免把已归档的结论重新搅乱）
   - 新批次强制注入 DSR，未注入记 `not_tested` 而非 `rejected`
