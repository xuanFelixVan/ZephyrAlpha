### 1.2 ★ verify 判据到底是什么（硬实查任务 1，逐条给行号）

**不是"逐位全量比对"，是"行数 + 随机 100 行多重集比对"两级**：

1. **行数比对**（`archiver.py:395-415`）
   - Parquet 侧 = `pq.read_metadata(pq_path).num_rows`（footer 元数据，不读数据，:396-400）；
   - CH 侧 = `ch_reader.query(_SQL_COUNT_PARTITION)`，模板 `_SQL_COUNT_PARTITION = "SELECT count() FROM {table} WHERE {where}"`（:118 区段常量），FINAL 由 ch_reader 通道自动注入（同 `backfill_checker.py:8` INVARIANTS 记载"查询走 ch_reader 自动注入 FINAL"）；
   - **容差：`tolerance = 1 if ch_count > 1_000_000 else 0`（:408-409）** → 千万级分区允许差 1 行仍算过；注释理由（:407）＝"ClickHouse count() 元数据优化 vs FORMAT Parquet 已知差异"。
2. **抽样逐字段比对**（`archiver.py:417-430` + `_compare_sample_rows:320-354`）
   - 抽样 SQL `SELECT * FROM {t} WHERE {where} ORDER BY rand() LIMIT 100 FORMAT JSON`（:120），同样 `inject_final`（:423）防采中未合并幻影行；
   - 比对方式 = 两侧列取**交集**、值经 `_normalize_val`（:276-317）归一（None/NaN→""、Decimal/Float→repr(round6)、tz-aware 时间戳归一到 Asia/Shanghai 墙钟、零毫秒后缀去尾），构造 Parquet 侧 `Counter` 做**多重集**判定，任一行取不到即 `return False`（:344-350）；
   - **`ingest_ts` 列被显式排除**（:334-336，2026-09-20 修：同版本重复行 FINAL 折叠在"导出"与"抽样"两次查询之间可翻转出不同 ingest_ts）→ **行情数据列 100% 严比对，灌入元数据列不比**；
   - **>10,000,000 行的分区跳过抽样**（:429-430，只留行数判定）；抽样返回 0 行也放行（:328-331 `if not ch_rows: … return True`）。
3. **"verify 不等则不进 drop"的保护在哪一行**
   - `archiver.py:517-522`：
     ```
     if not verify_partition(table, partition, pq_path, period=period):
         log.error("verify 失败，不执行 drop，数据安全")
         if pq_path.exists(): pq_path.unlink()   # 删不可信 Parquet
         return False
     ```
   - 纯备份模式同保护在 `:577-581`；`drop_partition` 自身失败只记 `verified=true, dropped=false` 不写 dropped 旗（:529-543）→ 断点续传可重跑。
   - **保护语义是"顺序控制"而非"事务控制"**：drop 成功后 manifest 才写（:546-556），若 manifest 写失败会出现"盘已删、清单无记"，此时只能靠 `list_archived`/`stats`（:720/:742）与盘侧 Parquet 反查，**无自动对账**（实测未见对账件）。

**verify 的两次历史病灶（在册，决定"verify 曾长期是假绿"）**：
- `archiver.py:356-381` `_http_query_json` 头注逐字：*"2026-09-20 修：原走 ch_reader.query（ch_writer TCP 通道），TCP 路径 FORMAT JSON 被驱动吞掉、返回手工拼的 TSV → json.loads 必炸（'Extra data'）；**抽样比对自该病灶起恒败**"*。→ 恒败方向是"误杀"（verify=False→不 drop），不丢数据但会**静默阻塞归档**（表现为盘不腾、清单不长）。修复批 = commit `6684ba5d83`（提交注记含"archiver verify三病灶修复"）。
- `export` 侧 FINAL 化（:203-209 注）：*"2026-08-16 实证：kline_5min 35 分区、news_data 几乎全部热分区存在重复摄入，verify 正确拦截 10 分区；裸导物理行会把冗余永久固化进冷库"*。
