排除法（三件都实测否掉；第四件见 9.1bis 的双路对照）：

**真根因（一行代码）**：`next_day_forecaster.py:268-271`
```
same = next_rets.get(f"{rb}:{vb}", [])
fallback = len(same) < int(params["min_bucket_n"])
use_rets = same if not fallback else all_rets
use_ranges = same if not fallback else all_ranges      # ← BUG：应是 next_ranges
```
`same` 取的是 **next_rets**（次日**收益**序列），于是 `expected_range_pct`（第 294 行 `sum(use_ranges)/len(use_ranges)*100`）算出的**不是"次日日内振幅均值"，而是"次日收益均值"**。铁证：`next_ranges` 在第 242 行建、第 263 行填，**全件再无任何读取**（`grep -n "next_ranges"` 仅 2 命中）——作者意图明确，接线漏了一环。

**为什么这会造成断供而不是算错数**：校验器 `judgment_ledger.py:273-275` 对 `expected_range_pct` 施加 `须 ≥0`（振幅的非负性是对的，错的是喂进去的量）：
```
for k in ("expected_vol_pct", "expected_range_pct"):
    if k in p and _num(p[k], k) < 0:
        raise ValueError(f"{k} 非法（须 ≥0）: {p[k]!r}")
```
收益均值可为负 ⇒ **凡"该桶历史次日收益均值为负"的日子，判定永不发射**。而 `down:mid`、`flat:mid` 这类桶的样本均值天然为负 ⇒ 断供是**按桶确定性**发生的。钩子侧 `judgment_ledger.py:553-555` 把 ValueError 收成 `action="data_insufficient"`（设计意图="fail-closed 漏判…下个唤醒点自愈"），**但自愈永远不会来**；编排层 `_stage_next_day:201` 又把一切压成 `{"status":"ok", detail:str(out)}`，而 detail **不被任何持久化通道接收**（`run_daily_loop` 只 return，scheduler 只在非全绿时记 summary）⇒ 圈级照样 SUCCESS。

**第二起独立杀手（同一天可以只死于它）**：Laplace 平滑后三个概率各自 `round(x,6)`（`:333-335`），而校验器要求 `|sum-1| ≤ 1e-6`。6 位小数三分量之和可偏至 1.5e-6 ⇒ **浮点边界随机杀**。实测算例：业务日 09-21 的 `p=(0.366071,0.248214,0.385714)`，`abs(sum-1)=1.0000000000287557e-06 > 1e-06` → 拒发，**超出容差 2.9e-17**。

**量化（本簿以真 reader + 真校验器、零写入复跑最近 30 个交易日）**：**可发射 9 天 / 被杀 21 天 = 70% 杀率**；其中 `expected_range_pct<0` 杀 15 天、`和≠1` 杀 6 天。逐日 verdict 表与桶分布见 §实查命令 (3)。09-21/22/23 三天分别是 `psum 杀 / range 杀 / range 杀`——**三天三种死法，两条病因都在起作用**。
**能力仍活**：同一钩子用桩 emit 于今日实跑 → `{'action':'emitted','trade_date':'2026-09-23'}` ⇒ 修一行即可复流，无须重建环节（这也是本格判 🔨 不判红条目的依据）。
