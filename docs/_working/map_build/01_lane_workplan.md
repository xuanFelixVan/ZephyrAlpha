# 波2 排产表与两条自裁

> 本件是总包对六份骨架的**第一次消费产出**：把"每环节一本作业簿"落到可执行粒度，并定封矿单元。
> 骨架文件已被 q-…-0002 入袋，本件**不改写它们**（同 sid 同件后袋会静默取代前袋，见战役坑），要改骨架一律写进本件或另开卷。

## 自裁 A · 作业簿粒度律（覆盖共识件 §2 的字面口径）

**裁定**：作业簿粒度 = **段/族级**，一本簿覆盖 3~6 个相邻环节，**不是**一环节一簿。

**理由（第一性原理 + 项目既有法源）**：
1. `skeleton_mining_policy.md` §3 停止判据第三问："只是标签/品种/参数变 → **不拆**"。环节是骨架层的完整性检查单元，作业簿再按环节切片=同一生产者同一验证口径下的纯标签分裂。
2. 宪法 §4 全资产净零 + 裁定#375 内收判据：六图环节合计 121（图11 28 + 图12 18 + 图13 44 + 图14 17 + 图15 待计 + 图16 14），一环节一簿=121 个新建资产 + 121 条 creation_token，而每簿的"六向台账"里 上/下/旁 三向在同段内高度重复 → 典型"同真源可派生"，按判据**必并**。
3. 上下文预算（宪法 §6）：碎簿会让后续任何消费者读一条流程线要开 6~10 个文件，实际执行率下降——#ARCH-310 R3 已实证"规范总量与执行率负相关"。
4. 挖矿深度不因此打折：**每簿内仍须逐环节开小节**，环节编号是簿内锚点，"每格可实查"的判据一条不减。

**簿内强制结构**（六项缺一判"欠"）：
```
# 0X_<族名>.md
frontmatter: ttl: task_bound / completes_when / title / owner
§0 本簿覆盖的环节编号清单 + 一句话族职责
§1..§N 每环节一节（编号为小节标题，内含六向台账：上/下/内/旁/史/新）
§末 溢出条目（骨架外发现，须回写骨架的条目列表，交总包落笔）
§末 自审裁定：干 / 欠（缺哪向补什么） / 溢
§末 实查命令（可复跑）
```

## 自裁 B · 封矿单元律（消解指令 §六.4 与 §七.1 的字面冲突）

指令 §六.4 写"全部作业簿三态=干后总包宣告封矿，封矿前禁入施工"，§七.1 写"谁挖干谁先开工，多车道并行"。
**裁定**：封矿单元 = **单图**，不是全战役。任一图的作业簿集全"干"且骨架 §封顶声明落盘 → 该图即封矿、即入施工，其余图继续挖。
**理由**：一域一图（裁定#409）下六图是六个独立域，域间无共享真源（已实证：图16 与图13 零节点交集、图14 与图11 只在 handoff 锚交接）；全局闸会让先挖干的域空等最慢的域，违反"不是全体干等"的指令预期状态（§十）。**共享写域仍由总包串行收口**（token/裁定册/挂轴/config），所以并行不产生连坐。
