## §1 十一条目的标签（冻结版）

| # | 标签 | 一句大白话（存在的意义） |
|---|------|------------------------|
| 1 | 「你是谁」 | 进场先登记身份，干活留名，出了事找得到人 |
| 2 | 「你还活着吗」 | 证明施工队没死，死了别让它继续"代表你"说话 |
| 3 | 「这块地在谁手里」 | 改文件前先领地，防止两个人同时改一个文件互相踩 |
| 4 | 「新文件上户口」 | 新建的东西必须登记姓名籍贯，否则就是黑户，门禁见一次拦一次 |
| 5 | 「别拿假地址骗我」 | 防幻觉漂移——文件名、路径、引用必须真实存在，不许凭记忆编 |
| 6 | 「别人犯错别连坐我」 | 他人的违规不能算在我头上，各扫门前雪；死人的错我顺路扫（见 §2.1） |
| 7 | 「宁可留错不可删错」 | 档案安全——销账不可逆，删东西必须过最高审 |
| 8 | 「账本必须对得上」 | 一致性对账——册子和现实必须一致，两处说法必有一假 |
| 9 | 「代码的底线体面」 | 质量底线——格式、命名、时区这些不改就难受的洁癖 |
| 10 | 「死也要死得明白」 | 死信生命周期——为什么死、能不能救、救不了怎么体面下葬 |
| 11 | 「快而不漏」 | 提速——安检可以快，但检查项一项不能少 |

## §2 三个设计点（终版裁定建议）

### 2.1 顺路修复
- 规则：**无主遗留**（死会话遗物/孤儿文件）的违规出现在提交者路径上 → 可顺路修复 +
  台账留痕（一笔带飞）；**活会话在途**工作 → 不代修（owner 责任制保留）。
- 机制落点：外来 staged 违规处置从"warn+审计"两态扩为三态，第三态"顺路修"
  走 --adopt 语义，与 FOREIGN 三级处方（acquire→adopt→overlap）对齐。
- 预期收益：165 孤儿从专门清算任务变成所有会话的顺路税收。

### 2.2 先查再建（reuse-first）
- 规则：开工前强制扫三处（主区暂存区 / 活跃 worktree / 死信袋）找同类半成品，
  验真（内容比对）后 adopt，不新建。
- 机制落点：会话 onboarding 第 0 步=reuse_scan；死信袋复用 doctor --scan 的分诊索引。
- 预期收益：消化 31.5% "改动没落地"存量；从源头防"同一目标重试到第 11 版"再生长。

### 2.3 入口强制位（说明书必读）
- 规则：领 claim 或首次 enqueue 的必经点核"说明书已读"（按提交文件类型路由到
  FT-* 卡片），未读不发货，读没读可审计。
- 机制落点：commit guide 递送接口 + 审计 store；说明书由门禁配置机生，
  禁手写第二真源（原则已立法："拦截成本前移为指引成本"，2026-09-24 commitsys 战役）。
- 前置依赖：F1 判据重蒸馏（当前 25 台漂移源 + 3 台未蒸馏）。

## §3 病历本挂载设计（casebooks）

环节节点新增标准字段 `casebooks`：挂与该环节相关的永久病历设施（按稳定标识符引用）。

四条机规：
1. 病历本是**设施**，必须有登记身份（module_id / 册号）；散文散页不算病历本。
2. 完备性铁律：每本永久病历本必须被 ≥1 环节挂载；未挂 = 覆盖账本判红
   （治"病历本建成孤儿没人翻"）。
3. **只挂本，不挂病例**：203 孤儿处置等个案留在书页内，地图只挂书。
4. 引用不复制（INV-1 同款）。

首批挂载清单（F4 结构化时全量落）：
- death_cases_registry（死因案例册）→ 门禁链环节 + 死信环节
- all_problems_ledger（堵点本五域）→ 各环节挂各章
- dead_letter_salvage_ledger_20261003（抢救台账）→ 死信环节
- review_findings / review_findings_round2 → 对账观测环节
- 记忆教训索引 → 各环节 facts 层

效果：看任何一个环节，同时看到三样——机制（谁在干活）+ 实测（干得怎么样）+
病历（这里历史上犯过什么病）。重复机制、零消费病历在挂载面上全是红的。

## §4 一岗多流程准入判据（Owner 2026-10-03 定）

判据原文：**只要属于这个流程、影响它的速度/效率/质量，就挂。**

- 多挂 = 多处**引用**（INV-1），不是复制；编制真源唯一（模块的"家图"），
  他图挂"伸进来的那只手"并标注影响因子。
- 覆盖账本判红两头：该挂没挂 = 孤儿；抄内容而非引用 = 第二真源。
- 首例：W-M1 意图 API——家在 GOMAP（数据层），图11 挂"注册册写入必经点"
  （提交改注册册必经它 = 提交速度因子）。
- 边界示例：W-M1 baseline 导入引擎（不落在提交路径上、不影响提交速度）不挂图11。
