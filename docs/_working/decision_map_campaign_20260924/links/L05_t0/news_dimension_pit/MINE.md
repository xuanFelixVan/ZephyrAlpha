# 新闻与情绪维度的时点可得性 · MINE

## ① 职责一句话

把"新闻十分位轴 v1 阻断"从一条**结论**挖成一份**根因解剖**：到底是没标注、标注填错了列、还是发布时点不可证——三者对应的解锁成本和解锁路径完全不同，本矿负责把它们分开量出来。

## ② 现状实测（2026-09-26 只读探针，`c3_fundamental.news_data` 全表 8,188,768 行）

**归因面（轴能不能建）**

| 列 | 类型 | 非空填充（全表 8.19M 行） | 判读 |
|---|---|---|---|
| `related_symbols` | `Array(String)` | **80 行**（0.001%） | 字段设计正确但采集侧几乎从未写入 |
| `related_symbol`（单数） | String | **0** | 死列 |
| `short_name` | String | **0** | 死列（本可承载股票简称→归因） |
| `security_type` | String | **0** | 死列 |
| `keyword` | String | 2,784,888（34%） | 唯一可能有标的指向的列，但按在册禁令**禁用它做模糊匹配造料** |
| `sentiment_score` / `sentiment_label` | — | **50 / 100 行** | 情绪打分实际未落地（与 L02 c6 车道独立实证"llm 分支 3 行=不可用级"**同向**，两独立内部源） |
| `category` / `data_source` | LowCardinality/String | 8,188,768（100%） | 唯一满填的两列（类别面可用，标的面不可用） |

- 研究窗（publish_time ∈ [2021-09-01, 2025-09-09]）行数=**2,865,189**，其中带 `related_symbols` 的=**0**（与 readme §3.4 的 2,841,834 相差 23,355 行，差因=readme 按日界/本探针含 09-09 全天秒界，属**窗口口径微差需统一**，L05-NW-G6）。
- 全表 `uniqExact(news_id)`=7,910,989 vs 8,188,768 行 ⇒ **约 27.8 万条重复 news_id（3.4%）**（聚合观察级，定性须逐条判重，本矿不动库、不判破坏性操作）。
- 源分布 top6（全部 related_symbols=0）：巨潮网 982,508 / 每日经济新闻 580,758 / 证券时报 420,426 / 界面新闻 343,334 / `akshare_research_report` 339,178 / 空 source 276,377。⇒ **巨潮网=交易所指定披露平台，其公告天然带股票代码，却在落库时把归因丢了**（L05-NW-G1 是本矿性价比最高的解锁线索）。

**时点面（PIT 审计的真正靶子：一行新闻有四个时间）**

| 列 | 类型/时区 | 覆盖 |
|---|---|---|
| `publish_time` | `DateTime64(3,'Asia/Shanghai')` | 全程（2010-01-02 → 2026-09-25） |
| `full_publish_time` | `DateTime64(3,'Asia/Shanghai')` | 与上列并存、语义差未核 |
| `crawl_time` | UTC | **仅 2026-07-02 → 2026-09-25（约 3 个月）** |
| `ingest_ts` | `DateTime64(3,'UTC')` | 落库时刻 |

- publish→ingest 滞后实测（样本=publish_time ≥ 2025-09-09 的 200,000 行，单位小时）：p01=2 / p25=18 / **p50=398（≈16.6 天）** / p75=886 / p99=8,016。⇒ 半数新闻在其"发布时刻"之后半个月才入库。
- `countIf(crawl_time=publish_time)`=68、`|Δ|<5min`=13,125（占 0.16%）⇒ 抓取时刻与发布时刻几乎从不相等（正常）；但 **crawl_time 只存在近 3 个月** ⇒ 研究窗内"当时是否已可见"**无法用抓取侧证明**。
- ⇒ 结论：**"发布时点审计未过"不是保守姿态，而是字段级不可能**——研究窗内既无抓取时点、又无标的归因，则"某票某日的新闻活跃度十分位"这一轴在 PIT 上无法构造；任何按 `publish_time` 直接回取的活跃度序列都含后视（数据当时尚未入库）。

**生产触发面**：`c1_market.news_sentiment_window`（symbol 列在、`scope` 支持 market/symbol、`window_ts` Asia/Shanghai、`ingest_ts` UTC）由情绪车道写入，readme 与 L02 c6 两独立记录均证 **symbol 级为预留、研究窗 scope=market、symbol 腿断更 1 个月+** ⇒ 现成替代轴也不存在。L05 侧无任何件消费新闻维（矩阵 `news_axis` 列=常量 `blocked_no_pit_symbol_news`，`t0_state_match_readme` §3.3）。

## ③ 六向台账

**①上游（还有什么信息该喂进来）**
- 内部反查：候选归因来源三条——(a) 巨潮公告侧的 `security_code`（采集即有，落库丢）；(b) `news_source_id`/`source_url`（URL 里常含代码，解析=一次性可自动化）；(c) `c1_market.news_sentiment_window` 的 symbol 腿修复（属 L02 车道，只登记边界）。
- 全网搜索：GPT/LLM 情绪做收益预测的**前视偏差**已是显学研究对象——Glasserman & Lin《Assessing Look-Ahead Bias in Stock Return Predictions Generated by GPT Sentiment Analysis》，两条记录：SSRN 工作稿 2023 https://doi.org/10.2139/ssrn.4586726 与 *The Journal of Financial Data Science* 2023 https://doi.org/10.3905/jfds.2023.1.143（发布方=SSRN / 期刊；年份 2023）。**诚实标注**：两条记录同作者团队=出版形态独立而作者不独立，按闸 2 需再加一个独立团队源（下条）。

**②下游**
- 内部反查：新闻轴的下游清单=①17 §三.3 的矩阵 `news_axis` 十分位（当前占位常量）②法 8.3"隔夜新闻情绪过冲"（SKEL C-F8，须先过发布时点审计）③情绪车道自己的 G6/G1 腿。⇒ 本轴的"消费方存在但都在等料"，与 LK-05（矩阵消费面为零）是**两类不同缺口**：这里是供给侧缺料。
- 全网搜索：Heston & Sinha《News versus Sentiment: Predicting Stock Returns from News Stories》SSRN 2311310（2013，https://doi.org/10.2139/ssrn.2311310）——独立团队，其结论"新闻本身与情绪指标预测力不同"正是"新闻活跃度≠情绪，二者须分轴"的外部依据（与本项目把"活跃度十分位"与"情绪指数"分开的做法一致）。

**③算法/机制**
- 内部反查：仓内无"新闻 PIT 审计件"（`grep` 无发布时点审计脚本）；在册要求"发布时点审计先行"（readme §3.4 / SKEL D3 ⑥ / L05-C11）但**审计的可判定标准从未写出** ⇒ 本矿给出可机检判据三条：A1 每行须能证明 `可见时刻 ≤ 该研究日的收盘`（现仅近 3 月有 crawl_time 可证）；A2 归因列非空率 ≥ 阈值（现 0.001%）；A3 归因来源须是结构化代码而非标题匹配（现无）。
- 全网搜索：上引两篇构成"必须用时点戳而非发布戳"的族证据；A 股适配闸=二者用美股新闻时间戳（分钟级）做事件研究，A 股公告多在盘后/夜间披露且有停牌制度，**移植方式=把"可见时刻"定义为次一交易日开盘前**，与本项目 9:30-9:40 禁开新T 的时段准入（SKEL A1 ②）天然兼容。

**④后端**
- 内部反查：解锁三件的顺序与工量差异极大——(1) **采集侧归因回填**（改爬虫/解析器，收益最大、工量中）；(2) **抓取时点补列**（历史不可追，只能从今往后新增 `first_seen`，属"为未来积累语料"）；(3) **发布时点审计件**（小件，判据即上条 A1-A3，纯只读可跑）。
- 全网搜索：已查无（无公开"A 股新闻 PIT 审计"标准件可引，不硬造）。

**⑤前端**
- 内部反查：无呈现件（新闻轴在矩阵里就是一列常量，前端无从呈现）。外部：已查无（查法未做，判向无矿：呈现依赖轴可用）。

**⑥数据字段（"字段在"≠"数据可得"的教科书案例）**
- 内部反查：轴所需的两个字段（`related_symbols`、时点戳）**schema 全在、质量画像为不可用级**（上表逐列填充率实测）。另需登记的字段债：`publish_time` 与 `full_publish_time` 语义未辨（L02 c6 的"双时点口径未辨"在册，本矿仍未证，如实挂"受阻"）；`quality_flag` 无字典（与 tick 矿 L05-TK-G5 同类）。
- 全网搜索：字段口径"publish time vs first-seen time vs ingest time"三态区分是新闻数据集通用要求（上引 Glasserman/Lin 即以"模型可见时刻"为准），登记为外部口径依据。

## ⑤ 自审闸三态裁定

**裁定=一条小件施工 + 一条挂起排期 + 一条永久留案（非封矿）。**

- **施工**：L05-NW-G3（审计判据 A1/A2/A3 形式化 + 只读探针脚本）——工量极小、消灭"每次都要重新验一遍新闻到底能不能用"的人工环节，且它是 L05-C11 的准入闸。
- **挂起排期**：新闻轴整体入矩阵（17 §三.3 的十分位维）——解锁条件**明写三条且相互独立**：①归因非空率达到阈值（依赖 NW-G1 采集侧回填，属数据车道）②研究窗内可见时刻可证（NW-G2 已判历史段不可补 ⇒ 只能走"研究窗右移/新开近期短窗"这一 Owner 门位路径）③去重口径落地（NW-G7）。三者全绿前，矩阵 `news_axis` 保持占位常量。
- **永久留案（区别于封矿）**：`keyword` 模糊归因通道（NW-G5）与"用 `etf_nav`/日频代理顶替"同构，属**已判不做的可行通道**，按 SOP §7 留案底不预建、不重挖。
- **禁用的封矿理由自查**：本矿未以"现状规模小"作任何裁定——事实是**语料规模大（819 万行）而归因质量为零级**，封的只是"历史段可见时刻可证性"这一条（其性质=结构性不可得，判定本身即完整结论）。
- 反驳者一问（对"是否该现在就做采集侧归因回填"）：(a) 回填后历史段仍缺可见时刻（NW-G2）⇒ 做了也进不了 PIT 轴，只能进"截面统计"→ **成立且致命**，故回填须与"研究窗右移"配套才有意义，单做=半件；(b) 回填工量属数据车道非本链 ⇒ 边界正确；(c) 巨潮 URL 解析即可低成本归因 ⇒ 部分成立，但归因"公告挂到哪只票"与"新闻挂到哪只票"是两件事，只解决前者。**综合：登记为 L05-C11 的前置分解项，不在本矿立项。**
