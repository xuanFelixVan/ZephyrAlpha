# 0. 一句话结论（先说坏消息）

**R2 情报所称"板块指数实时供给已修通常驻在线"经实测不成立**，且真正卡住 6.1/6.2 两法的
**不是行情流，是板块成分的 PIT 序列**（成分快照只有 3 天）。
⇒ 本稿的核心建议是一处**架构反向**：
**板块指数应由"成分 × 个股分钟线"自行合成，把厂商实时流降为对账兜底**——
这样历史深度立刻从"0 天可用"变成"2021-09-01 起 1,220 交易日可用"，
而实时链路从"断了就没数据"降级为"断了只影响当日"。

# 2. 消费方到底要多粗的粒度（按做T 需求定，不按需最多定）

| 消费方 | 要什么 | 需要粒度 | **不需要**什么 |
|---|---|---|---|
| 6.1 龙头-跟风扩散 | 龙头封板后 N 分钟内板块整体跟涨幅度、扩散宽度（涨家数占比） | **1 分钟板块价 + 1 分钟板块内涨家数占比** | 不需要 tick/3s：扩散是分钟尺度现象，3s 只增噪声与存储 |
| 6.2 板块内补涨 | 同板块内滞涨个股相对板块均值的收敛速度 | **1 分钟个股-板块相对量** | 不需要厂商指数（自算更一致） |
| 盘中情绪门（emotion_index C1/C2） | 涨停温度、晋级率 | **事件级**（封板/炸板/晋级时点），非价格级 | 不需要连续价格 |
| 做T 触发（2.x/3.x 族） | 标的自身分钟路径 + 当日 VWAP | 个股 1 分钟（**已在库**） | 不需要板块指数即可开工 |

⇒ **结论粒度＝1 分钟**；3s/tick 只对 5.4 微观动量有意义，且那是另一条线（不是板块供给）。
本稿因此**不建议**为板块指数投入 tick 级存储（每日 595 板块 × 240 分钟仅 14.3 万行，
而 tick 级是 10⁸ 量级——收益不匹配）。

# 3. 设计：三层供给（合成优先、实时兜底、事件独立）

### L1 板块 1 分钟指数（自算，主力层）
- 输入：`kline_1min`（成分股）× **PIT 成分映射**（见 L3）。
- 算法口径：流通市值加权（**与厂商口径差异必须显式登记**，不声称"复现同花顺/东财指数"），
  基准=首个有效交易日板块内等权归一；输出列建议
  `(board_code, ts, close, adv_count, dec_count, breadth_pct, amount, member_n, version, ingest_ts)`。
- 表型：**ReplacingMergeTree(ingest_ts)**，`ORDER BY (board_code, ts)`；
  消费侧必须带 `FINAL` 或 `argMax(...,ingest_ts)`（本包已在做T 件里踩过这个坑，别再踩）。
- 历史回填：2021-09-01→今（受成分 PIT 限制，见 L3）。
- 成本：595×240×1,220 ≈ 1.74 亿行，单行约 60B ⇒ ~10GB 级，可全量落库，无需外部存储。

### L2 板块实时最后一公里（兜底，可断）
- 保留 `BoardIndexRealtime`，但定位改为**当日对账源**：
  盘中以 L1 的同一口径自算（用 `kline_1min` 当日增量或 `tick_data` 聚合），
  厂商板块指数仅做**偏差监控**（|自算−厂商|/厂商 > 阈值即告警，阈值由数据线定）。
- **必须去掉的隐式依赖**：任何策略/情绪卡不得把"厂商板块 tick 在场"当运行前提；
  断流时 L1 自算腿必须能独立供给（本次 R2 误判的根因就是把干跑当成了常驻）。

### L3 板块成分 PIT 序列（**真正的瓶颈，优先级最高**）
- 现状：仅 3 个快照日 ⇒ 任何历史板块指数都用"今日成分回看历史"=**前视偏差**
  （新股纳入/剔除、板块改组都会把未来信息带进历史）。
- 要求：每日一份成分快照落库，键 `(board_code, stock_code, snapshot_date)`，
  保留全史不覆写；**回溯期能补多久补多久**（厂商历史成分若不可得，
  则显式登记"成分可得起点"，并把 L1 的历史可用起点收缩到该日，**禁止用近端成分回填远端**）。
- 这是本稿**唯一必须先做、否则 L1 白做**的一层。

### L4 事件层（与价格层解耦，独立推进）
- `daban_board_event` / `limit_up_pool` 现仅 16–17 日 ⇒ 与情绪门 C1/C2 同源问题。
- 要求：只做一件事——**每日稳定落库、停止回填改写**（现观测到 09-01 的数据 09-17 才入库，
  close-static 语义尚可，intraday-as-of 语义不可用）。事件史靠时间自然长，没有捷径。

# 4. 验收判据（数据线交付时逐条打勾，缺一不算修通）

1. **连续性**：L1 任一板块 × 任一交易日的分钟覆盖数 = 240（缺分钟须给出停牌/无成交原因位，禁静默缺）。
2. **PIT**：L3 成分快照的 `snapshot_date` 与 L1 使用的成分严格满足 `snapshot_date ≤ ts 日`；
   抽样 30 个 (板块, 日) 复核，**零前视**方可放行。
3. **对账**：L1 自算 vs 厂商板块指数，日收益相关系数与平均绝对偏差登记入册；
   偏差不设"必须小于 X"的硬门（口径本就不同），但**必须可解释**（成分口径/加权方式差异能对上）。
4. **断流可活**：人为切断 L2（厂商流）一个交易日，L1 与下游情绪门**不得变红**。
   ——这条是本次 R2 事故的直接免疫测试。
5. **表型与读法**：L1/L3 建为 ReplacingMergeTree 并在注册表 `hard_constraint` 写明
   "消费侧须 FINAL/argMax(ingest_ts)"；本包已踩坑，勿重复。
6. **注册表一致**：`board_index_tick`、`sector_constituent_snapshot`、`daban_engine_load`
   等**当前未注册品类**一并入 `business_data_categories.yaml`
   （实测 `get_registry()` 73 键中无这几张）；同时纠正 `auction_book` 的"未启用"在册状态
   与实有约 390 万行的矛盾（登记漂移）。

# 5. 风险与未决（如实，不粉饰）

1. **加权口径不可比**：自算板块指数与厂商指数必然有差；若下游把两者当同一序列混用，
   会产生假的"板块动量"信号。缓解=版本号 + 列名带 `self_comp_` 前缀 + 禁止跨源拼接。
2. **`tick_data` 时区纪元嫌疑**（普查红旗：早期行出现 01:30 墙钟戳，与已解决的 ETF 分钟案同类）。
   **不定此项，L1 的日内聚合会有系统性错位**。列为 L1 前置。
3. **BSE（北交所）在所有分钟族缺席** ⇒ 板块覆盖天然不全，须登记为宇宙边界，不得当作"全市场板块"。
4. **停牌表 `suspend` = 0 行** ⇒ 停牌/退市判定只能从数据缺失反推，会污染板块宽度分母。
   建议 L1 显式产出 `member_n_effective`（当日有成交成员数）而非用静态成分数。
5. **2021-09 前无分钟腿** ⇒ 板块 1 分钟指数最早只能到 2021-09-01，与做T 闭卷窗
   [2019-01-04, 2025-09-09] **不完全重叠**；若要用板块维做长窗考试，须接受窗口被截短。
6. 本稿不评估"自建 L2 十档/委托流"路线（`l2_tick`=0 且属权限缺口，非工程可解）。
