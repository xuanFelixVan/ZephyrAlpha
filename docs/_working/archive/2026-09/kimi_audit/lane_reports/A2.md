## 3. 专项

### 3.1 CLAIM-REQUIRED 成因链（×50 全窗 / 近 24h ×40 P50 33s）

机制锚点：`claim_required_gate.py:58-89`（session 已注册且目标文件未 claim → 阻断；检查本身是集合运算，**门禁自身耗时≈0**，33s/74.9s 全是它之前整条门禁链的白烧）。

成因链三段（均有实测证据）：

1. **失败即释放 claim**：`scripts/git_commit.py:1044-1059`——`gw.commit()` 的 `finally: gw.release_files(args.session, claimed)`，门禁拦截后文件保持 staged 但 claim 归零。重试时若走队列或其他入口而未重新 claim（或 claim 因 FOREIGN_CHANGE/HELD 失败），下次提交即撞 CLAIM-REQUIRED。与旧版宪法（v1，2026-09-12 换版蒸发）记载的 FOREIGN_CHANGE 恶性循环同源。
2. **派生写入混入暂存区**：阻断明细里最高频文件是 `capability_canonical_file_registry.yaml`（≥12 个不同 session 被它拦）——该文件由 post-commit reconciler/integrity post-flush 重登记自动改写到 tracked 区，下一个提交者 `git add` 时把它带进 staged 集，但 session 从未 claim 它 → 必拦。**治理派生提交本身在制造下一个提交的阻断**。
3. **报错文案自引用悬空**：`claim_required_gate.py:86` 指引"AGENTS.md §8 L284"——09-12 宪法换版后 §8 已是「词汇与对齐」且无 L284 锚，AI 按指引找不到真规则，增加重试迷路概率。

治本方向（非止痛）：①失败路径"释放 claim"与"保留 staged"语义绑定——重试入口默认 `--adopt-prior-work` 行为内建而非旗标可选；②派生写入并入触发它的那一笔 commit（S18-R2 裁定范围）或迁出 tracked 区；③报错文案引用改为规则真源路径（rules/*.yaml）而非宪法行号。

### 3.2 DANGLING-REFERENCE 成因链（blocked ×13 / gate stats failed ×18 / 死信 ×48）

机制锚点：`dangling_reference_gate.py:90-96`（`_SECTION_HEADING_RE` 从工作区 AGENTS.md 提取 `^#{2,4} §N.N`）、`:162-223`（只检测新增引用，HEAD 差分）。

成因实测：13 条阻断中 **六点一节占 10 条**（另三点四节 ×1）；触发文件集中在 `docs/03_modules/*/blueprint.md` 与 `_working` 交付文档。09-12 宪法换版（v1 1639 行 → L0 ≤300 行）后旧章节体系蒸发，新宪法无该节；AI 凭旧版记忆写「AGENTS.md 六点一节」即悬空。

判定：**门禁设计如此**（抓的是真悬空，且只拦新增不误伤历史）；**病灶在换版未做全仓引用迁移 + 模型记忆滞后**。治本方向：宪法换版时同 commit 原子化全仓 § 引用改写（或换版后跑一次引用普查并一次性修复存量）；长期把"宪法行号/章节引用"替换为规则真源 ID（trae_NNN），使章节号不再是跨文件硬引用。

### 3.3 GATE-REGENERATE 超时 与 DEPGRAPH-FRESHNESS WARN 1048min

- `GATE-REGENERATE: reconciler timed out (timeout=180s)`：抛出点 `reconciliation_registry.py:815-821`（`subprocess.TimeoutExpired` → critical_warn）；触发位置=GATE-REGENERATE 组合 reconciler（`:5821`，3 spec 合成）内串联跑 15 个生成器，单个 subprocess `timeout=180`（`:8097`，注释"单个生成器最多 3 分钟（depgraph 查询 + MD 写入）"）；同文件另有 7 处 `timeout=180`（`:3764/:4076/:5594/:5701/:5918/:5939/:8257`）。基线实测 20s（`:5907` 注释），超时发生在并发期 PG depgraph 查询变慢。**在册裁定已存在**：`architecture_issue_registry.yaml:20916`「GATE-REGENERATE 超时告警裁定=零工程（并发期环境噪音）」——本 lane 不重复裁定，只指出：180s 硬顶 × 15 串联 = 最坏 45min 的串行链，若裁定翻案，治本在生成器改增量（O(diff)）而非加秒数。
- `DEPGRAPH-FRESHNESS WARN 1048min`：触发点 `depgraph_freshness_gate.py:187-195`（warn 档：`_WARN_SECONDS` ≤ age < 24h 阻断档，print 到控制台）。1048min≈17.5h，即 depgraph scan cache 17.5 小时未刷。warn-only 放行、语义**设计如此**；它浮出的真信号是：depgraph 刷新依赖 reconciler/手工节拍，在施工高峰期跟不上。治本属刷新触发链（事件触发已具备），不在本门禁。

## 4. hook_tracked_drift（1995 行）：真信号，但告警形态已噪声化

- 字段分布：allowed=False ×1270、True ×397、None ×328（旧 schema）。
- 语义锚点：`git_commit_gateway.py:2421-2466`（gate 运行期 tracked 区写入=违规报警，裁定 #ARCH-PRECOMMIT-STASH-ADAPT-001）；未归因文件存在时升级为 TRACKED-DRIFT-READONLY 硬阻断（commit_blocked ×14、死信 ×34）。
- **真信号部分**：unattributed TOP 文件全部是生成器/对账器维护的热文件——`capability_canonical_file_registry.yaml` ×187、`module_translation_registry.yaml` ×98、`architecture_health/latest.json` ×84、`architecture_model/index.yaml` ×73、`trading_decision_map.yaml` ×72；366 个文件跨日复发（capability 注册表 09-04→09-17 持续在烧）。这证明**派生写入者在他 session 的 gate 窗口内改写 tracked 区**是结构性 TOCTOU——门禁校验内容≠提交内容，正是 TRACKED-DRIFT-READONLY 升硬的理由。
- **噪声化部分**：`gate_tracked_write_allowlist.yaml` 对 TOP30 未归因文件的文件名子串覆盖率仅 **18%**——已知的派生写入者大多没进白名单，于是同一事实每 commit 报警一次，33 天无人处置（`data/architecture_health/latest.json` 09-04 首报→09-12 仍在报）。allowed=True ×397 说明部分波次已走逃生通道留痕。
- 判定：**信号为真、报警为噪**。治本在写入层（派生写入并入触发 commit / 迁出 tracked 区，同 §3.1-② 与 S18-R2）+ 白名单按"写入者身份"而非文件名归因；在写入层未治前，建议（裁定归 L0/S18-R1）把纯 warn 档改为按签名日去重。

## 5. 结论（≤10 行，交 L0）

1. 门禁语义大体健康：974 次阻断中绝大多数是语义型门禁真触发（设计如此），问题不在"门禁太严"。
2. 真正烧吞吐的是三处实现层：①每次阻断平均白烧 63s 门禁链（累计 22.0h/4.5d）；②队列死信 1217 条（快照-落地窗口无保护 + git 互踩）；③堵点本告警自激 1095 行（P50 2s 间隔，纯噪）。
3. CLAIM-REQUIRED 的病灶不是 AI 不守规矩，而是"失败即释放 claim"（`git_commit.py:1058` finally）+ 派生写入混入暂存区——治理机制在制造下一个阻断。
4. 注册表 YAML 解析 fail-closed 是最大单点放大器：一处 ParserError 连锁硬拦 CREATE-GUARD/SSOT-REDEFINITION/ARCH-REFERENCE 多门禁，需独立错误码+坏条目隔离。
5. DANGLING-REFERENCE ×13 中 10 次是六点一节：09-12 宪法换版留下的悬空引用尾债，治本=换版原子化改写存量引用，与门禁无关。
6. hook_tracked_drift 1995 行是真信号（生成器在他人 gate 窗口写 tracked 区=TOCTOU）但告警已噪声化（同文件复发 33 天、白名单覆盖 18%）；治本在写入层，与 S18-R2 同源。
7. GATE-REGENERATE 180s 超时已有在册裁定（零工程）；DEPGRAPH-FRESHNESS WARN=刷新节拍问题的仪表盘，两者均不建议动门禁。
8. P0-A 锁外预检已验证有效（376 次 × P50 2s 快败），可作为"确定性门禁前置"模式的样板，但预检只覆盖 15 个门禁——门禁链 P50 46s 的全套成本仍在锁内。
9. 裁定归 L0/S18-R1~R4：本 lane 只取证，未提任何超时/重试类止痛建议。
