# 裁定书草案 S18-R2：衍生提交并入策略

## 现状（含证据锚点）

- 近 24h 309 笔提交中衍生税 79 笔=25.6%（A1 实测；严格可消除 34 笔=11%：integrity post-flush 31+watchdog 3）。
- integrity 重登记链：`git_commit_gateway.py:1831/1894` 每笔 flush 后**无条件**跑 `--register` 并**独立成 commit**；触发源高度集中=`capability_canonical_file_registry.yaml`（golden-hash 保护清单成员，`validate_rules_integrity.py:123-127`）24h 被 42 笔触碰。
- 时序窗残余（S4-F3）：主 commit 与重登记 commit 之间 `--check` 对旧基线报 TAMPERED；重登记失败只 warning。

## 选项

| 选项 | 内容 | 最坏情形 |
|---|---|---|
| A. 维持 | 每 flush 派生一笔 | 衍生税+时序窗+队列死信三害持续 |
| B. **并入触发笔** | 重登记产物（rules_integrity_db.json）与 reconciler 派生物作为触发 commit 的追加文件同 commit 原子落盘；内容哈希未变不出数 | 主 commit 门禁链需覆盖追加文件——派生物是机生件，门禁口径已豁免 derived_sync B 类；最坏=主 commit 因派生物被拦（用既有 B 类白名单通道） |
| C. 独立笔但合并节拍 | 攒批 30min 一笔 | 时序窗拉长到 30min，TAMPERED 误报面扩大 |

## 依据

治本定义（指令书 §2.1）："衍生提交并入触发它的那一笔而非另起一笔"。原子化同时消灭时序窗（同一 commit 内基线与内容同步变更）。机读判据：无受保护文件变更的 commit 后 24h 内 integrity 独立 commit 数=0；反例=受保护文件变更而 DB 未更新→`--check` 真报 TAMPERED。

## 风险

主 commit 体积微增（一个 json）；回滚单笔即可（revert 含派生物）。

## 建议+置信度

**建议 B，置信度高。** 附前提：B 类白名单通道对派生物保持豁免（已在案）。

## 若不同意应看什么数据

派生物并入后若某域门禁误判率上升（COMMIT_SCOPE 把派生件算跨域）——用 `--allow-multi-domain` 既有留痕通道，发生率进周审计。
