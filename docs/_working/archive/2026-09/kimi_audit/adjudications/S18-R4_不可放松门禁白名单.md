# 裁定书草案 S18-R4：不可放松门禁白名单

## 现状

S18 提速压力下，"松门禁换吞吐"是永远的诱惑项。本裁定把**不许放松**的白名单钉死；白名单外的门禁优化只允许"同语义提速"（diff 化/缓存），不许改判据。

## 建议白名单（签署即生效）

| 门禁族 | 锚点 | 为什么不可放松 |
|---|---|---|
| 钱闸族：DSR/FDR/Wilson/binomial/PIT 闸 | `deflated_sharpe_calculator.py`/`bhy_fdr.py`/`pattern_win_rate_provider.py`/`pattern_evidence_certifier.py`/`strategy_runner.py:412` PIT 闸 | 放松=假策略进库=真金白银 |
| own-scope 差分口径 | `_diff_helpers._build_own_scope`（`bare_sql_gate.py:111-127` 同族） | 连坐与漏扫的分界线；口径改动=全门禁信任面重估 |
| 内容寻址（golden hash 清单） | `validate_rules_integrity.py:123-127` | 防篡改锚；S18-R2 原子化解决的是频率不是口径 |
| POST-COMMIT-GUARD | 提交后归属核实（`[GW:]` 伪造检测） | 提交链最后一道；伪造通过=全部留痕失真 |
| RULING-REFERENCE | `ruling_reference_gate.py` | 方向只许加严（S4-R1 扩检提案在案），不许放松 |
| 仲裁前置项：CREATE-GUARD/REGISTRY-YAML-PARSE | 注册表完整性 | 第二真源防火墙 |

## 选项

| 选项 | 内容 | 最坏情形 |
|---|---|---|
| A. 不定白名单 | 提速压力下逐件个案放松 | 钱闸被"提速"名义磨穿 |
| B. **白名单钉死+白名单外同语义提速** | 如上 | 白名单漏列某新钱闸——新门禁默认入名单（fail-closed 方向）即可兜底 |

## 依据

S1/S4/S14 实证：钱闸族的每一处放松都对应过真实事故或实锤缺陷（DSR 欠折减/pit_shift 静默吞/裁定引用悬空）。门禁耗时榜头部（CREATE-GUARD P99 94s）全是 O(仓库) 成本问题，**慢是实现的病，不是语义的病**——语义一件不许动。

## 风险

白名单外门禁若被过度 diff 化引入漏扫——由 own-scope 审计（_audit_foreign_staged）与 S12 门禁失效探针兜底。

## 建议+置信度

**建议 B，置信度高。**

## 若不同意应看什么数据

任一白名单门禁的误拦率实测 >30%（真误拦，非"拦对了但我嫌烦"）——拿数据来再议单件。
