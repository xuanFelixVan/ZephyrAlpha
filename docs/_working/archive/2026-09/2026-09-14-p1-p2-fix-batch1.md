## 2. P2-5 调查结论（乱码根因）

- 本会话 shell（Git Bash）`sys.stdout.encoding=utf-8`，中文全程正常，无法直接复现。
- `GBK-AS-UTF8` 字样真源=ENCODING-SAFETY(INJ-007) gate（`check_encoding.py`），管的是**文件**
  双重编码，不是控制台——报告里该前缀是红方按 INJ-007 词汇对乱码原文的转义描述。
- 机制定位：Windows 上交互控制台走 WriteConsoleW（UTF-16）不受代码页影响——**管道/重定向**
  场景 Python 默认按 ANSI 代码页（GBK）编码 stdout，采集端（agent harness/IDE 终端）按 UTF-8
  解码 → GBK-AS-UTF8 双重编码乱码。同控制台"其他中文报错正常"= 来自 git 子进程（自行处理控制台
  API），与本 CLI 的 Python print 链路不同。修法（强制 UTF-8 输出）与仓内 INJ-007 UTF-8-first
  宪法一致，规格改法正确，已实施。
