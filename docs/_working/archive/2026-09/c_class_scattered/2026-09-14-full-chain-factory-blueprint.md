## 〇、一句话结论

全链路九个环节里，**真正有"工厂"的只有 4 个**（因子 / 信号 / 策略 / 模型），而**这 4 个一个都没接进产线**（全仓只被自己的 `__init__.py` 和 tests 引用）。
其余五个环节全是**求解器 / 引擎 / 守卫**——它们能算，但不会自己发明新方法。
最硬的两个断点：① **仓位与组合域 19 个件、零工厂**（全仓最大的洼地）；② **不存在任何一条"结果 → 生成器"的自动回灌边**（所以现在不是闭环，是一条半自动传送带）。

## 一、终局定义

**人只做四件事（且只因为这四件事法律上/物理上不能交给 AI）**：

1. 注册账号、实名、申请并付费 API；
2. 把密钥喂进 `secrets`（本项目三道 gate）；
3. 资金与风控额度授权（最多亏多少 / 最大仓位 / 单策略上限）；
4. 合规红线（哪些不能碰）。

除这四件之外，全链路 AI 全自动：全网搜索 → 寻路区域 → 设计消费 → 打通链路 → 开发 → 回测 → 测试 → 上线（额度内）→ 复盘 → 回灌再生。

## 二、判据：什么时候该建工厂，什么时候不该

不是每个环节都需要工厂。三问法：

| 问 | 答 no 的后果 |
|---|---|
| ① 这个环节的**设计空间**大到人想不全吗？ | 空间小 → 人工定死即可，建工厂是浪费 |
| ② 这个空间**能机器枚举**吗（有白名单 / 网格 / 语法）？ | 不能 → 只能靠人拍脑袋或 LLM 自由发挥，风险不可控 |
| ③ 有**客观评分**吗（能进咽喉考试）？ | 没有 → 建了也是随机游走 |

**三问全 yes → 建工厂；否则建"求解器"或"守卫"。**

按此判据裁决九个环节：

| # | 环节 | ①空间大 | ②可枚举 | ③可评分 | 裁决 |
|---|---|---|---|---|---|
| 1 | 数据接入与质量 | 否 | 否 | 部分 | **不建工厂**，建守卫 + SLA |
| 2 | 因子生产 | 是 | 是 | 是 | **建工厂**（已有，待接线） |

| 5 | 模型生产 | 是 | 是 | 是 | **建工厂**（已有，待接线） |
| 6 | 仓位与组合 | **是** | **是** | 是 | **建工厂——最大洼地，零基础** |
| 7 | 执行与通道 | 是 | 是 | 是 | 二期建（执行算法工厂） |

## 八、第一性原理：终局形态到底是什么

### 8.1 定义与五要素

**工厂 = 在有限资源下，把「设计空间」转化为「可验证知识 + 可执行产物」的闭环转换器。**

从这个定义反推，终局形态不是"九个工厂"，而是**五个恒久部件 + 一条回路**：

| 部件 | 干什么 | 我们有没有 |
|---|---|---|
| **D 设计空间** | 可枚举、有白名单/语法的可配置域 | 🟡 分散在各域，未统一成可声明的 schema |
| **C 编译器** | 把意图/配置编译成可执行候选；含常量折叠、活性折叠、共享前缀 | ❌ **没有**（本章 §十 即为它的第一个部件） |

| **M 记忆** | 阴性库 + 结构知识 + 决策台账；可检索、**可归因** | 🟡 台账齐，阴性库弱，结构知识无 |
| **G 资源 Governor** | 算力/资金/API 预算 **+ 多重检验预算（N 账本）** | 🟡 E0 只管时段，不管 multiplicity budget |

**九个 F-xx 不是九个系统，是「设计空间 D 在不同环节的实例化」，它们共用同一个 E、同一份 M、同一个 G。**
按此判读，我们目前的家底是：**有咽喉、有台账、缺编译器、缺「多重检验预算」那一半的 governor**。

## 十、Owner 点名的那个机制：维度活性谓词（conditional schema）

### 10.1 维度声明格式

```yaml
# 示例：多策略合并维（v1 曾建议砍掉——v2 改为保留）
- id: F_merge_policy
  desc: 多策略合并方式
  values: [single, equal_capital, equal_risk, signal_additive]
  baseline: single                          # 折叠时的取值
  active_if: "len(strategy_pool) > 1"       # ← 活跃谓词：这就是 Owner 要的机制
  depends_on: [strategy_pool]
  cost_tier: weight_invariant               # 不影响信号生成，只影响权重
```

每条维度都带 `active_if` 与 `baseline`。**没有 `active_if` 的维度视为恒活跃。**

### 10.2 生成算法（惰性笛卡尔积 + 折叠 + 前缀共享）

1. **依赖拓扑排序**：按 `depends_on` 排序维度；
2. **求值 `active_if`**：不活跃 → 折叠为 `baseline`，**对 N 的贡献 = 1（不是 |values|）**；
3. **展开活跃维**：产出笛卡尔积；
4. **前缀共享**：`cost_tier=signal_*` 的维（A1/A2 因子侧）只在最外层计算一次并缓存为信号，内层维廉价重放；
5. **出生证留痕**：每条 recipe 记录 `folded_dimensions`（哪些维被折叠 + 折叠原因），供阴性库归因与 N 记账复核。

**效果**：今天 F 维（4 个取值）自动折叠为 1 个值 → 零重复结果、零额外算力；将来出现第二个策略时**自动展开，不需要改任何代码**。这正是 Owner 说的"没有第二个策略的时候它自动就不算呗"。

### 10.3 连带影响（重要）

**折叠不等于白得。** 折叠维对 N 贡献 1 而非 4 —— 这与附录 A 矿脉 3 的 N_eff 一起，构成"N 只数真正发生过的尝试"这一原则的两端：**死掉的空间（相关性高的格点）按 N_eff 折；没展开的空间（失活维）按 1 计**。

### 10.4 外部佐证（这不是我们发明的）

| 做法 | 出处 | 处理失活维的方式 |
|---|---|---|
| **SMAC**（随机森林替代模型） | Hutter, Hoos & Leyton-Brown, 2011 | 用默认值**填充**失活维（副作用：维度虚高、效率下降） |
| **TPE**（树结构 Parzen 密度估计） | Bergstra et al., NeurIPS 2011 | 天然支持树结构/条件空间；缺点是不建模维度间关系 |
| **Add-Tree 协方差（GP）** | Jenatton et al. 2017；Ma & Blaschko 2020b | 显式建模"配置相似度 = 共享树顶点数" |

> 交叉验证：以上三处互相独立提及（① AI Wiki 综述 ② Eggensperger et al., AAAI 2015 基准 PDF ③ ICLR 2024 在投论文综述章），一致确认"条件/树结构搜索空间"是成熟标准概念。
> **附加收益**：Add-Tree 一类的核函数顺带给出了「**两个配方有多像**」的距离定义 —— 这同时解决了 E5 协同去重判据（共享祖先 = 同义反复）与 N_eff 的先验结构。
