# C4 历史修复工程设计方案 v1.0（2026-09-14，Owner 立项"全部开工"）

> 使命：用 research_report 自带的 PDF 原文（2017-2021 段约 6 万份，存活率普查 ~100%，
> 见 c4_pdf_survey 9f963ed9）提取**发布时点的盈利预测值**，重建 consensus_daily 历史段。
> 依据链：源污染定性=policies/expectation_consumption_design_policy.md §9；
> 普查档案=commit 9f963ed9；端到端实证=2017 茅台 PDF"2017E 每股收益 15.6 元"。

## 1. 边界（先说清不做什么）

- 只修 2017-2021 段（~60,477 份，全活）。2022-2026 段（~86,192 份）被 EO_Bot 反爬挡，
  =独立子工程（JS 质询求解器/商业源），本方案不含。
- 不动 research_report 原表（数据保存者）；提取结果落新表，来源可溯、可整体废弃重建。
- 扫描件风险已排除（抽样 11/11 文字层健康，1000-2500 字/页）；管线保留文字层厚度守卫，
  疑似扫描件标记跳过不硬解。

## 2. 架构四层

### L1 下载层（c4_fetcher）
- URL 形态：`http://pdf.dfcfw.com/pdf/H3_{infoCode}_1.pdf`（https 端点=反爬页，禁用）。
- 限速：8 并发 + 失败重试 2 次（指数退避）；单日配额上限可配（对免费渠道克制）。
- 缓存：`data/c4_pdf_cache/{year}/{report_id}.pdf`（gitignore 区，约 30GB 量级；
  已下载跳过=断点续传天然实现）。
- 存活分类沿用普查口径：real_pdf/bot_page/http_err。

### L2 文本层（PyMuPDF）
- 全文提取 + 逐页字符数守卫（<200 字/页 → 标记 low_text 跳过）。
- 中间产物：`{report_id}.txt` 缓存于同目录（重复提取零成本）。

### L3 提取层（两层，业界实践对齐：规则工具管标准表、LLM 兜底疑难）
- **3a 启发式**（零成本先跑，预计命中大头）：
  定位"盈利预测"段 → 找年度表头（`20XXE`/`20XX`）→ 抓"每股收益/EPS"行邻近数值 →
  输出 (forecast_year, eps, 页码, 上下文片段)。
- **3b LLM 兜底**（3a 未命中或置信度低的残差）：走 LSG 网关 + intelligence 域池化通道
  （DeepSeek/GLM，C4 设计原文口径），输入=预测段文本切片（非全文，控 token），
  输出=JSON 结构化 (year, eps, pe, rating) + 提取置信分。
- **置信度模型**：3a 数值紧邻年度表头=high；3a 跨行推断=mid；3b LLM 自报分+格式整齐度=low~high；
  low 不入正表只留档。

### L4 落表层（新表，原表不动）
- `c3_fundamental.pdf_forecast_extracted`：/report_id/symbol/publish_date/forecast_year/
  eps/pe/confidence(高中低)/method(heuristic/llm)/snippet(证据片段)/extracted_at。
- ReplacingMergeTree，ORDER BY (report_id, forecast_year)；同键重提取幂等覆盖。
- 历史重建：新视图/新表 consensus_daily_repaired（从本表按 consensus 口径重聚合），
  与现 consensus_daily（污染历史）物理隔离——禁直接改历史，双轨并存待 Owner 验收切换。

## 3. 验证三层（置信度的锚）

1. **重复一致性**：同一 PDF 两次提取（间隔/参数微变）值不同 → 降级。
2. **已知锚点集**：人工核对样本逐步积累（起点=茅台 2017E 15.6 元等），
   提取器对锚点集的准确率即发布门禁（原型期目标准确率 ≥90% 方可全量批）。
3. **人工抽核协议**：每批次随机抽 30 份人工对照 PDF 原文，错误率 >5% 停批返工。

## 4. 调度与断点

- 批处理 CLI（`scripts/ch/c4_extract_batch.py`，--limit/--year/--symbols），checkpoint
  即缓存目录本身（有 PDF+有提取行=完成），可中断续跑。
- 排班：每晚批量窗口跑 2-4 小时（配额与限速可调），预计 6 万份 3-5 晚跑完。
