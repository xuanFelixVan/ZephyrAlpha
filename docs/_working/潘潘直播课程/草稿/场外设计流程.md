> **定位**: 从能力定位到架构图到功能域到依赖图YAML，完整场外设计闭环流程。所有设计活动的"元框架"。

> **核心变化**: 新增架构图自进化循环协议（AI自动迭代→收敛→人类审查）
> **状态**: v3.0 | **最后更新**: 2026-05-25

### §1.2 核心原则

| 原则 | 说明 |
|------|------|
| **能力定位书是唯一源头** | 任何设计决策必须能追溯到某项能力。不能→可能是冗余 |
| **架构图定义"是什么"，功能域定义"怎么做"** | 两者正交，互不替代 |
| **每个架构图只回答自己的核心问题** | 越界内容写"详见A_X§Y"，不重复定义 |
| **AI自进化循环→收敛→人类审查** | AI自动迭代直到连续2轮无新发现，人类只在最后审查 |
| **反馈闭环是强制的** | 下层发现的问题必须回溯修正上层，不是"以后再说" |
| **搬入是受控替换** | 备份→逐个替换→验证，不是一口气全换 |

#### §2.2.2 10项检查清单

| 清单 | 检查内容 | 检查方法 |
|:----:|---------|---------|
| 1️⃣ 缺失的功能 | 本架构应覆盖但未覆盖的功能点 | 对标头部机构+学术论文，逐项比对 |
| 2️⃣ 缺失的轨道 | 应并行但未并行的独立路径 | 检查是否有"被压平"的并行逻辑 |
| 3️⃣ 缺失的横切面 | 应跨组件但未跨组件的关注点 | 检查是否有"被嵌入"的横切逻辑 |
| 4️⃣ 缺失的枢纽 | 应有但未有的指挥/协调/仲裁中心 | 检查是否有"无人协调"的交叉点 |
| 5️⃣ 缺失的闭环 | 应有反馈但无反馈的路径 | 检查每个输出是否有对应的反馈输入 |
| 6️⃣ 缺失的硬边界 | 应有但未定义的不可违反规则 | 检查是否有"可以但不应该"的场景 |
| 7️⃣ 缺失的度量 | 应度量但未度量的指标 | 检查§12成功指标是否覆盖所有核心关注点 |
| 8️⃣ 能力定位书覆盖缺口 | 45项能力中哪些与本文档相关但未被引用 | 逐项检查C-001~C-047 |
| 9️⃣ 交叉引用缺口 | 其他架构图引用了本文档但本文档未定义 | 检查XREF索引 |
| 🔟 一人+AI特殊考量 | 一人开发+AI维护场景下的特殊需求 | 检查是否有"假设有团队"的设计 |

#### §2.2.3 收敛判定规则

| 条件 | 判定 | 动作 |
|------|------|------|
| 连续2轮N=0（无新发现） | ✅ 收敛 | 退出循环，输出审查报告 |
| 单轮发现>5项 | ⚠️ 可能方向偏了 | 暂停，输出发现清单，等人类确认方向 |
| 循环超过5轮仍未收敛 | ⚠️ 可能陷入发散 | 强制退出，输出当前状态+未解决问题 |
| 发现与其他架构图矛盾 | 🔄 需要协调 | 记录矛盾，继续本架构循环，矛盾留到人类审查时解决 |

```
    │   - A2定义的治理边界是否与域间依赖一致？
    │   - A3定义的数据血缘是否与域间依赖一致？
    │   - A4定义的风险否决是否与域间依赖一致？
    │
    ▼
Step 4: 生成最终YAML
    │   - project-entity-depgraph.yaml
    │   - 包含：nodes + edges + metadata
    │
    ▼
Step 5: YAML自洽性校验
        - 无循环依赖
        - 每行H依赖数≤3
        - 所有架构图约束在YAML中有对应条目
```

### §4.2 YAML铁律

```yaml
铁律:
  - 对角线必须为空（域不依赖自己）
  - H依赖无环（所有H最终指向根域）
  - 每行H依赖数应≤3（过度耦合的域需要拆分）
  - 所有架构图定义的约束在YAML中有对应条目
  - 所有能力定位书的45项能力在YAML中有对应节点
```

## §8 七层架构遗产（v1.0保留内容）

> 以下内容来自v1.0《中大型工业级系统开发方法论—七层架构》，在v3.0中仍然有效，作为功能域设计的子流程保留。

### §8.1 契约设计（原第五层）

| 类别 | 编号前缀 | 内容 | 示例 |
|------|:------:|------|------|
| 数据契约 | CTR-xxx | 跨域数据结构定义 | CTR-001 NormalizedMarketData |
| 错误契约 | CTR-ERR-xxx | 错误类型和格式 | CTR-ERR-001 DataQualityError |
| 追踪契约 | CTR-TRACE-xxx | 全链路追踪上下文 | CTR-TRACE-001 TraceContext |
| 背压契约 | CTR-BP-xxx | 流控信号 | CTR-BP-001 BackpressurePause |
| 蓝图契约 | CTR-P1-xxx | 业务级数据契约 | CTR-P1-001 FactorMonitorReport |
| 扩展点契约 | OCP-xxx | 抽象接口+注册机制 | OCP-001 FactorBase |
| 外部契约 | EXT-xxx | 与外部系统的接口 | EXT-001 Broker API |

### §8.2 契约版本规则

| 规则 | 内容 |
|------|------|
| VER-R1 | 同MAJOR版本前后兼容，消费者忽略未知可选字段 |
| VER-R2 | MAJOR不匹配必须拒绝并触发CTR-ERR-006 |
| VER-R3 | 新MAJOR发布前30天通知所有注册消费者 |
| VER-R4 | 过渡窗口内消费者同时支持新旧两个MAJOR |
| VER-R5 | 消费者启动时查询依赖契约的当前active版本 |

### §8.3 共享内核（原第六层）

| 类别 | 编号前缀 | 内容 | 示例 |
|------|:------:|------|------|
| 聚合根 | AGG-xxx | 跨域一致的核心业务对象 | AGG-001 Order |
| 值对象 | VO-xxx | 不可变的通用数据类型 | VO-001 Money |

### §8.4 架构不变量（原第七层）

| 维度 | 说明 |
|------|------|
| INV-001~INV-020 | 不可违反的规则 |
| 执行域 | 哪个域负责执行 |
| 违反动作 | 违反后的自动处置 |
| 优先级 | P0（立即halt）/ P1（告警+人工介入） |

### §8.5 插件化模块架构原则

| 原则 | 内容 |
|------|------|
| **先接口后模块** | 任何新的分析能力，必须先定义抽象接口，再实现具体模块 |
| **核心引擎不可变** | 数据管道、信号引擎、组合引擎、执行引擎是稳定内核 |
| **可插拔模块** | 每个因子/信号/策略/执行算法是独立模块，实现统一接口 |
| **扩展点** | OCP-001 FactorBase / OCP-002 SignalAlgoBase / OCP-003 ExecAlgoBase |
