## 1. 立项施工单（四件）

### WORK-ORDER-1 组合级收益归因例行报告 [P1]

- **要什么**：纸面盘组合的例行归因报告，能回答四个问题：本期赚的钱哪个策略贡献的 / 成本吃了多少（佣金+滑点+冲击）/ 相对基准（中证1000）超额多少 / 风险贡献怎么分解。
- **为什么现在**：E7 前哨正在攒 30 笔纸面样本。偏差报告回答"差多少"，归因回答"差在哪、钱从哪来"——是验证环的下一层。
- **落点**：`scripts/backtest/` sim 家族旁（与 `sim_paper_ledger.py` 同源 `c1_backtest.sim_pocket_daily`；与 `sim_deviation_report.py` 并列），建议命名 `sim_attribution_report.py`。
- **复用资产**：`backtest/core/cost_attribution.py`（成本归因已有）、`regime_snapshot_history`（基准态）、`strategy_registry`（策略映射）。
- **验收**：① 日频自动产出（daily_kline 完成钩子串联，走 pipeline_events 正门）；② 输出含策略级 P&L 分解 / 成本拖累 / 基准相对收益 / 风险贡献四段；③ 入 CH 一张归因表（DDL 走 `schemas/categories` 真源，禁裸 SQL）；④ 用已有 62 天账本回放，数字与账本对得上。
- **不做什么**：不做逐笔 trade-level 归因（账本日频颗粒度）；不做前端页（先出数据表+报告文件）。
- **预估**：1-2 个夜班会话。

### WORK-ORDER-2 黑天鹅系统三件 [2a P0 / 2b P0 / 2c P2]

现状盘点：感知/判定层基本齐（regime CRISIS 态、`tail_risk_monitor`、`risk_contagion_modeler`、`liquidity_crisis_scenarios`、kill switch、熔断器）。缺动作/对冲/演练三层。五层框架：感知→判定→**动作→对冲→演练**（加粗为缺件）。

- **2a 危机态→动作自动接线 [P0]**：regime=CRISIS 时自动触发动作（停新开仓 / 砍额度系数）。TDM-E-L1 大盘总闸从"影响额度"升级为"能拦单"。**与既有审计 P0（ex_core 风控栈未接自动链）合并施工**：`pipeline_events` + `pf_alloc/vol_target_allocator` + `ex_core` 风控栈一条线打通。验收：注入 CRISIS 快照→次日 pf_alloc 额度收缩 + 账本拒新开仓，全程 fail-closed 留审计。注：这是全项目最危险的雷——今天若接实盘，风控不在自动路径上。
- **2b 对冲腿 [P0]**：股指期货（IF/IC/IM）对冲执行能力，纸面盘先行。数据侧已备（B 线期货回补）；执行侧需期货通道适配 + 对冲触发规则（哪些危机态、多大幅度）。验收：纸面环境完成一次"危机态→自动开对冲腿→危机解除→平对冲"全流程演练。
- **2c 演练机制 [P2]**：每月例行——历史极端日（2015 千股跌停 / 2018 贸易战 / 2020 疫情 / 2024 微盘崩盘）重放当前持仓，出伤亡报告（MaxDD / 是否触及破产地板 / 恢复天数）。落点：backtest 域脚本 + 月频计划任务。验收：首份演练报告落地并挂 task_board 被消费。

### WORK-ORDER-3 配置生效核对器 [P2，约半个会话]

- **要什么**：消灭"以为生效实际没生效"的静默失败。**不做热更新本体**（已裁定搁置，见 §2），只做烟雾报警器。
- **方案**：核对脚本，对关键配置（`schedule.yaml` / `tasks.yaml` / `risk_params.yaml` / `trading_decision_map.yaml` 等）对比"磁盘当前值" vs "目标进程运行时已加载值"，不一致即告警（failures/*.json + task_board）。
- **验收**：① 改 schedule.yaml 不重启→核对器报不一致（指到具体键）；② 重启调度器→转绿；③ 覆盖 ≥4 个关键配置文件。
- **预估**：半个会话。

### WORK-ORDER-4 告警外推通道 [前置条件：实盘前必建]

- **前置条件**：实盘（真金白银）启动前 MUST 建成。纸面盘亏了明天还在；实盘后睡觉时仓位是醒着的。
- **最低版本**：单通道（Server 酱/钉钉/飞书任一，推一个手机），触发条件 = failures/*.json 出现 CRITICAL 或 kill_switch 触发。
- **历史**：2026-09-15 裁撤飞书/SMTP 通道（当时合理：纯纸面 + Owner 日均 16h 在机前）；GRAFANA 失守告警实现可参考。
- **预估**：半个会话（极简单通道版）。
