## §2 与既有资产边界

1. **事件 vs 信号域**：099/101 是 D_ASHARE_SIGNAL 域（MODIFY-GUARD=AUD-DRAFT-001 深挖批 B10-01369/01371+CAND-TESTB-014/016）——L3 施工只**接线+定义新事件**，不改两件的判定核（改核=深挖批注册面重开）。
2. **vs bottom_confirmation_entry（MOD-SIG-103）**：:21-25 明文分工——099 管"是不是恐慌底"（事件），103 管"什么时候进、止损放哪"（确认整合+入场触发）——E1/E2 接线时落 099 侧，**禁把事件直接接成 entry 信号**（违研究档 §7.4 负面清单）。
3. **vs detect_phase_transition（sentiment_cycle.py:267）**：输出 PhaseTransitionSignal（:253-264，transition_type=bottom_reversal/top_divergence/none，先行+确认双触发）——这是**段间转移信号**（L2 面），与 L3 事件集分属两层；E6 放量反扑的"先行指标"设计可复用其先行+确认双判定模式，但不并入 L3 封闭集。
4. **vs TDM S3**：S3 是传感器节点（读数连续面），E4 是离散事件——事件化落点=新事件表+TDM S6（Q14 挂 entry_flow 传感器阵列），**不改 S3 本体**（S3 有 CASEBOOK-001#outage 在案，2026-09-16 note_confirmed）。
5. **vs compute_sentiment_temperature 的段粗映射**（sentiment_cycle.py:198"<20 冰点/<40 反核/<70 主升/<90 疯狂/≥90 退潮前兆"）：这是温度→五段粗映射（L2 面），禁当事件触发用——事件触发必须显式离散条件+滞后面申报。

## §3 施工要点（实读代码的坑）

1. **099 阈值全部可配且构造即校验**（:119-167 fail-closed：repair_prob_threshold∈(0,1)、查表键须=0..max_lag、收回比率 0<true<shakeout<1）——接线时配置对象走 config 注入，禁散改默认值；shakeout/真破位区分（:35：收回>0.5→shakeout、<0.2→true_breakdown）是 E1 的否决腿，接线必须带上（真破位强制阻断反转，INVARIANTS）。
2. **修复概率是静态查表非实时频率**（:8 INVARIANTS"查表静态可审计（非实时频率估计）"）——4_validation 的事件命中率判据在滚动样本外对 0.7x 复验时，**不得反查表调参**（那是语义参数=Owner 门位）。
3. **101 的零方差降级**：窗零方差→z=0+notes 不伪造背离（:8）——E3 接线时监控 notes 频率，高频零方差=情绪指数或价格序列断流的前兆信号。
4. **E4 的口径对齐坑**：S3 算法注记的溢价口径（昨日涨停股今日平均溢价）与 lhb_premium_analyzer 模块、daban 七要素派生三个来源并存——事件定义须钉唯一口径源（建议=daban 派生，与 C1/C2 同源可考）并在事件表带 source 字段。
5. **E5/E7 的史浅依赖**：250 日分位窗在 daban 22 交易日历史上不可算——两事件的触发阈值在史补完成前只能按绝对阈值（社区经验值：炸板率 35%=隶属度 0.5 锚，TDM:6464 在册）过渡，史补后切分位=机械参数自修留痕。
6. **E6 新定义的落位**：建议复用 099 的 frozen dataclass+静态查表模式（asdict JSON 可序列化先例），触发草案进呈批包（Q2 后续），**不抢跑实现**。
7. **事件表落库纪律**：事件=append-only（禁改写，快照器先例 emotion_index_snapshot）；每事件行必带 {event_id, trade_date, trigger_condition_snapshot, confidence, pit_lag_days, source_version}——P2 判据冻结时按 event_id 逐件核。
