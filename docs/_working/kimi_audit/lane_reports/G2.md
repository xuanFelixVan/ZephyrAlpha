## 1. R-05 复核取证（A3 数据抽查验证）

账本 `.runtime/audit/worktree_drift_watchdog.jsonl`（本班测量时 72,456,165 B，估算约 14.3 万行，与 A3 截止时点 156,900 行同量级）：

- **同键重复（file, work_hash, verdict）抽样**：随机 400 段抽样 127,031 条，**62.9%** 的记录其签名在样本内存在重复——同哈希零变化重复写大量存在，方向与 A3 实锤一致。
- **verdict 分布抽样**：`grace_suppressed` ≈58.6%（A3 全量 57.4%）、`alerted` 11.6%（A3 11.8%）——分布精确吻合，佐证抽样有效。
- 口径差异披露：A3 的 37% 为"逐文件相邻同哈希同 verdict"口径；我用朴素逐行相邻口径在连续窗口（122,107 条）只得 0.6%（多文件交错稀释），按签名分组口径则得 62.9%（高于 37%，因样本内任意位置重复都计入）。**结论：37% 量级可信，病根成立。**
- 源码级复核（改前）：`scan_once` 收尾 `_save_state(root, state)` 位于 `if alert_enabled:` 块内（原 :1270），observe-only 即时扫（网关 post-commit 挂点 `make_worktree_drift_watchdog_reconciler`）写审计但**不落 state** → 下一笔 commit 重读旧 state → 同哈希漂移重复落盘。与 A3 §2.2 机理判定一致。

## 2. R-05 治本改动（`src/zephyr/gov_enforcement/rule_bridge/worktree_drift_watchdog.py`）

| 点 | 改前 | 改后 |
|---|---|---|
| state 持久化 | `_save_state` 被 `alert_enabled` 门控，observe-only 扫描后内存态直接丢弃 | **始终落盘**（:1290，`alert_enabled` 块外）：files_state 漂移指纹集成为全模式共享去重真源 |
| 审计落盘时机 | observe-only 每次扫描对同哈希漂移重复写 `grace_suppressed`/`claimed` 等行 | 同签名由既有 dedup（:1184 `prev.work_hash == wh` → `dedup_skipped`）拦截，**审计行只在指纹变化时落盘** |
| 活着证明 | 无 | 新增 `_heartbeat`（:397）：每 UTC 日至多一行 `verdict=heartbeat`，先于 `_save_state` 调用使 `heartbeat_date` 随 state 落盘 |
| 告警语义 | — | **零变化**：`alerted` 字典推进、critical_warn/clean 自愈仍由 daemon 单写（`if alert_enabled:` 块保留）；observe-only 的 `observed` 分支仍不推进指纹（防吞设计不动） |

附带行为披露（非语义变更）：删除型漂移首见容忍轮现在跨 observe-only/daemon 共享指纹态，daemon 升级告警可能提前一个扫描周期（检测对象、告警文案、升级判据均未变）。

## 6. 结论（≤10 行）

1. R-05 病根源码级坐实并治本：`_save_state` 与 alert 门控解耦，指纹态全模式始终落盘，observe-only 自激环断根。

3. 新增每日一行心跳（verdict=heartbeat）区分"watchdog 死了"与"全仓零漂移"。
4. R-06 治本：档位签名状态机 + 30min 冷却常量 `_LEDGER_ALERT_COOLDOWN_S`；同档冷却、跨档立即、期后重报、回落归零四态齐备。
5. 纪律达标：只改"什么时候落盘"；检测判据、告警文案、daemon 唯一告警写者语义零变化（belt 告警行仅新增 backlog_level 附加字段）。
6. 测试 117 全绿（含 8 条新增 + 6 个 redteam 套回归）。
7. 验收判据可观测：R-05 看账本日增量与 heartbeat 行；R-06 看同档 30min 内 ≤1 条。
