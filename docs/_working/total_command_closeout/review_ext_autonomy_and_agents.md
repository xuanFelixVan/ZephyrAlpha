**主题 2 阶段性共识（≥2 独立来源：Kleppmann E2-01 + etcd E2-02 + ZooKeeper E2-03）**：TTL/心跳过期机制在三家成熟系统里**都只负责"清理资源占用"**（删键 / 删临时节点 / 摘 leader），**没有一家把"TTL 过期"当作"原持有者已停止写入"的证明**。Kleppmann 明确指出该证明在异步系统里不可能靠锁/TTL 获得，必须由**资源侧校验单调 fencing token** 才成立。⇒ 本仓"90s 判死 + 自动收回全部 claim"若被当作安全机制使用（即认为收回后就不会有双写），是与三家系统一致否定的假设。**正确形态＝TTL 管回收 + epoch 管正确性，两者分工，不可互相替代。**

```
assumed:    [{claim: "...", why_unverified: "..."}]        # 显式分离"验证过"与"假设"（E5-11 verification 类）
next_actions: [{action: "...", precondition: "..."}]       # 续跑入口（E5-03 进度笔记）
blocked_by: [{kind: "gate|lock|missing_source|injection_suspect", ref: "..."}]
resume_cmd: "python -m zephyr.... --resume <lane_id>"       # 若无可执行续跑入口，此字段写 null 并计入度量
```

**为什么这四组字段是"最小充分"**（每组对应一个已实测事故）：
- `turn_budget` + `status: turn_limit_hit` → 直接对基线 8 条撞限车道；`pct ≥ 80%` 时强制刷 checkpoint（业界对应：durable execution 的定期快照）。
- `verified` / `assumed` **分离** → 对 MAST 的 task verification 大类（E5-11），也对本次两路红队 5 条假 P0（假 P0 ＝ 把 assumed 当 verified 报）。
- `input_set_disjoint_with` → 对 ≥14 簇重复事实（E5-01）与 11 份交接书互相矛盾（E5-04/E5-06）。
- `evidence_ref.cmd` 必填 → 对 G-71「exit 0≠跑完」与 G-72「红队结论二次复验」：无 cmd 的声称不可被复算，即不算 verified。

**度量**：`resume_credential_exists_ratio`（基线 0/8）、`verified_assumed_separated`（基线 False）、`events_append_only`（布尔）、`checkpoint_generated_not_handwritten`（布尔，对标 E6-05）。

### T-2 · 声称→验证契约（对标 E6-04 Pact、E6-01 ADR 不可变律、E6-03 Backstage lifecycle/owner）

**要解决的问题**："已完成"无法机械验证；40+ 处叙述与 HEAD 不符系抽样发现。

## §五 我最没把握的 3 条

1. **E1-01（Job Object）的落地覆盖率——最没把握，且可能推翻我对痛点 1 的处方强度。**
