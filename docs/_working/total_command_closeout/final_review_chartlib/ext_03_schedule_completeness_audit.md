### 7.2 根因分层（三层，全部实测确认）

- **L1 形状契约陷阱**：`ch_reader.query()` 返回 `str`（TSV），不是行集。类型上合法、语义上极易违约——连外部审查员（本卷作者）都踩了；仓内 12+ 消费文件多数正确（变量名就叫 `tsv`），但**任何新消费者都会重蹈**。`count()` 自带 `int(result.strip())` 解析所以安全——危险面集中在 `query()`。
- **L2 fail-silent 错误契约**：`ch_reader` 头注 `[ERROR_CONTRACT] query失败->返回空字符串(同ch_writer); count失败->返回0`。这正是交接令明令"禁 ch_writer.query（出错返回空串＝静默无数据幻觉）"想防的病——**但 ch_reader.query 只是薄包装，同样的病原样透传**，交接令要求的"会抛错的 reader"在数据层根本不存在（全仓 grep `query_strict/strict_query` 零命中，仅 ch_config 有配置加载的 raise）。**衍生风险（高危）**：`count()` 失败返回 0 会被下游当成"空壳表"证据——**W-34 空壳表清单本身可能是 fail-silent 的产物**，须用严格口径复测重出。
- **L3 判据类读数无标准工具**：X-26/X-27 立法了"双探测/证据降级"，但没有工具化——每个审计员各自手写探测（本卷两次手写探测一次踩坑即为例证），无传输路径标记、无时间戳落盘、无"真空 vs 失败"区分。
