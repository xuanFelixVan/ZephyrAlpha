## 〇、通则（本次裁定的一条可复用判据，适用全部"净删/退役"类案）

**Owner 门位的四类高险动作（生产流转／注册表净删／flag 出厂翻转／资金破坏性）不在夜间自裁范围内。**
但"不能删"≠"不能推进"：凡待裁案的动作本质是**清除脏数据/退役死物**，一律改造成
**"可逆隔离 + dry-run 清单 + diff 化披露"** 三段式，改造后的动作不再触及门位，故可由本册直接裁定开工：

| 原动作 | 改造成（本册裁法） | 为什么不再触门位 |
|---|---|---|
| DROP 表 | `RENAME` 到 `*_retired_<日期>` 隔离区＋挂"零消费"探针，30 天无引用再走正式退役裁定 | 可逆；注册表/表集合条目未净删 |
| DELETE 脏行 | 先出 `dry_run` 清单（行数+主键+抽样）入册，改写侧加"追加更正行"通道（禁 UPDATE/DELETE 原行） | 数据面只增不改，判据见既有 exam_result 追加更正先例 |
| 关/翻 flag | 只加 opt-in 旗标与披露，默认值不动 | 出厂默认未翻转 |

配套铁律继承：净删零容忍（REGISTRY-MASS-DELETION）、追加更正优于原地改写、
判重用 `check_tick_duplication.py` 禁聚合数（RULE-DATA-OPS 三步验证）。
