# 全流通挖矿分工册

> **一句话**：把《00_全环节总册.md》的 122 环节按域切成 12 个深挖组，每组=环节集+真源清单+产出子目录+与既有九车道（M1-M8）的关系，供总筹派工。
> **派工原则**（继承总筹册 00_orchestration.md）：①挖矿车道只读+写本目录作业簿，**零 commit、零 enqueue、零主区写入**；②已挖干车道（M1-M8）**引用不重挖**，深挖组只补其声明的"补挖项/待挖扩展项"；③新组先挖全流通断链点（总册 §二 红叉位 7 处）；④作业簿按总筹册 §二 模板（六向台账/子模块清单/堵点/三态自审）。
> **优先级口径**：P0=断链点/唯一人工门/缺位件（先挖即施工价值最高）；P1=主链；P2=支线。

1. **新组先立 overview 册再拆册**：防止总筹看不到组级结论；每册完成即更新本分工册 §一 状态列（待派→挖矿中→挖干/待裁）。
2. **在飞避让**（继承总筹册）：docs/03_modules/**、TDM 本体、AGENTS.md、pf_core/backtest 禁写；GPU T1（PID 在跑）禁中动；禁 kill belt；禁插队；热文件 safe_write_text CAS。
3. **真源优先序**：capability_lookup.find(<kw>) 留审计 → 本分工册列的真源 → ROOR 反查 → Grep 符号发现；发现本册未列的新矿脉→写进该组 overview 的"矿脉增补"节，回填总筹。
4. **零 commit**：全部产出落 docs/_working/fullflow_mining/ 各子目录，交付=TTL 内 promote 判定归总筹/Owner。
5. **对账回写**：各组挖干后回写总册两处——§一 该组环节状态列、§四 断链点清单翻绿/确认；口径漂移（总册 §五）发现新证据一并回填。
