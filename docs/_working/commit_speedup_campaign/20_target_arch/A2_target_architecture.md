# A2 目标架构 —— 分片车道 + 不可变树校验

> 车道 L5（目标架构）｜立档 2026-09-24｜数据依据同目录 `a1_conflict_graph.yaml`（冲突实测图）与 `a3_gate_repointing_matrix.yaml`（102 台门逐台改指表）
> 合同与判据锚点：`../00_commit_speedup_master_plan.md` 第 1 节（G1 提交者等待 <10 秒 / G2 后台吞吐 ≥60 件/小时）

## 0. 对 Owner 提案的判定：方向对，三处要改

提案原话：**「每个区域一条传送带；施工队先查区域 ID，在该区域建 worktree，提交只走该区域的通道；同一区域同时只允许一支施工队（两支就排队）」**

| # | 提案成分 | 判定 | 实测依据（A1） |
|---|---|---|---|
| 1 | 一条区域一条传送带（分片） | ✅ 采纳，但"区域"必须由**冲突图**导出而非组织图 | 103 个实测冲突域；5.95% 的跨会话件对在文件路径层真冲突，改片后 0.6% |
| 2 | 施工队查区域 ID 建 worktree | ✅ 采纳（车道 worktree = 不可变树的落地壳） | 门禁今日读的是共享暂存区（543 个他人 AM 文件）⇒ 与 worktree 无冲突，但**必须换成读自己的树** |
| 3 | 同一区域同时只允许一支施工队 | ❌ **不采纳（全域）**：会把四分之三的可并行工作白扔掉 | 同域在途件对 13,012 对里 **74.8% 文件互不相交**；若按域独占，平均需要 14.2 条车道而当前在途件只有 7 件（中位数） |
| 4 | （隐含）分片即提速 | ❌ 分片**不充分**。今天 5 台全仓扫描门 53.2s / 64s 链，读的是共享可变暂存区；不改输入源，加道只是把"排队"切成分段排队 | 前五门 1 文件 16.7s vs 184 文件 15.6s ⇒ 成本与你的 diff 无关 |
| 5 | （缺件）派生产物与热册才是真串行源 | ❌ 必须补：**整册重写的派生产物出窗 + 手 append 热册按条目键 merge** | 8 个共享文件吃掉 71% 冲突重量，单 `capability_canonical_file_registry.yaml` 吃 53.4%；把这 8 个摘出提交路径，跨会话冲突从 5.95% → 0.63% |

一句话：**分片键 = 变更触及的路径集合（+ 派生产物出窗），不是"区域"；一条全局串行点只保留在 git 分支 ref 的 CAS 上（预算 <5 秒）。**

## 1. 目标拓扑

```
施工队(6-50 AI)
   │ git_commit.py --enqueue（CLI 不变）
   ▼
┌─ C1 提交受理台 presubmit ────────────── <10s，同步，返回"受理令牌"
│   只读：本件不可变树（own-tree）＋ 控制面（claim/意图/队列台账）
│   40 台 own-tree 内容门 ＋ 34 台触发门快路径 ＋ 16 台信号门
└──────────────────────────────────────
   │ 入队（件里带 own_tree_sha + base_tree_sha + 声明的条目键）
   ▼
┌─ C2 冲突域车道 ×N（按需动态开，非固定编制）── 校验/落地并行，不占提交者
│   每条车道 = 1 个 lane worktree + 1 条工线程 + 1 个临时索引
│   C6 校验引擎：100% 读不可变树（基树∪本件树），绝不读主工作区/共享 index
├─ C3 热册条目道（registry-append）────── 按 gate_id/module_path/裁定号做三方键 merge，仅同键真撞才串
├─ C4 派生整合者（derived consolidator，唯一写者，异步）── 4 张整册重写的派生册不再由提交者产出
└──────────────────────────────────────
   │ 批次（TAP 式）：merge-tree 内存合成 trial tip → 一次重活校验
   ▼
┌─ C5 唯一全局串行点 ref-cas ─────────── git commit-tree + update-ref dev <new> <old>，持锁 <5s
└──────────────────────────────────────
   ▼ post-merge 全量回归 + revert-first 兜底（C7）
```

## 3. 要害：校验只读不可变树（102 台逐台改指见 A3）

### 3.1 一个收口点解决 72 台

A3 实测：**72/102 台**的门在代码里走 `_get_staged_py_files` / `_get_staged_files` / `_read_staged_file` / `--cached`（`commit_gates/_diff_helpers.py:232-290`）。它们今天返回的是**整份共享暂存区**，这就是"我的等待随别人暂存多少而涨"的根。另有 15 台读暂存区却**没有** own-scope 收窄，19 台暂存区干净但直读主工作区，39 台读 `_registry/catalogs` 名册，31 台依赖 HEAD。

改法（判据一行不动，只换输入源）：

1. 新增 `commit_gates/tree_view.py::CommitTreeView(base_commit, files, blobs)`：
   - `GIT_INDEX_FILE` 临时索引：`read-tree <base>` + `update-index --add --cacheinfo <mode>,<blob>,<path>` + `write-tree` → `own_tree_sha`。
     **先例已在本仓两处**：`git_commit_gateway.py:3199-3260 _run_precommit_channel`（裁定登记过的方案②通道）与 `emergency_commit.py:608`。
   - 只读 API：`list_paths(diff_filter)`、`read(path) -> bytes`（`git cat-file --batch` 批读）、`added_lines(path)`（`diff-tree -p` 解析）、`tree_sha`。
   - 件间复用：blob 已在 `.runtime/commit_queue/blobs/`（内容寻址），受理台不必重新 `hash-object`。
2. `_diff_helpers` 的 4 个函数改成**代理**：有活动 `CommitTreeView` 就读树，没有就走旧路径（flag 分档，见 A4）。这一步把 72 台一次性改指，代码零逐台重写。
3. 名册读取根同源化：网关已有 `roster_root` 参数（`git_commit_gateway.py:981`），扩一个 `ref=`（从被校验的树里读名册字节，而非主工作区）⇒ 39 台读 `_registry/catalogs` 的门不再看到"半路被人改过的册"。派生整合者出册前，车道看到的永远是 base 树里的册。
4. HEAD 依赖 31 台：缓存键与判定基线一律改用 `base_tree_sha`（受理时钉死），HEAD 前进不再让缓存全废——现状 `gate_cache_preflight.py:164-184` 把 `head_sha` 同时塞进键与 `lookup` 复核，所以 24 小时只有 87 次命中 / 6541 次跳过。
5. 唯一需要额外快照的是读 DB/PG 的门（`DEPGRAPH-PRE-REGISTRATION` 等）：受理时锁 `depgraph_snapshot_id` 写进件，门读该快照。
6. **不可读工作区的强制护栏**：车道内跑门时 `CommitTreeView` 装"工作树直读探针"（读路径命中 repo 物理路径即记违规并 fail-closed），与本仓拦截裸 duckdb / 裸 LLM 的同族做法。没有护栏的"约定"会在一周内退化。

### 3.2 缓存按内容，不按 HEAD

`GateResultCache._path`（`gate_cache_preflight.py:165-169`）键改为
`gate_id × spec_sha(门源码+规则 YAML 哈希) × own_tree_sha × sorted(inputs_sha)`，
`lookup` 去掉 HEAD 复核，改为"件落地时 base_tree 仍是当前 HEAD 祖先"这一**廉价**前提（不成立 ⇒ 车道重跑，不打扰提交者）。缓存白名单从 14 台扩到 **86 台**（A3 `own_tree_able_count=86`）。

## 4. 分片车道：键、租约、唯一串行点

1. **车道 = 冲突域，按需动态开**，键 = A1 导出的 3 级路径前缀（103 个实测域，`scripts/governance`、`tests/governance`、`src/zephyr/gov_enforcement`… 见 A1 `conflict_domains`）。域不是编制、不是人：`lane_registry.yaml`（生成器产出，禁手工维护）记 `lane_id → 域前缀 → 当前持有件`。
2. **一件可跨多域**（36% 的件触及 ≥2 个残差域）⇒ 按域 ID 字典序**批量申请**全部所需租约，拿不齐就整体退避（不死锁、不半持）。这把"多域件"变成调度问题而非排队问题。
3. **租约粒度 = 路径，不是队**。同域在途件对里 74.8% 文件互不相交（A1）：路径租约让它们并发，域独占让它们白等。这就是**不采纳"同一区域只允许一支施工队"**的量化理由：域独占的可实现并发上限只有 14.2 条道，而在途件中位数 7 件；按路径租约则可实现的独立并发 = 平均 3.9 / 峰值 10，且**零额外等待**。
4. **唯一全局串行点 `ref-cas`**：`git commit-tree`（可并行，内容寻址）+ `git update-ref refs/heads/dev <new> <old>`（必须独占，CAS 失败即重放）。持锁预算 **<5 秒**（只包 ref 移动与队列件状态翻转），超预算告警并计入遥测。今天 `_GlobalCommitLock`（`git_commit_gateway.py:2501`）把 102 台门 + 68 台 hook 全关在锁里 ⇒ 产能恒等 1.000。
5. **高门位域例外**（`risk_tier_registry.yaml` 里的 high 域：资金破坏性、注册表净删、flag 出厂翻转）：保持"同步等真落地"语义（`--wait-landed`），吞吐不重要、确定性重要。
6. 队列件 schema **向后兼容**地加字段：`base_tree_sha`、`own_tree_sha`、`declared_keys`（热册条目键）、`lanes`、`snapshot_ids`。旧件缺字段 ⇒ 受理台补算一次（派生出窗前须完成，见 A4 S4 的前置）。A1 证据：今日袋里 **79/80、22/22、21/22、21/22** 的键级差分**因缺 base 溯源而不可测**——这正是必须先补 base 的原因。

## 6. TAP 式分批与投机并行

1. **成批**：调度器从各车道头凑一个 batch（默认 N=4，硬顶 = 车道数的 2 倍），成员两两**租约不相交**（这才让合树是机械的）；`merge-tree --write-tree` 合成 `trial_tip`，不建工作区。
2. **投机校验**：重活（全量门 + 全量 hook + 受影响测试）对 `trial_tip` 跑**一次**，成员并行等待。校验中 HEAD 可继续前进：trial_tip 是钉死的树，与 HEAD 无关——这是"读不可变树"给分片带来的第二重收益。
3. **失败处置**（定义清楚，不靠临场判断）：
   - 组内二分定位（先试去掉最后加入者，再对半）；
   - 定位到的成员：`retry-without` = 其余成员照常落地，肇事成员回炉（base 前进 ⇒ 自动 rebase 重试，≤2 次）；
   - 2 次仍红 ⇒ `dead` 态（写 `dead_reason` + 证据锚点），走既有 `commit_queue.py requeue <qid>` 正门复活；
   - 组内**非肇事**成员永不为他人连坐等待（本仓 own-diff 作用域纪律的车道版）。
4. **公平**（修今天两个 bug）：
   - 队首键从 qid 字符串（=会话名字母序，`commit_queue.py:1193` + `_pick_head:1100`）改成 `created_at` + 单调序号；当前 77 件 pending（快照，队列在动） 里实测**倒挂率 27.8%**；
   - aging：等待超过窗口 p50 的 2 倍 ⇒ 进"优先批"，最长等待预算 3 分钟；
   - 反饿死：每条**活跃车道**每 5 分钟至少被组进一次（组不进的证据落遥测），杜绝"大批次永远压着小批次"；
   - 批大小上限 + "超顶大批不参与队首独占"（沿用战役批5 口径）。
5. **吞吐上限核算**：串行点持锁 <5s ⇒ 单纯 ref 上限 720 件/小时；车道 μ≈60–90s × 4–8 条 ⇒ 160–480 件/小时；真正的约束变成校验算力与派生整合者，而不是排队。G2 的 ≥60/小时 有余量。

## 7. revert-first：把"重活后移"换成的风险补回来（Owner 的担忧正面回答）

**原则：判据一个字不动，只搬执行位置。** A3 表逐台给了 `target_position` 与 `repoint_recipe`；每台搬家的门都要留一条"位置换了、结论一样"的证据。

| 今天 | 目标 | 结论如何保住 |
|---|---|---|
| 红 = 提交被拒（同步） | 红 = **不许落地**（车道/post-merge 校验，异步但强制） | 件只有 `verified` 才能进 ref-cas；verdict 位从"拒提交"变"拒落地 + 自动退件" |
| 无 post-merge 全量 | C7 全量回归（门 + hook + 受影响测试）每批次必跑 | 不可变树 ⇒ 结果只随内容变；红 ⇒ 自动 backout |
| 失败重试人肉 | 自动 backout：`revert --no-commit` 进临时索引，门链跑完再 CAS；同时冻结该件所有者的后续入队（2 次红进隔离道） | 退件本身也是被门校验过的提交，不产生"未校验窗口" |
| 未校验窗口不可见 | `verification_pending` 计数上仪表盘；超预算（>10 分钟或 >20 件）⇒ 车道自动停油门 | 停油门由既有 belt 守护执行，不新增人审 |
| Owner 门位 | high 域（`risk_tier_registry.yaml`）保持同步等落地；其余全自动 | 门位语义不变 |
| **谁被呼叫** | 值守 = commit belt 守护所在车道值班（自动）；Owner 只收"裁定级"升级（flag 出厂翻转、注册表净删、退件回滚不掉） | 不把治理成本转嫁成人力 |

**自证要求（硬）**：搬位置的门 MUST 通过"重放判据全等"——取最近 100→1000 笔历史提交，逐笔在旧通道与新通道各跑一次，verdict 差异集必须为空；这就是战役批6 判据（本仓 F3 的历史欠账），红测优先（恒绿尺＝无效尺）。

## 8. AI 专属问题（6–50 并发小提交者）

1. **跨会话重复劳动**（同文件被两支改）：真冲突率在摘掉派生册后是 **0.63% 的件对**，处理点=**合树**（`merge-tree`）而非编辑前禁止；键级真撞（同一条目键）⇒ 后到者收到 `stale_by` + 可 rebase 的重投件，不判违规。今天 115 条"重复链"（同件最多重投 26 次）是**再生命**，不是重复劳动：派生出窗后自然消失。
2. **claim 与进程普查的相互作用**（施工队实测：`Get-CimInstance` 判活 × claim 释放）：租约必须有 TTL + 僵尸持有者回收（现有 `_GlobalCommitLock` 已有 PID 死亡清理逻辑，`git_commit_gateway.py:551`），搬到路径租约时保留同款语义；车道 worker 的 cmdline 子串登记进 `data/runtime/process_reaper_keep.txt`，否则 reaper 会把校验中的车道当孤儿杀掉（本仓有熄火零证据的前科）。
3. **"一域一 Owner" 要不要？** 不要。证据：103 域里 65 个多会话、41 个 ≥3 会话；同域在途对 74.8% 文件互不相交；独占后上限并发 14.2 道但实际在途中位数只有 7 件 ⇒ **独占买不到安全，只买等待**。唯一需要"唯一写者"的是**派生产物**（§5 C4），那是产物属性不是人属性。
4. **袋的自残**：同 sid 后袋静默超前袋（本仓在册）→ 件 schema 必填 `supersedes`，受理台拒绝隐式超并；这是分片后仍然存在的坑，与车道无关，列在 A4 S1 判据里顺手闭掉。

## 8.5 反目标（本设计刻意**不**做的事，以及为什么）

| 不做 | 为什么 |
|---|---|
| **删门禁 / 降判据口径 / 抬阈值** | Owner 明令只允许合并、降档、diff 化、改执行位置；本方案 102 台全留，且 A3 逐台写明"搬家后结论如何保住"。A1/A2 全部数字是在"一台不删"的约束下算出来的 |
| **换 VCS / 换托管模型 / 上 Gerrit 式人审队列** | 迁移成本与本病无关；本仓真源是 git + 本地 dev，且人审串行只会把等待从分钟变小时。Bors 式纯串行评审队列的公开产能口径（≈4 改动/小时）**低于**我们今天名义 24/小时，方向不对；该外部说法在战役总纲第 4 节已降级为"待第二来源"，本设计不据其立项 |
| **分布式 git / 多副本共写同一分支** | 分支 ref 是线性历史的唯一真源；我们要的是"把独占窗口压到 <5 秒"，不是"把 ref 复制成 N 份"。后者会把冲突从合并前搬到合并后，代价更高且不可回滚 |
| **给每个会话开一条永久队列（"按 session 分片"）** | 已实测否证：k=4 池并发恰 1.000，因为病根是共享可变态不是工人数量。按会话分片既不解共享 index 依赖，也不解热册冲突，只是把同一把锁排成 N 条队 |
| **按组织/功能域固定编制车道** | 103 个实测域里 65 个多会话、同域在途对 74.8% 文件不相交；固定编制必然与漂移的实际热点错配。车道是**动态租约**，不是编制 |
| **长命分支 + 大合并** | 会把"每步可验证"变成"一次性对账"，与本仓 diff 作用域纪律和 revert-first 直接冲突 |
| **把治理搬到人工评审（让人来看提交）** | Owner 的时间比机器贵一个量级；门位只保留在 `risk_tier_registry.yaml` 的 high 域，其余用"落地前必校验 + 落地后自动退件"替人 |
| **为了吞吐放宽 own-scope / 连坐判定** | 连坐是今天的痛，但解法是"件只看自己的树"，不是"少看内容"。S1 判据是重放全等，不是变快就算过 |
| **用"缓存命中率高"当唯一 KPI** | 缓存是手段；若命中率靠缩小被扫内容来达成，就是判据退化。S2 的红测（改名册必须立刻判失）就是为这条设的 |


## 9. 兼容面与净零声明

- **不变**：`scripts/git_commit.py` / `commit_queue.py` CLI 与队列件 schema（只增列）；`[GW:]` 标记与 POST-COMMIT-GUARD；102 台门与 68 台 hook 的**集合**；pre-commit 通道（位置后移，不删）；worktree 施工规程；ROOR / 注册表真源方向；flags 默认 OFF（逐档翻转属 Owner 窗口）。
- **净零**：本设计**不新增门禁台、不新增规则册**。新增物仅 3 件设施：`tree_view.py`（收口共享暂存区读取）、`lane_registry.yaml`（生成器产出的运行时台账）、`derived consolidator` 的调度入口（挂现有 belt 守护）。若后续要加"派生册一致性不变式"门，须按全资产净零声明替代条目（候选＝A4 普查出的同簇恒绿门合并，属 L4 车道）。
