# 节点级可回测治理——全量问题清单（已裁定：个人量化精简版）

> **日期**：2026-09-09 ｜ **提出**：Owner ｜ **状态**：已裁定（个人量化精简版，见 §七）
> **一句话目标**：交易决策全景图的每一个节点都能被回测验证——有日志、有依据、有结论（有效还是噪音），前端一键可查。
> **说明**：§一~§六 是盘点与调研过程，**§七 是 Owner 已裁定的最终口径**，施工以 §七 为准。
> **用语**：文中"回测"=用历史行情验证设计（Owner 口中的"回撤"）。

## 一、总目标拆解（Owner 原话 → 治理语言）

| Owner 要什么 | 治理语言 | 现状 |
|---|---|---|
| 每个节点都可以回测 | 节点级验证方法学（每类节点定义"怎么算对错"） | ❌ 缺，最大的一块 |
| 每个节点有回测日志（时间/地图版本/算法/结论） | 节点验证台账（run 级+节点级两层） | ❌ 缺 |
| 结论：哪些数据有效、哪些是噪音 | 验证结论三态（有效/噪音/待观察）+ 治理闭环 | ❌ 缺 |
| 前端右侧详情栏加"回测详情"栏 | 抽屉新增「验证档案」区（读台账） | ❌ 缺 |
| 节点用了哪些算法、是不是共振 | 算法链登记（多算法+共振逻辑结构化） | ⚠️ 半缺（algo_refs 只有技术指标/执行算法，决策算法如 HMM/RegimeSnapshot/六段预算未登记） |
| 回测必须能追到地图版本 | 快照绑定（D-a，已在途） | ⚠️ 待裁定 |
| 数据不能偷看未来 | PIT 数据层已有 pit_policy/valid_since ✅；参数层缺 holdout 纪律（D-c） | ⚠️ 部分缺 |

**核心认知（先说清，防止过度施工）**：地图 YAML 是**设计真源**（静态），回测台账是**运行产物**（动态）。验证状态、回测日志**不进 YAML**——存数据库，前端抽屉实时查。否则地图文件被运行数据污染，门禁和 diff 都会烂。

## 二、问题全量清单（PB-01 ~ PB-12，逐条裁定）

### PB-01 节点验证方法学（每类节点"怎么算对错"）★最大缺口

- **大白话**：节点是"判定"，不是"交易"，不能直接看盈亏。比如"市场状态判定"说今天过热——那要验证的是：**它喊热的那些天，后面真的跌了吗？** 每类节点要定义自己的"对错标准"。
- **建议分类**（按节点职责分五类验证法）：
  | 节点类型 | 例子 | 验证方法 |
  |---|---|---|
  | 传感器类 | L1 五传感器 | 信号分档 vs 未来 N 日收益/波动的**单调性**（喊越热是不是真越危险） |
  | 判定/聚合类 | 市场状态判定、九阶段 | 分档 vs 后续走势的**区分度**（各档之后行情是否显著不同） |
  | 执行类 | L4 买卖执行 | 执行质量（滑点、成交率、未成交率）vs 基准 |
  | 离场/风控类 | X 流 S1/R1 | 触发后是否**避免更大损失**（触发 vs 不触发的反事实对照） |
  | 组合类 | F 流 C1-C3 | 归因准确性（归因结论 vs 逐笔账本对账） |
- **改动面**：地图 YAML 节点加一个 `validation_method` 枚举字段（五类之一）→ 过门禁 R15 需同步扩枚举；或存登记表不动 YAML（推荐后者，少一门禁改动）。
- **裁定点**：五类分法是否认可？存 YAML 还是存登记表？

### PB-02 节点验证台账（Owner 说的"回测日志"）★核心存储

- **大白话**：一张台账表，每次回测往里记一行行"节点成绩单"。
- **建议字段**（草案）：`run_id（哪次回测）/ snapshot_hash（哪版地图）/ window（回测窗口）/ node_id / validation_method / 触发次数 / 命中方向占比 / 显著性(p值) / 结论(有效|噪音|待观察) / 结论时间 / 备注`。
- **存储**：ClickHouse 新表（如 `c1_backtest.node_verdict`），与既有回测 run 体系挂靠。
- **裁定点**：字段清单是否认可？表名/库归属确认。

### PB-03 验证结论反哺地图（噪音治理闭环）

- **大白话**：台账里标了"噪音"的节点，不能标完就完——要回流到地图上让人看见、处置。噪音节点：图上标灰/标"噪音"徽章，连续两次验证噪音 → 自动列进半年复审的"待处置清单"（降权/改参数/下线，走 D 裁定）。
- **关键分层**：验证状态存 DB，前端查；**地图 YAML 不写验证状态**（保持设计真源纯净）。
- **裁定点**：噪音节点的处置规则（标灰即可 or 必须进复审清单）。

### PB-04 前端抽屉加「验证档案」栏

- **大白话**：右侧详情栏新增一区：该节点**验证状态徽章**（未验证/有效/噪音/待观察）+ **历次验证记录列表**（时间、窗口、结论、一句话结论）。
- **改动面**：api_server 加一个只读端点（如 `/api/tdm/validation?node_id=`，查台账表）；tdm.js drawer() 加一区；Kimi 正在重设计的抽屉样式需预留该区块（**给 Kimi 的指令要补一句**）。
- **裁定点**：是否本期做？与 Kimi 抽屉重设计的先后顺序（建议：Kimi 先做样式框架，本区块留占位）。

### PB-05 算法链登记（Owner 说的"算法共振"）★登记缺口

- **大白话**：节点机制里写"RegimeSnapshot 概率 × 谨慎度 × 六段预算"——这背后是**多个算法一起共振**才出结论。但现在这些决策算法（HMM 四态、RegimeSnapshot、水温六段）**没有结构化登记**，只有一句大白话写在机制里。algo_refs 现在只能挂"技术指标 IND / 执行算法 EXA"，决策算法没地方挂。
- **建议**：新增**决策算法登记**（建议前缀 `DAL-*`，真源=new YAML 登记表）：每个算法一条（算法 id/中文名/一句话机制/代码位置/输入数据/输出形态/首次生效日）。节点上挂 `algo_refs: [DAL-xxx, ...]` + 共振方式字段（`resonance: AND|OR|加权`，大白话写清"几个条件同时满足才触发"）。
- **改动面**：新登记表文件 + 地图 YAML 节点字段扩展 + 门禁 R13 扩展（algo_refs 允许 DAL-*）+ 抽屉"算法链"显示（算法1+算法2 → 共振方式）。
- **裁定点**：是否新建 DAL 决策算法库？共振方式字段要不要进 YAML？

### PB-06 回测快照绑定（原 D-a）

- **大白话**：每次回测强制记录"用的哪版地图存档（commit 号+时间）"，成绩单永远能追到版本。
- **改动面**：回测配置/报告加必填字段 `map_snapshot`。
- **裁定点**：确认加。（Owner 上轮未明确裁定，纳入本轮）

### PB-07 地图生效日（原 D-b）

- **大白话**：地图文件头盖"生效日期"章：首版=2026-09-09（首次盘点无历史），以后每次大改版更新。DAL/新登记表同样首版盖今天。
- **裁定点**：确认加。

### PB-08 回测窗口纪律（原 D-c）★防作弊关键

- **大白话**：今天拍的参数是"看着过去行情"定的——再拿同一段行情回测=考前看过答案。把**最近 6 个月封存当保密考卷**：调参只用 6 个月前数据，定稿后保密考卷只考一次。
- **裁定点**：holdout 窗口 6 个月还是 12 个月；只约束"参数类回测"还是所有回测。

### PB-09 半年复审（原 D-d）

- **大白话**：日历加一条半年循环任务：强制体检地图（过时节点/参数/噪音清单处置）。是"必须审"，不是"必须改"。
- **裁定点**：确认加；复审产出物挂哪（复审备忘录，走既有编号体系）。

### PB-10 参数来源分级标记

- **大白话**：给关键参数标"出身"：`业界标准`（如涨跌停幅度）/`回测调优`（跑出来的）/`经验拍定`（Owner 拍的）。回测报告看到"经验拍定"的参数要格外警惕过拟合。
- **改动面**：THD/RLM/DAL 登记表加 `param_origin` 枚举字段（轻量）。
- **裁定点**：是否加；三档够不够。

### PB-11 节点回测的"反事实对照"数据准备（离场/风控类专用）

- **大白话**：验证"止损线救了多少人"，需要知道"如果没触发会怎样"——要提前备好**无风控对照回放**（同一窗口、同一信号、关掉风控再跑一遍）。这是离场类节点验证的前提数据。
- **改动面**：回测引擎支持"关掉某类节点"的对照模式（引擎侧改动，中等工作量）。
- **裁定点**：是否本期做（可 P2 延后）。

### PB-12 验证优先级排序（125 节点不可能一次全验）

- **大白话**：按"离钱近的程度"排验证顺序：**L4 执行类（直接影响成交成本）→ X 流风控类（保命）→ L1 判定类（仓位总闸）→ L2/L3 选股类 → P 流做T/加仓 → F 流归因**。每期验证一批，结论进台账。
- **裁定点**：排序认可否；第一期验多少个。

## 六、全网调研：专业机构做法对照（2026-09-09，结论=12 条全部有业界依据，另补 4 条业界标配）

### 6.1 对照表（我们的条目 vs 业界实践）

| 我们的条目 | 业界对应实践 | 依据来源 |
|---|---|---|
| PB-01 验证方法学 | 信号级独立验证是行业标准：IC/分档收益/单调性检验（alphalens 家族就是干这个的）；SR 11-7 要求 outcomes analysis | alphalens-reloaded、alpha-lens |
| PB-02 验证台账 | 模型清单（Model Inventory）是监管硬要求：每模型唯一 ID+用途+风险分级+**验证状态和日期**+监控状态+已知局限；WorldQuant alpha 库每个 alpha 一条 DB 记录带状态机 | Fed SR 11-7、OCC 2026-13 |
| PB-03 噪音闭环 | alpha 生命周期状态机是业界明文：WorldQuant 六态（INIT→SIMULATED→SYNC→CHECKED→SUBMITTED/DISCARDED）；开源 Quant-Agent 七态（CANDIDATE→VALIDATED→PAPER→ACTIVE→**DECAYING**→RETIRED/SUPERSEDED）；国内私募"衍生因子月度复盘，衰减直接替换下线" | WorldQuant Brain、Quant-Agent、私募札记 |
| PB-04 抽屉验证档案 | 模型清单可视化+验证状态徽章=SR 11-7 文档化要求；Quant-Agent/WorldQuant 均有前端 | 同上 |

| PB-06 快照绑定 | 机构回测参考架构明文：平台验证 PIT 完整性后返回**带内容哈希的冻结数据快照**，"Reproducibility starts here" | Finantrix《Backtesting at Scale》 |

### 6.2 业界有、我们清单漏掉的 → 补为 PB-13~PB-16

**PB-13 验证结论必须带显著性检验**（业界最强调的一条）
- 大白话：跑一次回测就说"有效"，在统计上不可信——你试了 50 组参数，总有一组靠运气最好。业界金标准：Deflated Sharpe Ratio（按试验次数折减）、PBO（回测过拟合概率）、多重检验 haircut。"90% 以上回测策略实盘失败"的根源就是这个。
- 落法：PB-02 台账的结论字段加显著性列（p 值/DSR 至少其一）；参数类验证必带，方法学类可从宽。

**PB-14 衰减监控+验证生命周期状态机**
- 大白话：验证不是"考一次试管一辈子"——信号会随市场变化衰减。业界给验证状态做了**会流动的状态机**：有效→衰减中→退役/被替代，配衰减监控（IC 衰减半衰期、滚动 IC 连续 3 个月低于阈值预警）。
- 落法：PB-03 的三态升级为状态机（未验证→验证中→有效→衰减中→噪音/退役），衰减监控挂半年复审（或月度自动巡检）。

**PB-15 数据快照内容哈希**
- 大白话：光记"哪版地图"还不够——回测用的**数据**也要封存指纹（哈希）。业界参考架构明文：数据快照带内容哈希，可复现从这一步开始。否则同一段行情数据被回填修正过，回测就复现不出来。
- 落法：PB-06 扩展：map_snapshot 之外加 data_snapshot 哈希（我们 ClickHouse 数据按表+窗口+回填批次可算指纹，落法施工时定）。

**PB-16 前视诊断三招进验证 SOP**
- 大白话：业界有三个标准动作主动抓"偷看未来"：①**加滞后重算**（数据多滞后 1-5 天，成绩暴跌=有前视）；②**去掉某数据源重算**（成绩崩=那个源在做功，查它）；③**walk-forward 前后对照**。我们 PB-11 只覆盖了第二招的变体，三招都进 SOP。
- 落法：并入 PB-01 验证方法学，作为每类节点的标准诊断步骤。

### 6.3 结论

1. **你要做的这套，专业机构确实都在做**——而且不是民间土法：银行端有监管明文（SR 11-7，2026-04 更新为 OCC 2026-13/SR 26-02），顶级基金端有 WorldQuant/alphalens 体系的信号级验证，学术端有 López de Prado 的完整反过拟合方法论。
2. **业界没有的只有一处**：PB-05"决策节点算法共振登记"——因为业界没有"决策地图"这个形态（他们是一条条 alpha 信号流水线），我们的地图本身是自创形态，配套登记是合理延伸。
3. **业界最狠的两条纪律**要抄到位：①"模型没完全定稿前不许跑回测"（López de Prado：回测中做研究=酒后驾车）；②结论必须过显著性折减（试了 50 组参数，最好那组的夏普要打折看）。
4. PB-08 holdout 建议从 6 个月上调为 **12 个月**（WorldQuant 惯例），最少 6 个月保底。

### 7.3 两条铁律（业界最狠，抄到位）

1. **模型没完全定稿前不许跑回测**（López de Prado："回测中做研究=酒后驾车"）——先定稿、后考试。
2. **保密考卷只考一次**——holdout 窗口考完就作废前移，改参数再考=换新卷，不许在同一张卷上反复考。
