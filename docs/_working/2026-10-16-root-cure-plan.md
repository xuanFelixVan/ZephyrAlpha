# 治本方案：未来怎么办，如何不再堆积爆发

## 0. 一页结论

**"只走主线 git 提交一条路"= 已经是现状**：裸 commit 被 `_run_git` 守卫拦、plumbing 禁令在册、所有提交必经 GitCommitGateway+队列——昨夜 5,000+ 件抢救全部走正门即证明。**昨晚爆盘的真因不是"门太多"，是"出口没人扫"**：东西从正门进来后，死车道/死信/审计/证据/tmp 五个出口只进不出。治本＝**出口闭环五层架构**（L1 创建有闸→L2 存活有账→L3 死亡有收→L4 有界有偿→L5 红线有警），其中 L1/L2 已落地，L3/L4 落地过半（今晨补齐），L5 差一个九面遥测。外加一个必须修的 P0：merge 失败静默回滚工作树 bug（修复车道在途）。

## 1. 昨晚怎么爆的（机制复盘，30 秒版）

```
12 岗自动化 × 重试不复用 → 100 棵新车道（36GiB）
+ 10-14 滞留 20 棵死车道（7GiB）——L3 缺失：死了没人收
+ .runtime/tmp 自由生长（W 之前无 TTL）——L4 缺失
+ 审计单文件无限增长 ——L4 缺失
+ 死信只进不出（dead/ 永不清理是设计，但归档通道没人跑）——L4 缺失
+ VHDX 570GiB 静态地板把余量压到 19.5GiB ——L5 缺失：红线无告警
= 44GiB 增量击穿 19.5GiB 余量 → 3.2MB
```

**九面堆积的每一面都对应一个缺失的出口**，不是任何"侧门"造成的。

## 2. "全部关闭、只走主线"裁定（逐通道）

| 通道 | 裁定 | 理由 |
|---|---|---|
| 裸 `git commit` | **已关闭**（保持） | `_in_commit_flow` 守卫+POST-COMMIT-GUARD，昨夜零绕过 |
| plumbing（read-tree 等） | **已关闭**（保持） | 提交工具红线 #8 |
| `git stash` | **收紧**（不消灭） | 会话 stash 已被 worktree 制取代（阶段3）；现存制造者只剩 ①merge 失败路径（修 P0 bug 即断源）②手工救场（保留但立法：stash 必须登记 stash_notice.json+30 天自动过期提示） |
| worktree/车道创建 | **不关，加闸** | 车道=宪法规定的并发隔离正道（RULE-WORKTREE），关掉=所有会话挤主区互相踩。已加：D1 磁盘地板闸+同岗位强制复用+创建即打印回收命令 |
| `.runtime/tmp` 自由写 | **收紧** | 临时面本身就是需要的（禁不掉），治本=D3 的 48h TTL 自动清（已挂 reaper wire） |
| 队列 dead/ | **不关，加出口** | "dead 永不清理"是防误删设计，保留；加：内容级归档自动化（见 §3-L4） |
| 直接文件写 | **已分层守卫**（保持） | safe_write_text CAS/热文件面/ops_guard 在岗 |

**结论：不需要也不能"只留一条物理通道"——需要的是每条通道都有出场闸。**

## 3. 出口闭环五层架构（治本主体）

### L1 创建有闸（✅ 已落地，W 队 D1）
车道创建前三闸：磁盘地板（<15GiB 拒绝+清障指引）｜同岗位死车道强制复用（判活与 archive 同源）｜创建即打印回收命令。阈值单真源 `config/flags.yaml: disk_floor.min_free_gib`。

### L2 存活有账（✅ 已落地，Z2 队）
SessionRegistry+heartbeat+三证立法；接管台账立案活性闸（registry-alive 不立案）+TAKEOVER 自动回收（五要件+isfinite 守卫）+自指死锁治本。**效果：不再出现 259 条永 open 的拦截工厂。**

### L3 死亡有收（🔶 落地过半，今晨补齐）
已落地：官方 archive 通道（死判→V 判型→patch 存证→remove→prune→branch 处置）。
待补两件：
- **死车道自动收**：把"死车道扫描→archive 干跑→超龄自动 execute"挂进 reaper 既有 wire（与 D3 hygiene 同伴；判死用 registry 同源，保守双确认：registry 无记录+锁无主+mtime>48h）。这样"滞留 20 棵死车道 4 天"不可能再发生。
- **悬空 worktree 注册自愈**：archive 已做 per-lane prune；补 reaper wire 里 `git worktree list` vs 实体目录的周期对账（排除表保护项除外）。

### L4 有界有偿（🔶 落地过半，今晨补齐）
已落地：审计 50MB 轮转+最老段 gzip（挂 reaper）｜tmp 48h TTL｜VHDX 采样。
今晨落地：死信内容级归档战役（dead→0 或机械地板）｜quarantine 压缩+packs 化。
待立两件（立法呈批）：
- **死信自动归档**：dead-archive --content-level 挂 reaper wire（age>7d 才动，保持官方 TTL 语义；fail-closed 只放行 A_LANDED）。运行成本≈每袋一次 blob 比对。
- **quarantine 季度打包**立法：把"季度合并审计同窗"落成日历事件（事件驱动挂 scheduler 的既有季检槽，禁 cron 语义）。
- **stash 生命周期**：30 天自动提醒+absorbed 判定（stash 树 ⊆ HEAD 则提示可 drop，判定只提示不自动删）。

### L5 红线有警（🔶 差一件）
已落地：VHDX 小时采样+15GiB 红线告警（D2）。
待建（本方案唯一新工程）：**九面遥测预算**——一个只读脚本挂 reaper wire：每面一个预算阈值（如 dead<50 袋、tmp<5G、audit<2G、quarantine<1G、车道<50 棵、staged<500），任一超限写 workspace_alerts 告警件。**治本的本质是把"6 天 3 观测点"变成"每小时全-face 巡检+超限即喊"。**

## 4. P0 缺陷：merge 失败静默回滚（修复车道在途）

两次实锤（01:43:36/今晨 10:0x）：merge 被拒后工作树的已提交文件被回滚为旧版——造成"HEAD 新码跑旧码"的假绿面+import 断链，是整夜"修改自愈消失"之谜的机制。修复车道在途（含回归测试：失败后工作树逐字节等断言）。**此 bug 不修，任何"工作树==HEAD"的假设都不可靠——它是所有面治理的地基。**

## 5. 与"仅主线提交"配套的执行纪律（对 AI 会话）

1. 会话收尾序列已有立法（收班即清）——补执法：收班未清=archive wire 自动收（L3）。
2. 大批落地一律走队列 40 件/批语义分片（R2 大批硬顶已在）。
3. 禁 `git add -A` 式广撒网（昨夜 Bag 面全部显式清单）。
4. 队列袋快照必须在**入队时刻**校验工作树==HEAD 一致性（昨夜 Z2 二次落地事故根因：快照混入回滚后旧文件）——已在修复车道顺带评估是否需要补袋级一致性校验。

## 6. 清零战役终态预期（本次授权执行后）

| 面 | 可达终态 | 不可清零的原因（机械地板） |
|---|---|---|
| ① dead | →0 或仅剩 content_held/foreign（有主/未落地证据袋） | 他会话在产袋非我方可裁 |
| ② tmp | →仅剩 <48h 在产件 | 今日在班车 |
| ③ worktree/分支 | →仅活跃+11 条待 Owner merge | 生产在跑+价值待裁 |
| ④ 主区 | →仅生产班在途 WIP | 在产=仓库活着的证据 |
| ⑤ quarantine | →packs 压缩态（证据零删除） | 证据保存义务 |
| ⑥ sessions | →仅活跃 | 同④ |
| ⑦ blobs | →git gc 后（**Owner 明示后执行**） | .git 禁区 |
| ⑧ audit | →轮转+压缩态 | 今日活跃件 |
| ⑨ 根散件 | →0（已达成） | — |

**"全部为 0"的正确形态＝每面收敛到"在产量+有界证据量"，且超出量由 L3/L4/L5 自动收敛——人不用再救火。**

## 7. 待 Owner 裁定清单（**2026-10-16 重校准版**——按"可逆性×机械可验证性"新分界线重裁，调查报告含 19 项外证）

> 重校准结论：原六裁定的保守性全部来自"把可逆+机械可验证的操作按不可逆操作设防"——在 100% AI 开发语境下不产生安全增益（gate 体系独立保证强度），只产生 Owner 带宽损耗与出口淤积。重裁后 Owner 保留面六类一寸未让，让掉的全部是机器面。

1. **git gc 拆分**（改道）：`git gc --auto`（默认 2 周宽限+reflog 90 天保护，业界=cargo/git maintenance 官方推荐例行维护）挂 reaper wire 作例行维护，AI 自裁；`--prune=now` 深清维持 Owner；本次爆发后首清走一次性明示。
2. **死信自动归档**（维持照准）：7 天龄+content-gate fail-closed——与 Kafka 默认保留 168h 精确同频，blob 级比对已超 SQS"到期即删无比对"的业界标准。
3. **quarantine 打包**（维持）：超阈值+季度兜底＝SRE 日志保留标准混合模式，逐字同构。
4. **九面遥测**（升级）：**默认 ON+宽松起步**（阈值=30 天观测基线 P95×2 机器冻结 v1，Owner 落册知会即可）+双窗确认防抖——"OFF 的告警=不存在的告警"，昨晚爆盘即 L5 无警之代价；SRE 冷启动惯例=宽松起步后收紧，非关闸等批。
5. **absorbed stash 自动迁 refs/quarantine**（升级）：已机械判定"树⊆HEAD 零信息丢失"的超龄 stash 自动纯 ref mv+台账（与死信归档/分支 absorbed -D 两在册先例同构，可逆）；drop 永不自动；未 absorbed 超龄维持提醒。只提醒版被否：AI 无跨会话记忆，提醒大概率永无消费方（实测 30 条 stash 多条宿主分支已删）。
6. **分支 merge**（维持+执行律）：超集优先/基建优先/旧代殿后不变，补"每笔 merge 后全量门禁+测试绿再下一笔（merge train+可 bisect）"；超集落地后 4 条子集/前代由 absorbed 机制机器收口，Owner 实裁面 11→7 条。
## 8. 两层清扫体系与告警路由（2026-10-16 Owner 简化裁定：夜巡层暂缓——防过度复杂，未来需要时用 API 编译器型 AI 补，不本地部署）

**分层原则：确定性清理不留给模型，判断性分诊才给模型，不可逆永远给人。**

| 层 | 执行者 | 时机 | 覆盖面 | 出错代价 |
|---|---|---|---|---|
| L-自动（7×24 事件驱动 wire） | 纯脚本，零模型 | reaper 扫描循环内实时 | 死信归档/gc --auto/死车道 zero_loss 收/审计轮转/tmp TTL/absorbed stash 迁/quarantine 打包/九面告警 | fail-closed 设计=错一次最多零动作或浪费一轮 |
| L-终裁 | 主模型/Owner | 按需 | 超出机械判据+夜巡置信度的少数件；六类保留面 | — |



**"超限必喊"喊谁（三级路由，前两级零配置已接）**：
1. **机器层（默认）**：告警落 `.runtime/workspace_alerts/`+审计 jsonl → 在岗 AI 会话经提交上下文/冷启动自检自动读到并处置（本会话"堵点提醒"同款机制，已实证）——多数超限在机器层被自愈；
2. **面板层（已在跑）**：reaper `--status` 与 dashboard 可见九面读数；
3. **你本人（可选一格配置）**：复用既有可插拔 webhook（`zephyr.data.alert_webhook_dispatch`，CRITICAL 落盘后外发）——填一个飞书/企微/Server酱 webhook 即推送手机；不配则照常自愈，只是少收推送。

## 9. 保证书的诚实边界（什么情况仍会"堆积"）

1. **结构性地板**：VHDX 570GiB 若业务数据继续长，盘仍会满——D2 会在 15GiB 红线喊你，但"压缩窗口/迁移"是 Owner 域（§7-1 首清＋后续窗口）。
2. **预算风暴**：20+ 会话同日齐死+大车道——地板闸会拒新车道、告警会响、自动收在 48h 周期内清完；系统降级但不死。
3. **自动化自身的 bug**（今夜 merge 回滚 bug 即例）：对策=落地即红蓝+遥测"看门人互看"+全部 wire 带 flag 可断可回滚。
4. **接线完成前**：本方案 5 项自动化正在装配（死信 wire/gc wire/死车道 wire/stash 哨兵/pack 触发器）——装配完才生效，收班即报。

**一句话总结**：垃圾=并发工作的必然副产品，本方案消灭的不是"产生"而是"无人收"——每面有出口、出口有判据、判据可回滚、超限有告警；你从"消防员"降级为"收到告警时看一眼的人"。
