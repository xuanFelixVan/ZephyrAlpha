# 链路挖矿总纲（L01-L09 · 封矿制）

> 授权：Owner 09-26 凌晨总筹令——"线内先挖后干、线间并行流水；挖干判据=每本作业簿六向台账+自审闸三态裁定；封矿后进施工 SOP，施工遵守内收原则"。
> 骨架真源=../09_link_skeletons.md（758 行九环节总表）；本目录=每环节挖干作业簿。

## 六向台账（每个子块必填，缺一不可封矿）

| 向 | 内容 |
|---|---|
| ①上游输入 | 谁喂本块（表/文件/事件/上游环节） |
| ②数据原料 | 用到的表/文件/因子/指标（含登记状态） |
| ③状态输出 | 本块产出的状态量/产物（schema+落点） |
| ④下游消费 | 谁吃本块输出（消费代码路径实证） |
| ⑤自动化挂点 | 产槽/事件触发/计划任务（现状：在产/休眠/缺位） |
| ⑥缺口债 | 缺什么断什么欠什么（编号引 LK/DU/IBT/TRD/CNS 账本） |

## 自审闸三态（挖干判据）

- **SEALED 封矿**：六向全填+章节内全部指针文件已读+最新算法对表完成（按 18 号文纪律：有行业标准/开源实现必须引用并采用，不自造）
- **MINING 待挖**：仍有未读指针/未探子块（列出清单）
- **BLOCKED 阻断**：依赖缺失或外部等待（登记原因+放行条件）

## 施工纪律

- 内收原则：新增组件必须声明替代/合并的旧组件（净零增长）
- 施工项编号沿用既有账本（IBT/TRD/DU/CNS/LK）；新卡接续编号
- 挖干即开工：本簿 SEALED 后施工项直接进执行队列，不等逐条点头
- 全部论文/标准引用带出处；GitHub 开源可复用实现须在 §标准件 标注仓库与许可证
