# LANE-GPU④ 等价性验证框架

> 真源纪律（不可动项）：红蓝对拍的判据与阈值**沿用 17 号文既有口径，本件一个字都不改**——
> 方案①线=`docs/_working/decision_map_campaign_20260924/17_quantified_acceptance.md:28`（Spearman≥0.99 且 top50 重合率≥0.9 且轻档单格≤8s，任一不达标=草案作废走裁定通道）；
> 成绩单线=同文 §一（完成率/成本门真实性/N_eff/DSR/负结果纪律/垃圾触发线）；
> 五档单调性容差=`config/exam_scale_cost_gate.yaml`（`monotonic_tol: 1.0e-9`，禁双头硬编码）；
> 本件**只新增"实现等价性"一维**，不替代、不稀释多校链（DSR/PBO/CSCV）。
> 真源方向：**现行 CPU 引擎（`_c4_engine.py`）=蓝军真源；向量化/GPU 实现=红军被测**。判定函数两侧共用同一实现（`exam_cost_gate.py:8` 扫描/判定分离既有纪律）。

## 一、逐位 vs 容差的取舍（有公开依据，不是工程偏好）

| 改造层 | 是否改变浮点运算顺序 | 对拍标准 | 依据 |
|---|---|---|---|
| **L1 去重/hoist/缓存** | 否（只挪计算位置与物化方式） | **bitwise 全等，容差=0**；任一位漂移=实现错误，不是 FP 特性 | 同一实现同一顺序必然逐位同；仓内成例：T2c 向量化"与逐日循环逐位等价"（`factory_grid_executor.py:37-42` docstring） |
| **L1 中的掩码向量化改写** | 不涉及浮点（布尔判定路径重写） | **布尔掩码逐元素全等**（`np.array_equal`）＋ fail-open 行集合全等（NULL/缺价/非股票） | 同上；且掩码是真值语义，无任何容差空间 |
| **L2/L3 GPU** | 是（并行归约改变加法分组） | **分层：离散量精确一致＋浮点容差＋排名严格**（见 §二） | ②文 B1（CUDA FP 文档 v13.4：**"Take this into account when doing comparisons between implementations"**、"Differences are not automatically evidence that the result computed by the GPU is wrong"）；B2（CCCL 2026-03-05：逐位=确定性最高档，仅承诺跨 GPU 一致，**不承诺 CPU 等价**）；B3（PyTorch：CPU/GPU 即便同种子也不可复现） |
| **跨实现"要求逐位"唯一合法场景** | — | 显式固定归约序（CCCL 式分箱累加）——**本项目不采用**（成本/复杂度不成比例，且会锁死硬件） | B2 |

**禁止项（写死）**：①以"GPU 天然不等价"免验；②开启 TF32/FP16/混合精度（引入第二不确定性源，与 B1 的"分组改变即改精度"叠加不可辨识）；③只比最终 sharpe 不比中间量（net 序列必须逐日对，否则 1,622 日复利漂移被平均掉）。

### 一·补 硬件红线与对拍容差冻结值（前一轮 `validation_framework.md`／`compute_inventory.md` 证据并入，2026-09-26 双版合并）

**硬件红线（本框架容差线的"因"，不是工程偏好）**

- **RTX 3090 的双精度（FP64）性能只有单精度（FP32）的 1/64** → "整卡搬 float64"会把 GPU 打回 CPU 水平，
  故 GPU 重写**必须走 FP32 计算＋对拍容差路线**，FP64 只保留为争议格单格仲裁开关（③文 L2 精度策略）。
  前一轮原文（已落 HEAD commit 37aeecedcd）：`compute_inventory.md:14`"**注意 3090 的 FP64 吞吐是 FP32 的 1/64——精度选型是 L2 设计的第一约束**"、
  `rewrite_architecture.md:12`"**FP64 吞吐≈FP32 的 1/64**"。**这条红线在合并前只存在于③文，本件（容差线真源位）没有——读④文者当时不知"为何必须 FP32"，此为本次合并补的第一处实质缺口。**
  证据等级如实标：1/64 系**硬件规格推演，本机未做 GPU 实测**（T1 单卡独占期禁起 GPU 作业；③文挖矿日志 R6 已登记"待验证"）。
- **显存配额 18GB**（`docs/_working/decision_map_campaign/03_gpu_campaign.md:24`，前一轮①文硬件锚同值）；
- **单卡独占**（prereg `vram.concurrency: 1`＝单卡禁共存，⑤文 §〇 实测态）；

### 二·补 近并列翻转的处置条款（2026-10-11 Owner 裁定，总统统筹 05:3x 转达；实测据=st-gpux-20261011 级2 199 格配对）

**现象**（不是假说，是产物级实测）：`all_a_ex_st` 宇宙 5,217 只里取 `top10` 的一格，
CPU/GPU 双后端跑出的 net 序列在 970 个交易日里有 **462 天不同**、单日最大 4.0e-3，
但 `avg_turnover`/`net_days`/门判定/degraded **逐位等**——即持仓集合的**边界成员**换了、
组合结构没变。机制＝卡上并行归约的 ~1e-16 序差把一对**近并列**分数拆到 `rank ≤ top_n` 边界的两侧。
本框架 §一 早已承认"并行归约改变分组即改变末位"，只是没写过**它会被离散选择放大**这一层。

**裁定条款**：

1. 此类格**标注为组合等价**（`equivalence_class = near_tie_selection`）并**另判**，不挂 §一·补 红线；
   报告必须同时给出：越线条目的 (相对差, 绝对差, 该格 top_n, 宇宙规模, 差异天数)，缺一即视为借条款藏真缺陷。
2. **禁为过线去动卡**——不得为了让容差变绿而调整 GPU 归约序、加偏置、改 tie-break 或改 dtype
   （那是拿算力面去碰判据面，属本文件 §一"禁止项"同族）。
3. 判定顺序不变：先按 §一·补（含新增绝对地板）判，判不过的**再**逐格核是否落入本条款，
   不得跳过前者直接引用本条款。
4. 放大风险的边界条件写死：`top_n / 宇宙规模` 比值越小、并列密度越高（如 `fillna(0.0)` 造出的
   大块同值）越易触发；这类格的数量应随 n 增长而**被计数披露**，不是被平均掉。
5. **载体扩列（三问裁定①「扩，同条同款」，总统统筹 2026-10-11 13:5x 批；本班 `date` 实测入册时点）**：
   本条款的适用范围从"**top_n 类判据**"的近并列翻转，**扩至"调仓触发日翻转"同一物理现象的第二载体**
   （`D2_rebalance_trigger=drift_band` 的带宽阈值穿越）。批准理由=已证其为 **1-ULP 离散选择的合法形态**，
   与 top-N 近并列**同族**：
   - 实测据（级 3，1,049 同格，同日背靠背+成分指纹 drift_free 协议）：1e-6 档 底 4 格 vs 设备 13 格，
     z=2.19／双侧 p=0.028 ⇒ 按 §二·丙 乙 条**逐格归因**；13 格里 **12 格 `trig=drift_band`**，
     净增 10 格 **100% 落在 `A1=rank × A2=equal`** 前缀（该族命中 10/126，其余 7 种 combine 各 0-1/126）；
   - 机制据（合成面板复现，零生产数据）：CPU 真源写法 `concat+groupby(level=0).mean()`
     对设备 `gpu_core._equal_combine` 差 **≤2.22e-16（1 ULP）**，而**纯 CPU 换一种合法求和实现**
     （`np.nanmean` 换 `groupby.mean`）差**同样 2.22e-16、同样 23.67% 元素、翻转同一批 14 行** top-20；
     连续值对照族边界间隙中位大 6.5 倍、间隙<1e-15 的行=0/400 ⇒ 解释"为何只有这一族中招"。
   执行口径（**只扩归类，不松程序**）：
   (a) 判名 `equivalence_class = tie_amplified_selection`，与 `near_tie_selection` **并列同款**，另判、不挂 §一·补 红线；
   (b) 第 1 条的披露五元组对本类**增列为七元组**：(相对差, 绝对差, 该格 top_n, 宇宙规模, 差异天数,
       **触发载体与阈值档**, **边界间隙或并列组规模**)——缺一即视为借条款藏真缺陷；
   (c) 第 3 条判定顺序**一字不改**：仍须先按 §一·补/§二·丙 判、判不过**再**逐格归因，
       **不得**跳过归因直接引用本条（p<0.05 的档必须先看集合/维度/机制三步，才允许定名）；
   (d) 第 2 条禁令对本类同样生效且**更要用**：不得为过线改归约序/加偏置/改 tie-break/改 dtype——
       本类的正确处置是**承认它是离散选择的本质**，不是把它抹平。
   ⚠边界自识：本条**只覆盖"有实测机制证据的 ULP 级放大"**。若某格差异的机制证据不成立
   （例如两侧 combined 面板差值 >1 ULP、或 aux 面板取值不同、或只在一个后端出现 NaN 面），
   那属实现缺陷，**不在本条豁免内**，必须修。判定用尺：`.runtime/tmp/.../n3_band_attribution.py`
   与 `rank_equal_amp_probe.py` 两步都过，才允许定名。


### 二·丙 逐日线的重定＝对"引擎自噪底"做双比例检验（Owner 第二令裁定②（本班 2026-10-11 13:4x 收悉即行；前稿误标 07:2x 系体感钟漂移，已就地更正）；性质=实现等价线，非考试判据）

**为什么要重定**：原 `net 逐日相对差 ≤1e-8（FP64）` 是一条**绝对线**，但级 3 实测把它证伪成
"连引擎自己都过不了自己的线"：同一夜、同一数据态（跑前跑后成分集 sha1 逐字相同）、同一后端（纯 CPU）、
同 seed 同参两跑，1,049 条净值曲线里**没有一条逐位相同**，17 条(1.62%)破 1e-8，最大绝对差 6.19e-4。
拿一条"绝对线"当实现等价判据＝把引擎自身的 FP64 归约序噪声一律判成"设备面不等价"，尺失灵。

**新判定=甲乙两条同时成立（缺一不可）**：

- **甲（聚合五项线，硬闸不变）**：sharpe 与 ann_return 各绝对差 ≤0.005；max_drawdown 相对 ≤1e-4 **或**
  绝对 ≤1e-5（任一即过，§一·补 同行）；离散量（调仓日集合／持仓只数／门 PASS-FAIL／net_days／degrade）
  100% 一致；avg_turnover 相对 ≤1e-6（④暂给线，须在全精度位取，见 §一·补 该行）。
- **乙（对自噪底的双比例检验，取代旧绝对线）**：在**同日背靠背 + 成分面指纹 drift_free** 协议下
  ①先量自噪底 `p₀`＝CPU-vs-CPU 越线格率；②再量设备面 `p₁`＝CPU-vs-GPU 越线格率；
  ③在 **1e-8 / 1e-6 / 1e-4 三档各自做一次**双侧两比例 z 检验（n 同格集）；
  ④三档全 `p≥0.05` ⇒ 判**实现等价**；任一档 `p<0.05` ⇒ **该档必须逐格归因后才能判绿**，
  归因结论按 §二·补（含其命名类；**第 5 条已把第二载体"调仓触发日翻转"并入同款**，三问裁定①）落纸，
  禁以"整体看起来差不多"过关，也禁为过线去动卡。
- 旧 `≤1e-8`／`≤1e-5` 两值**保留为披露位**（写进报告，不再当闸），披露时同时给 `p₀` 与 `p₁`。

**本规则的自证（它第一次上场就抓到一个真信号）**：级 3 实测 `p₀(1e-8)=17/1,049=1.62%` vs
`p₁(1e-8)=26/1,049=2.48%` ⇒ z=1.39，**p=0.166 不显著**；而 `p₀(1e-6)=4/1,049=0.38%` vs
`p₁(1e-6)=13/1,049=1.24%` ⇒ z=2.19，**p=0.028 < 0.05 ⇒ 必须归因**。
若沿用旧绝对线，这两档会被混成同一句"1e-8 越线 26 格，FAIL"——既抓不出 1e-6 档那个显著信号，
也把引擎自己的 17 格噪声算到设备面头上。**这就是"带"而不是"线"的全部价值。**
归因结论（已做，见 `02_gpux_equivalence_ladder.md` 级 3 与 `.runtime/tmp/st-gpux-20261011/rank_equal_amp_probe.py`）：
10/13 净增格集中在 `A1=rank × A2=equal` 前缀（该家族命中率 10/126，其余 a2 家族 0-1/126），
合成面板复现出**同一批 14 行 top-20 边界翻转**在"cupy 归约"与"**纯 CPU 换个求和实现（np.nanmean vs groupby.mean）**"
