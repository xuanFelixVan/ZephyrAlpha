## 四、四条最贵的发现（这才是我建议你早上先看的）

### ① A00：一件"批文说 NO、然后做了 YES"的既成事实
`裁定#333`（category=Owner 门位）在 09-18 **04:02~04:34 之间**入册，第 ⑤ 条原文写着
"**时区劈叉 4.12 亿行 `--execute` 修复未在本批授权内，仍按原工单等低峰窗**"；
而修复实跑在 **03:55→06:07**，并于 **07:22** 以 `60ed3aa49c` 宣布"全部转正"。
我独立只读复核了技术效果：live 小时域 `[09,15]`、备份表 `[01,07]`、**两侧行数完全相等 319,456** ⇒ **数据是对的、可逆性是真的**。
所以这不是要抢救数据，是**要一个说法**：追认 / 回滚 / 或只立"机器拒跑"的硬门（我给的意见：第三条必做，前两条二选一）。
**三处诚实保留**写在 A00 里（我查不到聊天通道的批文，且"低峰窗"客观上可能被认为已满足）。

### ② A00b：保命链路是跨进程不可达的
三套熔断旗标（KillSwitch / 交易级 kill switch / last-resort watchdog）在**发起它的进程里**为 True，
**新进程读到全部 False**；编排器 `route_incident()` 返回 success 但跨进程无人可见，
而 `check_consistency()` 仍报 `consistent=True`。最要命的是：每 5 分钟跑这个检查的 `process_reaper`
**就是在自己进程里拉的闸**，而交易执行体是另一个进程 ⇒ **"拉闸拉在自家庭院"**。
落盘方案里"过期旗标算仍在熔断还是算已解除"**两个方向都危险**，我判不了。

### ③ A14：「接线率」至今没有权威口径 ⇒ "所有模块全流通"目前**不可测**
三套机械口径互斥且差两个数量级：GOMAP 说 **95** 件孤儿、裸 AST 说 **1685** 件、
而普查点名当权威的那个门禁 `check_wiring_orphan.py` 报 **0**（其册 313 条里 **304 条自免 exempt=97.1%**，
`generated_at` 停在 08-27）。**选哪个口径=定标准**，不该由执行侧默认。这条直接决定你的验收语能不能被回答。

### ④ 制度层面：验证器有牙，但牙可以被"一格单元格"拔掉
E1/E5 证明尺子在**分母诚实 + 切分诚实**时拦得住纯噪声（200 次逐 trial 通过 0 次）；
E3 证明**只改 CSV 里的试错次数**就能让它判"通过"；E2 证明**全样本选参**时比率门被**反向击穿**（OOS/IS=2.311>0.70）。
⇒ 一条改进的优先级排序应该是：**先给分母立溯源闸（已做），再给切分立机械判据（B 类待办）**，
而不是继续加"看起来更聪明"的统计量。
