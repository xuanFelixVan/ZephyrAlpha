## 五、字段方案设计（只设计不落册——落册=Owner 门位+独立工单）

**适用三册**：technical_indicator_registry（REG-IND-001，schema v2.1→建议 v2.2）/ chart_pattern_registry（REG-PAT-001）/ factor_registry。

```yaml
# entry_schema 增补（三册同构，语义正交性见下）
application_markets: list[enum]   # 多选子集：[A股, 港股, 美股, 期货, 币圈]；默认 []
usage_note: str                   # 一句话用途（≤60 字）；默认 ""（=未填）
```

设计要点（5 条）：
1. **与 applies_to 正交不冲突**：applies_to=标的类型（index/stock，答"算在什么标的"）；application_markets=市场制度环境（答"在哪个市场有效/可算"）。两轴正交，无同义漂移。
2. **默认 [] 语义=未判定**，既非"全适用"也非"全不适用"——对齐本册 header 既有教训（"既有条目为默认值/空值占位，禁止视为已填写内容"）。显式不适用=[市场]空集须以 `none` 注记或 usage_note 说明（落册时定死一种）。
3. **赋值判据字段化**（写入 entry_schema 注释）：制度依赖判据=数据输入是否绑定市场特有制度数据（涨跌停/ST/T+1/融券券源/流通盘披露/交易时段）；纯量价变换=全市场可算，"可算"≠"有效"，有效性主张由 usage_note 承载。
4. **回填=生成器工单禁手工**（宪法 §9.5 静态清单禁手工维护）：全册 605 条（IND 143+PAT 287+FCT 175）回填走 generator 脚本机生 YAML diff（输入=本报告 §六表+census 判定面），人工复核走 GW 提交；工单编号建议挂 L12 接线批，前置=Owner 批准 schema v2.2 与净删终裁。
5. **图形形态册特殊语义**：PAT 287 条输入多为 OHLCV 形态几何→币圈天然可识别，但 A 股连板/一字板制度使部分形态统计语义漂移（如"缺口"类在 7×24 币圈高频出现）——该语义差异正是 usage_note 的主要载荷，回填时 PAT 册逐条必填、IND/FCT 册可空。
