### §1.2 三档判定依据（对齐 risk_tier 分级逻辑）

- **全自动档**：同时满足①效果机械可证（五要素/触发条件/纯展示）②只增不破坏或可无损重放③gate 可在写入前硬拦。对应 risk_tier low——未列出域默认 low，全自动；门禁强度由 gate 体系独立保证，分级不放松 gate。
- **Max 复审档**：①涉资产语义与证据链判断，机械不可全证②误操作可逆（状态可回退+账本可追溯）③频度低，人审不堵队列。对应 medium 思路：质量风险外溢但非破坏性。
- **Owner 门位档**：命中宪法§5 high 清单之一（本表=注册表净删），或效果不可逆（墓碑 q_id 不复用=永久性；ISO 15489"处置必须预授权"+yank 窄门双背书）。
- 越档执行=违约，入 §6 阶梯处置。

## §2 审计账本

### §2.1 留痕规范

**留痕时点**：每次状态流转（draft→registered→mining→in_exam→answered→复考/挂起/合并/退役全量）+每次字段修订（含机生字段变更）。

| 留痕字段 | 规范 |
|----------|------|
| who | session_id+角色（AI/Max/Owner）；伪造=§6 L0 处置 |
| when | PG timestamptz+显式时区（RULE-SCHEMA-TZ 的 DateTime64 红线属 ClickHouse 侧，PG 通道以 timestamptz+显式时区等价执行；由写入 API 统一注入，禁业务侧 datetime.now()） |
| what | 操作枚举——**全族 SSOT 词表**（四件套+总册审计事件一律映射本词表，禁另起枚举）：登记族 register/update/merge/retire/reexam/suspend/template_add/template_update/template_retire/board_config/read；intake 族 intake_submit/intake_reject/intake_rate_limited/intake_override/dedup_hit/degraded_check；blind 族 intake_blind_park/blind_promote/blind_retire；exam 族 exam_writeback/exam_contradiction_case/exam_arbitrate（《入库闸设计》§7.3 九事件即 intake+blind 两族的映射表） |
| object | q_id（PQ-NNNN）或模板 id/看板配置 id |
| diff | 逐字段 JSON：old→new；状态流转=status 单字段 diff |
| evidence | 证据指针：裁定号（本班从 #400 起，台账 a1§6 实测）/commit 短哈希/机检报告 id/红蓝轮次；指针必须可达（抽查项） |

**时序**：写入 API 单事务内**先写账本行再提交业务行**（账实同事务=馆员"一书双卡账实互为镜像"的库表化）；落地即账，未领账的变更视同未发生（"流水登记先于一切动作"）。

**账本行样例（JSONL 一行，PG 表同构）**：

```json
{"who": "st-chainpile-20260922|AI", "when": "2026-09-22 14:30:00.123+08",
 "what": "register", "object": "PQ-0001",
 "diff": [{"field": "status", "old": "draft", "new": "registered"}],
 "evidence": {"gate_report": "five_elements#R-017", "net_zero": "NZ-0001",
              "commit": "abc1234", "ruling": null}}
```

### §2.2 账本载体（PG+JSONL 双轨，对齐 lookup_audit 先例）

- **PG 审计表 `meta_question_audit`**：append-only，与主表同实例同事务；通道=get_depgraph_pg_connection（与 depgraph 同实例），沿 `scripts/ai_layer/apply_ai_intake_ddl.py` DDL-as-Code 先例。角色=对账与查询真源。
- **JSONL 追加账 `meta_question_audit.jsonl`**：每行一 JSON 留痕事件（lookup_audit 同构）。角色=进程外留痕，防 PG 单点；PG 故障时回放补账（§7 降级预案默认路径）。
- read 事件量大，仅入 JSONL 不入 PG 表（治理级事件才双写）。
- **差集仲裁**：JSONL 与 PG 审计差集以 PG 为真源，差异即告警事件（差异本身入审计）；JSONL 独有行须附原始载荷复核后回放补账，回放后双向清零方可关窗。

### §2.3 不可变性与抽查机制

- **不可变**：审计行禁 UPDATE/DELETE；API 账号仅 INSERT+SELECT（馆员先例"账本写权限收口：app 角色仅 EXECUTE"）；写错不删，追加更正行（ISO 15489：记录本体不可改，变更走批注）。
- **抽查**：①季度窗机检**双向差集**——按账本重放主表末态 vs 主表实态，blind（有状态无账）/ghost（有账无状态）双向清零才算盘平（馆员盘点权同判据）②红蓝每轮抽 ≥10 条账本行核证据指针可达 ③JSONL 与 PG 表逐行哈希比对（治理级事件）。

## §3 多会话并发写入规则

### §3.1 与 claim 制挂接（lock_files.py acquire / gateway release）

| 资产 | 并发原语 | 规则 |
|------|---------|------|
| PG 主表+审计表行 | 乐观锁（§3.2） | **不占文件 claim** |
| 机生 YAML 快照 | 免 claim（生成器唯一写者） | 人工直改机生文件=§6 违约 |
| 模板库文件 | lock_files.py acquire | 改前 claim、毕后 release |
| 本总册及四件套设计文档 | lock_files.py acquire | 同上 |
| 看板配置文件 | lock_files.py acquire | 同上 |

### §3.2 PG 行级并发：乐观锁唯一闸（同问两会话同写的设计+理由）

- **设计**：PG 行写不走 claim，走乐观锁——写入 API 带 `WHERE q_id=:id AND version=:expected` 条件更新（version 为行版本号，§9 提案）；零行命中=冲突，客户端**重读重放**（同 git rebase）；禁止 SELECT 后裸 UPDATE。
- **理由**：①馆员先例定案"同条目并发=行级串行+指纹基线乐观锁（冲突=重读重放）"②PG 条件写=单一执行口（Terraform state lock/DynamoDB 条件写先例，07§路三）；文件 claim 管不着 PG 行，两闸叠加只会制造假阳性③MVCC 下后写者必冲突重读，前值已在账本，**结构性无丢失更新**。
- **结论（乐观锁 vs claim 之问）**：两域各一闸不混用——PG 行=乐观锁（claim 不适用），文件=claim；同问两会话同写由乐观锁+账本兜底，无需行级 claim。

### §3.3 热 YAML 快照的 CAS 基哈希

机生快照落盘必经 `safe_write_text`（CAS 基哈希，宪法硬规则 13）；哈希不符=存在并发生成或外部改动，处置=**重新生成覆盖**（机生文件可无损重放，禁人工仲裁合并）；写后进程外核实。

### §3.4 队列正门纪律

涉本注册表的 commit 一律 `git_commit.py --enqueue`（队列正门，锁忙自动改道不空转）；裁定引用与变更**同 commit 原子**；commit 后 `git log -1 --name-only` 核实归属（暂存区可能吸收他会话内容）；禁 plumbing 绕过，禁裸 git commit（[纪要§10]）。

| L2 人审驳回 | warn | Max 复审不通过（证据链断/拆并不当/挂起理由不成立） | 驳回退回 draft 或原状态，理由入账本；测出即修 | 账本+红蓝轮次 |
| L3 裁定立案 | escalate | 涉翻案/净删未批/跨域/gate 误伤申诉/schema 语义争议 | 登记 ruling_registry（本班 #400 起）**同 commit 原子**，Owner 裁定后回放 | 裁定号入账本 evidence |

原则：机械可证即自裁并留痕台账（[纪要§10]；台账 a1§3 先例 S-1）；涉净删/门位/翻案/跨域一律登记上报不擅动。

**自裁 vs 上报判定三问**（处置前逐问）：
1. 违规是否机械可证（内容比对/重复检测/引用扫描）？可证→L1/L2 自裁留痕；
2. 处置是否触及净删/Owner 门位/翻案/跨域？触及→L3 上报，禁自裁；
3. 证据是否涉及"谁做的"真伪？涉真伪→L0 直报，禁自裁。
三问判定与 [纪要§10] 自裁框架一字对齐；判定过程随处置留痕入台账 a1。
