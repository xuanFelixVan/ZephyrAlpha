# 考试回填闭环骨架设计

> **定位**：meta_question_registry（原问题中央登记表）基建四件套之第四件，使命="把值得问的问题变成受治理资产"中的**答案落账**环节。四件套分工边界：入库闸=问题进门｜模板生成器=问题展开｜未答看板=排队消费｜**本件=考试回填闭环**（回写/矛盾仲裁/复考周期/退役墓碑）；管理办法总册收录本闭环运行细则（接口引用，内容归总册，本件禁代写）。
> **唯一输入真源**：[00_piling_minutes.md](../00_piling_minutes.md)，本文每条可回溯，引用格式 [纪要§N]。
> **硬边界**：考试执行本身不在本基建内——E1C 三轨各考各的 [纪要§4]；整装回测/WFA 等考尺划分的引证出处=E1C 政策件（随裁定批补引，非纪要条款）。本闭环只管"考没考/结论/证据"的账。不建因子、不接线、不动业务考试器、不改 src/zephyr 业务模块 [纪要§10]。
> **角色体系**：AI 会话（执行考试+回填）｜Max（矛盾仲裁复审+裁定）｜Owner（退役墓碑签发门位）。
> **治理挂接**（禁另起炉灶）：矛盾终裁终点=裁定 #NNN 落 ruling_registry，同 commit 原子 [纪要§10]｜gate 体系承担全部机械拒收｜净零铁律约束新增字段（§7）｜时间分层铁律"今日输出→明日输入，同一时戳禁循环" [纪要§8.2] 硬约束复考（§3.3）。
> **状态机分工**：draft→registered→mining→in_exam 前半段归入库闸/未答看板件管；本件只裁定 in_exam 之后的流转（answered/复考/挂起/合并/退役）。q_id=PQ-NNNN，墓碑永不复用 [纪要§7]。

## §1 回写契约——考试完成后回填什么

> 对标 OSF 预注册机制：exam_plan 是"预注册"（问题入库时锁定考法与判据），exam_result 是"结果"（考后回填），二者逐字段对照、偏离必须披露（§5.2）。回填唯一合法入口=W2 施工的回填 API `writeback(q_id, exam_result)`（gate 前置校验+全程留痕；**回写鉴权=该问当前认领人**——claimed_by==调用会话，Max/Owner 可越过，无认领或认领不匹配的回写拒收，错误码对齐《入库闸设计》`claim_missing`），禁直改表、禁绕过 API 的任何写路径 [纪要§10][宪法§9.1]。

### §1.1 exam_result 回填记录结构（执行头+结果四段）

| 块 | 字段 | 存真内容 |
|----|------|---------|
| 执行头 | examiner_ref / run_ref / exam_plan_version | 考尺引用（E1C/整装/WFA，只记账不发指令）+ 执行留痕 ref + 本次所对照的 exam_plan 版本号（矛盾检测只比同版本，§2.1） |
| 结论段 | conclusion_value / conclusion_dir | 判据字段的量化取值（如 IC=0.031），必须对照 exam_plan 预锁判据字段；方向为机械枚举三值：支持/证伪/不可判，禁自由文本 |
| 置信段 | confidence_level / ci_lo / ci_hi | 置信水平（如 95%）与置信区间 [lo, hi] |
| 窗口段 | data_window_start / data_window_end | 输入数据起止时戳；end ≤ 执行日-1 收盘（§3.3 时间分层） |
| 断言段 | pit_assertion / pit_check_ref | PIT 断言 bool + 核对留痕 ref：所引各数据源 as-of 时戳均在决策时点之前已知 [纪要§2.5]；本断言是对该问 pit_proof（预注册时点的 PIT 设计证明，字段 10）的执行级复核 |

### §1.2 answered 判定标准（六查，全过才算"答了"）

什么算"答了"=**判据字段+阈值字段都被证据填充**，机械六查，任一失败即不得 answered：

| # | 检查 | 内容 |
|---|------|------|
| A1 | 结论已填充 | conclusion_value 非空且 direction ≠ 不可判 |
| A2 | 置信达标 | confidence_level ≥ exam_plan 预锁的最低置信阈 |
| A3 | 判据+阈值双填充 | exam_plan 的判据字段与阈值字段在 exam_result 中均有取值可对照 |
| A4 | 窗口合规 | data_window 起止齐备且 end 满足时间分层（§3.3） |
| A5 | PIT 断言成立 | pit_assertion=true 且 pit_check_ref 可查 |
| A6 | 证据可核 | evidence_refs ≥1 且逐条实存可核（§1.3） |

### §1.3 evidence_refs 证据引用规范

1. 每条 ref = 仓内留痕路径（文件或表）+可核锚点（commit hash / 表名+查询语句），指向考试原始输出、数据 as-of 核对记录或考尺运行日志；
2. 禁外部 URL 作唯一证据；禁凭记忆引用；禁指向不可复算的临时路径——临时产物先落 `.runtime/sessions/<sid>/staging/` 并 promote 后方可引用 [纪要§10 写域][宪法§9.4]。

### §1.4 last_exam 字段更新规则

1. 类型=PG timestamptz+显式时区（例 `2026-09-22 15:30:00.123+08`）；RULE-SCHEMA-TZ 的 DateTime64 红线属 ClickHouse 侧，PG 通道以 timestamptz+显式时区等价执行，生成与写入禁 datetime.now() 裸取 [宪法§1.10]；
2. 语义=最近一次**完成回填**的考试时点，由回填 API 写入，禁手工改；覆盖写但历史不丢——历次 exam_result 追加于结果记录区，last_exam 仅是指针（§7 P1）。

### §1.5 状态流转机械判定（in_exam 之后归本件）

| 流转 | 机械触发 |
|------|---------|
| in_exam→answered | §1.2 六查全过 |
| in_exam→复考 | §2 矛盾命中，或执行中断无结论 |
| in_exam→挂起 | 数据不可得/判据未定义/证据不可核（A3-A6 类失败），suspend_reason 必填（缓议台账列，激活前以 status+审计留痕替代，读法=查 meta_question_audit 最近 suspend 事件） |
| answered→复考 | §3 对账器盘出 last_exam 逾期 |
| in_exam/answered→挂起 | 复考连续失败 2 次挂起（《未答看板设计》§4 三态规则） |
| 挂起→复考 | 挂起原因消除事件触发 |
| 挂起→registered | 唤醒通道：重算事件达唤醒阈（执行者=《未答看板设计》§4 唤醒操作） |
| 任意→合并 | merged_into 登记并入目标问后转合并态（一问一考拆并留痕 [纪要§3]） |
| 任意→退役 | 仅经 §4 Owner 门位，别无入口 |

## §2 考试矛盾仲裁链

### §2.1 矛盾检测机械定义

前提：同 q_id + **同 exam_plan_version** 的两次 exam_result（R1/R2）；版本不同=方案修订不是矛盾，不比；同版本但数据窗口交叠的重复回写标 `supplement` 不入矛盾检测（writeback 机检，防重复劳动触发伪仲裁）。任一命中即矛盾成立：

| 规则 | 定义 | 可判定式 |
|------|------|---------|
| C1 方向相反 | conclusion_dir 一支持一证伪，且两侧置信均达 exam_plan 最低阈 | dir(R1),dir(R2)∈{支持,证伪} ∧ dir(R1)≠dir(R2) ∧ conf(R1)≥阈 ∧ conf(R2)≥阈 |
| C2 区间分离 | 置信区间互不重叠且分居异侧 | max(lo1,lo2) > min(hi1,hi2) ∧ dir(R1)≠dir(R2) |
| C3 阈值异侧 | 判据值分居 exam_plan 预锁阈值两侧 | (v1-阈)×(v2-阈) < 0 |

### §2.2 四步仲裁链（触发/留痕/时限）

| 步 | 动作 | 触发条件 | 留痕 | 时限 |
|----|------|---------|------|------|
| 1 机械检测 | 回填 API 比对新结果与该问现存最新同版本结果 | 每次回填写入即时比对 | 矛盾案卷 case_id（双方 result ref+命中规则号） | 回填当轮，秒级机械 |
| 2 复考一次 | 用下一复考窗口数据再考一次（执行仍走原考尺） | 步 1 矛盾成立，状态转复考 | 案卷追加复考 result ref | 矛盾登记后 ≤5 个交易日 [待裁，推荐 5 交易日] |
| 3 升级 Max | Max 复审考尺口径/数据窗口/判据解释差异 | 三取二不成：复考结果与 R1、R2 均命中 C1-C3 | Max 复审意见落案卷 | 升级后 ≤10 个工作日 [待裁，推荐 10 工作日]；超时未决自动升级 Owner |
| 4 裁定落册 | 终裁登记 ruling_registry，同 commit 原子 [纪要§10] | Max 意见形成 | 裁定 #NNN 与案卷互链 | 意见形成后立即 |

三取二机械判定：复考结果 R3 与 R1/R2 之一不命中任何 C 规则 → 与其同侧胜出，按该侧结果走 §1.2 六查后转 answered；R3 与两者均矛盾、或与两者均不命中任何 C 规则（归属不可判，如 R3 不可判）→ 均升级 Max。仲裁期间 status=复考，消费方可见"仲裁中"标记（机读标识=该问最近审计事件 exam_contradiction_case 载荷带 case_ref，P4 案卷指针缓议期的替代载体）；仲裁期间禁发新考（防矛盾滚雪球，机检以上述事件为凭）。

## §3 复考周期

### §3.1 各 frequency 的复考窗口与逾期判定

| frequency | 复考窗口 | 逾期判定 |
|-----------|---------|---------|
| 日 | 每交易日一次 | last_exam 距今 >1 个交易日 |
| 周 | 每 5 个交易日 [待裁：交易日 vs 自然日，推荐交易日历] | >1 周期未考 |
| 月 | 每自然月一次 | 跨自然月未考 |
| 季 | 每自然季一次 | 跨自然季未考 |
| 事件驱动 | 无固定窗口 | 逾期不适用；但必须登记事件源引用（§7 P6），无事件源引用的事件驱动问=不合格，回填 API 拒收 |
| 实时（realtime） | 无固定窗口（事件驱动档） | 复考由事件触发，逾期判定不适用 |
| 静态（static） | 无复考 | 静态事实问，answered 即终态，除非裁定重开 |

枚举值↔档名对照：realtime=实时／daily=日／weekly=周／monthly=月／quarterly=季／event_driven=事件驱动／static=静态（7 值全集真源=《入库闸设计》§3 要素 4）。

逾期清单由对账器产出，落本件复考台账；推送消费经未答看板件的复考队列接口（《未答看板设计》§1 复考队列视图=§2.1 `status=复考` 过滤端点；看板内容归其姊妹件，本件禁代写）。

### §3.2 复考触发机制（双通道，禁 sleep-loop）

1. **拉取式对账器**：事件触发（回填完成事件/交易日历日切事件/挂起消除事件）→ 盘 last_exam vs frequency 窗口 → 产出逾期清单。reconciler 必须**事件触发**，禁 cron/Timer/sleep-loop [宪法§9.3]；
2. **事件回写通道**：考试器完成后主动调 `writeback(q_id, exam_result)`——唯一合法回填入口，回填即触发 §1.5 状态流转；
3. 分工闭环：对账器只产出"该考了"的欠账清单→AI 会话按清单领题执行考试（执行走各考尺，硬边界）→完成后走回写通道落账。本件发账不发考试指令。

### §3.3 时间分层铁律约束（显式写死）

1. **今日输出→明日输入** [纪要§8.2]：D 日执行的考试（含复考），数据窗口 end ≤ D-1 收盘；违反即 gate 拒收（A4 查）；
2. **同一时戳禁循环**：复考执行时戳与输入数据窗口不得落在同一时戳，此即五角星死循环的时间分层拆环约束；
3. pit_assertion 必须显式断言上述两条，缺断言=A5 失败，不得 answered。

## §4 退役墓碑

> 退役=墓碑：问题死了，碑立着。对齐图书馆"期刊停刊即墓碑编目记录+死亡证明"先例：记录不死、身份不复用、死因可查。

### §4.1 墓碑九字段（死亡证明先例映射，取七补二）

图书馆死亡证明九字段先例：①死者身份 ②死亡日期 ③死亡原因 ④签发机关 ⑤签发日期 ⑥证明编号 ⑦继承关系 ⑧葬地 ⑨复核人。本墓碑取前七直接映射，补二（最终快照+证据复核）：

| # | 先例字段 | 本墓碑字段 | 说明 |
|---|---------|-----------|------|
| 1 | 死者身份 | q_id + title | 墓碑永不复用 [纪要§7] |
| 2 | 死亡日期 | retired_at | PG timestamptz+显式时区（等价口径见 §1.4） |
| 3 | 死亡原因 | retire_reason | 机械枚举：证伪/无消费方/数据断供/被更优问替代/裁定判死 |
| 4 | 签发机关 | issued_by = Owner | 门位唯一，无授权不得签发 |
| 5 | 签发日期 | issued_at | 与裁定同 commit |
| 6 | 证明编号 | ruling_ref（裁定 #NNN） | 签发必挂裁定 [纪要§10] |
| 7 | 继承关系 | merged_into / successor_ref | 并入/后继问指针 |
| 8 | 葬地（补） | final_snapshot | 最终状态快照：last_exam+末次结论+状态史摘要 |
| 9 | 复核人（补） | evidence_refs + review_trail | 退役证据引用+Max 复核留痕（先例单人复核→本件双签：Max 复核+Owner 签发） |

### §4.2 签发权限与流程（Owner 门位）

1. AI 会话仅可**提名**（机械判据：连续 N 周期无消费方调用/矛盾裁定判死/数据源断供超 N 周期；N [待裁，推荐 3 周期]），Max 复核背书；
2. **签发仅 Owner**——无 Owner 授权不得签发；净删/门位/翻案一律登记上报不擅动 [纪要§10][宪法§5]；
3. 流程：提名留台账 → Max 复核 → 上报 Owner → Owner 批 → 裁定 #NNN 登记（同 commit 原子）→ 墓碑生效。

### §4.3 q_id 处置与引用语义

1. q_id 墓碑**永不复用** [纪要§7.1]：墓碑后号码永久占用，新问只发新号；
2. merged_into / parent_id 引用墓碑问=**只读语义**：可查其历史链，不得据引用续命；基于墓碑内容的新需求一律新建问走入库闸；
3. 墓碑问不进未答看板、不进复考台账（对账器跳过退役态）。

### §4.4 可逆性（翻案走裁定，禁直接复活）

1. 翻案=登记裁定 #NNN+Owner 批 [纪要§10]，禁直接改状态字段复活（gate 拦截）；
2. 翻案不销毁墓碑：死亡证明不撤回，加"翻案附页"（裁定 ref+复活日期+理由），状态转回 registered 重走状态机。
