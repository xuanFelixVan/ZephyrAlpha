## 2. 成因假设（本会话实验实证）

### 2.1 信号码实验（现场复现，逐一对账）

| 终止方式 | 被杀原生子进程退出码 |
|---|---|
| **Git Bash（MSYS）`kill -TERM`** | **143**（POSIX 128+15 约定，msys 信号层注入）|
| psutil `terminate()`（=reaper 杀法，:620-663） | 15 |
| `taskkill /F`（=session_worktree 杀法，:1588） | 1 |
| Python `os.kill(pid, SIGTERM)` | 15 |
| PowerShell `Stop-Process -Force` | -1 |

**结论：143 只能来自 MSYS/Git-Bash 信号层对原生进程的终止**——repo 内全部既有杀器（reaper/supervisor `proc.kill` :149/subprocess 超时/taskkill）无一直产 143。

### 2.2 同窗旁证（reaper_kill.log 只读量取）

rc=143 窗口内（09-30 00:11-00:47）reaper 活跃收割：`incubation_expired:lifetime=1800s owner=reconcile_runner`，victim cmdline=`python -m zephyr.governance.audit.rec...`（reconcile 链），且多条 `[FAILED]` 记录 name/cmd 错位（msedge/svchost/conhost 挂着 python cmdline）——收割判据在 `python -m zephyr.*` 命令行家族上工作，且 kill 面存在树级联（`_KILL_CHILD_RECURSIVE=True` :180）。

### 2.3 假设排序

- **H1（主）会话工具层 bash 树收割**：st-c9-final 的提交链跑在 bash 会话内，harness/bash 层超时或会话收割对进程组发 SIGTERM → 原生孙进程 `python -m pre_commit` 得 143；gateway 进程侥幸存活（非同组/不同 console）观察到 rc 并记账。与 143 特征码完全吻合；与四次"同批重投"形态吻合（收割→队重投→再收割）。
- **H2（次）reaper 树级联连坐**：reaper 收割 reconcile 链祖先进程时级联杀树带走 pre_commit——但 reaper 杀法=psutil.terminate（实测 15≠143），除非祖先进程链经 msys 层被杀，置信下调。
- **H3（待捕证）**：pre_commit 内部 hook 链中的 bash shim 被信号杀，pre_commit 传播其码——需运行时证据。

**处置姿态：不排他定谳，用捕证面一夜定真身（§3.2）。**

## 3. 处方（四件）

1. **判读面（治表，防误判违规）**：`_run_precommit_channel` 记账后（:3711-3723）加一分支——`rc` 命中信号码区间（128..192 或负值）→ 归 **infra 瞬态语义**（同 E4 拒袋形态：requeue 退避重投、不进真阻断统计、不产出「违规」措辞阻断 message、审计 event=`precommit_channel_signalled` 落 `commit_block_events.jsonl`）。判据零变化：hook 集/归因器/阈值全不动。
2. **捕证面（一夜定谳）**：`precommit_channel_run` 账本补记子进程 `pid`+`create_time`；rc≥128 时落 pid/时刻 → 与 `reaper_kill.log` 时窗 join（reaper kill 也落 PID+时刻，:602-617）——一晚数据即可在 H1/H2 间机械判明（PID 命中=H2 树级联实锤；PID 不命中而 143 依旧=H1 工具层）。
3. **防杀面（运维，零代码）**：长批/整夜任务把 cmdline 子串（`pre_commit`、`git_commit`、队列落地工）登记 `data/runtime/process_reaper_keep.txt`（宪法 §0 RULE-GUARDIAN 既有机制），防 H2 面误杀。
4. **不动面**：pre_commit 超时数值、失败归因器、own-scope 判定——143 分支只改「记账归因方向」，不改任何门禁判据。

## 4. 红测两针

- **R-F1 信号码分流红**：构造 rc=143 的 CompletedProcess 喂 `_run_precommit_channel` 判定段 → 断言走瞬态分支（无「GATE-PRECOMMIT-RUN 阻断」违规 message、审计 event=precommit_channel_signalled、返回可 requeue 瞬态形态）——**现码把 143 当普通失败喂 `_precommit_decide_failure`（空输出→own/foreign 均无→fallback 分支），必红**。
- **R-F2 真违规不吞锚**：rc=1 且输出含 own 失败段的现行阻断判定逐字段不变（143 分支不得捕获 rc=1）；矩阵对照 rc∈{0,1,143,-1} 四值终局行为表——**现码对 143 的行为在 F1 落地后由本测锁死不再漂**。
