# K-16(F128) data_security 盲区收窄档

## 现状证据

- 域规模实测：`src/zephyr/data_security/` **12 py**（骨架"10 py"口径微漂移）=实件 5（ai_masking_pipeline.py / data_access_auditor.py / data_masking_engine.py / wiring/audit_sink.py / wiring/data_exit_guard.py / wiring/lsg_masking_front.py）+空包 `__init__` 7。
- 接线线索：J-03 LSG 消费面 grep（LSGSecurityGateway 25 文件/10 域）**含 data_security 域**——wiring/lsg_masking_front.py 即"LLM 出口脱敏前置"的挂接意向件。
- 三件套语义齐：脱敏（masking_engine+ai_masking_pipeline）/访问审计（data_access_auditor）/出口守卫（data_exit_guard）。

## 断点根因（盲区成因）

- 与 F88（LSG 输出面）/F105（密钥治理）职责边界未裁（骨架 §5 定版理由原话"与 F88/F105 异域"），故从未获六向登记；实际数据面→治理动作的消费者（A 段落库链、前端导出面）未挂。

## 施工处方（P1）

1. 先裁边界：lsg_masking_front 归 F128 还是 F88 消费件（一处真源，另一处引注册表锚）。
2. data_access_auditor 的 sink（audit_sink.py）落点核验：审计行写到哪套审计链（K-06 gov_audit/merkle 面是否吸收）。
3. 逐件登记六向台账后从 ROOR/域覆盖核对把 F128 从"语义已覆盖待挖"升"已挖"。

## 风险
