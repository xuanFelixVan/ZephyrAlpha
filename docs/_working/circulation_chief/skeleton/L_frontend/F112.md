# L-02(F112) AI 层两新页·三层三断点定位档

## 现状证据（代码级）

- 新页面 API 实锚（api_server.py 尾部路由族，54 路由实测）：
  - **页一·排产工单（schedulegate）**：`/api/schedulegate-queue`(:5389)、`/api/schedulegate-skeletons`(:5417)、`/api/schedulegate-confirm`(:5445)。
  - **页二·审批/建议族**：`/api/promotion-advisories`(:4968)+`/api/promotion-decide`(:5014，Owner 拍板写台账)、`/api/budget-advisories`(:5373)。
- 三层三断点定位（每端点同构三层：seed 源→事件账投影→持久化）：
  1. **seed 源空**：schedulegate_queue 内 `doc = load_seeds()`（:5405 区域），`orders = doc.get("orders") or doc.get("seeds")`——seed 文件/源缺位即空数组；端点 except 分支自注"排产件缺位降级空态"，`return {"ok": False, ..., "count": 0}`。
  2. **事件账（SchedulingJournal）不可达**：`dispatcher.skeleton_decisions(SchedulingJournal())` 包 `except Exception` 自注"事件账不可达=按未拍板投影（拍板留痕缺席不假造）"——PG 面未部署（F86 M4 议题）时此层恒走降级。
  3. **ConfirmGate 持久化**：:5455 `from zephyr.ai_layer.scheduling.confirm_gate import ConfirmGate, ConfirmPersistError`——显式引入持久化错误类型，persist 面依赖与断点 2 同一 PG 面。

## 断点根因

三断点同根：**ai_layer scheduling 的 PG 面（schema/表/审计账）部署与数据供给未闭环**——页面骨架（路由+降级逻辑）是 built，上游数据链三处空转，页面呈现恒空态/未拍板投影。

## 施工处方（P0 收敛为一案）

1. 一案两步：①跑 `scripts/ai_layer/apply_ai_layer_scheduling_ddl.py`（幂等，写操作走正式工单+Owner 门确认目标库）；②造 1 条 seed+1 条 journal 事件做端到端冒烟（queue→skeletons→confirm→promotion-decide 全链 200 响应留证）。
2. 前端页头加"数据源状态"角标（seed 源/journal 连通性），空态不再无声降级——避免"页面在、数据断"不可见。
3. 与 ../I_scheduler/F82.md、../J_ai_layer/F86.md 三案一并复测（同一 PG 面依赖）。

## 风险

- promotion-decide 是全链唯一 Owner 拍板写入口（H-03）：若 Owner 在数据断链期误判"无建议=无待办"，转正门流量将静默滞留——冒烟通过前禁对外宣称转正门在线。
