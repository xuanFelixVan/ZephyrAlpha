# OBJ_T 工具对象线骨架卡（Owner 2026-09-17 口述新增）

> **Owner 定调原话要点**：AI 升级 AI 不光是升级模型，还要升级工具——AI 的手、眼、脚
> 等等都要升级；执行、修改、删除等等这些能力都要有升级通道。

## 职责一句话

让 AI 的"身体"持续变强：工具（执行/修改/删除的手、搜索/观测的眼、浏览器/爬虫/传输的脚）
同走七段循环——新工具扫描→试用→入库→考试（任务成功率）→切换；考尺=**任务成功率实测**。

## 工具家族初始清单

| 器官 | 现有件（在档） | 升级方向 |
|------|---------------|---------|
| 手（执行/修改/删除） | scripts/ 工具链、批处理、git 工具 | 新执行器/更强批处理/安全删除器 |
| 眼（搜索/观测） | WebSearch/WebFetch、监控探测器 | 更强检索、多模态观测 |
| 脚（行动） | browser-use、computer-use、MCP servers（蓝图在档） | 新 MCP 接入、自动化外设 |

## 与七段的映射

- 感知：全网新工具扫描（新 MCP/新自动化框架/新爬虫）
- 收集：工具试用档案（装在哪/怎么用/坑）
- 清洗：接入规格化（配置/权限/沙箱边界）
- 对比：**基准任务集实测**——同一批标准任务，新工具 vs 老工具比成功率/速度/成本
- 排产：工具切换工单（默认低危——工具层故障不伤数据，走自动切换）
- 切换：灰度换用→老工具退役不删（墓碑）
- 传承：工具坑集回写（哪些工具在什么场景翻过车）
