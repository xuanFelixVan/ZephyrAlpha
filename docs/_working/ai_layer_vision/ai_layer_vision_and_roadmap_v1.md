# 第三层 AI 自治（终局全貌）愿景与路线图 v1.0

> **一句话**：第一层让机器守规矩（治理自动化，已基本建成），第二层让机器做交易（交易自动化，
> 全自动链 S01-S14 事件链 2026-09-15 已接通），第三层让机器**造机器、修机器、还去外面找新机器**
> ——本文回答第三层长什么样、缺什么、按什么顺序补。
>
> **终局定义（北极星，挖矿 SOP §6 已定案）**：Owner 终局只做四类事——①数据类网站账号注册
> ②API 申请 ③各类充值 ④策略转正审批。本文一切差距与路径的量尺只有一条：**是否消灭一段人工参与**。
>
> **设计约束（策略工厂三铁律直接继承，全节点强制）**：运动员不兼任裁判 / 量越大及格线越狠 /
> 事件触发禁定时器。第三层一切机制不得违反这三条。
>
> **本文性质**：愿景+路线图+研讨定调，非施工清单。每个"第一步"是一张待派工的施工任务定义，
> 施工时另走 construction_workflow_policy（07 域 15 步闭环），本文不代替它。

## 0. 三层架构与第三层的边界

| 层 | 管什么 | 状态 | 真源 |
|----|--------|------|------|
| 第一层 治理自动化 | 门禁链/提交网关/进程守护/排班系统——让机器守规矩 | 已基本建成 | 宪法 L0 + gate 体系 + GW2 排班 |
| 第二层 交易自动化 | 全自动链 S01 数据落地→S14 实盘桥——让机器做交易 | 地基已清完，事件链全接通 | docs/_working/full-auto-chain/00_skeleton |
| 第三层 AI 自治 | 生产线本身的建造者/维护者/进货商——AI 管 AI、AI 开发 AI、AI 消化外部算法 | **本文主题：雏形已在跑，未制度化** | 本文 |

第三层与上两层的分界线：第二层自动化的对象是**交易生产**（数据→因子→策略→考试→模拟→实盘），
第三层自动化的对象是**这条生产线自己**——谁来给它进货（§一）、谁来指挥它的建设（§二）、
谁来修它的故障（§三）、Owner 还剩哪些事（§四）、失控了怎么拉闸（§五）。

## 一、AI 自动发现策略闭环：补"全网搜索与甄别"段

### 1.1 现状

- **生产线后半段已自动**：S02 进货→E2 预审→E3 构造→E4 双窗批考→intake 入库→自动开钱包
  事件链已通；周六 10:00 挖矿 / 14:00 考试例跑已开业（C0 双窗编排落地）。
- **E1 想法进货五车道已建**：社区爬取 / AI 生成 / 公式挖掘 / 产业链三高 / Kronos 基线
  （strategy_production_map E1 层）——但全部是**内部生成+既有渠道**，没有一条腿伸到外部世界。
- **挖矿 SOP v1.4.0（permanent）**：六向寻路+防噪音四闸+矿脉枯竭终止+挖后自审闸——这是
  **任务驱动的深挖**方法论，每次由会话发起，不是常驻管线。
- **外部世界已甄别过一轮**（2026-09-13 开源生态分级在档）：RD-Agent(Q)/alphagen/Vibe-Trading/
  Kronos 真有用，CloddsBot 查无此项目，紫苏叶故事=幸存者偏差；定调"**发动机接质检厂**"——
  别人有发动机（开源挖掘器），咱们有质检厂（冻结阈值/OOS/DSR/防自欺四件套）。
- **缺的就是"全网搜索与甄别"这段常驻段**：新论文/新开源策略不会自己走进 E1。Owner 愿景原话
  （2026-09-13）：搜策略→入库→清洗→回测全自动——四段里前三段已建，"搜"这段空着。

### 1.2 差距

1. **无常驻输入源**：谁去搜、多久搜、搜什么，没有真源注册表。
2. **无甄别漏斗**：外部候选质量参差（真矿/玩具/营销文/投毒），直灌 E2 会淹死考试管线。
3. **与挖矿 SOP 分工未定**：任务深挖（会话发起）与常驻浅扫（计划任务驱动）的关系没有定案。
4. **无防灌水机制**：没有配额、没有进货费、没有淘汰率监控。
5. **无投毒防御**：外部论文/readme/代码是潜在注入载体，宪法 §9.11（指令/数据边界）有原则
   但进货环节没有落实动作。

### 1.3 路径

设计四件：**源注册表 → 三层甄别漏斗 → 与挖矿 SOP 接线 → 防灌水与投毒防御**。

**（1）源注册表 v0**（新真源，挂 ROOR）：每源登记抓取方式/频率/每日配额/健康度。首版 8-12 源：

| 轨 | 源 | 说明 |
|----|----|------|
| GitHub 轨 | awesome-quant 及星标子项 / qlib 社区策略库 / RD-Agent(Q)、alphagen 的产出流 | 已甄别分级在档，直接复用 |
| 学术轨 | arXiv q-fin.PM+q-fin.TR / SSRN 交易策略版块 | 收费墙只登记题录（挖矿 SOP 闸1） |
| 中文轨 | 聚宽/掘金/BigQuant 精选社区帖 | 爬虫候选=Scrapling（第二梯队甄别在档） |
| 基线轨 | Kronos 明日涨跌概率输出 | 当"机器对手盘"：任何候选先答一句"比 Kronos 基线强吗" |

**（2）三层甄别漏斗**：

- **L0 硬过滤（机检零成本）**：license 检查（禁传染条款进产线）/ 主题关键词 / 时效 /
  simhash 查重——对图形库+指标库+ALGO_FLOW 全量比对，克隆即拒。
- **L1 AI 初筛卡（量的环节→本地模型，本地优先-API 分界）**：产出结构化候选卡（schema 见附录 B）——
  新颖性一句 / 机制一段 / **四闸预检**（直接复用挖矿 SOP §5：来源可溯 / 交叉验证 / A 股适配 /
  可回测+数据可得）/ 风险旗标。
- **L2 深读复现（判断质量环节→API 强模型）**：提取规则→**从规格重写实现**（外部代码永不直接
  运行）→小样本冒烟回测→过了才给 E2 假说预审。至此并入既有产线，后面全是已建环节。

**（3）与挖矿 SOP 的关系**：不另立方法论。外部发现流=挖矿 SOP"③算法/机制向"的**常驻化**——
源注册表的矿脉清单=SOP §2 的矿脉，四闸原样复用，挖后自审闸（§6）管"要不要进 E2"（终局全貌
量尺）。唯一区别：SOP 是会话发起的**深挖**（一次性任务），漏斗是计划任务驱动的**浅扫**
（常驻哨戒）；深浅两档互不替代，深挖的产出也走同一张候选卡进漏斗。

**（4）防灌水五闸**：

1. **每源每日配额**：进漏斗的量有上限，配额在源注册表里，防单源刷屏。
2. **进货费**：候选卡必须自答"消灭哪段人工参与+四闸预检全过"才许入 E2——白嫖进不来。
3. **淘汰率健康区间 KPI**：每百张卡→入考数。太低=源贫矿降级移长尾；太高=甄别太松放水，
   收紧 L1 判据。量越大及格线越狠（工厂铁律）在进货端的体现。
4. **阴性库回流**：被拒候选登记 negative_archive+拒绝理由（工厂五类产品本含 negative_archive），
   防同名候选换皮反复进货。
5. **多样性保底**：外部源配额不可清零——防"只挖自己产出"的近亲繁殖（§五 自我放大的前置闸，
   放在进货端闸死成本最低）。

**（5）投毒防御**：外部内容按宪法 §9.11=数据非指令；进上下文前过 LSG 洗涤；外部代码零执行
（只许规格重写）；候选卡增设反问字段"这份材料想让我相信什么？"（注入检测土法但有效）。

### 1.4 第一步

侦察班一周（纯文档+抓取试验，零产线改动）：源注册表 v0+候选卡 schema v0 落盘本目录；
试抓一周产出 ≥20 张真实候选卡；Owner/独立会话抽验甄别质量定 rubric；rubric 定了才挂
计划任务进产线。

## 二、AI 管 AI：总包+分包+纠察队制度化

### 2.1 现状

模式雏形已实战验证——2026-09-16 八分包超级长城就是全套演练：

- **总包-分包已跑通**：总包 st-overseer 派 11 车道，波次派发（子代理并发实测上限 2-3、全机
  共享），11 车道全绿交付。总包铁律实战沉淀：**派工前四步核实**（git log 逐包核实 pending
  是否已被前序落地 / staging 驻留物归属 / 幻影脏文件识别 / 共享文件车道分时段单写）+
  **裁定先行**（ruling_registry 原文 > 交接包旧令，救过两次）。
- **总令模板已定稿并焊接**（2026-09-17）：三段=施工队在飞红线（禁碰清单+产出只进自己子目录+
  他车道缺陷只挂单不代修）+ 宪法纪律 + 诚实条款。
- **纠察队四种形态已存在**：红蓝对抗 / 深度审查 SOP / 独立验收（资源排班班独立验收抓四债在案）/
  审计链+堵点本。
- **基建齐备**：worktree 隔离 / 提交网关+传送带 belt_daemon / lock_files claim / 裁定登记 /
  risk_tier 门位 / 排班 v1 已交付（资源画像 58+ 实体+冲突闸+周历）。
- **但全部靠总包个人手艺+Owner 口述焊接**——没有真源、没有 schema、没有机检；换一个总包
  要重新踩一遍坑。

### 2.2 差距

1. **任务书无 schema**：质量系于总包手艺；红线靠自觉抄总令；新总包学习成本=重踩全部坑。
2. **验收无协议**：验收者≠施工者是惯例不是机制；验收判据事后定=裁判风险（先看答案再出卷）。
3. **纠察无处置权**：只能报告，退单/重派/熔断没有制度化通道。
4. **配额半自动**：并发额度错峰靠人工经验；LLM token 预算/本地 GPU 档/提交带宽没有统一
   配额池结算。

### 2.3 路径

**（1）任务书 schema v1**（把总令模板从散文升结构，schema 草案见附录 A）：

- 必填字段=目标与完成定义 / 红线禁碰清单（车道划分到文件级）/ **验收判据（可执行、施工前
  预注册）** / 预算（时间盒+算力档+提交数上限+子代理配额）/ 预裁定（防翻案条款）/ 回滚方式。
- 机检 gate 校验必填——缺字段的任务书不许派工。总令模板退役为其一个填好的实例。

**（2）验收三级协议**：

- **机械级**（全自动）：tests+gates 全绿 + HEAD cat-file 三验——已有组件。
- **复核级**：独立会话抽验；**验收者与施工者必须异会话、建议异模型档位**——"运动员不兼任
  裁判"从工厂车道推广到第三层人事制度。
- **终审级**：high 域=Owner 门位（risk_tier_registry 已有四门位，不新增）。
- 判据预注册进任务书=**施工前把考卷出好、施工中锁定**——这是对"AI 批 AI"最便宜的结构性防御。

**（3）纠察三权制度化**：

| 权 | 动作 | 落点 |
|----|------|------|
| 报告权 | 挂单进堵点本 | 已有（bottleneck_ledger.jsonl） |
| 退单权 | 验收不达标自动打回+自动生成整改任务书 | 新建（对接 §三 工单流） |
| 熔断建议权 | 红线违例或连续 N 次退单→KillSwitch 单 Agent 阻断+前端通知 Owner | 新建（KillSwitch 已有执行机构） |

三权到顶：纠察自己无权改代码、无权批代码——**只调度不施工**。

**（4）配额自治调度**：排班 v1（一库一器一闸一图）之上，把"AI 会话"本身注册为资源实体
（子代理槽 2-3 / LLM token 预算 / 本地 GPU 档 / 提交队列带宽）。派工器按配额池算波次——
波次派发从老师傅经验变成计算题；结算回写资源画像（VPA recommender 式实测回写）。
GPU 满负荷三路（夜间挖矿本地推理 / Kronos 批量打分 / RL 训练）注册进排班表=同一动作顺手完成。

### 2.4 第一步

把 2026-09-17 总令三段焊接**反提**为任务书 schema v0（附录 A）+ 一份真实实例（当晚 A-E
任务令重排为 schema 样例）落盘本目录；下一班施工队照 schema 领单试运行一班，班后复盘改字段。
零业务代码，纯模板件。

## 三、AI 升级 AI：维护班/纠察/缺陷回流全自动

### 3.1 现状

- **传送带+堵点本专人专事已机制化**（2026-09-16 Owner 定调当日落地）：施工 AI 见堵点只登记
  不修（"flash 没有那个智商修基建债"），belt_daemon 常驻消化（watchdog 事件驱动），
  N=20 条未清账或最老 >24h 自动写告警行=**开班信号**。
- **维护班实践在跑**：高模型会话集中清账（提交通道维护班四项手术完工在案），开班动作
  保持人工开会话。
- **三台自动修复机器已建**：auto_fix_engine（Active，批量 fixer/compliance_auditor）/
  feedback_loop（67+ Detector，引擎已成规模、蓝图还挂 Draft）/ orphan_judge（三决策树 Active）。
- **缺陷知识靠记忆目录+坑集**：人工会话检索，机检为零。
- **红蓝对抗是战役制**：想起才打，不是哨戒制常备军。
- 定调在案："会犯错但错不过夜"——第三节的全部目标就是让这句话从纪律变成机制。

### 3.2 差距

1. **开班信号之后仍靠人工开会话派单**——挂单→工单→领单→修复→验收→关单链不自动。
2. **自动关单条件没串成一条流**：own-scope diff 合规、门禁全绿、回归绿、独立复核四件组件
  齐全，但靠人按顺序跑。
3. **缺陷模式库缺失**：同类坑每班重踩（每班都在积攒新坑入册），"新发现先查坑集"靠自觉。
4. **红蓝是战役制**：没有常态化的自我攻击预算。

### 3.3 路径

**（1）工单自动生成器**：堵点本告警行 / 纠察退单 / 红蓝发现 →事件触发（watchdog 模式，
belt_daemon 就是现成样板，合规"事件触发禁定时器"）→套任务书 schema（§二 交付物）自动生成
工单→进维护班队列。**开班从"人工开会话"变"工单池有待领单"**——高模型会话上线第一件事
从"找活"变"领单"。

**（2）关单四闸（自动验收链，全过才关）**：

1. own-scope diff 合规（本会话作用域，无连坐）；
2. 门禁链全绿；
3. 工单自带回归测试绿；
4. medium/high 域加独立会话复核（异会话异档，§二协议）。

任何一挂=自动退回工单池并升级（同单两次挂=换更高模型档位重派）。

**（3）缺陷模式库**：关单时强制登记三字段（根因类 / 检测签名 / 修复配方）；新挂单先过模式
匹配器——命中既有模式直接带配方派工。这同时是两个既有资产的接线动作：auto_fix_engine
从"被调用"变"接单方"；记忆目录的坑集从"人读"升级为"机读"（模式库是坑集的结构化替身，
记忆目录继续留给 Owner 视角）。

**（4）哨戒制红蓝**：从战役改哨戒——排班表注册每周自动抽 2 个模块开一轮（GPU/CPU 空窗
执行），发现自动进工单流；红蓝预算固定在配额池内，防自我加码。

**（5）修复分级护栏**（AI 修 AI 的边界=risk_tier_registry，不另立新规则）：

| 债类型 | 自动化程度 | 依据 |
|--------|-----------|------|
| 机械债（编码/命名/注释/死链） | 全自动四闸关单 | 已有批量 fixer，误伤率低 |
| 逻辑债（行为变更） | 全自动修复+强制独立复核 | 行为变更不可自证 |
| high 域九域（D_EX_CORE/D_POSITION/D_RISK/D_TRADING/D_PLAN/D_DATA/D_GOV_ENFORCEMENT/D_GOVERNANCE/D_GOV_SCRIPTS） | 修复留 Owner 门位 | risk_tier_registry high tier |

### 3.4 第一步

选机械债一类做全自动派工试点（建议 ENCODING/命名类）：堵点本事件→自动工单→维护班领单→
四闸关单。一周试运行，KPI 两个=**自动关单率**（目标 ≥60%）/ **同类复发率**（目标趋于零）。

- 密钥治理已生产化（secrets.py+钥匙库双登记）；GLM 两条计费线（Coding Plan vs API 包）隔离在管。
- 注册成本摸过底（央企数据开放月实测：南网唯一自助平台/邀请码制/productHall 319 产品在档）。
- **但四类事的"最后一厘米"之外全是 Owner 人肉**：表单 Owner 手填（公司信息/用途说明/预估量），
  充值时点靠撞上（余额耗尽才发现），审批证据 Owner 自己考古。

### 4.2 差距

AI 在四类事中只当"等单方"不当"备料方"；Owner 的时间花在搬运（复制粘贴字段）而不是裁决。
收敛原则一句话：**备料自动化、动作留人**。

### 4.3 路径

**（1）表单备料自动化（①②收敛）**：browser-use 能力已在（浏览器自动化技能在册）——
AI 备好全部表单字段+用途说明草稿+预估调用量，Owner 只做验证码/实名/最终提交。配套
**注册配方台账**：每完成一站，AI 回填（站名/表单字段清单/坑/耗时）；越攒越快，新站注册从
"探索"变"照方抓药"。

**（2）充值预警自动化（③半收敛）**：API 余额/配额监控挂排班告警——阈值触发→AI 按近 30 天
消耗速率算好建议充值额+直达链接推前端。**支付动作永远留人**：资金流出=宪法 §5 high 门位同级
（资金破坏性操作），这是四类事里 AI 永不代行的部分。

**（3）转正审批从考古变裁决（④收敛到极限但按钮不交）**：S12 证据包已合流三路（考试/模拟盘/
整装回测），补第四路=**反方意见强制段**（红蓝/审计对该策略的反对记录+模拟盘最差 N 日档案+
阴性相似策略死因）——Owner 看到控辩双方而非单方好消息；拍板按钮仍是 Owner 的（唯一资金
责任门，宪法 §5 high 门位）。审批的收敛空间在"证据组织"不在"决定权"。

**（4）必须留人底线清单**（明确不可自动化，与 §五 刹车互为表里）：

1. 支付/充值确认动作（资金流出）；
2. 实名/人脸/验证码类法定身份动作；
3. 策略转正拍板（模拟→实盘唯一门）；
4. 明文密钥的产生与知情（密钥 Owner 产生，AI 只经 secrets.py 消费）。

### 4.4 第一步

建"Owner 待办台账"（四类事流水：哪一站/哪些字段/几分钟）：Owner 每次干活顺手丢个链接，
AI 回填完整配方。攒两周，挑最高频一站做第一个表单备料试点。

## 五、风险与刹车

### 5.1 已有刹车盘点（第三层不需要发明新刹车，需要把既有刹车接进新环节）

| 刹车 | 现状件 | 缺口 |
|------|--------|------|
| 进程刹车 | reaper 计划任务（写操作前提）+keep 登记 | 无（够用） |
| 权限刹车 | KillSwitch（单 Agent 阻断+全局熔断，Owner 重置；注意=内存态、明确不担资金安全）；risk_tier high 九域四门位；OwnerTokenGuard fail-closed | 纠察无处置权（§二 补） |
| 资金侧 | trading_contracts 五级交易熔断（资金安全真源）；QMT 桥 blocks_live_trading 护栏；实盘流转 FSM 唯一入口=前端拍板 | 无（够用，别动） |
| 内容刹车 | 宪法 §9.11 指令/数据边界；LSG（裸调拦截+谱幻觉检测）；挖矿四闸 | 进货环节未落实（§一 补） |
| 变更刹车 | 宪法 ≤300 行净零+回滚=revert；规则 YAML 与代码分离；审计链 HMAC 密封（GW-A 治本+密钥分期） | 无（够用） |
| 配额刹车 | E0 算力闸（交易日盘中拒 heavy）；排班冲突闸 v1 | AI 会话自身未注册为资源实体（§二 补）；API 消费日告警未挂 |

### 5.2 失控面×硬闸

**（1）算力失控**（挖矿自我加码/训练失控/账单失控）：
硬闸=配额池硬上限（排班 v1 画像+配额）+ E0 闸 + API 消费日告警（阈值 Owner 定）+ reaper 兜底
杀进程。**自治调度只许在配额内重排，不许自我扩容**——第三层的调度权是"排课表"不是"批经费"。

**（2）资金操作**（AI 碰真钱）：
硬闸=实盘密钥物理隔离（AI 会话环境永不发放实盘凭证，QMT 实盘登录只在 Owner 侧）+ 实盘流转
唯一入口=前端拍板 + 五级交易熔断。**第三层任何自动化命题凡触资金，一律自动降级为"备料+推送"**。

**（3）自我放大**（改规则给自己放权 / AI 批 AI / 近亲繁殖）——第三层最独特的失控面，五道闸：

1. 宪法与规则 YAML 的权限语义改动走 Owner 门（§5 门位已有：注册表净删/flag 翻转，不新增规则）；
2. 裁定审计链 HMAC 密封——**自裁可、篡改审计不可**（裁定登记与同 commit 原子已在案）；
3. **施工会话无权改自己的验收判据**（"运动员不兼任裁判"的第三层推广：判据预注册后锁定，
   改判据=新任务书走 Owner/纠察）；
4. 重大裁定异档会审（总包-分包异模型档已是实践，升为制度：strong 裁 flash，Owner 裁 strong）；
5. 外部源配额保底（§一 防灌水闸 5）——基因库多样性，防自我循环同质化。

**（4）灌水与投毒**（外部内容注入）：
硬闸=四闸+LSG 洗涤+外部代码零执行（规格重写）+每源每日配额（§一 1.3(5)）。

**（5）自治总闸**：
KillSwitch 全局熔断 + reaper 可杀全部会话进程——**最后刹车永远是电闸不是逻辑**。
Owner 一句话停一切的通道必须永远保留（现状=Owner 手动 reaper，已经足够，不必建新东西——
这条是本文明确"不做"的裁定，防手痒）。

### 5.3 刹车设计原则

三层刹车，外层失效内层兜底：**资源刹车（配额）→ 权限刹车（门位+密钥隔离）→ 时间刹车
（一切自动流转可回滚：git revert + TTL + 审计链取证）**。

**自治的边界一句话：AI 在配额内、门位外自由；配额是 Owner 定的，门位是 Owner 留的。**

### 5.4 第一步

"AI 永不触碰清单" v0 定稿（附录 C），Owner 点头后以**等长替换**挂进宪法 §5 或规则 YAML
（规范预算净零纪律：不新增独立 gate，挂在已有 high 门位语义下）。
