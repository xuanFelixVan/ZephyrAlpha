## 1. 讨论缘起

Owner 以主观交易员视角提出：实盘决策是一条分层流水线——**看大盘（决定今天下不下单/开不开仓）→ 看板块（开仓开哪个板块）→ 看个股（板块里选哪只票）→ 看买卖点（何时进出）**。项目现有 8 个策略（打板、默认多头、事件驱动、多因子、TopN动量、30秒冲高回落做T、盘口失衡反转做T、VWAP回归做T）各对应流程中不同环节，但项目里**缺一个总口子**：没有一张完整的"交易决策地图"回答——**什么市场情况、在决策链哪个环节、用哪个策略/因子**。

现有 6 类全景图（路径/依赖/数据流/作战地图等）回答的是"系统怎么运转"（工程视图），缺的是"钱怎么赚"（决策内容视图）。

## 3. 业界实证（调研结论）

### 3.1 机构实践
- **作战预案（Playbook，作战手册）**：机构把"什么市场状态、做什么、用哪套打法"写成制度。D.E. Shaw 2025 年=人机混合预案（AI 风控+人工主观高信念下注）；Bridgewater 全天候（All Weather）靠宏观状态预案在状态切换中获利。
- **状态驱动的策略路由（Regime-based Strategy Routing）**：Millennium 330 个 pod 各管一摊，中央办公室按"市场状态+策略近期表现"动态调配资金；FactSet 宏观四态模型（Heating 过热/Growing 增长/Slowing 放缓/Stagflation 滞胀）下不同策略当家。
- **机构"地图"的实质**：不是画出来的图，是**决策矩阵——行=市场状态，列=决策环节，格子=用什么策略、配多少资金**。

### 3.2 量化社区
- **QuantConnect 算法框架（Algorithm Framework）**：200 万+算法沉淀的官方标准，所有策略抽象为 5 个可插拔模块——选股池（Universe Selection）→ 信号（Alpha Creation）→ 仓位构建（Portfolio Construction）→ 风控（Risk Management）→ 执行（Execution）。前端 Algorithm Wizard 向导支持选模块搭积木组合后整装回测——**即"分类→方案→清单"页面的业界标准原型**。
- **微软 Qlib 嵌套执行（NestedExecutor）**：高层策略（日级仓位/选股）内嵌低层执行器（日内做T），联合回测——对应"大盘定仓位+做T执行"两层结构，是整装回测的标准做法。
- **配置即流程**：Qlib 用一份 YAML 定义整条流水线，一条命令跑通——整装方案=一份 YAML。
- 注意 QC 官方自述局限：该框架适合满仓轮动/多因子风格，对"进出信号强耦合、跟随市场定退出"的策略风格（如 A股打板/做T）并不适配——**QC 五模块是通用骨架，但没有"大盘闸门"概念**。

### 3.3 AI/氛围编程社区
- 流行"策略注册表+路由器（Strategy Registry + Router）"模式：市场状态分类器当路由器，把行情路由给对应策略。
- 微软 RD-Agent 在 Qlib 上自动跑"提假设→回测→迭代"闭环。

## 4. 四大结构争议（深度讨论中，未拍板）

### 争议1：总体骨架——地图按什么轴画？

**三个候选轴：**

| 轴 | 内容 | 硬伤 |
|---|------|------|
| A 漏斗制 | 大盘→板块→个股→买卖点（一笔新交易怎么诞生） | 只覆盖建仓流，装不下 3 个做T策略（做T前提是已有持仓）和卖出；漏斗只是建仓流的内部解剖，不是地图全貌 |
| B 生命周期三流制 | 建仓流→持仓流→离场流（一笔交易的一生） | — |
| C 时点制 | 盘前→盘中→盘后（一天怎么过） | 环节间只有时间先后没有因果，"大盘弱→打板不激活"的推理表达不出来 |

**AI 倾向：主骨架用生命周期三流，时点降级为环节属性，漏斗降级为建仓流内部解剖。**

理由：
- 三流保得住**决策依赖**（L1 大盘闸不过→整条建仓流不启动；离场流触发→持仓流降级）。没有依赖的地图只是分类表，有依赖的地图才能推理。
- 与作战地图 buy_flow / sell_flow / position_management 三段天然对齐，互相引用不建第二真源。
- 时点做成环节属性（如"多因子选股=盘前跑""30秒冲高回落做T=盘中跑"），作战指挥页要查"当前时刻该跑哪些环节"按属性过滤即可。项目实盘导航（作战指挥三区=昨天预案/今天匹配/明天推演）本来就是时点制，属性化后两套视角共存。
- 补丁：**应急保命不是第四条流，是横切标志**（暴跌/流动性危机在任何流任何环节触发），与作战地图"四轨融合"中应急保命的处理一致。

待审视假设：三流是否穷尽？疑似缺"资金预算流"（总仓位怎么切给各策略），但太薄，倾向作为 L1 大盘闸的输出属性而非独立流。

**8 策略在三流下的归位：**
- 建仓流 L1-L4：打板 / 默认多头 / 事件驱动 / 多因子 / TopN动量
- 持仓流 P2（做T/加减仓）：30秒冲高回落做T / 盘口失衡反转做T / VWAP回归做T

### 争议2：大盘层定位——是"层"还是"闸"？

业界两派：
- 机构派（TAA 战术资产配置）：大盘分析是决策链第一环，输出资产目标权重——**连续旋钮**，永远有输出。
- 游资派（A股主观）：大盘不行就空仓休息——**离散闸门**，非开即关。

Owner 原话"大盘看完决定今天下不下单"=闸门语义；但实际还有"开多大"，故必然是**闸门+旋钮**。

往深一层：大盘层真正角色是**信号枢纽**，有三个不同下游：
1. **预算输出** → 总仓位上限（喂资金预算：每条流/每个策略分多少钱）
2. **风格输出** → 今日占优风格（成长/价值/题材/防御，喂板块层候选池）
3. **状态标签** → 强势/震荡/弱势/极端（喂状态矩阵，决定哪些策略激活）

**AI 倾向：大盘层=三输出枢纽，画在建仓流顶端，但有广播边到持仓流（大盘转弱→风险处置）和离场流（提高警戒）。** 呼应首页"决策简报"（A股：观望·不新开仓）已是该输出的展示位。另按市场分片铁律，A股与币圈各有独立闸门，无全局大盘闸。

### 争议3：币圈怎么装进地图？

项目既有硬约束：
- 市场分片三层强制隔离（物理闸/数据闸/治理闸）——反对一锅烩
- A股与币圈共用 60-70% 模块，框架共用、规则参数独立（既有裁定）——反对彻底分家
- 交易所可插拔（OKX 主/币安备）——币圈内部将来还可能分实例

结构差异实底：
- A股有强板块层（板块轮动是核心玩法）；币圈赛道联动弱
- A股做T受 T+1 约束（底仓做T）；币圈无 T+1，做T≈资金费率/波段逻辑，持仓流语义不同
- A股离场有涨跌停卖不出风险；币圈 7×24 随时可卖——离场流规则不同

**AI 倾向：同一套 schema（结构定义），两张实例图。** 三流+激活时间+矩阵是"类"（真源一份），A股图和币圈图是两个"实例"（内容独立，币圈 L2 弱化为赛道层）。收益：整装回测引擎/预案调度器写一套跑两个市场（落实"框架共用、参数独立"既定裁定）；代价：币圈图 V0 大概率空壳，但空壳也按同一结构长，免得将来返工。

### 争议4：环节×市场状态矩阵 V0 建不建？

问题本质：**"什么情况用什么策略"由谁承载？**
- 只在每环节写"适用环境"文字 → 地图永远只是人看的分类图
- 建成结构化矩阵（环节×状态→激活策略+仓位比例）→ 变成机读真源，**整装回测方案、明日预案、实盘调度器将来全从这张表派生**——这是地图最值钱的部分，也是它区别于"又一个分类页"的地方

坑：格子内容目前没有实证支撑（"打板适用强势市"是主观经验，未经回测归因验证）。Owner 是实证派，拍脑袋矩阵上系统=把假设伪装成结论。

解法（抄作战地图参数双向状态 implemented/proposed/testing 的治理模式）：矩阵格子带**置信度标注**——
- `verified`：该策略在该状态有回测归因支撑
- `proposed`：主观假设，待回测验证
- `untested`：未填

**AI 倾向：V0 就建矩阵结构（骨架+格子+置信度机制），内容允许先填 proposed。** 理由：矩阵是整装回测和预案引擎的共同上游，晚建一天下游返工一天；置信度机制保证 V0 主观填法不冒充结论，后续用回测归因逐格升级 verified——地图本身成为"主观经验→量化验证"的转化器。

## 5. 组合起来的一句话版本（AI 整体倾向，待拍板）

> **三流骨架（建仓/持仓/离场）+ 时点属性 + 大盘三输出枢纽 + 同 schema 两张市场实例 + 环节×状态带置信度矩阵。**

## 8. 第二轮讨论：Owner 需求画像（2026-09-04 追记）

| # | 需求 | 原话依据 |

### 8.1 本轮业界实证（补充第一轮调研）

- **机构 ML 平台粘合层 = 元数据目录+血缘（metadata catalog & lineage）**：Two Sigma / D.E. Shaw / Man AHL / AQR 的生产平台均为五层（数据→特征存储→实验→部署→监控），由 Apache Atlas / DataHub / Amundsen 类工具提供跨层血缘追溯（点任意信号→追溯到数据源、管道、消费方）。N1+N2+N3 正是这套东西的交易版。
- **因子→数据需求映射为行业标准**：Barra/Axioma 模型手册逐因子写明数据依赖、最低历史长度（Barra 风格因子 60 个月）、质量门槛（缺失率≤5%）。
- **开源社区同构**：A股量化开源项目（stock_good 等）已把"血缘记录 source→job→snapshot→model + 因子库 + Feature Store"作为标准架构。
- **主观流程的机构对应**：机构 PM 研究流水线（idea capture→筛选→深研→评分→批准→下单→复盘）即"大盘→板块→个股→买卖点"的机构版画法。

### 8.2 关键设计结论：骨架=图谱，视图=投影（化解争议1）

N4（可扩展）直接化解 §4 争议1 的骨架之争：

> **存储用图谱（节点+边），展示用投影（projection）。漏斗、状态矩阵、三流泳道都是同一张图的不同视图，将来新想法=加节点/边，不动骨架。**

- 漏斗视图 = N1 要求的决策链导航
- 环节×状态矩阵 = "什么情况用什么策略"（§4 争议4 的载体）
- 三流泳道 = 生命周期视角（若 Owner 认可仍可作为一视图）
- 时点（盘前/盘中/盘后）= 节点属性，支持"当前时刻该跑哪些环节"过滤

### 8.3 五层链每层都有现成真源 → 地图=索引层+缺口检测层

| 层 | 真源（项目已有） | 现状 |
|---|---|---|
| 环节 | 作战地图 battle_map_steps | 已建 |
| 策略 | StrategyMeta / 策略注册表 | 已建 |
| 因子 | 因子注册表 | 已建 |
| 数据 | ClickHouse system.tables 实时真源（数据监管页同款） | 已建 |
