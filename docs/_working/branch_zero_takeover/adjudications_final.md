# 终局裁定书（st-ffchief-20261002 · 七项全裁 + 分支终态 + 死信机制）

> 框架：第一性原理 → 长远战略 → 100% AI 开发前提 → 专业机构/量化社区/氛围编程实践 → OSS 对照。每项附大白话。

## 裁定一：分支终态 8 条不再减少（否决"合并成一条"）

**分析**：8 条 = dev（主干）+ serializer×5（k=4 池每工位独立分支/worktree——并发门禁链的物理隔离）+ 2 条活会话分支。
- 第一性原理：分支是并发隔离的指针，不是历史包袱。昨晚堵队的根因从来不是"分支多"，而是"分支/袋/暂存无主"。153 条的问题=无生命周期；现存 8 条每条有主有职责。
- 专业实践：CI 流水线的并行 runner 各占独立分支/worktree 是标准做法（GitHub Actions matrix / GitLab parallel）；砍并行换分支数=吞吐降 4 倍，重蹈 900s 覆辙。
- 大白话：这 5 条 serializer 分支是四个工人各自的工作台，拆了工作台四个工人挤一张桌子，落地速度慢四倍——昨天堵死就是这么来的。
**裁定**：维持 8 条。真正要管的目标改为「零无主分支」——今后会话分支随会话干净关闭自动删（接管台账已含此 prescription），稳态=dev+5 功能条+≤2 活会话条。

## 裁定二：TRD-A10 实盘腿——保持关闭

**分析**：全仓无实盘业绩证据（架构审查实证）；执行/交易域 execution_simulation 薄；风控五闸链虽已接线但无实盘审计史。第一性原理：实盘门存在的意义=用真金白银倒逼质量前置。量化社区实践：paper trading ≥3-6 个月+Sharpe 证据+风控审计后才碰真钱；机构 O32 上线流程更重。100% AI 开发放大风险（无人类交易员直觉兜底）。
**大白话：现在开实盘=让一个从没考过模拟考的学生直接高考。先把 CI 真跑、模拟盘 Sharpe、风控审计这三张成绩单攒出来。**
**裁定**：保持关闭。解锁条件=模拟盘连续 60 交易日运行+Sharpe>1 证据+Owner 签字。已录 TRD-A10 议题。

## 裁定三：origin 远端 3 ref——保留 origin/dev，origin/master 留 Owner

**分析**：origin/dev=异地备份镜像（备份冷储体系的一环，保留）；origin/HEAD=符号指针（自动，删了会重建）；origin/master 指向陈旧历史。删除需 Owner 的 GitHub 凭证（我不可达）。
**大白话：云端三个指针，一个是有用的备份，一个是自动小标签，一个是老古董。老古董的删除键在你手里。**
**裁定**：origin/dev 保留；origin/master 删除命令留 Owner：`git push origin --delete master`（删前确认无外部消费）。

## 裁定四：config 内存天花板 4 冲突——不抬上限，出错峰处方

**分析**：天花板目的是防排产压垮机器。实测 10.5/11.5GB>10GB 是排程堆积（两个大槽同窗），抬上限=掩盖排程缺陷。专业做法=容量规划错峰，不是加内存。机构实践：生产调度变更需窗口验证。
**大白话：两个人挤一部电梯超载了，正确做法是错开上班时间，不是把电梯改装大。**
**裁定**：不抬 10GB 上限。处方=两个大槽错峰 2 小时，白班数据域验证后执行；验证前这两件 config 保持拦置（gate 拦截=保护在生效）。

## 裁定五：scripts/ 148→120 拆簇——批准五簇方案，白班分批执行

**分析**：148>120 软限，81 件可迁（register_*×32→tasks/register 等）。内收原则：拆簇不减功能只理路径。100% AI 开发下路径记忆由 library.lookup/ROOR 承担（不靠人脑），搬迁成本可控；收益=GOV-DOC-018 达标+门禁不再误伤。

## 裁定六：F87 redline 与 GateEngine——保留双轨划边界

**分析**：语义重叠仅在"扫描"动作。GateEngine=运行时执法编排（依赖注入全链），redline=静态密钥/敏感词扫描（commit 面）。合并=commit 门反向依赖运行时编排器，违反分层（第一性原理：静态检查不该依赖动态系统）。
**大白话：一个是机场安检（起飞前查），一个是飞行中监控系统（空中查）。都查"异常"，但合并成一台机器飞机就造不出来了。**
**裁定**：双轨保留，接口互指注释（已随批登记），议题关闭。
