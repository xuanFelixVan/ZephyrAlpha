## §3. 深挖 #9：BM-PLAN-01 明日情景预案引擎详细设计

> 这是 6 个盲点里最关键的——它是"编排层枢纽"，不创造新能力，而是把已有的 5 个碎片串成跨日闭环。

### 3.1 一句话定位

**BM-PLAN-01 = A 股 T+1 跨日决策的"指挥官"**——它不自己打仗（不选股/不下单），而是每天做三件事：盘中实时推演明天、盘后做明天 N 情景预案、次日盘前加载预案并按竞价结果触发对应分支。

### 3.2 要解决的痛点（为什么需要它）

A 股 T+1 机制下，"今天能不能买/要不要卖"强依赖"对明天的预判"。主观交易老手每天做的事：

```
盘中：今天压力位过了+尾盘走稳 → 明天可能高开 → 今天加仓博明天
盘后：做明天高开/低开/平开 × 真涨/假涨/洗盘 的 N 情景应对矩阵
盘前：9:25 看竞价 → 匹配昨晚哪个情景 → 自动执行对应方案
```

**作战地图现状**：这 3 件事的能力碎片散落在 5 个环节里，但缺一个把它们串成闭环的枢纽。

### 3.3 5 个碎片盘点（已有能力）

| 碎片 | 现有环节 | 状态 | 提供什么能力 |
|---|---|---|---|
| ① 次日走势预测 | BM-SEL-04 次日8态走势预测 | 🟧设计态 | 预测明天高开/低开/平开概率 |
| ② 市场状态感知 | BM-SEL-03 市场状态感知 + BM-SEL-03-A 市场情绪分析 | 🟦运营态 | 当前市场情绪温度/体制 |
| ③ 主力行为推演 | BM-SEL-05 主力行为感知 + BM-SEL-05-D 自迭代推演 | 🟦+🟨 | 主力在吸筹/洗盘/拉升/出货 |
| ④ 卖出侧预案 | BM-SELL-07 卖出情景预案 | 🟧设计态 | 盘前预计算6类卖出预案+盘中触发执行 |
| ⑤ 情绪周期 | BM-SEL-23 游资接力情绪周期 | 🟦运营态 | 冰点/反核/主升/疯狂/退潮定位 |

**关键发现**：碎片④（BM-SELL-07）已经实现了"盘前预计算+盘中触发执行"的预案引擎模式，但**只管卖出侧**。BM-PLAN-01 的设计核心就是**把 BM-SELL-07 的这个模式抽出来泛化成跨买卖仓风的全局预案引擎**。

### 3.4 核心设计哲学：双层架构（边界约束 + 实时推演）

> ⚠️ **本节为 2026-08-05 重大修正**。原设计是"三段式并行"（盘后预案/盘中推演/盘前加载），经用户实战经验拷问后发现核心误区：**把盘后预案当成"给机器用的具体方案"是错的**。

#### 3.4.1 关键洞察：人脑决策 vs 机器决策的本质差异

| 维度 | 人脑（需要盘后预案） | 机器（看似不需要） |
|---|---|---|
| 反应速度 | 30 分钟 | **50ms**（整个逻辑链） |
| 冷静度 | 盘中会冲动 | **⚠️ 机器也会"冲动"**（被噪声信号触发） |
| 过拟合当下 | 容易 | **⚠️ 更容易**（一根插针 spike 就触发追高） |

**机器的"冲动"和人脑不一样**——人脑冲动是情绪，机器冲动是**被噪声信号驱动**。比如盘中一根插针 spike，机器可能瞬间算出"突破压力位"然后追高，但其实那是假突破。

**所以盘后预案不是"替代实时推演"，而是"约束实时推演"**——给机器戴的"纪律手铐"。

#### 3.4.2 量化铁律：预计算约束 > 实时计算

- **速度**：机器毫秒级，远超人脑，**速度根本不是问题**
- **准度**：实时推演会过拟合当下噪声，**必须用边界约束**
- **纪律**：盘中情绪/信号上头时，盘后冷静算的边界踩刹车

#### 3.4.4 ⭐ 实战锚点案例（开发时必看——这是整个双层架构设计的起源）

> ⚠️ **开发 BM-PLAN-01 前必读本案例**。这个案例来自用户 2026-08-05 的实战拷问，是双层架构"边界约束+实时推演"设计的起源。丢了它就忘了为什么不做"三段式并行"。

> **场景**：昨晚美股利空，今天预期低开；但实际低开后迅速拉高，该弱不弱→10点前站稳→考虑加仓；但触及箱体上沿+连拉2天→明天可能低开→只能小仓位加+做T出货。

```
【昨晚盘后 BM-PLAN-01-B】生成边界（冷静用昨日数据算）：
  - 箱体上沿 3150，下沿 3050
  - 预期今天低开（美股利空传导）
  - "该弱不弱拉高站稳"场景允许加仓，但仓位上限 ≤30%
  - 过 3120 不再加仓（接近上沿防追高）
  - 冲 3180 必出（假突破诱多防护）
  - "真涨"判据：黄线在上 + 科技领涨 + 放量站稳10分钟

【今天 09:00 BM-PLAN-01-C】加载边界到机器

【今天 09:30 开盘】实际低开 3080
  → 机器实时推演：检测到"低开"符合预期

【今天 9:35】迅速拉高到 3100
  → 实时推演：检测到"该弱不弱"信号
  → 查边界：站稳需≥10分钟，当前才5分钟
  → 动作：不动作（等站稳验证）

【今天 9:55】拉到 3115 并站稳 10 分钟
  → 实时推演：站稳确认 + 放量 + 黄线在上（真涨判据满足）
  → 查边界：3120 以下可加仓，仓位≤30%
  → 执行：小仓位加仓 ✅（在边界内，允许）

【今天 10:30】冲到 3170
  → 实时推演：触及上沿，明天可能低开（连拉2天）
  → 查边界：冲 3180 必出
  → 执行：做T出货 ✅（纪律线触发，不贪）

【今天 11:00】回踩 3130
  → 实时推演：回踩不破 3120，明天可能反弹
  → 查边界：3120 以下可加仓
  → 执行：可回补 ✅（在边界内）
```

**关键点**：盘后预案**不是**给机器定"明天每种情况怎么办"的剧本（那是人脑思维移植），**而是**给机器定"纪律圈"（箱体/仓位上限/必出价位/真涨判据）。机器在圈内用速度优势自由跑。

### 3.5 修正后的环节结构（双层三模块）

```
BM-PLAN-01 明日情景预案引擎（横切环节，归 12 横切阶段）
│
├── BM-PLAN-01-B 盘后边界生成（上层，15:00-23:00）
│   │  作用：画操作圈，不画具体剧本

│   ├── 情景分类判据（真涨/假涨/真跌/假跌/洗盘的量化定义）
│   └── 输出：TomorrowBoundary（持久化 Redis/DB）
│       ⚠️ 注意：不再是 TomorrowScenarioMatrix（不是情景矩阵方案）
│
├── BM-PLAN-01-C 盘前加载（中层，次日 09:00-09:30）
│   │  作用：载入边界，初始化约束状态
│   ├── 09:00 加载昨晚 TomorrowBoundary
│   ├── 09:25 竞价数据 → 标记今日初始情景倾向
│   └── 输出：约束状态初始化（给 BM-PLAN-01-A 戴手铐）
│
└── BM-PLAN-01-A 盘中实时推演（下层，9:30-15:00，毫秒级）
    │  作用：在边界内自由跑，享受速度优势
    ├── 每个 tick 重算明天高开/低开概率
    ├── 每个 tick 重算今天节奏（15分钟级高点/回落）
    ├── 每个 tick 检查是否触及边界（禁加仓/必出）
    ├── 实时推演要推翻边界？必须满足"突破验证"
    │   （放量站稳N分钟，不是插针就算）
    └── 输出：约束下的操作建议 → BM-BUY/SELL/POS
```

| 约束状态初始化 | 出（内部） | BM-PLAN-01-A | ConstraintState 事件 |
| **约束下操作建议** | **出** | **BM-BUY / BM-SELL / BM-POS** | **BoundedActionAdvice 事件（带边界校验结果）** |

**关键修正**：原 `PreMarketDirective`（次日初始指令）改为 `ConstraintState`（约束状态初始化）——盘前不再下"具体指令"，而是把"纪律手铐"戴到机器手上。

### 3.8 与 BM-SELL-07 的关系（修正版）

```
现状：BM-SELL-07 卖出情景预案（盘前预计算6类卖出预案+盘中触发执行）
      └── 只管卖出侧，产出具体卖出方案

改造后（双层架构下 BM-SELL-07 的角色）：
BM-PLAN-01-B 盘后边界生成
├── 买入侧边界（新）—— 箱体/仓位上限/禁加仓价
├── 持仓侧边界（新）—— 转防御触发条件
└── 卖出侧边界 —— 复用 BM-SELL-07 的"6类卖出预案"逻辑
    ⚠️ 但语义改变：BM-SELL-07 产出的是"必出价位/排队预案"等卖出纪律线
    （不再是"明天暴跌3%就卖"这种具体剧本，而是"明天若触发X条件，必出价位是Y"的约束）

BM-PLAN-01-A 盘中实时推演
└── 卖出侧触发 → 复用 BM-SELL-07 的"盘中触发执行"逻辑
    （实时推演检测到触发条件 → 查 BM-SELL-07 提供的卖出边界 → 执行）
```

**BM-SELL-07 的定位变化**：从"独立的卖出预案引擎"变为"BM-PLAN-01 的卖出侧边界提供者"。其核心价值（6类卖出场景的触发条件+执行逻辑）被保留，但产出从"具体方案"改为"卖出纪律边界"。

### 3.10 降级路径（🆘 坏了怎么办，修正版）

| 子环节 | 降级 | 保命开关 |
|---|---|---|
| BM-PLAN-01-A（盘中推演）不可用 | 退化为日级预测+固定边界（无实时） | 今天按 BM-PLAN-01-C 加载的边界机械执行，无实时调整 |
| BM-PLAN-01-B（盘后边界）不可用 | 退化为 BM-SELL-07 单一卖出边界 | 只有卖出侧纪律线，买入侧无约束（⚠️ 风险高，暂停加仓操作） |
| BM-PLAN-01-C（盘前加载）不可用 | 人工加载边界 | 人工读 Redis TomorrowBoundary + 手动注入约束状态 |

**⚠️ 关键降级原则**（双层架构特有）：
- **边界层（B/C）坏掉 = 致命**——机器失去纪律手铐，必须**暂停所有操作**或退化为 BM-SELL-07 卖出单边纪律
- **推演层（A）坏掉 = 可接受**——机器还有边界约束，只是失去实时调整能力，机械执行边界内操作即可
- **这个降级优先级反直觉但正确**：纪律比聪明更重要。有边界无推演 = 笨但安全；有推演无边界 = 聪明但危险

### 3.11 实施优先级建议（修正版）

| 子环节 | 优先级 | 依赖 | 工作量估算 | 为什么 |
|---|---|---|---|---|
| **BM-PLAN-01-B 盘后边界生成** | P0 | BM-SEL-04 次日预测（设计态，需先建） | 中（核心逻辑） | 没有边界就没有纪律，是整个架构的地基 |
| **BM-PLAN-01-C 盘前加载** | P0 | BM-PLAN-01-B | 小（加载+初始化） | 把边界戴到机器手上，小工作量 |
| BM-PLAN-01-A 盘中实时推演 | P1 | B+C 已通 + 盘中 tick 数据源 | 大（毫秒级实时计算） | 有了边界再叠加推演，锦上添花 |

**建议实施顺序**：
1. **先做 B+C**（盘后边界 + 盘前加载）→ 形成纪律闭环，机器已有"手铐"
2. **再补 A**（盘中实时推演）→ 享受速度优势，在圈内自由跑

**这样即使 A 没做，机器也能靠 B+C 的边界机械执行**——虽然笨但安全。反过来如果先做 A 没做 B+C，机器跑得飞快但没纪律，危险。

### 3.12 为什么必须自建（开源替代判定）

- **A 股 T+1 机制**：美股 T+0 不需要"明天预案"——今天买今天就能卖，没有跨日决策锁仓问题
- **A 股集合竞价**：9:25 集合竞价决定开盘价，这个时点是 A 股独有的"预案触发点"
- **涨跌质量分类**：白线黄线/领涨板块属性是 A 股指数结构独有
- **结论**：全球开源量化项目无此能力，🔴 必须自建
