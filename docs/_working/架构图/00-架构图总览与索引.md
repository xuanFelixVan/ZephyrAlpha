### §2.2 交叉引用规则

当架构图A需要定义架构图B的核心内容时：

| 规则 | 说明 |
|------|------|
| **定义权唯一** | 每个维度只有一个架构图有定义权（矩阵中标注"✅定义"的格子） |
| **引用不重复** | 其他架构图需要该维度内容时，写"详见A4风险架构§X"，不重复定义 |
| **冲突以定义方为准** | 当两个架构图对同一维度有不同描述时，以拥有定义权的架构图为准 |
| **变更通知** | 定义方变更该维度时，必须通知所有消费方 |

## §3 架构图与能力定位书的关系

### §3.1 能力定位书的定位

能力定位书是**所有架构图的元初输入**，不属于9+1架构图中的任何一个。它定义：

| 能力定位书定义 | 被哪个架构图消费 |
|--------------|----------------|
| 45项能力清单（C-001~C-047） | A1（能力如何实现）、A2（能力如何治理） |
| P0/P1/P2优先级 | 所有架构图（按优先级分配设计精力） |
| 硬边界约束（约束一~六） | A1（业务约束）、A4（风险约束）、A5（安全约束）、A9（运维约束） |
| AI行为安全边界 | A2（治理执行）、A5（安全执行）、A7（Agent约束） |
| 五象限能力架构 | A1（交易能力）、A8（进化能力）、A9（运维能力） |

### §3.2 引用规则

| 规则 | 说明 |
|------|------|
| 能力定位书是唯一真源 | 能力的定义、优先级、边界以能力定位书为准 |
| 架构图不重新定义能力 | 架构图只说"这个能力怎么实现/怎么治理/怎么保护"，不说"这个能力是什么" |
| 架构图可发现新能力 | 设计过程中发现的新能力，必须回写到能力定位书，再由架构图引用 |

```

    │
    ├──→ 架构图（9+1） ── 定义"系统长什么样"
    │         │
    │         │ 约束
    │         ▼
    │    功能域（30+1个） ── 定义"每个域内部怎么做"
    │         │
    │         │ 合并
    │         ▼
```
