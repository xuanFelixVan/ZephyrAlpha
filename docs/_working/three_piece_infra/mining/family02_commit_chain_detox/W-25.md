## 4. 缺口与根因

1. **根因 A：装载器的返回类型把三态压成一态。** `load_flags_from_yaml() -> int`：`0` 同时表示"册里没有键"与"册读不到"。下游 `is_enabled(key, default=False)` 只看到"注册表空"⇒ 一律 OFF。Z-10 要的三态**在当前函数签名下无法表达** ⇒ 这不是"加个日志"能收的，必须改返回契约（抛错 / 返回带状态的结果对象）。**这就是它至今不算完成的原因**：所有"补一条 warning"的尝试都会撞回同一个签名。
2. **根因 B：`except Exception → None`（M2/M3）是**同一写法的两副本，且都自带 `# noqa: BLE001`。任何"禁止裸 broad-except"的既有门都被显式豁免掉了 ⇒ 复发面为零、存量面为二。⇒ 内收对价要落在"把两副本并成一个带错误通道的 helper"，而不是再造第三份。
3. **根因 C（X-30 那一侧）**：⚑-4 的"翻 flag"动作对象必须是**真载体**。若两枚旗标实际只是模块常量，则翻 `flags.yaml` 里不存在的键**不会有任何效果也不会报错**——因为 M1 对未知键的处理是"读不到→OFF→静默"。**两案合起来才完整**：M1 让人无法发现"翻了个不存在的东西"。
4. 非根因：不是 YAML 解析错（`yaml.safe_load` 在 `:345` 附近，解析异常会真抛，不在此案面）；不是时区/schema 面。

## 5. 能红判据

- **主尺**：构造三种输入，断言三者**可分辨**（不同异常类型或不同返回态）：
  ① `flags.yaml` 正常含键 K=ON → `is_enabled(K)=True`；② 正常但不含 K → OFF；③ 路径不可解析/文件缺失 → **必抛（或被尺点名）**，禁落回 ②。
  **必红变异体**：在当前 HEAD 上把 `config/flags.yaml` 临时改名（沙盘断言层，禁真动主区）⇒ 尺必红；**今天的真实行为是 `logger.warning` + `return 0` ⇒ 尺红即是"缺陷在场"的证明**。若实现者把 ③ 判成与 ② 同态，尺必红——这正是本尺存在的意义。
- **副尺（禁 broad-except 复发）**：`flags.py` 内 `except Exception` 的数量在改动后**不增加**（当前基线=2，见 M2/M3）。
  **必红变异体**：新增第 3 处吞异常 ⇒ 必红。反事实：删掉一处并接真错误通道 ⇒ 计数下降、尺绿。
- **⚑ 呈现尺**：任何呈 Owner 的"翻 flag"项，其键名必须先 `git show HEAD:config/flags.yaml | grep -c '^ *<key>:'` ≥1，否则**禁以"翻 flag"名义呈报**（X-30 处方）。
  **必红变异体**：拿"价格笼子两枚"去跑本尺 ⇒ 必红（它们在 flags.yaml 里 0 命中）⇒ 尺能拦住历史上已经发生过的那次误呈报。
- **就绪度**：主尺/副尺/呈现尺均可写变异体 ⇒ 就绪。
