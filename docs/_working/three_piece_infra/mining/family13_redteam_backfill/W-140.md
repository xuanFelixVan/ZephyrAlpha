## 4. 缺口与根因

1. **根因 A：`[DEPENDENCIES]` / `[CONSUMERS]` 头注是**手写散文**，且同一文件内两行可以互相矛盾（M2：一边标"TYPE_CHECKING 预接线"，一边宣称"订单事件/fill 回调消费"）。⇒ 治理锚块被下游（人、仪表盘、呈报）当作真源引用，而**没有任何台把它与 AST 实测对账**。这不是合规门独有的病——它是**全仓模块锚块的真值问题**，本案只是撞见的最清楚的一处。
2. **根因 B："零接线"与"接线但未启用"两态在案卷里不可分辨。** 逐闸表必须至少四列：①运行时引用数、②仅类型期引用、③装载路径（有没有 factory/注册点）、④fail-open/closed。M1–M4 的四闸里，①全 0、②1 处、③未测、④未测 ⇒ **本层拒绝把"12 闸零接线"换成"12 闸逐闸零运行时接线"，因为另 8 闸我根本没测**（诚实边界：4/12 已实测）。
3. **根因 C：接线的前置是外部义务（程序化交易报告回执）**，所以"没人接"可能是**审慎而非疏漏**——Z 册 ⚑-1 明写"接线前置是您先人工履行报告义务并回填回执（否则 fail-closed 会把第一笔单全拒）"。⇒ 本案的表**必须区分"未接=待前置"与"未接=被遗忘"**，否则呈报会把审慎当缺陷报。判据＝闸的默认态（fail-closed 者属"待前置"合理，fail-open 者属"被遗忘"可疑）。
4. 非根因：不是缺实现（四闸文件都在 HEAD）。
