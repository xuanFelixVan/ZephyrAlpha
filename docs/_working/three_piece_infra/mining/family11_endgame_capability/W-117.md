## 4. 缺口与根因

1. **根因 A：库建在了"设计态"，实现域真源规则把责任推给了一次未施工的回填。** M2 的规则是"代码未落地=库（设计态），代码落地锚定后=代码"，而**所有 287 条的锚点字段都是 null 占位** ⇒ 该规则当前**永假**，于是"库有 287 条形态"这件事在生产语义上等于 0 条被锚定的形态。⇒ 缺的不是算法，是**回填批**（且回填批被 `human_gated` 卡在半径上：条目内容重填需人过）。
2. **根因 B：支撑阻力聚类与趋势线 RANSAC 在 HEAD 零命中**（`git grep -ln "RANSAC\|支撑阻力" HEAD` 只回 4 本**册**，全部是候选/能力登记表，**零实现件**）⇒ 这两块是**真缺**（与形态库的"在册未锚定"是**两种不同的缺**，混在一起谈会得出"图形库差 61 个形态"这种错处方）。
3. **根因 C：Owner 定性它为"第一大指标"，但它没有任何一把能红的尺。** 本战役的执法面全在"提交/名册/数据链"三侧，业务价值类条目（族 11 全体）缺的是**验收尺**而非施工许可 ⇒ 骨架册把它列 ⬜ 是诚实的，但它与 ⬜ 的其它项不同：其它 ⬜ 是"知道怎么做没做"，这项是"**还没定义什么叫做完**"。
4. 非根因：不是缺 TA-Lib 依赖（M3）。
