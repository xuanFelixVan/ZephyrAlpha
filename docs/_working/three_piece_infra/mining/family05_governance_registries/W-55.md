## 4. 缺口与根因

1. **根因 A：三件断言中的"在途占号感知"缺数据源，不是缺代码。** "在途"＝已取号但未入册（因为入册要等 commit 原子）。当前体系里**没有任何地方登记"占号未落地"**（`commit_queue` 存袋、`.aidocks` 存会话、议题册存议题，都不是号占位）。⇒ 除非本案同时新增一个占号登记面，否则"在途感知"无从实现。**这是本叶簿对 Z-38 处方的一条实质异议**：处方假定了一个不存在的输入。⇒ 出路二选一（须总筹裁）：①占号写入 `commit_queue` 袋的 message 前置元数据（复用既有面，零新册）；②把该断言降档为"最大号+1 且撞号必拒"，**诚实承认"在途窗口内的并发撞号无解"**。
2. **根因 B：两份车道副本（M3）＝取号器自身已经在示范"没有取号器的后果"**（两个会话各自发号、各自留副本）。这是本案最好的自指红证素材（见 §5）。
3. **根因 C：号段空洞（M6）与"连续分配"铁律冲突，而 Z-59 已裁"不修"** ⇒ 取号器实现若天真地做"找第一个空洞填上"，**会违反 Z-59**；若做"max+1"，**会违反'连续分配'的字面**（因为 max 与条目数不等）。⇒ 必须在尺里把"取 max+1，禁回填空洞"写成显式判据，否则实现者会各自理解。
4. 非根因：不是"号不够用"；不是 RULING-REFERENCE 门失效（它管引用侧）。
