## 4. 缺口与根因

1. **根因 A：判据对象错位。** 本案写的是"工作树自赋 → HEAD 查无"，而**执法点（门）在提交期**、**检测面（M1）在 HEAD 引用面** ⇒ 三者交集为空：车道内的号在落地前**没有任何机械面看得到**（这正是 W-10/W-11 反复出现的"HEAD 之外的东西无人知晓"模式）。⇒ 修法是**把扫描面从 HEAD 改到"待落地袋的 diff 文本"**——门其实已经在提交期看到 staged 内容，缺的是"引用号集合 ⊖ 在册号集合（含本袋新增）"这一条差集判据。
2. **根因 B：迁号无闭包（M5）。** `#404 → #407`，旧号 404 在文档里可能仍被引用且语义改变；**没有台要求"被迁走的号必须在引用处一并改指"**。⇒ 本层判这是本案的**真实残留缺口**（不是"悬空号"），应作为 W-56 的第二子判据。
3. **根因 C：号在册≠事已办（M4 下游向）**。X-49 的 #410"授权空转"是比悬空号更危险的反向病：**号查得到、事没做**，而一切现有尺都只查"号查不查得到"。⇒ 与 W-28（自述绿 vs HEAD 在册）**同根**；本层建议把"号在册 + 其批准对象的 HEAD 实存"合成一条尺，服务两案。
4. 非根因：号段空洞（M4）属 Z-59 明令不修，禁当缺陷重挖。
