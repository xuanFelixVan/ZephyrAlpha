## 4. 缺口与根因

1. **根因：`空` 与 `一致` 在同一张表里用同一个查询表达。** 表是差异登记表 ⇒ 表空在语义上等于"无差异"，但真实的三态是"无差异 / 没比 / 比不了"。写侧纪律（M3）已经**声明**了"QMT 不在线要显式标注"、"不一致要 exit 3"，但**没有任何读侧把这三态分开统计** ⇒ 表空即可被下游（含人）读成"今天对账干净"。Z-18 的"空不能证明一致"就是这个意思，落点应是一个**每次运行的三态计数产物**，而不是一条新 SQL。
2. **根因（双源）**：同一逻辑对象落两库（CH `c1_market` + `governance.db`），**没有任何尺比对两库**；而 DDL 面自带"legacy 坏 DDL 毒化"（M1）与 `ReplacingMergeTree`（需 `FINAL`）两个会造成两库长期不一致的机制。⇒ 收敛方向必须选一个真源并把另一个改成**派生视图或删除**（RULE-SSOT 分类：这是**架构数据** ⇒ 直写 DB 的那侧为真源；YAML 侧只登记）。这一条**本层不代裁**，只给判据。
3. **根因（读法二义）**：M1③——`ReplacingMergeTree` + 不加 `FINAL` 时，"行数"包含未合并版本 ⇒ 同一个"空"在两处查询里可以一个是真空一个是有重复待合并。**任何本项的尺都必须写明 `FINAL` 用法**（这条与 X-26"表不存在判定必带 database= 限定 + 双探测"同族）。
4. 非根因：不是缺 DDL（M1 显示 DDL-as-Code 在场）。

## 5. 能红判据

- **尺 1（三态必分）**：一次盘后运行产物必须含三个可区分的计数：`compared_with_diff` / `compared_no_diff` / `not_comparable(原因)`。
  **必红变异体**：把 QMT 侧人为置为不可用（沙盘/注入层，禁真动生产）⇒ 今天的行为是"降级为仅系统侧 + 显式标注"，尺**必须**把它计入 `not_comparable` 而**不得**计入 `compared_no_diff`；若尺判其"一致"，尺无效。**这条是本案唯一有意义的判据**，因为"空"本身就是它要审的对象。
- **尺 2（两库对账）**：断言 `(CH 表 FINAL 计数, governance.db 计数)` 的键集合差可解释；两库同侧皆空 **且** 当日 `not_comparable>0` ⇒ 必报红（禁"两库都空所以干净"）。
  **必红变异体**：只写 CH 不写 governance.db（或反之）⇒ 尺必点名单源缺失。
- **尺 3（坏 DDL 面）**：`apply_cross_asset_ddl.py:24` 自述"legacy 坏 DDL 毒化（首败致 TCP 失效）"⇒ 断言 DDL 部署失败时尺必红而不是"部署过=成功"。
- **就绪度**：尺 1/2/3 都能写变异体 ⇒ **技术上就绪**，但**施工前必须先现跑取真值**（M4 只有 E4 级读数），否则尺是在空表上自证。
