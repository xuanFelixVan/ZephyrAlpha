## 4. 缺口与根因

1. **根因：现在的检测是"绝对阈值"，不是"守恒"。** M2 的语义是"这张表超过 N 天没写 ⇒ 报警"。守恒断言的语义应当是"**进入量 = 落地量 + 显式豁免量**"——即上游声称取了 X 行，落地 Y 行，则 X−Y 必须逐条有归因（去重/清洗丢弃/字段不全/已知缺口在册）。当前**没有任何一处**能回答"取了多少 vs 落了多少 vs 为什么不等"（`task_runs.rows_written` 只有落地侧，见 W-31 §1）。⇒ 这不是阈值调参问题，是**记账面缺一列**。
2. **根因（为什么会"合法静默"）**：`known_data_gaps.yaml` 有 63 条豁免性登记（W-34 M1），而**豁免没有到期日/没有归因字段**（登记一次即永久免检）⇒ 守恒断言若直接接入，会被既有豁免吞掉。**处方**：守恒必须区分"在册缺口"与"未解释差额"，且"在册缺口"也要能算出**应有多少行**（哪怕只声明"无基线"）。
3. **根因（EV-03 的教训本身未消化）**：M4——提交链侧 EV 件"未跟踪且 4 红"，X-48 已判"落地了但没达标是最危险的假完成"。⇒ 数据链搬方前，必须先确认搬的是**已转绿的 EV 语义**，否则本案会重复同一形态。
4. 非根因：不是"没有断供检测"（M1/M2 显示哨兵在场且有读者，这一点比多数案子好）。

## 5. 能红判据

- **主尺（守恒）**：对每个被检任务，断言 `intake_count == landed_count + deduped_count + rejected_count + registered_gap_count`，任一项缺记 ⇒ 判 `unexplained_delta>0` 报红。
  **必红变异体**：今天跑 ⇒ **必红**（`rejected_count`/`deduped_count` 两侧当前无记账位，§4-C1）。若有人把尺实现成"只比 landed 与 intake 且允许 ±N% 容差"，尺会今天变绿 ⇒ 该实现**无效**，容差就是把病藏回阈值里。
- **反事实控制组（Z-16 硬性要求）**：造一个"上游 0 行 + 在册 known_gap 覆盖该表该窗"的输入 ⇒ 尺必**绿**（证明它不是"凡不等即红"的噪声机）。
- **第二把（豁免有期）**：断言 `known_data_gaps.yaml` 每条含 `expires` 或 `review_at`；无 ⇒ 点名。
  **必红变异体**：任一既有条目去掉该字段 ⇒ 必红；这是防止守恒尺被永久豁免蛀空的配套。
- **就绪度**：主尺**未就绪**——缺"intake/dedup/reject 三个记账列"的实现前置（属实现缺陷修复面，不是判据变更，故 Z-16 可自裁）；第二把尺**立即就绪**。⇒ **诚实结论：本案不能一步施工，必须先做记账面扩列，再谈守恒尺。**
