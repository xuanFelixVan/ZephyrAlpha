### 1.2 抽取通道与量产路线

- **通道已建**：MOD-BT-193 `graph_enrich_staging`（新闻/文档→LLM 抽供应链关系→暂存台账→`graph_enrich_ingest --approve` 入正图，Owner 门位）。研报喂链=同一通道换语料源，**不新建管线**。
- **LLM 调用必经 LSG 网关**；抽取产出全部先进暂存台账，正图写入走 Owner 批准（红线不破）。
- **量产批次建议**：第一批=行业深度研报（链结构信息密度最高）；第二批=公司深度报告（客户/供应商关系段落）；第三批=宏观测评（全球链/跨界关系）。每批先 50 篇试点抽质检（关系四元组准确率抽检 ≥80% 再放量）。

### 1.3 最值钱的架构点：证据时点=历史 PIT 免费

- 传统做法：今天挖到"甲供乙"就写 valid_from=今天→图谱永远是"现在的样子"，历史回测没得用。
- **研报喂链的正确姿势**：valid_from=**研报发布日期**（证据可用时点），录入日另记。2017→2026 的研报流按发布日回填，图谱自动长出**十年历史 vintage 序列**——"2019 年的锂电产业链长什么样"变成一条 SQL。
- 与 483 年报边同构（year=Y 的边 Y+1-05-01 起可用——leadlag 原型已实现该纪律）；与总账 D1（全图快照）互补：D1 管"向前滚动快照"，研报回填管"历史段重建"，两者合成完整 PIT 轴。
- 全网引文佐证：专业机构链数据产品的核心卖点就是 historical vintages（FactSet Revere/Bloomberg SPLC），我们用自家研报库自建——零采购。

## 2. 问2：时点机制定稿（不加列，补纪律）

- **已有**：ig_node/ig_edge/ig_node_company/ig_company_edge 全带 valid_from/valid_to（SCD-2），ig_fact 带 as_of，stock_concept 即 SCD-2 实例——"每个节点以往时间节点是什么样子"在架构上已经成立。已知坑：ig_company_edge 无 updated_at 列（维护时点靠 valid_from/批次留痕）。

### 3.2 裁定：升级 ig_unlisted_entity 为项目级 Entity Master（总账新增 D7）

- **主键族设计**：每个真实世界实体一个 master 身份——上市实体：master 行挂多市场代码映射表（2330.TW / TSM.US-ADR / TWSE:2330 同指一行）；非上市实体：UE- 主键；未来接全球行情时按代码映射直接 join。

- **业界对齐**：Bloomberg FIGI / LEI / OpenFIGI / FactSet Permanent ID——专业机构全靠唯一实体 ID 库防一司多身份；Owner 直觉=业界正解。
- **施工边界**：Entity Master 是图谱域 DDL+数据工程，走 apply_industry_graph_ddl 正门+图谱施工班；本会话只登记。
