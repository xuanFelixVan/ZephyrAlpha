| 属性 | 说明 |
|------|------|
| **问题背景** | 审计发现因子库蓝图(FACTOR_BACKTEST_001)与策略引擎蓝图(STRAT_ENGINE_001)在回测集成方面存在职责重叠 |

## 🗺️ 整体职责地图

### Layer 0-8 架构中的模块定位

```
Layer 8: 人机交互层
    ↑
Layer 7: AI报告层 (绩效归因、自动报告)
    ↑
Layer 6: 组合优化层 (组合权重优化)
    ↑
Layer 5: 策略执行层 ←─┬─ 策略引擎蓝图 (策略逻辑)
                       └─ 因子库蓝图 (因子回测验证)
    ↑
Layer 4: 机器学习层 (AI因子挖掘)
    ↑
Layer 3: 舆情分析层 (情感分析、事件驱动)
    ↑
Layer 2: Alpha因子层 ←─ 因子库蓝图 (因子计算、存储)
    ↑
Layer 1: 数据预处理层
    ↑
Layer 0: 数据源层
```

### 核心模块职责概览

| 模块 | 模块ID | 所属Layer | 核心职责 | 职责边界 |
|------|--------|-----------|----------|----------|
| **因子库模块** | FACTOR_BACKTEST_001 | Layer 2 + Layer 5 | 因子计算、存储、IC分析、因子回测验证 | **因子层面**的回测验证 |
| **策略引擎模块** | STRAT_ENGINE_001 | Layer 3 + Layer 5 | 策略逻辑开发、策略回测执行、绩效分析 | **策略层面**的回测执行 |
| **回测执行模块** | (Backtrader集成) | Layer 5 | 回测引擎执行、交易模拟、成本计算 | **引擎层面**的回测执行 |

## 🔍 详细职责边界定义

### 1. 因子库蓝图 (FACTOR_BACKTEST_001)

#### ✅ 核心职责 (必须负责)

| 职责领域 | 具体任务 | 输出产物 | 说明 |
|----------|----------|----------|------|
| **因子计算** | 5700+因子的计算逻辑实现 | 因子数据文件、计算脚本 | Layer 2核心职责 |
| **因子存储** | 因子特征库(Feature Store)管理 | 因子数据库、版本管理 | 中间层数据管理 |
| **IC分析** | 因子信息系数计算与统计 | IC分析报告、因子有效性评估 | 因子有效性验证 |
| **因子回测验证** | 单因子回测、因子分组收益 | 因子回测报告、分组收益分析 | **因子层面**的回测验证 |
| **因子合成** | 多因子合成、因子组合优化 | 合成因子、因子权重 | 因子组合管理 |

#### ❌ 非职责 (不应负责)

| 职责领域 | 原因 | 应负责模块 |
|----------|------|------------|
| 策略逻辑开发 | 属于策略引擎职责 | 策略引擎蓝图 |
| 策略回测执行 | 属于回测引擎职责 | Backtrader引擎 |
| 策略绩效分析 | 属于策略分析职责 | 策略引擎蓝图 |
| 组合优化 | 属于Layer 6职责 | 组合优化层 |

#### ⚡ 边界接口 (与其他模块交互)

| 接口类型 | 接口内容 | 对接模块 | 数据格式 |
|----------|----------|----------|----------|
| **数据输出** | 因子数据、IC分析结果 | 策略引擎模块 | Parquet/CSV + 元数据 |
| **回测请求** | 因子回测验证请求 | 回测执行模块 | JSON配置 + 因子数据 |

## 🎯 回测集成链职责划分

### 完整回测流程的职责分配

```
┌─────────────────────────────────────────────────────────────────────┐
│                    回测集成链职责划分                                │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  1. 因子准备阶段 (因子库职责)                                       │
│     ├── 因子计算 → 因子存储 → IC分析 → 因子筛选                     │
│     └── 输出: 有效因子数据集 + IC分析报告                          │
│                                                                     │
│  2. 策略开发阶段 (策略引擎职责)                                     │
│     ├── 策略逻辑设计 → 参数配置 → 回测准备                         │
│     └── 输出: 策略类 + 回测配置                                    │
│                                                                     │
│  3. 回测执行阶段 (回测引擎职责)                                     │
│     ├── 数据加载 → 引擎初始化 → 事件驱动回测 → 成本计算            │
│     └── 输出: 回测结果对象 + 交易记录                              │
│                                                                     │
│  4. 分析优化阶段 (策略引擎+AI报告层职责)                           │
│     ├── 绩效分析 → 参数优化 → 报告生成                             │
│     └── 输出: 绩效报告 + 优化建议                                  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 关键决策点边界

| 决策点 | 负责模块 | 决策内容 | 输出 |
|--------|----------|----------|------|
| **因子选择** | 因子库蓝图 | 选择哪些因子进入回测 | 因子列表 + 有效性证据 |
| **策略逻辑** | 策略引擎蓝图 | 具体的交易信号逻辑 | 策略Python类 |
| **回测参数** | 策略引擎蓝图 | 回测时间范围、初始资金等 | 回测配置字典 |
| **成本模型** | 回测执行模块 | 手续费率、滑点模型 | 成本配置 |
| **绩效评估** | 策略引擎蓝图 | 使用哪些绩效指标 | 指标计算脚本 |

## 🔄 协作流程示例

### 场景：开发一个基于动量因子的策略

#### 步骤1：因子准备 (因子库职责)
```python
# 因子库模块执行
1. 计算动量因子数据
2. 进行IC分析，验证因子有效性
3. 存储因子数据到特征库
4. 生成因子有效性报告
```

#### 步骤2：策略开发 (策略引擎职责)
```python
# 策略引擎模块执行
1. 设计动量因子策略逻辑
2. 配置回测参数（时间范围、初始资金）
3. 准备回测数据（市场数据 + 因子数据）
4. 创建策略类
```

#### 步骤3：回测执行 (回测引擎职责)
```python
# Backtrader引擎执行
1. 初始化Cerebro引擎
2. 加载数据馈送
3. 添加策略和成本模型
4. 运行回测，生成结果
```

#### 步骤4：分析优化 (策略引擎+AI报告层职责)
```python
# 策略引擎模块执行
1. 分析回测结果，计算绩效指标
2. 进行参数优化（如动量周期）
3. 生成绩效报告
4. 提出优化建议
```

## 📋 职责冲突解决机制

### 冲突类型识别

| 冲突类型 | 典型表现 | 解决方案 |
|----------|----------|----------|
| **职责重叠** | 两个模块都实现相似功能 | 参考本文档明确划分，重构代码 |
| **接口不一致** | 模块间数据格式不匹配 | 制定统一接口标准，创建适配器 |
| **依赖循环** | 模块A依赖B，B又依赖A | 引入中间层，打破循环依赖 |
| **版本冲突** | 不同模块对同一库的版本要求不同 | 使用虚拟环境隔离，或统一版本 |

### 冲突解决流程

1. **识别冲突**: 通过代码审查或运行时错误识别职责冲突
2. **定位边界**: 参考本文档确定正确的职责归属
3. **代码重构**: 将代码移动到正确的模块
4. **接口适配**: 如有必要，创建适配器接口
5. **文档更新**: 更新相关文档，记录变更
6. **测试验证**: 确保重构后功能正常
