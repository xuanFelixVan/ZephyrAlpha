## 1. 模块依赖概述

### 1.1 依赖关系定义

**模块依赖**: 一个模块使用另一个模块提供的功能或服务的关系

**依赖类型**:
- **强依赖**: 必需的依赖，缺失会导致功能不可用
- **弱依赖**: 可选的依赖，缺失只会降低功能
- **循环依赖**: 双向依赖，需要避免

---

### 1.2 依赖管理原则

**原则1: 单向依赖**
- 依赖关系应该是单向的
- 避免循环依赖
- 高层模块不应依赖低层模块

**原则2: 接口依赖**
- 依赖接口而非实现
- 使用依赖注入
- 降低耦合度

**原则3: 最小依赖**
- 只依赖必需的模块
- 避免过度依赖
- 保持模块独立性

---

## 2. Layer层级依赖关系

### 2.1 层级依赖规则

```
Layer 0 (用户界面层)
  ↓ 依赖
Layer 1 (应用服务层)
  ↓ 依赖
Layer 2 (领域模型层)
  ↓ 依赖
Layer 3 (引擎层)
  ↓ 依赖
Layer 4 (基础设施层)
  ↓ 依赖
Layer 5 (数据存储层)
  ↓ 依赖
Layer 6 (外部接口层)
  ↓ 依赖
Layer 7 (数据源层)
```

**依赖规则**:
- 上层可以依赖下层
- 下层不能依赖上层
- 同层模块尽量不相互依赖

## 6. 循环依赖检测与解决

### 6.1 循环依赖检测

**检测方法**:
1. 静态代码分析
2. 运行时检测
3. 依赖图分析

**检测工具**:
```python
def detect_circular_dependency(modules: Dict[str, List[str]]) -> List[List[str]]:
    """
    检测循环依赖
    
    Args:
        modules: 模块依赖关系字典
    
    Returns:
        循环依赖链列表
    """
    circular_deps = []
    visited = set()
    path = []
    
    def dfs(module: str):
        if module in path:
            cycle_start = path.index(module)
            circular_deps.append(path[cycle_start:] + [module])
            return
        
        if module in visited:
            return
        
        visited.add(module)
        path.append(module)
        
        for dep in modules.get(module, []):
            dfs(dep)
        
        path.pop()
    
    for module in modules:
        dfs(module)
    
    return circular_deps
```

### 6.2 循环依赖解决

**解决方法**:

**方法1: 引入中间层**
```python
# 循环依赖
Module A → Module B
Module B → Module A

# 解决方案：引入中间层
Module A → Module C
Module B → Module C
```

**方法2: 依赖倒置**
```python
# 循环依赖
Module A → Module B
Module B → Module A

# 解决方案：依赖倒置
Module A → Interface
Module B → Interface
```

**方法3: 事件驱动**
```python
# 循环依赖
Module A → Module B
Module B → Module A

# 解决方案：事件驱动
Module A → Event Bus
Module B → Event Bus
```
