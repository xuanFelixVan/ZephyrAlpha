## 1. 数据源选择

| 数据源 | 定位 | 理由 |
|--------|------|------|
| **iFind终端** | 主数据源 | 5700+因子，机构级质量 |
| **同花顺SuperCommand** | 补充数据源 | 实时行情/选股 |
| **Baostock** | 免费财务验证 | 历史财务数据免费 |
| **AkShare** | 另类数据补充 | 宏观/非结构化数据 |

### iFind核心优势

- 财务报表指标完整（THS_BD系列）
- 因子库丰富（技术/财务/情绪）
- 机构用户基数大，数据质量高

## 2. 回测/实盘平台

| 平台 | 选择 | 理由 |
|------|------|------|
| **QMT (迅投)** | ✅ 主平台 | 国金证券QMT，深度API支持 |
| **Backtrader** | 备选/研究 | 轻量回测，快速验证 |
| **自研引擎** | 最终目标 | 完全可控的完整回测 |

### QMT核心能力

```
回测模式:
├── handlebar逐K线驱动
├── 本地数据回测（速度快）
├── 撮合规则可配置
└── 绩效报告自动生成

实盘模式:
├── 逐K线交易（模拟回测效果）
├── 立即下单（快速交易）
├── 订阅推送（事件驱动）
└── 定时任务（条件触发）
```

### 双回测平台架构

```
┌─────────────────┐    ┌─────────────────┐
│    Backtrader   │    │    VectorBT     │
│   (开发调试)     │    │   (批量优化)    │
├─────────────────┤    ├─────────────────┤
│  逐K线运行      │    │  向量化批量     │
│  断点调试       │    │  参数扫描       │
│  灵活定制       │    │  速度极快      │
│  策略开发期     │    │  策略成熟后     │
└────────┬────────┘    └────────┬────────┘
         │                          │
         └──────────┬─────────────┘
                    ↓
          ┌─────────────────┐
          │   策略信号池   │
          │   (统一输出)   │
          └─────────────────┘
                    ↓
          ┌─────────────────┐
          │   QMT 实盘     │
          └─────────────────┘
```

## 7. 为什么不选其他方案

| 选项 | 放弃原因 |
|------|----------|
| **QuantConnect** | 云平台，数据需上传，隐私风险 |
| **Backtrader作为主回测** | 与QMT实盘割裂，需双套代码 |
| **自建完整数据源** | 成本高，iFind已够用 |
| **复杂多智能体** | 过度工程，当前不需要 |

## 8. 关键技术决策

| 选择 | 理由 |
|------|------|
| **QMT为主** | 国金证券对接，Python API完善，回测实盘一致 |
| **iFind数据** | 5700+因子，机构级质量，数据直接可用 |
| **Qlib Alpha158** | 业界验证的AI因子库，减少自己造轮子 |
| **Streamlit** | 快速开发，AI辅助生成代码 |
| **DeepSeek/Qwen3** | 情感分析双引擎，降级策略完备 |
