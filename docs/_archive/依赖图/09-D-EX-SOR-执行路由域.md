## §6 关键设计决策

1. **SOR不直接H依赖D-RISK**：风控由EX-CORE做Pre-Trade检查，SOR只负责路由和执行
2. **Hot路径延迟目标<1ms**：T1真实资金阶段，核心路径需达到<1ms延迟(C++/Rust)
3. **FIX 4.2+协议**：券商对接用FIX协议，不直接使用券商自家API（降低耦合）
4. **路由决策可审计**：每条SOR决策必须留痕，支持事后复盘
5. **券商切换零中断**：Broker Adapter支持运行时切换券商(Feature Toggle)，不重启服务
6. **下单零重试(HB-07)**：下单操作不可自动重试，防止重复下单
7. **交易通道熔断必须人工恢复(HB-06)**：自动恢复可能导致状态不一致下的错误交易
8. **交易执行禁止走A2A(A2A-01)**：A2A协商延迟不可控，交易通道唯一性
9. **MCP交易执行Server不能建(QP-02)**：MCP协议安全生态未成熟
10. **下单执行使用编排式Saga(D-15)**：下单流程有严格顺序依赖和超时约束

## §8 安全架构约束

### 8.1 资产分类与信任等级

| 资产类型 | 信任等级 | 分类 |
|---------|---------|------|
| 交易指令 | 绝密（L3） | 核心资产 |
| 策略参数 | 绝密（L3） | 核心资产 |
| 持仓数据 | 机密（L2） | 敏感资产 |
| 订单状态 | 机密（L2） | 敏感资产 |
| 行情数据 | 内部（L1） | 业务资产 |
| 交易日志 | 机密（L2） | 敏感资产 |

### 8.2 数据流入规则

| 来源域 | 允许流入的数据 | 安全检查点 |
|--------|--------------|-----------|
| 数据域 | 行情数据、因子值、信号 | 数据签名验证+时间戳校验 |
| 治理域 | 审批通过的策略参数 | 审批令牌验证+策略签名 |
| 运维域 | 系统配置、密钥 | 配置签名验证+密钥加密传输 |

### 8.3 数据流出规则

| 目标域 | 允许流出的数据 | 安全检查点 |
|--------|--------------|-----------|
| 数据域 | 交易结果数据（脱敏后） | 数据降级处理+脱敏 |
| 治理域 | 交易审批请求 | 最小信息量原则 |
| 运维域 | 审计日志（仅追加） | 日志签名+哈希链 |
| 外部（合规报告） | 交易报告（监管要求） | 预定义格式+审批 |

### 8.4 安全控制要求

- 交易指令生成到提交的完整链路必须有签名链，任何环节篡改可追溯
- miniQMT连接凭证仅在交易域进程内可见，禁止跨域传递
- 交易域进程与其他域进程通过进程级隔离（Windows Job Object+受限令牌）
- 所有交易指令在提交前必须经过确定性校验（价格合理性、数量合规性、风控检查）

### 8.5 miniQMT接口加固

| 安全维度 | 实现 |
|---------|------|
| 连接认证 | 客户端证书+API Token双重认证 |
| 指令签名 | 每条交易指令附带HMAC-SHA256签名 |
| 指令限速 | 每秒最大指令数限制(10笔/秒) |
| 会话超时 | 交易会话30分钟无操作自动断开 |
| 传输加密 | TLS 1.3强制+证书固定(Certificate Pinning) |
| 进程隔离 | 交易进程gVisor容器隔离(当前最高可用)；Firecracker microVM需Linux KVM(②受限) |
| 密钥管理 | DK-TRADING保护交易指令和订单数据，月度轮换，非交易时段访问检测 |

### 8.6 关键Agent安全定义

- **关键Agent**：工具调用权限包含"提交交易指令"的Agent。路由Agent为关键Agent(HG级)
- 关键Agent高风险工具调用需人类审批或二次确认
- 关键Agent预算超限：非关键Agent达100%即暂停；关键Agent紧急模式可继续但受更严格频率限制
- SEC Rule 15c3-5市场接入规则6/6满足（预交易风控/Kill Switch/错误订单控制/独占控制权/CEO认证/供应商尽调）

### 8.7 PQC迁移约束

| 子项 | 裁定 | 门禁 |
|------|------|------|
| 混合模式加密 | ①可建 | 密钥交换/签名使用混合模式，交易指令延迟影响<5ms |
| 纯PQC模式 | ②受限 | GATE-PQC: miniQMT/iFind接口不支持PQC+PQC库成熟度不足+监管未要求 |

## §13 执行算法框架

### 13.1 Almgren-Chriss最优执行框架

| 参数 | 定义 | 默认值 |
|------|------|--------|
| 临时冲击η | 交易速率的线性冲击系数 | 历史冲击回归估计 |
| 永久冲击γ | 累积成交量的线性冲击系数 | 历史冲击回归估计 |
| 风险厌恶λ | E[cost]+λ×Var[cost]中的系数 | Trader设定；λ=0→TWAP, λ→∞→前端加载 |
| 参与率上限 | 单笔订单占ADV的比例 | ≤15%(超则否决+拆分) |

### 13.2 日内时变参与率

| 时段 | 成交量占比 | 建议参与率上限 | 冲击成本倍数 |
|------|:---------:|:-------------:|:-----------:|
| 开盘(9:30-10:00) | ~20% | 15% | 0.8x |
| 上午(10:00-11:30) | ~25% | 10% | 1.2x |
| 午盘(13:00-14:00) | ~10% | 5% | 2.5x |
| 尾盘(14:00-15:00) | ~45% | 15% | 0.7x |

> 时变参与率可降低执行成本15-25%。Almgren-Chriss框架本身支持时变执行速率。

### 13.3 成本模型

| 成本类型 | 模型 | 参数 |
|---------|------|------|
| 市场冲击 | 平方根冲击模型(Almgren-Chriss简化) | 冲击成本=σ×√(订单量/日均成交量)×参与率系数 |
| 滑点 | 固定滑点+与波动率成比例的动态滑点 | 基础滑点0.05%；动态=0.1×日波动率×√(订单量/日均成交量) |
| Intraday Round-trip Trading(做T)额外成本 | 做T滑点×2(买+卖)+做T失败风险溢价 | 做T滑点基准0.1% |

### 13.4 日历约束对执行的影响

| 约束类型 | 对执行的影响 |
|---------|-------------|
| 交割日效应 | 尾盘流动性降级→TWAP替代VWAP |
| 财报季约束 | 限价单替代市价单 |
| 节假日效应 | 参与率控制更保守(<10%) |
| 月末/季末效应 | 参与率控制更保守 |

### 13.5 市场微观结构建模

| 建模维度 | 方法 | 应用 |
|---------|------|------|
| 订单流毒性(VPIN) | VPIN>阈值→暂停买入执行 | 风控监控层额外输入 |
| LOB不平衡度 | 买盘深度vs卖盘深度→短期价格方向 | 调整Almgren-Chriss参与率 |
| LOB恢复速度 | 大单吃掉后多久恢复→恢复慢=冲击成本高 | 流动性评估 |
| Hawkes过程 | 订单到达的自我激发和交叉激发→预测短期订单流 | 执行时机优化 |
| 做市商行为推断 | 订单簿中大单的挂单/撤单模式分析 | 短期价格承压预判 |

> Level-2数据需求：当前miniQMT提供Level-1(3秒Tick)；Level-2(逐笔委托+逐笔成交+十档行情)需券商额外权限，当前未开通。无Level-2时用Level-1的3秒Tick近似LOB不平衡度。

### 13.6 RL最优执行(增强Almgren-Chriss)

| 维度 | 设计 |
|------|------|
| 核心思想 | Almgren-Chriss=基线执行轨迹；RL=在基线上微调学习更优执行 |
| 状态空间 | 未完成订单量+当前价量+订单簿深度(L2) |
| 动作空间 | 本次发送的订单量/价 |
| 奖励函数 | Implementation Shortfall(执行价vs决策价) |
| 算法 | DQN(离散动作)/PPO(连续动作) |
| 安全约束 | RL不可偏离Almgren-Chriss轨迹超过阈值 |

## §14 执行风险约束

### 14.1 LVaR流动性调整VaR四级模型

| 模型 | 公式 | 适用场景 |
|------|------|---------|
| LVaR(价差模型) | LVaR = VaR + ½×S×W | 正常市场+小仓位 |
| LVaR(Amihud冲击模型) | LVaR = VaR + ILLIQ×(Q/V)^α | 大仓位+非标资产 |
| LVaR(EVT尾部模型) | LVaR = VaR + EVT_尾部流动性溢价 | 极端行情+流动性枯竭 |
| CoVaR跨市场传染 | CoVaR^(j\|i) = 条件VaR(给定i机构压力) | 系统性流动性风险 |

### 14.2 流动性降级模式

| 流动性等级 | 条件 | VaR处理 | 溢价 |
|-----------|------|---------|:---:|
| 正常 | 退出时间≤1天 | 标准LVaR | 0% |
| 降级 | 退出时间1-3天 | VaR+0.5%溢价 | +0.5% |
| 极端 | 退出时间>3天 | 退化为标准VaR+1%溢价+强制减仓 | +1.0% |

### 14.3 流动性螺旋防护

| 螺旋阶段 | 信号 | 系统响应 | 硬约束 |
|---------|------|---------|--------|
| 阶段1:价差异常 | 买卖价差扩大>2倍+成交量萎缩>30% | 参与率收紧至5%+暂停做T | 不可Distressed Selling(追跌卖出) |
| 阶段2:强制卖出 | 两融余额单日降>10%+融资保证金上调 | 降杠杆敞口+暂停融资标的 | 保证金覆盖率<120%→强制降杠杆 |
| 阶段3:流动性冻结 | 成交量<日均10%+买卖价差>10倍 | Kill Switch(P0) | 全系统暂停 |

> 止损减仓允许(风控减仓)，策略Distressed Selling(追跌卖出)禁止。

### 14.4 策略容量估算

策略容量=f(ADV, 参与率上限, 换手率, 冲击成本容忍度)。Grinold & Kahn容量公式。容量超限→Sharpe衰减非线性+冲击成本指数增长+策略失效。容量预警线=估算容量×80%→预警；AUM超容量→否决新资金接入。

### 14.5 风险否决权执行

| 设计要素 | 实现 |
|---------|------|
| 同步拦截 | 否决规则引擎在订单执行入口同步执行，延迟<50ms(P99) |
| 不可绕过 | 所有下单指令必须经过否决规则引擎，无旁路(HC-RISK-03) |
| Pre-Trade硬前置(CP-06) | Pre-Trade是下单硬前置，Fail-Closed |
