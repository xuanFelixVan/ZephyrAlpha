02

第一性原理：为什么是钟摆错了，而不是门禁错了

命题一 · 约束穿透
结构约束不该变成可用性约束
容量 gate 的职能是防「线性增长无封顶型目录」的结构卫生，120 这个数字本身无治理语义。顶格即全员阻断，把结构问题转嫁为每一次提交的可用性问题——约束穿透到无关提交人是最坏失败模式。B5 系列已治「外来 staged 连坐」，但「目录顶格全员阻断」是同一病根的第二张脸。
命题二 · 本质定位
_working = 跨会话短期记忆，必须流动
git tracked 的意义 = 防删除潮丢失（#ARCH-311 实证），不是永久冻结。二者合成的正确形态是「低频写入、必须流动」的耐久化暂存；只进不出的沉淀池必然顶格。
命题三 · 钟摆定律
矫枉过正 = 把 A 事故换成 B 事故
「误杀 → 全禁」是治理最常见钟摆。全禁把风险从「低频误删」平移到「确定性堵塞」，后者 24h 内就兑现了 300+ 次提交堵点。正确解不是二选一，是带豁免与可逆性的中间机制。
命题四 · 100% AI 开发特化
AI 会话的写入速率是人肉仓库的百倍
每会话每任务都产交接文档，人肉开发的「随手归档」习惯不存在——AI 不做记忆整理，只做记忆追加。生命周期必须机制化（TTL + 豁免集），不能依赖任何会话的自觉。

外部实践对照（17 条证据的核心样本）

来源机制对本项目的映射
actions/stale（GitHub 官方）TTL 两阶段：60 天标记 → 7 天处置，活动即重置，豁免标签保护在途件预警先于阻断；豁免集先于 TTL 判断
OpenHands SDK AGENTS.md.pr/ 临时区「intentionally temporary」，PR 批准即自动清除归档绑事件（会话收尾），不绑数量

qlib + MLflow实验记录走仓库外 tracking 系统；逻辑删除 + gc 两阶段可逆清理软归档（可逆）→ 宽限 → 处置
NIH ELN 政策Active → Inactive → 处置；按引用价值而非单纯年龄定保留结论性报告长留，交接件短留
curl 黄金法则 / dev.to 文档宪法「价值 > 审查成本才收」；无真实决策不配入库_working 收录门槛：只收跨会话件
Obsidian Simple Archiver规则引擎：年龄 + 名称 regex → 镜像归档路径，定时评估 + 补跑日期前缀命名天然支持自动判龄
Scala3 LLM_POLICY源头披露制，元数据让下游判定自动化不加新元数据负担，沿用现有 frontmatter
跨社区最大公约数：三段式 = 源头只收耐久产物 → 到期软归档冷区 → 宽限后处置，且前两段必须可逆。 开源界未发现任何「数字文件数上限 + 顶格全面阻断」先例（Chromium/LLVM/AOSP 检索均空）——容量上限作为唯一硬闸门属于本项目原创的反模式。 完整 17 条及全部来源 URL 见归档证据两份（evidence 档案）。
04

裁定五条（登记于 ruling_registry #234）

①
TTL 软归档基线（修正 641c343632 极端）
task_bound 交接文档按未修改天数计龄，默认 30 天到期移入 docs/_working/archive/YYYY-MM/（区内镜像，沿既有惯例）。只移动不删除、git 历史天然保留、ops_guard 回收站兜底——彻底继承 auto-delete 治理裁定的防误杀设计。「tracked 永不归档」修正为「tracked 到期可归档」。
②
豁免集（判断先于 TTL）
permanent frontmatter ∪ protected_subdirs 禁区（design_memos/、04_architecture_principles_decisions/）∪ 7 天内活跃 WIP——与 actions/stale exempt-labels 同构，统筹/裁定真源永不被自动触碰。
③
容量语义重定义：告警线 + 断路器
120 保留为双角色：≥110 预警提示 housekeeping；硬阻断收窄为「顶格目录的新增类 staged 文件」——存量 modified/deleted 提交不再被顶格连坐（与 B5-1 own-scope 化互补）。施工细节按 fail-open 实现登记 #234.1。
④
源头减量（长期）
过程性产物默认落 .runtime/sessions/<sid>/staging/（24h TTL 已有），docs/_working 只收需跨会话/跨天存活的交接件。日期前缀命名已保证年龄可自动判定，不新增元数据负担。
⑤
执行序：裁定先行、施工分离
本轮登记语义；TTL 归档执行器（doc_lifecycle tracked-mode 扩展）= #234.1、gate 预警带/断路器收窄改造 = #234.2，登记为后续债由下一 housekeeping 会话承接。
