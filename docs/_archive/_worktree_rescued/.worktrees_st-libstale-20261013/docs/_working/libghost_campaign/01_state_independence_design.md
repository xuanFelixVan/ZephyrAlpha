# `lookup state` 三源独立性改法与正对照设计（方案③，未落地）

提出班：st-libstale-20261013（2026-10-13 夜→10-14 凌晨）。性质=**方案件**：本批不改一行业务码，
`state` 面判据数值/语义变更属复杂面，留 Owner 终裁后另批施工。

## 1. 病根（本班实测，非推演）

| # | 实测事实 | 证据 |
|---|---|---|
| F1 | 在册负存在探针串查下来 **rc=0**，`sources-with-hits: 2/3` | `python -m zephyr.library.lookup state "<XYZQ 探针串>"` 两次复跑（23:3x 主区），E1 |
| F2 | 换成毫不相干的纯噪声串（含英文常见词）同样 **rc=0**，源② 抓出 10 条不相干提交 | 同命令形态复跑，E1 |
| F3 | 源②的 `channel:paths` **不独立**：它拿源③命中的文件反查落库提交 | `src/zephyr/library/lookup.py:498-520`（docstring 自述"源③命中文件的落库提交"+`dir_hit_paths` 入参） |
| F4 | 逐词拆分使常见词乱命中：`_state_words` 仅按空白拆词，无停用词/无频次闸 | `lookup.py:414-421`＋`:505-507`（pickaxe/grep 均"逐词补充"） |
| F5 | 文档自指：探针字面串被写进战役交付文档，而源③ 正好扫 `docs/_working` | `docs/_working/examcard_campaign/99_delivery.md:44` 与源③ 扫描根 `lookup.py:66-67` |
| F6 | rc 语义=任一源命中即 0（保守方向对，但把"无法证伪"与"有证据"混成同一个 0） | `lookup.py:796` `return 0 if sources_with_hits else 1` |

一句话：**现在的 `state` 能证明"命令跑得通"，不能证明"某能力不存在"，而门面（FRONT_DOOR 六单口
第 6 行）把它当成后者卖给 agent。** 这恰是本仓最怕的幻觉形态——agent 拿一个恒给绿灯的尺去下
"没做过"的结论。

## 2. 目标契约（改完必须能回答的问题）

`lookup state X` 的输出必须让调用方分清四态，且每态有独立退出码：

| 退出码 | 语义 | agent 允许的结论 |
|---|---|---|
| 0 | 存在性证据成立（≥1 源给出**非自指**的落地证据） | "X 存在/已做"，并须引具体锚 |
| 1 | 三源全零且**负对照通过** | "在本仓当前面与 90 天历史内查无 X"——可作负存在断言 |
| 2 | 某源不可达（DB/git 故障） | 不得下任何结论，只能报"尺没通电" |
| 3 | **尺自判失真**（负对照命中了本不该命中的东西） | 不得下任何结论，须上报尺坏 |

第 4 态是本方案的核心新增：现在"尺坏"与"查无"同形（都是零命中/都是非零 rc），
这正是本仓在册事故形态"静默降级看起来像未触发"。

## 3. 改法（四条，逐条可独立回退）

### 3.1 源独立性：把"派生通道"从计分里摘出去

- 源②保留两通道：`channel:pickaxe`（-S 全串）与 `channel:grep`（--grep 全串）；
  `channel:paths` 改为**只展示不计分**，并在行尾标 `[derived-from-source-3]`。
- `sources-with-hits` 计数改为 `独立源命中数/3`，派生通道不参与分母。
- 效果：F1 的 "2/3" 会降为 "1/3（且为自指源）"，见 3.3 后为 0/3。

### 3.2 停用词与频次闸：阈值不发明，从仓库现算

- 词表来源=**本仓自测**：对候选词 w，用 `git log --since=90.days --oneline | grep -c w` 与总提交数求
  命中率 `p(w)`；`p(w) ≥ 1/总提交行数开根`（等价于"命中面过宽"）的词判为无判别力，逐词通道不用它。
- 为什么这样定：任何写死的停用词表在这个体量的中英混排仓里都会过期；现算的成本=一次性
  `git log --oneline` 读入 + 内存计数（≈10 万行量级，亚秒）。
- ⚠ 这里是**判据数值面**（`p(w)` 的定义式），须 Owner 认可后落地；本班不动码。

### 3.3 自指控制串集中登记 + 引用/存在二分

- 新增一册（建议 `docs/01_policies_and_standards/_registry/catalogs/library_state_controls.yaml`）：
  登记全部"控制用字符串"（正对照 P+ 的锚、负对照 P− 的 token），字段含 `token/kind/expected`。
- 源③与源②匹配到的行若命中物∈控制串册，则归类为 `citation`（有人在讨论这个串），
  不计入 `existence` 证据；输出分区显示"仅引用面 N 条"。
- 现有三处已把探针字面串写进散文（`99_delivery.md:44` 及其更正行、`lookup.py:407-409` 注释、
  测试夹具）——施工时一并改为引用控制串册，不再复制字面串。

### 3.4 正/负对照内置，每次自检都跑

```
P+（已知存在）：state <控制串册里 kind=positive 的锚，如 src/zephyr/library/lookup.py>
   期望：rc=0 且 源①命中 且 盘面存在
P−（已知不存在）：state <kind=negative 的随机 token，登记时校验盘上与 HEAD 均无>
   期望：rc=1 且 三源全 -- no hits --
任一不符 ⇒ 本次运行改口 rc=3 + "ruler unreliable" 行，绝不把"尺坏"报成"查无"或"查到"
```

- 落地位置：`lookup_state()` 收尾处加一次成对自检（成本≈2 次子查询，实测 state 面主要耗时在
  git log 全串扫描，90 天窗口；本班实测一次 state **>3 分钟**，见 §5），
  或提供 `--selfcheck` 由测试与 CI 调用，避免每次交互都付双倍 git 成本。
- 在册教训对照：这条正是"0 命中尺必须先用在册已知命中件做正对照"的门面化——
  我以前靠自己想起来，尺自己想不到。

## 5. 本班实测的两条硬约束（施工前须认）

1. `state` 面**慢**：一次三源查询实测 >180 s（源② 的 `git log --all -S` 逐词扫 90 天）。
   任何"每次调用都跑双对照"的设计在交互形态上不可用；建议源② 先做单次 `--grep` 全串、
   逐词仅在 `--any-word` 显式旗下降级使用，把最贵的一路变成可选。
2. `state` 面无执法消费者：全仓只有文档把它当单口卖，没有任何门或链读它的 rc。
   ⇒ 改它不产生连坐风险，但也意味着**改完不会有人自动发现它坏**——所以 3.4 的内置对照是
   本方案的承重墙，不是可选装饰。
