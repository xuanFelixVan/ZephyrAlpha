# 裁定书：C3 翻译管道化论证——结论=不宜全自动，保持 AI 会话逐件翻译（交接清单⑩）

> 2026-09-15｜session=st-autopipeline-20260915｜自裁定协议授权=Owner 2026-09-15 03:37 令（"全部施工不停歇、不提问、自裁定"；无法裁定的才登记+跳过——本项可裁定，故出裁定书而非挂起）。

## 分析过程（第一性原理+业界对照+项目实证）

1. **管线自动化的边界判据**：一个环节可全自动，当且仅当它的正确性可以被机器验证。C4 批测正确性=引擎契约（build 签名/窗口/成本）+DSR 数学；C5 聚类=ρ 矩阵可复算；C6 入库=三轴+only-add 断言。**C3 翻译的正确性=语义等价**（聚宽源码→本引擎语义一致），这是开放问题：同一源码两种翻译都对，机器无法从产物本身判定"没翻丢一个止损条件"。
2. **实证证据（BacktestBench, SIGKDD 2026）**：LLM 回测能力评估准确率 67%——三分之一的"翻译/实现判断"是错的。方案真源 §1 已据此把"LLM 直接生成策略自动入册"滤为 noise；同一证据以更大力度适用于"LLM 全自动翻译、无人复核"。
3. **本项目防线不可让渡**：C3 现行件带三道语义防线——①聚宽 API shim（执行语义 T+1/手数/涨跌停显式映射）②**知识生效日哨兵 D120**（翻译件声明写成日 vs 回测窗口起点，防知识漂移——S3 预检在 c4_batch_screen 每批必跑）③build 契约+run 档案可溯。三道防线的共同前提=**有一个对源码负责的翻译主体**（AI 会话逐件读过原文）。全自动翻译流水线若靠 LLM 无人值守跑批，哨兵声明本身就成了无人背书的自说自话（D120 是"声明制"，声明者的可靠性=防线本身）。
4. **量化社区先例**：聚宽/掘金社区翻译迁移、开源因子库（qlib-alpha158 等）移植均是"人工逐件+批测兜底"，无"全自动翻译批"成功先例；worldquant-miner 类全自动生成器全部依赖平台侧统一 API（等价于我们的 shim），且仍设提交审核门。
5. **ROI 核算**：C3 是漏斗最大瓶颈（600→150），但每件翻译的边际成本=一次 AI 会话（分钟级 token），而全自动化的前置投入=覆盖聚宽 API 全集的语义验证器（工程量≫当班施工预算，且验证器本身又需翻译正确性背书——循环依赖）。**瓶颈的正确解法=并行增加会话供给，不是无人值守**。

## 裁定结果

1. **C3 保持人工/AI 会话逐件翻译**，不建全自动翻译流水线；每件仍须：shim 语义映射+D120 哨兵声明+build 契约三件套。
2. **管道化的正确形态=已建成的"检测-批测自动链"**（本班 MOD-BT-190/076 接线）：翻译件落盘→积压扫描（c4_batch_due）→`--auto-only` 批测→及格件自动进 C5/C6（run_intake_auto）。C3 之后的全部机械环节零人工；C3 本身=唯一保留的会话作业面。
3. 供给扩容建议（登记不在本班施工）：多会话并行翻译+批量试点（SOP-C §3 定稿 D3 试点规则不变）。
4. **净零声明**：本裁定书=交接清单⑩"论证"任务的交付物，不新增常设规范对象；替代对象=本清单⑩原文（人工论证悬案）。

## 消费方式

下一班/未来会话不得在本裁定未撤销前，把"全自动翻译"立项施工；若 LLM 评估能力出现量化级进步（如 BacktestBench 级准确率 ≥95% 的本地评估器），本裁定自动进入复审议题（届时以数据推翻本件）。
