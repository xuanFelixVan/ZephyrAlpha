# ZephyrAlpha 元标准宪法

> PS-STD-000 | v2.0.2 | active | ZephyrAlpha 最高层级元规则

本标准定义的不是"规则是什么"，而是"规则怎么分类"——什么规则有资格进入宪法，什么规则只能放在登记表。

**铁律**：分类标准 MUST 绝对二元——不是 A 就是 B，没有中间态。否则 AI 在写入规则时自行判断分类 → 宪法膨胀或关键规则遗漏。

**分类标准**：**后果不可逆性**——违反后后果不可逆 → 宪法层（ABS）；违反后后果可逆 → 登记表层（COND/REC/CODE）。

---

## 1. 宪法地位

本标准是 ZephyrAlpha 所有元标准（PS-STD 全系列）的前提。

- PS-STD-001（字段注册表）定义规则怎么写
- PS-STD-002（文档格式标准）定义规则文档怎么排版
- PS-STD-003（行为边界标准）定义规则的内容（ABS/COND/REC）
- PS-STD-004（规则分类标准）定义规则的维度（Domain/Layer/Scope/Stability/Executor）
- **PS-STD-000（本标准）定义规则的归属——什么进宪法、什么进登记表**

本标准的优先级高于所有其他 PS-STD。当本标准与其他标准冲突时，以本标准为准。

> 注：本标准创建于 `../governance/document/document-control-policy.md`（GOV-DOC-009）DOC-004（完整路径引用）之前。§1 中的 module_id 引用和 §3 中的相对路径引用属于历史遗留格式，功能等价于完整路径引用。后续修订时统一更新。

## 2. 二元分类标准：后果不可逆性

### 2.1 判定问题

对每条规则，问一个二值问题：

> **"如果这条规则被违反，后果能否通过后续操作完全消除？"**
> - **NO（不可逆）** → 宪法层
> - **YES（可逆）** → 登记表层

### 2.2 为什么是"不可逆"而非"严重"

| 候选标准 | 问题 | 结论 |
|---------|------|------|
| 后果严重性 | "多严重算严重？"——程度判断，不是二元 | ❌ 有灰色地带 |
| 自动化可执行性 | "代码级强制 = 宪法？"——但 ABS-03/04/11-13 目前是人工验证 | ❌ 与实际不符 |
| 可审核性 | "外部审核依据？"——ZephyrAlpha 不面临外部认证 | ❌ 不适用 |
| **后果不可逆性** | "可逆/不可逆"——天然二元，无需程度判断 | ✅ 无灰色地带 |

### 2.3 不可逆的判定规则

| 后果类型 | 是否不可逆 | 示例 |
|---------|:---------:|------|
| 数据永久丢失 | 不可逆 | 删除审计日志、删除锚点文件 |
| 信息永久泄露 | 不可逆 | 密钥进入 git 历史、敏感数据泄露到外部 |
| 资金永久损失 | 不可逆 | 交易系统失控、风险检查被绕过 |
| 治理体系永久失效 | 不可逆 | AI 自主修改宪法、规则冲突无法仲裁 |
| 安全防护永久突破 | 不可逆 | Prompt Injection 成功、沙箱被绕过 |
| 文件被重命名 | 可逆 | 改回来即可 |
| 配置被错误修改 | 可逆 | 回滚到上一个版本 |
| 代码审查未通过 | 可逆 | 修改后重新提交 |
| 日志格式不规范 | 可逆 | 修正格式即可 |

### 2.4 条件性不可逆

部分规则的后果是否不可逆取决于**触发条件**：

| 规则 | 默认状态 | 触发条件 | 触发后 |
|------|:-------:|---------|:-----:|
| 部署未经测试的代码 | 可逆（开发环境） | 部署到**生产环境且代码被执行**时 | **不可逆** |
| 绕过 kill switch | 可逆（模拟环境） | **交易系统运行**时 | **不可逆** |
| 审计日志未启用时执行关键操作 | 可逆（非关键操作） | 执行**关键操作**时 | **不可逆** |
| AI 访问超出任务所需的文件 | 可逆（非敏感文件） | 访问**敏感数据**时 | **不可逆** |

**判定规则**：如果一条规则在**任何触发条件下**后果不可逆，则该规则归入宪法层。

## 3. 宪法层与登记表层的定义

### 3.1 宪法层（Constitution）

| 属性 | 值 |
|------|-----|
| 存储位置 | `meta/behavior-boundaries-standard.md`（PS-STD-003） |
| 内容 | 所有 ABS 条目 + 条件性不可逆的 COND 条目 |
| 判定标准 | 违反后后果不可逆（包括条件性不可逆） |
| 修改门槛 | Owner 批准 + ADR |
| AI 权限 | `immutable_core`——AI 禁止自主修改 |
| 编号体系 | ABS-XX |
| 加载策略 | **热记忆（Hot Memory）**——会始终在 AI 系统提示中。对应 CR-010（P0）：Session 活跃时治理规则和门禁规则必须 always loaded |

### 3.2 登记表层（Registry）

| 属性 | 值 |
|------|-----|
| 存储位置 | `_registry/catalogs/rule-registry.md`（PS-REG-001）+ 各领域规则文件 |
| 内容 | 所有 COND 条目（后果可逆的）+ REC 条目 + CODE 条目 |
| 判定标准 | 违反后后果可逆（可通过后续操作完全消除） |
| 修改门槛 | 领域规则负责人批准 |
| AI 权限 | `human_gated`——AI 可提议修改，需 Owner 批准 |
| 编号体系 | COND-XX / REC-XX / CODE-XX / {域代码}-XX |
| 加载策略 | **领域触发（Domain-Triggered）**——按任务类型加载。对应 CR-005（P1）：新任务时 2 轮内预加载相关文档。CR-011（P2）：只加载相关架构层的上下文 |

### 3.3 层级关系与加载策略

| 层级 | 存储 | 编号 | 加载策略 | CR 规则 |
|------|------|------|---------|---------|
| PS-STD-000 元标准宪法（本文件） | 本文件 | — | 热记忆（always loaded） | — |
| PS-STD-003 行为边界标准（宪法内容） | `behavior-boundaries-standard.md` | ABS-XX | 热记忆 | CR-010（P0） |
| PS-REG-001 规则登记表（登记表内容） | `_registry/catalogs/rule-registry.md` + 各领域规则 | COND/REC/CODE/{域}-XX | 领域触发 + 冷记忆 | CR-005（P1）+ CR-006（P2）+ CR-011（P2） |

> 宪法层 ABS 编号为全局唯一前缀。领域级操作控制原则使用各自领域前缀（如 GOV-DOC-009 用 DOC-001~DOC-008，PS-STD-011 用 MTH-001），与 ABS 编号全局不冲突。详见 [PS-STD-003](behavior-boundaries-standard.md) §3.4 编号注册表。

> **三层记忆模型**：热记忆（宪法，always loaded）→ 领域触发（领域规则，按任务加载）→ 冷记忆（知识库，按需检索摘要）。宪法热记忆稳定在 ~400 行以下（社区验证上限），超过此阈值开始降低 AI 遵循度。加载规则完整定义见 [session-state-runbook.md](../operational/vibe_coding/vibe-coding-session-state-runbook.md)（CR-005/CR-006/CR-010/CR-011）。

## 4. 分类判定流程

| 步骤 | 问题/操作 | 结果 |
|------|---------|------|
| 1 | 违反此规则后，后果能否通过后续操作完全消除？ | — |
| 1a | NO（不可逆） | → 步骤 2 |
| 1b | YES（可逆） | → 步骤 3 |
| 2 | 不可逆 → 宪法层 | 写入 PS-STD-003 §3，编号 ABS-XX，同时在 PS-REG-001 对应域中登记 |
| 3 | 可逆 → 登记表层 | 写入 PS-REG-001 对应域，按类型编号 COND-XX / REC-XX / CODE-XX；条件禁止在领域规则中定义触发条件 |

### 4.1 边界案例处理

| 边界案例 | 判定 | 理由 |
|---------|------|------|
| 不确定是否可逆 | 归入宪法层 | 举证责任在"可逆"方——不确定 = 不可逆 |
| 当前阶段可逆、未来可能不可逆 | 归入宪法层 | 按最高风险阶段判定 |
| 代码级强制但后果可逆 | 归入登记表层 | 不可逆性是唯一标准，与强制方式无关 |
| 文档级声明但后果不可逆 | 归入宪法层 | 不可逆性是唯一标准，与强制方式无关 |

## 5. 本标准的不可变性

### 5.1 不可变条款

以下条款为 `immutable_core`，修改需 Owner 批准 + ADR：

- §1.1 框架原则（COBIT 2019 对标）
- §2 二元分类标准（后果不可逆性）
- §3 宪法层与登记表层的定义
- §4 分类判定流程
- §5 本标准的不可变性

### 5.2 可变条款

以下条款可由 Owner 批准后修改（不需要 ADR）：

- §2.3 不可逆的判定规则（可扩展新案例）
- §2.4 条件性不可逆（可扩展新条件）

### 5.3 修改流程

| 修改类型 | 审批要求 |
|---------|---------|
| 修改分类标准本身（§2.1） | Owner 批准 + ADR + 90 天过渡期 |
| 修改宪法层/登记表层定义（§3） | Owner 批准 + ADR |
| 新增不可逆判定案例（§2.3） | Owner 批准 |
| 新增条件性不可逆条件（§2.4） | Owner 批准 |

### 5.4 纵深防御（Defense in Depth）

| 设计原则 | 内容 |
|---------|------|
| **距离递减遵从** | 同一文件中越靠后的规则越容易被 AI 忽略。宪法 §2（分类标准）放在文件前部，§6（一致性校验）是事后参考，布局符合此规律 |
| **纵深防御** | 一条值得强制执行的约束至少应在两个位置声明。§2 的结果应至少出现在 AGENTS.md 或 `.cursor/rules/core-governance.mdc` 中作为引用点。单一宪法文件丢失不应导致治理体系失能 |
