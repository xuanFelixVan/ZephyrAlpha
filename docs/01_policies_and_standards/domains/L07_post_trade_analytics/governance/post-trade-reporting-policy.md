# 盘后报告策略

> module_id: DOM-L07-001 | version: 0.1.0 | status: draft | layer: l07_post_trade_analytics

---

## 1. 目的与范围

本策略定义 ZephyrAlpha 系统盘后必须产出的报告。适用于：

- 交易执行报告
- 策略绩效报告
- 风控合规报告
- 数据质量报告

## 2. 报告类型与产出时限

### ABS-001：盘后报告必须在规定时限内产出

| 报告类型 | 产出时限 | 格式 | 分发对象 |
|---------|---------|------|---------|
| 交易执行日报 | T+0 18:00 前 | Markdown + CSV | Owner |
| 策略绩效日报 | T+0 19:00 前 | Markdown + 图表 | Owner + 策略团队 |
| 风控合规日报 | T+0 19:30 前 | Markdown | Owner + 合规团队 |
| 数据质量日报 | T+0 17:30 前 | YAML | Owner + 数据团队 |
| 周度综合报告 | T+0 周五 20:00 前 | Markdown + PDF | Owner |
| 月度审计报告 | T+3 月初 | Markdown + PDF | Owner + 审计团队 |

### ABS-002：报告必须包含关键指标

每类报告必须包含以下关键指标，禁止省略：

| 报告类型 | 必须包含的指标 |
|---------|-------------|
| 交易执行日报 | 成交量、成交额、滑点、执行率、异常交易 |
| 策略绩效日报 | 日收益率、累计收益、夏普比率、最大回撤、因子贡献 |
| 风控合规日报 | 限额使用率、止损触发次数、敞口变化、合规检查结果 |
| 数据质量日报 | 数据源状态、缺失率、延迟率、异常值检测 |

### ABS-003：超常规事件必须触发即时报告

以下事件发生时，不等待定时报告，必须在事件发生后 30 分钟内产出 ad-hoc 即时报告：

| 触发事件 | 报告内容 | 通知级别 |
|---------|---------|---------|
| Kill Switch 触发 | 触发原因、当前持仓、净值影响 | P0 立即通知 Owner |
| 单日回撤 > 5% | 回撤来源、策略明细、市场关联 | P1 |
| 策略跌停无法平仓 | 持仓明细、预期亏损、应急预案 | P1 |
| 数据源核心级故障 | 故障数据源、影响策略、恢复预估 | P1 |

## 3. 质量标准

### COND-001：报告数据必须可追溯

所有报告中的数据必须可追溯到原始数据源：

- 报告中每个数字必须标注数据来源
- 数据血缘链路完整（参见 GOV-DATA-002）
- 报告生成时间戳精确到秒
- **追溯粒度**：数据必须可追溯到原始订单 ID（交易执行）、原始行情 tick（收益计算）、风控事件 ID（风控统计）

## 4. 分发规则

| 分发方式 | 适用场景 | 时效要求 |
|---------|---------|---------|
| 飞书消息 | 日报摘要 | 产出后 5 分钟内 |
| 文件存储 | 完整报告 | 产出后立即 |
| 告警通知 | 异常报告 | 产出后 1 分钟内 |

### COND-002：报告分发必须遵循最小权限原则

| 角色 | 可见范围 | 说明 |
|------|---------|------|
| Owner | 全部报告 | 最高权限 |
| 策略团队 | 仅可见所管策略的绩效报告 | 不能跨策略查看 |
| 数据团队 | 仅数据质量报告 | 不能查看交易和风控数据 |
| 合规/审计团队 | 风控合规 + 月度审计报告 | 不包含策略 Alpha 细节 |

分发权限与分发频率通过 `report-access-control.yaml` 管理（参见 GOV-SEC-001）

## 8. AI 可消费性声明

- 本文件所有规则以 `### ABS-NNN：` 和 `### COND-NNN：` 格式声明，AI 可通过正则自动提取
- 所有时限和质量标准以 Markdown 表格形式定义，AI 可解析为自动化管线配置
- 本文件的 `ai_autonomy: human_gated`——AI 可提议修改报告策略，需 Owner 审批后执行
- 本文件的 `stability: evolving`——内容可能频繁变更，AI 每次 session 应重新读取
- 本文件的 `verifiability: manual`——报告质量的最终验收由 Owner 人工完成

## 9. 禁止行为

| # | 禁止 | 原因 |
|---|------|------|
| 1 | 禁止延迟产出定期报告（日/周/月/季报） | 违反 ABS-001——SLA 时限不可逾越 |
| 2 | 禁止报告数据缺失率 > 5% | 违反 ABS-002——完整度不达标报告不可分发 |
| 3 | 禁止超常规事件发生后 30 分钟内未产出即时报告 | 违反 ABS-003——超常规事件必须即时报告 |
| 4 | 禁止未经权限审批分发给非授权收件人 | 违反 COND-002——Tier 3 报告不在默认分发范围 |
| 5 | 禁止连续 2 次报告质量不合格不清退管道 | 违反 COND-001——连续不达标必须暂停管道 |
