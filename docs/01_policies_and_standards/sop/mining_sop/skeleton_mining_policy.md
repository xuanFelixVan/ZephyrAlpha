# 骨架构建 SOP——域骨架的挖掘与建立（真源）

> **一句话**：任何新域开工前 MUST 先挖骨架——骨架=该域的路由表+完整性计分板+防腐对象；**骨架缺失则后续一切工作缺失**（重复建源/漏建/无收敛基准/状态盲区）。挖骨架本身是一套可制度化的流程，不是随缘聊天。
> **诞生**：2026-09-17 数据骨架六批迭代（72→95→108→110→114→115 中类）的方法论沉淀；Owner 定调「骨架必须先挖根——骨架缺失，我们后续的所有工作都会缺失」。
> **亲缘**：[mining_sop_policy.md](mining_sop_policy.md) = 通用挖矿方法论（六向寻路/防噪音四闸适用于本件 §4，本件=分类学挖矿专用实例）；[data_source_onboarding_sop.md](../data_ops_sop/data_source_onboarding_sop.md) §2 = 中类级数据源挖矿（本件 ⬜ 的下游消费者）；construction_workflow_policy = 骨架 ⬜→数据集的施工闭环准入；altdata_line/90 收敛判据 = 骨架产出物的评分消费端。
> **实战范例（方法论唯一完整实例）**：docs/_working/altdata_line/01_data_type_skeleton.md（六批批次记录+三扫判据+分类学纪律全文）。

## §1 骨架三律（是什么/不是什么）

1. **路由表**：一个 ⬜ 条目 = 一次挖矿/施工会话的入口；查重先查骨架——防重复建源。
2. **计分板**：覆盖度可度量（✅+🔨 占比），收敛与立项时有据可依。
3. **防腐对象**：拆分有停止判据（§3）、封顶有声明（§6）、状态标记有纪律（§5）。
- **反面（骨架不是什么）**：不是实现清单（叶层品种全集建表时由接口给全）；不是一次画完的（批次化）；不是装饰（每格必须可实查核验）。

## §2 骨架先行律（为什么必须先挖根）

1. 无骨架开工的四宗罪：重复建源、漏建（整族消失无人知）、无收敛基准（"挖干没有"永远靠感觉）、状态盲区（误以为有实则断供）。
2. **实证（2026-09-17 数据域）**：资金流整族漏网靠考古旧文档才发现；股东户数误标 ✅ 实为断供两月；05 产业链施工令之所以能直接开工，完全因为它建立在资产实盘清单上。
3. **操作律**：新域的第一个会话 = 骨架会话，产出 = 骨架文档 + 全条目状态标记；后续施工会话只准在骨架上有据地动工，骨架外发现的新条目须先回写骨架再施工。

## §3 分层与粒度（拆到哪一层为止）

- **四层**：大类（族，MECE 分域）→ 中类（完整性检查单元）→ 叶（枝叶示例）→ 数据集（施工产物）。
- **每层职责**：大类防漏族；中类=完整性检查与挖矿入口；叶=不同生产者的代表（**示例非穷举**）；数据集=建表实现。
- **停止判据三问**（通用化）：①生产者/来源系统变了 → 拆；②验证口径变了（频率/PIT 锚/量纲）→ 拆；③只是标签/品种/参数变 → **不拆**（那是建表字段）。
- 叶层防腐：枚举到「生产者代表」为止，品种全集由接入接口自然给全——图预先枚举到品种级 = 图会腐烂。

## §4 挖掘方法（四类批次，每批一个扫描视角）

| 批次类型 | 做法 | 数据域实证 |
|---|---|---|
| 需求批 | 从消费端缺口反向挖 | 公告因子家族反向立 C1 |
| 三重扫描批 | ①按生产者逐家过 ②按形态/资产类别逐类过 ③按消费者文献（学术+同业方法）逐个核 | 批次④补 A18/B13/H9/J10 |
| 案例批 | 拿一个真实案例（文章/事故/机会）反向拆成节点与链 | 油价五波文→E8/F13/E10+时滞矩阵；老蔡文→A19/D6/A7 |
| 考古批 | 旧系统/旧文档清产核资 | 清风 2.0/4.0→A19/市场广度/概念指数行情 |

- 每批落盘并记录批次号与主题（骨架文档头部批次志）；增量计数曲线是「挖干」的直观证据。

## §5 状态标记纪律（可核查性——骨架的生命线）

| 标记 | 定义 |
|---|---|
| ✅ | **有活跃管线在产数**——实查证据=库表 max(date) 新鲜 + tasks.yaml 有任务 + 调度日志可见执行 |
| 🔨 | 已定调在建（有设计文档/施工令） |
| ⬜ | 空白（可标的候选入口） |
| 💰 | 花钱可解（标价格量级） |
| 🌑 | 个人/当前形态不可得（点名留档） |
| 【快】 | 免费+公开+工程量小（快赢优先队列） |

- **✅ 误标 = 审计事故**：接口存在/存量存在 ≠ ✅（实证：股东户数表 50 万行存量但断供两月，曾误标 ✅）。
- 状态必须附实查路径（哪张表/哪个任务/哪条命令），禁凭印象标 ✅；改标留批次号。

## §6 挖干判据（何时封矿）

1. **三扫收敛**：三重扫描各完整跑一轮无新增条目；
2. **增长曲线拉平**：相邻两批增量趋零；
3. **🌑 清点**：做不了的已全部点名（数据域终局 3 个：做市报价/抖音财经/卫星）；
4. **封顶声明**写入骨架文档：此后增长 = 叶→数据集的实现，不再增枝；增枝须过 §3 停止判据并留理由；
5. 封顶 ≠ 死亡：新案例/新考古可触发批次重开（演化不禁止，需理由）。

## §7 骨架的活法（建成之后）

1. 路由入口：挖矿/施工会话从骨架领条目；域间挂接交叉引用（A7 龙虎榜↔D2 实体图；E8 成品油↔油价链）。
2. 收敛计分板：立项评分（四格）与覆盖度汇报直接引用骨架。
3. 状态变更纪律：每次实查后改标，改标留批次号与日期；骨架文档与域文档双向链接。

## §9 新域骨架 10 问检查单

①域职责一句话说得清？②大类 MECE 无交叉？③中类是否=完整性检查单元（不是产品功能清单）？④叶是否停在「生产者代表」？⑤三重扫描各跑一轮？⑥案例批至少一个？⑦考古批做过？⑧每个 ✅ 都有实查证据？⑨三扫收敛+封顶声明落盘？⑩路由/计分板/防腐三职责挂接完毕？
