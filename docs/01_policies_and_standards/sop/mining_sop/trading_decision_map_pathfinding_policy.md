# 交易决策全景图病菌寻路增长 SOP（TDM Pathfinding & Growth SOP）

> **一句话**：交易决策全景图不是一次画完的——本 SOP 定义它**长期增长**的标准作业：往哪个方向长（六向寻路）、长出来的东西怎么审（防噪音四道闸）、怎么落图（批次边界+四关验收）、什么时候算完（职能完备性）、以及**半年后怎么重跑一遍找最新的东西**（T2 复审模式）。
> **亲缘**：通用研究方法论真源=[mining_sop.md](mining_sop_policy.md)（2026-09-14 升 permanent，v1.3.0 起含矿脉枯竭终止/时间盒限流/失败模式——本文件为其在 TDM 地图增长域的专用实例）。
> **诞生**：2026-09-09 夜，Owner 裁定"每个节点延伸新节点直到能查的都查到；搜到的东西必须专业审查，编出来的噪音没意义"，由 TDM 后端负责人会话沉淀升 permanent。首次执行实例：[docs/_working/2026-09-09-tdm-growth-blueprint.md](../../../_working/2026-09-09-tdm-growth-blueprint.md)（task_bound，方法论冲突以本 SOP 为准）。
> **姊妹 SOP**：产业链图谱的寻路=[industry_chain_data_audit_sop §7.6/§7.7](../data_audit_sop/industry_chain_data_audit_policy.md)（群落编排+六向产业链版）；地图层位讨论闸=[trading_decision_map_layering_sop](../trading_decision_map_sop/trading_decision_map_layering_policy.md)（本 SOP 第 2 步的真源）。

## 3. 增长方法论：五步循环（每批一次）

1. **选母节点**：从职能完备性对照表（§6）缺口、当前施工波次节点、或 Owner 指定出发
2. **四道前置检查**（真源=trading_decision_map_layering_sop，一道不过不长）：①已有资产盘点五选一 ②四路外部调研 ③上层完整性（父节点立了吗，禁越级）④枝干分级
3. **拆分三条件过滤**（D108 铁律）：独立数据输入或动作输出 + 行为差异可回测区分 + 非纯参数变化——三条不全=不配成节点，写明驳回原因
4. **设计稿落档**：任务_bound 台账登记草案（node_id 预编号/name_zh/decision_question≤100 字/algo_note 大白话/五联锚候选/父节点/数据来源），**此步不碰真源 YAML**
5. **批量落图+四关验收**：`decision_map validate` error=0 + 双测试套件（test_decision_map + adversarial）全绿 + `align_all.py` exit 0 + 层位闸留痕 → GitCommitGateway 提交（地图+台账同 commit）→ **冻结版本号并通知施工轨**

## 4. 双轨铁律（增长与施工的批次边界）

- 增长轨（画图）与施工轨（建模块）**只在你来我往的批次边界交换**：增长批落图验收→冻结→施工轨消费冻结版→下一批。
- **施工中途禁改图**——防"一边加节点一边回填，目标漂移两头乱"。
- 单写手原则：同一时段地图真源只允许一个会话写（今晚先例：增长轨统一落图，接线会话只交节点规格卡）。

## 5. 六向寻路协议（每个母节点的标准作业）

对每个选定母节点，**六个方向**逐一探测，每向=内部反查+全网搜索双动作，产出 ≥1 条发现或"已查无"结论（查无也是有效结论，记档）：

| 方向 | 问的问题 | 内部动作（反查优先） | 全网搜索动作 | 产出物 |
|---|---|---|---|---|
| ①上游 | 还有什么信息应该喂进来？ | data_refs 反向审计+data_asset_registry 按类扫 | 机构同类决策看什么数据 | 新 data_refs 候选 / DS 缺口单 |
| ②下游 | 输出还该喂给谁？ | 地图边反向审计+决策链断点扫描 | 机构里这个判断触发哪些后续动作 | 新边 / 新消费节点候选 |
| ③算法/机制 | 业界学界最新怎么做？ | capability_lookup + Grep（内部已有实现优先复用） | 最新学术论文（SSRN/arXiv/顶刊会）+一线研报，**必须带 URL+发布方+年份** | 算法候选卡（含来源清单） |
| ④后端 | 代码侧缺什么？ | Step 1.5 三重搜索（src/+scripts/+tests/） | 开源实现参考（标 license 与成熟度） | 复用结论 或 拟建模块路径 |
| ⑤前端 | 怎么呈现给 Owner？ | web/frontend_map.yaml 查重 | 同类终端呈现惯例 | 前端需求登记单（**只登记不施工**） |
| ⑥数据字段 | 算法要什么字段？我们有吗？ | field_dictionary + data_asset_registry 逐字段核对 | 字段行业口径定义 | 字段清单 + DATA-GAP 标记 |

**时间盒=限流节奏，非停止判据（v1.2.0，随通用真源 mining_sop §3 同步）**：每向搜索 ≤20 分钟；查无=有效结论。**禁设轮数/深度/单批候选数上限**——候选多=富矿信号，长尾登记后继续挖，禁因候选多停挖；深挖顺序=算法/数据方向先行，**只定先后不定深浅，六个方向都挖到自然底**（该节点六向全部"已查无"+无未挖长尾才算挖尽）。

## 6. 来源与审查纪律：防噪音四道闸（Owner 铁律：编出来的东西是噪音，没意义）

1. **来源可溯闸**：每个外部发现必须带 来源 URL+发布方+年份；**禁凭模型训练记忆断言"业界都这么做"**。学术论文优先 SSRN/arXiv/期刊顶会；研报限一线机构；>10 年经典方法可用但标"经典"；收费墙内容只登记题录+可获取摘要，禁编造。
2. **交叉验证闸**：关键结论 ≥2 个独立来源相互印证；单来源=状态"待验证"，不入图。
3. **A 股适配闸**：外部方法逐条过 A 股微观结构（T+1/涨跌停/散户主导/无做市商），不适配的写明改造方案或驳回。
4. **可回测+数据可得闸**：新节点必须能回答"怎么算对错"（validation_method_registry 五类之一）**且**所需字段已登记或可登记；任一不满足=标 GAP-METHOD / DATA-GAP 挂起，禁带病入图。

**自审循环**：每批设计稿按本 SOP 全流程自审，**连续两轮 0 问题才放行落图**（对齐循环验收 CIRCULAR_ACCEPTANCE_ROUNDS=2 口径）；3 轮不过挂起登记，禁带病落图。统计硬结论（DSR/PBO 类检验）超执行会话能力时挂晨审强模型复核清单。

## 7. 职能完备性判据（"画完了"与复检模式）

- **十职能族对照**：大盘判断/板块赛道/个股选择/执行成交/持仓管理/离场/组合反馈/资讯传导/明日推演/新市场实例——每族核对"有节点承载、无断链"。
- **终止判据**：十族全覆盖 + 每条"输入→决策"边之间无未建模的中间判断 + 已有代码能力全部入图或入"不建清单" + 每节点六向自然挖到底（矿脉枯竭=六向全查无+无未挖长尾，无轮数/深度/候选数上限，v1.2.0 随通用真源同步）。**节点数不是判据**（业界无决策地图形态，对标职能完备性而非数量，禁为多而多）。
- **T2 半年复检清单**：①近半年新学术/新研报扫描（按 §5 六向③）②职能缺口重盘（十族表）③已有节点验证台账核对（衰减/噪音节点处理）④数据源可得性复查 ⑤新登记表/新图挂轴核对（alignment_checklist D38）。

## 8. 与治理体系的衔接

| 体系 | 衔接点 |
|---|---|
| layering_sop | §3 第 2 步四道前置检查的真源；层位讨论闸先行 |
| alignment_checklist | 落图批必过 align_all；新登记表必挂轴（D38） |
| CREATE-GUARD / depgraph | 新文件 token；新模块先 `--add-design-node` 再写码（施工轨职责） |
| GitCommitGateway | 落图批走网关提交；暂存区排队按 66 号备忘，禁清他会话 staged |
| 台账 | 每个候选五步进度+四闸结果+终态（已落图/已驳回/挂起）三态销账；台账随落图批同 commit 归档 |

## 9. 铁律

1. 真源 YAML 只在落图批边界动；禁施工中途改图。
2. 禁越级立节点（父未定不立子）；禁"参数变体"节点（D108 三条件）。
3. 新节点必须有数据来源或标 [ASSUMPTION]；来源不可溯的内容零容忍。
4. 禁为多而多：职能完备性是唯一终止判据。
5. 单写手：同一时段一个会话写地图。
6. 全部提交走 GitCommitGateway，禁裸 commit/禁 --no-verify。
