# 纵向地图挂图 SOP——血肉挂载、病历挂载与内收对审（真源）

> **一句话**：骨架挖完（[skeleton_mining_policy.md](skeleton_mining_policy.md) 管辖）只是有了骨头；**挂图=把「谁在干活 / 干得怎么样 / 这里犯过什么病」三样东西按机械判据挂到每个环节上**——挂得全，内收对审才判得出「并/退/留/修」；挂不全，就会重演「一个环节几十个模块」的重复建设惨案。
> **诞生**：2026-10-03 提交链地图战役（图11 交付流水线血肉填充）讨论定调。Owner 三原则：①地图必须 Owner 看得懂——目的标签=一句大白话说清存在的终极意义；②病历本这类永久设施**必须挂上流程**——不挂=孤儿病历没人翻、环节病了没档案；③**一岗多流程允许**——财务部在采购/报销/审计三张流程图里都出现，但编制表只有一份。
> **亲缘**：上游=[skeleton_mining_policy.md](skeleton_mining_policy.md)（先挖骨架后挂血肉）；字段纪律=六图终局卷 §1 裁定一（三层字段、同语义必同名，`docs/_working/map_build/03_final_blueprint_and_schema.md`）；立图准入=裁定#409 一域一图四问；挂载对账=纵轴覆盖账本（`docs/_working/map_census/`）；图专属实例=[trading_decision_map_layering_policy.md](../trading_decision_map_sop/trading_decision_map_layering_policy.md)（TDM 六步法=本 SOP 在 TDM 域的实例化）。

## §1 挂载四判据（什么必须上图）

1. **为该流程而生的模块** → 全挂：整个模块归本图所属环节（例：死信归因引擎之于图11 死信车道）。
2. **挂在流程路径上的部位**（模块编制在别的图/域）→ 只挂它伸进本流程的那只手，并标注影响因子（速度/效率/质量，例：W-M1 意图 API 之于图11——注册册写入必经点=提交速度因子）；编制表（真源身份）留在其归属图，本图只存指针。
3. **影响流程速度/效率/质量的设施**（含病历本/台账/守护册/说明书）→ 挂载；病历类走 §3 专项规则。
4. **一岗多流程**＝多处引用合法：同一 module_id 可出现在多张图，每处都是引用（INV-1：只存稳定标识符与指针，禁复制条目内容）。判「抄写而非引用」＝第二真源事故，覆盖账本判红。

**反面（什么不上图）**：纯个案（病例）不上图——留在病历本书页内（§3 规3）；决策判据类内容越域挂载（本家族 `tdm_refs` 禁则同款）；与流程速度/效率/质量无关的旁观资产。

## §2 目的标签层（横切轴；「Owner 看得懂」是验收标准）

1. 每图设图例：N 个目的标签（建议 8~12 条），**每条=一句大白话说清该类机制存在的终极意义**。例：「你活着吗」=证明施工队没死，死了别让它继续代表你说话；「新文件上户口」=新建的东西必须登记姓名籍贯，否则门禁见一次拦一次。
2. **冻结流程**：总筹起草 → Owner 一轮终审（验收=Owner 不看注释能懂）→ 冻结入图头 → 之后机贴不改名。定错类名后患是全量重贴，故终审必须 Owner。
3. 标签贴在**机制**上（纵轴=环节、横切=标签）：**同标签多钉=重复簇显形**——这是「一个环节多个模块」惨案的显影位，内收对审的入口。
4. 说不出一句大白话的标签＝拆分候选；贴不下任何标签的机制＝越域挂载嫌疑，两条都要回炉。

## §3 病历挂载（`casebooks` 字段，四机规）

1. **病历本是设施**：必须有登记身份（module_id/册号，如死因案例册、堵点本五域、抢救台账）；散文散页不算病历本。
2. **完备性铁律**：每本永久病历本必须被 ≥1 环节挂载；未挂=覆盖账本判红（治「病历本建成孤儿没人翻」——病历的价值在翻阅，不在存在）。
3. **只挂本，不挂病例**：个案（如某次事故处置记录）留在书页内，地图只挂书。
4. **引用不复制**（INV-1 同款）：挂载=读者从环节跳到病历册的指针，不是把病历内容搬进图。

## §4 字段三层与 L1 菜单新增四字段

字段纪律引用六图终局卷裁定一（同语义必同名）：**L0 通用层**全图同名（缺字段=校验器判红）；**L1 纵轴层**=共用字段菜单，各图按域取用；**L2 图专属层**各图自留（图头 `ssot_note_zh` 声明字段清单）。**不是每张图各自发明字段，也不是全部统一**：通用必同、菜单选用、专属须声明。

本 SOP 向 L1 菜单**新增四个标准字段**（各纵向地图取用时同名同义）：

| 字段 | 值域/形态 | 用途 |
|---|---|---|
| `purpose_tag` | 本图图例标签枚举 | 机制级目的标签（§2） |
| `casebooks` | 册籍标识符列表 | 病历挂载（§3） |
| `trigger_facts` | 机生计数 | 实测触发数——内收判据「零触发」证据位 |
| `consumers` | 引用面列表 | 谁在消费本机制——内收判据「零消费」证据位 |

**v1.1.0 补丁两则（2026-10-03，图12 数据供给链实例化时发现——周期任务域适用，图11 门禁域无此形态）**：

1. **节拍归一**（`trigger_facts` 判读铁律）：判「零触发」必须先按任务节拍折算期望次数——周末校准任务 7 天 1 跑、月度任务 30 天 1 跑，观测窗内计数 0 而期望次数（观测窗÷节拍）>1 才算真零触发；期望 ≤1 时计数缺席=观测窗不足，禁判死。防内收对审（步 7）误杀周期任务；期望次数一并记入 `trigger_facts`（禁只报裸计数）。
2. **gap 格四字段合法**：gap 节点挂 `casebooks`（缺口病历）与 `consumers`（在等该产物的消费方）合法且是常态宿主；`module_id` 保持 null（六图终局卷 §2 裁定二）。校验器不因 gap 格挂四字段判红（图12 validator CV-BLOOD 已按此实现，对抗测试在案）。

## §5 血肉填充流水线（七步，线内先挖后干）

| 步 | 干什么 | 谁 |
|---|---|---|
| 1 | 骨架契约（环节全集+封顶+三态计分） | 人工，归 skeleton_mining_policy |
| 2 | 目的标签冻结（起草→Owner 一轮终审→入图头） | Owner 终审 |
| 3 | 机制挂载（按 §1 四判据从注册表/代码扫描抽成员，含一岗多流程引用） | 机生 |
| 4 | 病历挂载（按 §3 四机规，完备性校验） | 机生 |
| 5 | facts 抽取（`trigger_facts`/`consumers`） | 机生 |
| 6 | 覆盖账本对账（三红：孤儿=该挂没挂／抄写=复制非引用／未挂病历=违 §3 规2） | 机生 |
| 7 | 内收对审（宪法内收四判据机械跑 → 四分处置清单：并/退/留/修） | 总筹裁定 |

## §6 看得懂验收（Owner 视角终检）

看任何一个环节必须三样齐：**机制**（谁在干活）+ **实测**（干得怎么样，trigger_facts/consumers）+ **病历**（这里历史上犯过什么病，casebooks）。缺任何一样=该环节血肉未满，不许进入内收对审。

## §7 防腐三律

1. 机生层禁手改（重扫即刷新；静态清单禁手工维护=宪法运维红线 §5）。
2. 计数用字段不写散文（文档矛盾=事故）。
3. 图只增语义不复制内容（INV-1；挂载是引用不是搬家）。
