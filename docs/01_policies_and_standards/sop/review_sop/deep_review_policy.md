# 代码与算法深度审查流程标准作业规程（SOP）——六轴审查法

> **生态位（与三邻居的分工边界，规范预算净零声明）**：
>
> | SOP | 维度 | 管什么 | 产出 |
> |---|---|---|---|
> | [audit_prompts_20_ai.md](../audit_prompts_20_ai.md) | 广度 × 文件 | 21 文件域逐域撒网，每文件都过一遍 | 域内问题清单+修复 |
> | [document_review_and_optimization_policy](../construction_sop/document_review_and_optimization_policy.md) | 深度 × 文档 | 文档七轮循环审查 | 文档修订 |
> | [mining_sop_policy](../mining_sop/mining_sop_policy.md) | 找**机会** | 六向寻路挖新矿脉（建/合/废/挂） | 节点挖矿文档 |
> | **本 SOP** | **深度 × 代码** | 对一个算法/管线/模块深钻**找缺陷**：数学正确性、上下游传导、旁系漂移、对抗面、SOTA 新鲜度 | 深度审查报告 |
>
> 挖矿问"还该建什么"，审查问"已建的哪里会出错"。审查报告中的"对等已有"结论可回流挖矿作子节点；挖矿产出的施工项完成后可触发本 SOP 验收（T2）。

## 1. 审查者与触发条件

**审查者**：任何强模型均可执行本 SOP——外部强模型（网页投喂或本地仓库直读）、内部 AI 会话、多代理组。审查者只出报告（产出=**数据**），不施工、不直接改代码（宪法 §9.11）；采纳与施工归主力会话。

| 编号 | 场景 | 说明 |
|---|---|---|
| T1 | **强模型可用窗口** | 好钢用在刀刃上：外部最强模型有使用期限/额度时，按 §2 优先级挑 P0 对象先审 |
| T2 | **施工完毕验收** | 新算法/新管线落地后、转 production 前 |
| T3 | **事故复盘横向排查** | 一处出系统性漏洞（如 DSR 口径翻案），同族/同链对象全查——"第一个洞"证明该类对象有系统性风险 |
| T4 | **定期审查** | P0 对象每季度至少一轮；P1 每半年 |

## 2. 审查对象优先级与模型分派

**优先级（Best-first：只定先后不定深浅，最终全部审到底）**：

| 级别 | 对象 | 判据 |
|---|---|---|
| P0 | 钱路径：验证认证链（四闸/Wilson/FDR/DSR）、资金分配、订单执行、对账 | 错了=静默亏钱或错账 |
| P1 | 决策链：TDM 权重生成、regime 切换、信号合成、回测 runner 内核 | 错了=决策系统性偏移，不报错只亏 |
| P2 | 基础设施：数据管线、调度、存储、前端 | 错了=断供/延迟，通常有报错可查 |

**模型分派二维法（输入体积 × 推理密度）**：

| | 推理密度高（数学/逻辑逐行验算） | 推理密度低（扫描/核对） |
|---|---|---|
| 输入小（单模块/单算法） | **最强推理模型**（如外部 Kimi）——性价比最高 | 常规模型 |
| 输入大（全仓一致性/跨模块） | 最强模型+长上下文 | 长上下文模型 |

**P0 加试（双角色单轮）**：钱路径对象配"审查者+复算反驳者"两角色：反驳者隔离推理链独立复算、只攻断言找反例，数值对拍实证门裁决（约 2×token；裁定依据与指令模板要点见 §8 与 [nodes 归档](../../../_working/sop_review_nodes/subnode_mining_round1.md)）。

## 3. 六轴审查法（核心方法论）

> **总原则**：六轴全查，一轴不落；查无也是有效结论（记"已查无"）；每条发现带证据锚点。

### 审查材料包（开工前投喂/自取清单，缺项在报告 §1 声明）

| 材料 | 用途 | 轴 |
|---|---|---|
| 对象源码+相关文档+裁定记录 | 审查主体 | 全轴 |
| 测试套件源码与最近运行结果 | 轴 A.3 审测试本身 | A |
| **运行时证据包**：近 N 天 error 日志摘要、reconcile 记录、异常告警 | 代码看不出运行行为——静默失败/吞异常常只在日志里有痕 | A/E |
| **变更热力**：`git log --follow` 频次统计 | 反复返工的文件=高危区（成本线七返工案例） | A |
| **数据画像**：对象消费关键表的缺失率/分位数/NaN 率/极端值 | 审统计代码不看真实数据分布=纸上谈兵（假设是否成立要用数据回答） | A |
| **缺陷模式 checklist**：[defect_pattern_checklist](defect_pattern_checklist.md) 14 条历史模式 | 教训不靠记忆靠清单——每轮审查强制前置过一遍，命中项直接出发现 | A/E |
| **运行环境锁定**：Python/关键库版本 | 数值行为随库版本漂移（rank 并列、rounding、NaN 语义） | A |
| 基线 commit hash | 证据过期判定 | 收口 |

### 轴 A 深度轴——对象本身

1. **数学正确性四问**（每个算法/公式逐个过）：
   - 数学上对不对（公式、统计口径、数值稳定性、量纲）？
   - 隐含假设是什么（分布假设、平稳性、无套利、样本独立）？假设在本项目数据上成立吗？
   - 边界条件（空输入/单样本/全 NaN/极端值/除零/溢出）行为是什么？
   - A 股口径适配（T+1、涨跌停、停牌、复权、散户主导、印花税/费率）对不对？
2. **代码实现 vs 意图逐段核对**：文档说的、代码写的、实际跑的三者一致吗？
3. **测试正确性审查**：测试本身会不会假阳性（断言过弱、mock 掉了核心逻辑、fixture 造的数据恰好绕过 bug、日期漂移式通过）？**测出的绿 ≠ 对，审查者要审测试本身**。
4. **状态机/并发**：FSM 状态转移完备性、竞态、重入、超时路径。

**通过条件**：对象内每个公式/算法有四问结论；每个测试文件有"信任/存疑"判定。

### 轴 B 上游轴——喂进来的对不对

1. 本对象消费的每个输入（数据表/上游函数返回/配置项/API）逐个追源：上游错了，本对象会发现吗（有无校验/断言/防御）？
2. 上游隐式契约（单位、时区、复权口径、索引对齐、NaN 语义）有没有文档化？没文档化的隐式契约=高危发现。
3. 配置项默认值审查：默认值错了，静默漂移还是显式报错？

**通过条件**：输入清单完整（逐条带来源锚点），每条有"上游错→本对象表现"的判定。

### 轴 C 下游轴——错了谁遭殃（爆炸半径）

1. 本对象的每个输出/副作用被谁消费（Grep 调用方全列）？
2. 对每个消费方回答：本对象若返回错值/晚值/空值，消费方是报错、静默吞掉还是带病传播？**静默吞掉=P0 级发现**。
3. 爆炸半径标注：给对象标"故障影响面"（单策略/全 sleeve/全账户）。

**通过条件**：调用方清单完整，静默传播点全部登记。

### 轴 D 旁系轴——兄弟模块与漂移

1. 全仓 Grep 同类功能（同公式、同口径、同职责的兄弟实现）逐个列出。
2. 兄弟实现间口径一致吗（同一概念两处算、两处结果不同=隐蔽 P1）？
3. 合并机会：三行相似不抽象，但**整套重复实现**（两份 weight 生成、两份 DSR）必须登记合并建议。
4. 文档 vs 代码漂移：本对象相关的文档断言逐条反查代码。

**通过条件**：兄弟清单完整，口径一致性逐对判定，合并建议登记。

### 轴 E 对抗轴——红蓝攻击

以攻击者视角过全链，逐问：
1. 哪里会**静默失败**（异常被 except 吞、日志埋太深、失败返回默认值）？
2. 哪里会**假阳性过关**（该拦的拦不住：数据迟到却判通过、重复触发却判新事件）？
3. 哪里**断了没人知道**（心跳缺失、监控盲区、告警依赖已死通道）？
4. 哪里**重复触发会出事**（重跑幂等吗、重放会双下单吗）？
5. 时序攻击：事件乱序/迟到/早到，状态机会进死角吗？

**通过条件**：五问逐条有结论；每个"会出事"的点给出触发剧本（怎么走到这一步）。

### 轴 F 新鲜度轴——SOTA 对照

1. 对象核心算法与业界学界最新做法对照：**每条必须 URL+发布方+年份**，禁凭训练记忆断言"业界都这么做"。
2. 中文研报/A 股语境来源**不算盲区**（很多项目只查英文 arXiv——中文卖方金工研报是独立矿脉）。
3. 结论三态：对等已有（注明对照项）/ 立卡候选（附理由与适配改造点）/ 驳回（附理由）。
4. 搜索受阻（限流/断网）如实记"受阻"，不算查无。

**通过条件**：核心算法每个都有≥1 条带来源的对照结论或"受阻"记录。

## 4. 证据纪律（铁律）

1. **每条发现必带锚点**：file:line 或文档锚点；无锚点的发现不进报告正文（进 §5 挂起疑问）。
2. **禁编造**：外部断言必须有真实来源；不确定就写不确定。审查报告最大罪=编造缺陷或编造引文。
3. **每条发现附"验证法"**：一行说明主力会话如何独立复核（跑什么命令/看哪个断言/造什么输入）。不可验证的发现降级为猜测。
4. **基线锚定**：报告必须注明审查基线（commit hash）；基线后代码变更会使发现过期，收口方负责重验。
5. **严重级四档**：P0=资金损失/静默错账/闸门失效；P1=决策系统性偏移/口径不一致；P2=可靠性/性能/断供；P3=风格/文档/整洁。

## 5. 产出格式（深度审查报告模板，审查者按此全文输出）

```
# 深度审查报告：<对象名>（审查者模型 / 基线 commit）
## 1 对象快照（审查范围、入口 file:line、排除项及理由、测试覆盖概况）
## 2 六轴审查日志表（轴 / 发现 / 证据锚点 / 严重级 / 验证法）
## 3 SOTA 对照（逐条：对等已有 / 立卡候选 / 驳回+理由，URL+发布方+年份）
## 4 缺陷清单（按严重级排序，每条：现状→证据→影响与爆炸半径→建议修法→验证法）
## 5 挂起疑问（不确定/证据不足/需 Owner 裁定的事项）
## 6 完备性自评（六轴是否全查？哪些子区域因材料不足未查透=长尾清单）
```

## 6. 主力会话侧收口流程

1. **逐条独立复核**：审查者也会错。按每条的"验证法"实测，判定三态：确认 / 驳回（留理由）/ 挂起（登记 `architecture_issue_registry.yaml`）。
2. **P0 插队**：确认的 P0 立即插队施工（钱闸修复优先级永远高于其他施工项）；P1-P3 进常规施工队列。
3. **修复走施工 SOP**：本 SOP 只管"找"，修走 [construction_workflow_policy](../construction_sop/construction_workflow_policy.md)。
4. **闭环复检**：P0/P1 修复后，将修复 diff 回传审查者（或换模型）做定向复检，确认修复未引入新洞。
5. **结论回填**：确认的"A 股口径适配/隐含假设/边界行为"结论回填对象相关文档与 capability cards——审查产出的知识不留在报告里发霉。
6. **误报档案**：被驳回的发现逐条留档（审查者模型/发现类型/误报原因）——长期数据用于修正 §2 模型分派二维法（哪类模型爱报哪类假阳）。
7. **矿脉联动**：轴 D 合并建议、轴 F 立卡候选转挖矿子节点（按 mining_sop 继续）；**轴 A 边界条件类发现直接转 property-based/变形测试用例**（衔接测试工厂）；T3 事故横向排查发现的新对象按 §2 重新排优先级。

## 7. 失败处置

| 情形 | 处置 |
|---|---|
| 审查者超出边界（直接改代码/提交） | 产出作废，换审查者重跑；向 Owner 报告 |
| 报告无锚点/编造嫌疑 | 该条不进收口流程；编造比例高则整份报告作废 |
| 审查中途代码基线漂移（施工并行） | 收口方逐条重验过期发现；无法重验的降级挂起 |
| 六轴有轴漏查 | 报告不收口，退回补查该轴 |

## 8. 开放问题（后续挖矿子节点登记）

| 子节点 | 为什么值得挖 | 状态 |
|---|---|---|
| **缺陷模式库** | 历史系统性缺陷归纳成机械 checklist（DSR 口径翻案、测试日期漂移、双份承载漂移等 14 条），每轮审查轴 A/E 强制过一遍 | **已建成**→[defect_pattern_checklist](defect_pattern_checklist.md) |
| **LLM 交叉评审/debate** | 溯源勘误："单 AI 53%→5 辩论 80%"出处=Milvus 博客单实验（转载壳多），无同行评审背书，定级待验证；可溯源的真源=Refute-or-Promote（arXiv 2604.19049：实证门裁决+80+ agent 共识同错反投票制）与辩论失败分析（arXiv 2510.20963：协作式挑错+10pp、饱和任务反有害）→收敛为 P0 双角色单轮方案（§2 已挂） | **立卡（收窄版）** |
| **变形关系测试（metamorphic）适配** | 回测/统计代码无真值可断言的机械化审查正解：首批 4 条不变式（S11 价格缩放/置换不变；四闸置换不变/效应量-p 值单调）≈8-10h，hypothesis+pytest 零新依赖；不变式清单与真源（Löw JOIS 2017 等）见归档 | **立卡（首批 4 条）** |
| mutation testing 适配 | mutmut 窄试点（WSL，P0 纯逻辑单文件+窄测试，手跑不进流水线）；边界=测"测试敏感度"不测 oracle 正确性（恰为人工审查互补面） | **立卡（窄试点）** |
| 审查报告机读 schema | 缺陷清单结构化→缺陷登记表→修复闭环自动化 | 待挖（等缺陷样本积累） |
| 形式化方法适用性 | Fagan inspection / 轻量形式化验证对 P0 数学对象是否值得 | 挂（重武器，随 P0 审查顺路判） |
| **审查材料包自动打包器** | 一键汇集源码+churn+数据画像+运行时证据的脚本 | 挂（P4：先手工，频次上来再施工） |
