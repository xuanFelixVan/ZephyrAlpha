# 规则处置程序法——六道闸判定 × 六类归宿

> **定位**：本文件只回答一个问题——**这条规则/这台裁判该怎么处置**。它是判决程序法，不是审查方法论。
> **分工矩阵**（防双真源，本文件不复述他库方法论）：广度×文件撒网 = `../audit_prompts_20_ai.md`；深度×代码六轴 = `deep_review_policy.md`；缺陷模式库 = `defect_pattern_checklist.md`；机会挖矿 = `../mining_sop/`。**本文件是它们的共同下游**：任何一处审出"某条规则可疑"，都按本文件走判决。
> **适用对象**：`docs/01_policies_and_standards/rules/*.yaml` 的每个判据小节；`policies/`、`sop/`、`templates/` 里每条规范性条款；两册门禁（`_registry/catalogs/gate_registry.yaml`、`in_process_gate_registry.yaml`）的每个条目；`src/zephyr/governance/audit/reconciliation_registry.py` 的每个 reconciler 规格；`scripts/governance/**` 的每台判定脚本。
> **案卷粒度**：**一个判据小节 = 一份案卷**（不以文件为单位）。文件只是小节的容器；退役/合并的最小单位必须是能单独判定、单独退役的原子条款。

## 0. 三条铁律

0.1 **出口封闭**：判决只能是第 1 节六类之一。禁止"看着还行""基本合理"这类无出口结论——无出口等于没审。
0.2 **案卷不含裁定**：闸 0–闸 4 的产出是**证据与实测数字**；裁定只在闸 5 出，且只能由强模型或 Owner 出。弱模型（Flash 档）只出案卷，不出判决。理由：弱模型在"该不该存在"上的失败模式不是答错，是**流畅地同意**，假裁定会以转报形式污染后续每一轮。
0.3 **能红才叫有牙**：任何"该规则有强制"的结论，必须附一次阴性对照——注入一个已知违规 → 观察是否被拦 → 撤样复跑。**未红过的强制 = 无强制**，一律按闸 4 处置。
   **恒真＝第三种假绿**：一律判"拦下/BLOCKED/FAIL"的检查器同样零信息量——`blocked_rate=1.0`、"全部拦住"这类满分不是防御强，是工具坏了（典型成因＝入参校验异常被宽 `except` 吞掉后按 fail-closed 计入拦截，于是任何输入都判 BLOCKED，区分度恒为 0）。所以**红证必须双向**：注入违规要红，且正常样本必须绿。只会红与只会绿的检查器同样作废。凡见"满分/全红/全拦"，先怀疑检查器，再怀疑被检对象。

## 1. 六类归宿（出口清单）

| 出口 | 判据（满足即归此类） | 落地动作 | 必附证据 | 执行档 |
|---|---|---|---|---|
| **A 维持** | 条文可二值判定、强制体实存、有红证、扫描面与声明一致、退化方向与风险档匹配 | 案卷盖"已核"，登记本次触发统计，不动代码 | 闸 0–4 全过的实测数字 | Flash |
| **B 修正** | 条文该留，但**写法或指向坏了**：措辞不可二值判定 / 执行体路径写错 / 别名对不上真身 / 扫描面与声明不符 | 改成"命令 + 退出码或输出行"的二值判据；修正指向；条数不变 | 改前改后的判据原文 + 一次红证 | Flash（改文案）/ Max（改判据语义） |
| **C 加牙** | 条文该留但当前是君子协定：无强制体，或强制体悬空 | **优先挂进既有门禁**（治理预算 D1：禁新增第 N 个门禁）；确实机检不了 → 转 B（改写成人判条款并写明谁判、看什么证据）或 D | 挂载点 gate_id + 挂载后的红证 | Max |
| **D 减重** | 让它变少。四个子型见下 | 见下 | 见下 | Max（删改真源）；Flash 只做登记同步 |
| **E 上交** | 命中门位四类（首次转 production / 注册表净删行 / 门禁 flag 出厂翻转 / 资金数据破坏性操作），或需要业务权衡（阈值、摩擦成本、花钱） | 进「待 Owner 裁定清单」：证据 + 建议 + **不裁的后果** | 案卷全文 + 建议出口 + 反对理由 | Owner |
| **F 挂起** | 证据不足。唯一合法的"不修" | 写清：缺什么证据、谁能补、何时复查 | 缺失证据清单 + 复查条件 | 任意档 |

**D 减重的四个子型**：

| 子型 | 判据 | 落地动作 |
|---|---|---|
| **D1 合并** | 两条以上条文说同一件事，或同一判据有多处承载（YAML + 代码兜底常量 + 文档） | 收敛为一条真源 + 派生副本；被合并条填 `superseded_by` 指向留存条（`rule_catalog_registry.yaml` 已有该字段） |
| **D2 拆分** | 一条条文塞多件事，导致其中一部分无法单独退役 | 拆成可独立判定、独立退役的原子小节；拆完各自过闸 |
| **D3 退役** | 条文曾成立，现被完全覆盖，或触发率为零（见闸 5 参数） | 走宪法 §4.2 退役审计：登记退役理由 → 删条或标 `archived` → 同步 ROOR / capability / 翻译登记 → 若有强制体，一并解除挂载 |
| **D4 判无效** | 条文声称的强制体在本仓**从未存在**（git 取证无改名、无退库记录） | 先走 `../audit_prompts_20_ai.md` §2.4A salvage 五步取证"谁还在消费它"，再按 D3 退役；**同时必须上报"规则登记环节不校验强制体存在性"这个流程缺陷**——D4 出现即说明登记流程有洞，不是单条规则的问题 |

## 2. 六道闸（顺序执行，第一个出结论的闸即定出口）

### 闸 0 · 身份闸（机械）
**问**：这条规则/这台裁判，能不能在各承载面对上号？
**判据**：规则的 `enforcement.paired_gate_id` 与 `executors` → 两册门禁；门禁 gate_id → `governance.db` 的 `gates`/`gate_runs`；触发记录 → `reconcile_execution_log`。
**命中（对不上）→ 出口**：先建映射，不改规则。身份不统一时，后续所有闸的机械判定都建在流沙上。
**当前实测状态**（复跑即刷新，勿引用本文数字）：YAML 两册 distinct 与 DB `gates` distinct 交集为 0；`reconcile_execution_log` 的 distinct 身份与 YAML 册交集个位数；DB 里存在整族仅见于历史时间段、全仓代码零命中的身份。查法见第 7 节。

### 闸 1 · 存在闸（机械）
**问**：它声称的强制体在不在？
**判据**：`paired_gate_id` 在两册可解析；`executors` 每一项可解析为实存文件/模块/外部工具/人工流程四类之一。
**未命中 → 取证二分**：
- **曾经有过**（`git log --all --diff-filter=AD --follow -- <path>` 查得到改名或退库）→ 归 **B**（改指向）或 **D3**（退役）。
- **从来没有过** → 归 **D4**（判无效 + 上报流程缺陷）。
**外部工具与人工流程不算悬空**：`ruff`/`mypy`/`pytest`/`pre-commit`/`import-linter` 属外部工具；`human_review`/`owner_review` 属人工流程——但**人工流程必须写明谁判、判什么证据**，否则按闸 2 处理。

### 闸 2 · 可判定闸（机械 + 轻判断）
**问**：判据是不是二值的？
**判据**：能否写成"命令 → 退出码 / 输出行"。措辞含"应合理 / 必要时 / 适当 / 尽量 / 建议 / 视情况" → 不可二值判定。
**未命中 → 出口 B**：改写成二值判据；改不出的，明确标注为**人判条款**并写清判定人与证据要求。
**副产物**：能二值化的条文进 T0 机械卡集（弱模型可执行）；人判条款进 T1（强模型）。**这一闸的通过率直接决定自动化审查能覆盖多少面。**

### 闸 3 · 真源闸（机械）
**问**：同一件事有几处承载？
**判据**：同一判据是否同时出现在规则 YAML、代码常量、文档三处；两条规则是否说同一件事；一条规则是否塞了多件可独立退役的事。
**未命中 → 出口**：多处承载 → **D1 合并**；一条塞多事 → **D2 拆分**。
**头号案例**：门禁身份的多个承载面（闸 0 那张表）本身就是本闸要治的对象。

### 闸 4 · 有效性闸（机械）
**问**：有牙吗？牙咬得动吗？咬不动时往哪边倒？
**三问三判据**：
1. **红证（双向）**：是否存在负向用例且实测会红，**并且**正常样本实测会绿（0.3 铁律）。无红证 → 先补；补不出红证 = 它拦不住任何东西 → 归 **B**（改写成可拦的）或 **D3**。**恒真（只会红、区分度 0）→ 归 B 或 D4**：它给的"全拦下"是假安全感，比没有门禁更危险，因为下游会据此停止警惕。
2. **扫描面**：实际扫描范围（own-scope / staged-only / 全仓）是否与条文声明一致。声明全仓而实现只扫 staged → 归 **B**（假强制，改声明或改实现）。
3. **退化方向**：读不到输入时 fail-open 还是 fail-closed。按风险档定应然方向（参数见下），不符 → 钱路径与门禁自身归 **E**（上交），其余归 **B** 并登记进 `_registry/catalogs/fail_open_register.yaml`。

**退化方向参数（Owner 可调）**：

| 风险档（`risk_tier_registry.yaml`） | 应然方向 |
|---|---|
| high（钱路径 / 门禁自身 / 注册表真源） | **fail-closed，无条件** |
| 结构类（路径 / 命名 / 表头 / 编码） | **fail-closed，但只拦本次改动面（own-scope）**——全仓拦会把历史存量算到所有提交人头上，造成全局卡死 |
| 文档叙事类 / 派生一致性类 | 可 fail-open，**但必须留痕进 `fail_open_register`**；"闭嘴不留痕"一律不许 |

### 闸 5 · 必要性闸（判断，强模型 / Owner）
**问**：今天从零开始写，还会写这条吗？
**五判据**：
1. **零触发** → **D3 退役候选**。阈值参数：**连续 90 天零触发**（与宪法 §4.2 季度审计同口径）。前提：闸 0 已统一身份键，否则触发率不可算 → 一律归 **F 挂起**。
2. **零触发必须先分两种**：(a) 真没触发过 → 退役候选；(b) **触发不了**（扫描面/开关/身份键坏） → 先按闸 4 修，不许退役。判法 = 注入已知违规看它响不响。
3. **被完全覆盖** → **D1 合并**或 **D3 退役**（注明被谁覆盖）。
4. **触发率高但全是误报** → **B**（收窄扫描面/改判据）或 **E**（阈值该 Owner 定）。
5. **是"规则"还是"当时的施工备忘"** → 备忘不占规则预算：移入 `docs/_working/` 或删除，登记为 **D3**。

**早期条款的嫌疑排序（只排序，不判定）**：按小节首次入库时间分层（`git log --diff-filter=A --follow -- <file>`），最老一档默认优先审；叠加机械信号——无 `paired_gate_id`、`executors` 为空或全为人工流程名、措辞不可二值判定、全仓被引用次数为 0。**四条信号同时命中的小节是瘦身主矿脉。**

## 3. 案卷字段（终审输入，固定 14 栏）

| # | 栏 | 内容要求 |
|---|---|---|
| 1 | 案卷号 | `<文件相对路径>#<小节键>`（小节键取 YAML `sections` 的键名或 md 的标题锚） |
| 2 | 判据原文 | 逐字摘录，不改写 |
| 3 | 闸0 身份对账 | 各承载面命中情况 + 交集结论 |
| 4 | 闸1 存在性 | `paired_gate_id` 解析结果；每个 executor 的四分类（实存/外部工具/人工流程/悬空）+ 取证命令 |
| 5 | 闸2 可判定性 | 可二值化 / 需改写 / 只能人判（附改写建议） |
| 6 | 闸3 承载处数 | 同一判据的承载点清单（文件:行） |
| 7 | 闸4-红证 | 负向用例位置 + 实测红证结果（命令 + 退出码） |
| 8 | 闸4-扫描面 | own-scope / staged-only / 全仓；与声明是否一致 |
| 9 | 闸4-退化方向 | fail-open / fail-closed / 未声明；与风险档应然方向是否一致 |
| 10 | 触发统计 | 近 90 天命中数 + 取数 SQL；不可算时写"身份键未统一，不可算" |
| 11 | 风险档 | `risk_tier_registry.yaml` 查得的 tier；未列出=low |
| 12 | 时间分层 | 小节首次入库时间 + 所属档位 |
| 13 | 建议出口 | A/B/C/D1-D4/E/F + 依据 + **我可能错在哪** |
| 14 | 证据等级 | 每栏标 `[亲验]`/`[转报]`/`[推断]`；`[转报]` 与 `[推断]` 不得作为判决唯一依据 |

出口为 D3/D4 的案卷，第 13 栏必须附 salvage 取证：**谁还在消费它**（生产调用方 grep，剔除 `__init__.py` re-export、测试引用、文档提及）。

## 4. 分工与模型档次

| 环节 | 谁 | 依据 |
|---|---|---|
| 写/改本程序法 | Max | 立法，措辞决定后续全部判决 |
| 闸 0 身份键统一 | Max | 改门禁自身 = high 档，命中门位 |
| 案卷生成（闸 0–4 机械部分） | Flash | 全是命令 + 二值判定 |
| 闸 5 判决 | Max / Owner | 需要"该不该存在"的判断力 |
| 执行 B 类（改文案/改指向） | Flash | 零歧义机械改 |
| 执行 C/D 类（加牙/合并/退役） | Max | 动真源，走门位 |
| E 类 | Owner | 门位 |

## 5. 出口指标（怎么算审完）

1. **出口分布**：A/B/C/D1-D4/E/F 各多少条。健康形状 = 维持多、上交少；**D4 占比高 = 登记流程有洞**，那比任何单条规则都严重。
2. **规则总量净变化 ≤ 0**（宪法 §4.1 净零增长）。
3. **可二值化条款占比**（闸 2 通过率）——决定自动化审查的覆盖上限。
4. **红证覆盖率** = 有负向用例的裁判 / 全部裁判。
5. **悬空强制数 = 0**（闸 1 未过者清零）。
6. **身份键交集率**（闸 0）——目标：规则↔门禁↔运行记录三方可对账。

## 6. 净零增长申报（本文件自身的对价）

本文件是宪法 §4.2 退役审计与 §4.1 净零增长的**可执行展开**，不新增任何新的规则要求；它吸收并替代此前散在各审查流程里的"逐条人工判"隐式做法。
后续按本文件新增任何门禁（例如"规则↔门禁对账门"），必须按 §4.1 申报对价：优先用**合并同族门**腾名额（门禁册里存在"增量版 + 审计版"成对同族门，合并为单门双模式即可释放名额），其次才考虑退役零触发门。

## 7. 地基限制与查法（数字一律现场取，勿引用本文）

**限制**：闸 0 未统一前，"零触发退役"不可判定，相关案卷一律归 **F 挂起**。这是当前唯一被结构卡住的出口。

**查法**（只读，可从仓根直接跑）：

| 要什么 | 怎么取 |
|---|---|
| 门禁册面 | `_registry/catalogs/gate_registry.yaml`、`in_process_gate_registry.yaml` 的 `gate_id` 集合（注意两册有包含关系，distinct 才是分母） |
| 门禁实现体 | `src/zephyr/gov_enforcement/commit_gates/*.py` |
| reconciler 规格 | `src/zephyr/governance/audit/reconciliation_registry.py` 的 `gate_id=` 去重 |
| 判定脚本族 | `scripts/governance/**/{check,validate,audit,detect,verify}_*.py` |
| 运行与触发记录 | `data/databases/governance.db`：`gates`、`gate_runs`（列含 `gate_id`/`passed`/`created_at`）、`gate_decisions`、`reconcile_execution_log`（列含 `gate_id`/`action`/`logged_at`/`trigger_source`）。只读连接 |
| 规则的强制声明 | `rules/trae_*.yaml` 的 `enforcement`（`paired_gate_id` / `type` / `executors` / `bypass_allowed`） |
| 风险档 | `_registry/catalogs/risk_tier_registry.yaml`（`domain_tiers[].tier`，未列出默认 low） |
| fail-open 台账 | `_registry/catalogs/fail_open_register.yaml`（派生册，重跑 `scripts/governance/d7_code/generate_fail_open_register.py`，禁手改） |
| 小节分母 | `_registry/catalogs/rule_catalog_registry.yaml` 的 `section_count` 字段（机生；缺失即源文档 frontmatter 无 `sections`） |

**案卷生成的落地形态**：产物写 `.runtime/sessions/<sid>/staging/`（24h TTL），终审通过后再 promote 到 `docs/_working/`；**案卷本身是派生物，不入 git**。
