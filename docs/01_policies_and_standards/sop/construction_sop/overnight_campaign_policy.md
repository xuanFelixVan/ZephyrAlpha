# 通宵战役 SOP——长城任务全链组织方法论（真源）

> **一句话**：Owner 下达「通宵令/长城任务/全部施工」类指令时，按本件把一段自然语言总攻令解析为**骨架先行→分簿挖矿→封矿→并行流水施工→循环检查→红蓝收口→自裁兜底→收尾报告**的完整战役流程；目标是 Owner 睡觉期间零中断、零提问、零遗留地推进，醒来收到可核验的端到端交付报告。
> **诞生**：2026-09-18，Owner 将其高频使用的通宵令原文（先建方案→挖环节骨架→逐环节挖干→封矿→线内先挖后干线间并行流水→循环检查连续两次归零→红蓝对抗→自裁栈→GitCommitGateway 落地→端到端交付）直接制度化。
> **亲缘**：[mining_sop_policy](../mining_sop/mining_sop_policy.md)（挖矿上位法：六向寻路/防噪音四闸/挖后自审闸）｜[skeleton_mining_policy](../mining_sop/skeleton_mining_policy.md)（骨架先行律的制度源）｜[construction_workflow_policy](construction_workflow_policy.md)（单线施工闭环——本件每条线内部照它走）｜[data_source_onboarding_sop](../data_ops_sop/data_source_onboarding_sop.md)（数据类环节的专用流程）｜收口机制=`.github/workflows/red-blue-validator.yml` + 六向台账格式范例 `docs/_working/ai_layer_vision/L*/DESIGN.md`。

## §1 指令解析（Phase 0）

从自然语言总攻令提取五要素并回写确认：①**目标终态**（什么样算完成）②**范围边界**（动哪些域、禁碰哪些）③**验收标准**（红蓝+循环轮次+端到端实测点）④**授权栈级别**（§7 自裁栈开到哪一级）⑤**起床报告期望**（§9 格式）。要素缺失时按 §7 自裁补齐，不提问。

## §2 组织结构与并发工程约束

- **总会话=总统筹**：方案、派工、验收、记账、跨线协调；**分层子代理**执行任务（主会话统揽全局，子代理各管一线）。
- **并发硬约束（实测教训入册）**：子代理有效并发 **2-3**（12 连发 10 秒即死——user concurrency limit）；超量任务改**波次派发**；主会话回合可能被拖长至 30-60 分钟，时间盒留系数。
- **多会话纪律**：子代理分包各锁自己目录；创建类 token 主会话统一办理；**多会话并发写同一目录期间禁止 rm 清理**（传导链文档丢失事故在案）；共享暂存区并发期提交要么快、要么直接走队列（吸收事故在案）。

## §3 文档树（作业簿结构）

```
docs/_working/<campaign_name>/          # 字母 snake_case 子目录
├── 00_master_ledger.md                 # 总簿：环节全景骨架（骨架 SOP 产出）+ 战役批次志
├── 01_<环节A>/DESIGN.md                # 环节子簿：六向台账+挖矿日志+自审闸裁定
│   └── （子类目按需再分文档）
├── 02_<环节B>/DESIGN.md
└── 90_report.md                        # 起床报告（§9）
```

挖矿日志写进各簿，**禁无日志交稿**（mining_sop 铁律）；总簿记环节全景，环节簿记本环节挖干全貌。

## §4 挖矿阶段（先环节后内容）

1. **先挖环节骨架**：全链到底有多少环节——按骨架构建 SOP（四层分层/三重扫描/停止判据）产出总簿环节全景；环节清单未封矿前不进入任何单环节深挖。
2. **逐环节挖干**：每环节按 mining_sop（六向寻路/防噪音四闸）挖透；**挖干判据 = 该簿六向台账填全 + 挖后自审闸三态裁定（施工/挂起/封矿）**；三态非「施工」的环节不进入 §5。
3. 万无一失标准：环节父子子孙全覆盖、每格可溯源（路径/行号/接口名实底），叙事性描述视为未挖。

## §5 施工调度协议：线内先挖后干、线间并行流水

- **线内**：同一环节串行——本环节封矿后才准施工本环节；
- **线间**：并行流水——**谁挖干谁先开工，不逐条等 Owner 点头**（通宵令即总授权）；
- Owner 睡觉期的健康状态 = 「挖矿主力在跑 + 个别挖干子块已开始施工」，而非全体干等；
- 每条线内部照 construction_workflow_policy 闭环走；数据类环节照 data_source_onboarding_sop 走。

## §6 循环检查与红蓝收口

1. 全部任务完成后 → **循环检查**：重查已完成内容，发现问题即修复 → **连续两轮问题=0 才算通过**；
2. **红蓝对抗**：跑 red-blue-validator + 人工红蓝视角互审，测出即修；
3. 测试纪律：真断言真弹——端到端实测点必须真实打穿（范式：QMT 模拟桥真实下 100 股并核对回报），禁模拟桩自证。

## §7 自裁栈（Owner 缺席裁定授权）

遇到问题按序裁定，**必须留分析过程与依据来源**：

1. 第一性原理推演（从项目目标与约束出发）；
2. 专业机构实践（同类系统的行业标准做法）；
3. 量化社区/氛围编程社区惯例；
4. GitHub 开源先例（有无现成实现可抄）；
5. 以上皆不能裁定 → **登记 + 跳过**，执行下一任务，起床报告列待裁定清单（附全部案由）；
6. 遇到无法跳过的硬阻塞 → 允许停止该线，其余线继续。

通宵令有效期内：不问问题、不中断、不停下等批复。

## §8 收尾协议

1. 全部产出经 GitCommitGateway 落地（并发期优先 `--enqueue` 队列；改前 claim、毕后 release）；
2. 临时文件清理（.runtime/tmp/ 本战役产物、中间脚本、消息文件）；
3. 骨架/总簿/台账状态回写（⬜→✅ 的批次号留痕）；
4. 死会话 claim 释放、stash_notice 检查（编辑"消失"先查stash）。

## §9 起床报告格式（Owner 醒来看到的第一份文档）

必须包含且按序：①全套链路状态一张表（环节×状态×证据 commit hash）②红蓝对抗结果与循环轮次（连续两次 0 的证据）③端到端实测记录（如实，含失败重试过程）④遗留问题=0 声明（非零则逐条案由）⑤待裁定清单（目标为空，非空逐条附 §7 五级分析）⑥临时文件清理确认。

## §10 红线（通宵令也不豁免）

宪法十二硬规则全程适用（ENV/reaper/worktree/claim/正门提交/GW 标记/热文件 safe_write）；测试隔离（tests 写 tmp_path）；RULE-DATA-OPS 三步验证；LLM 调用过 LSG；**交付报告禁止虚报**——「全绿」必须可被 Owner 独立复验，做不到的如实写「未达成+原因」，宁实勿华。
