# 通宵战役令模板（通用版·一键复制直发）

> 用法：复制下方指令全文，把【任务范围】行换成当次任务一句话后直接发给施工会话；【任务目标】固定为端到端完成，不必逐次改写（几乎所有施工任务目标同一）。接令 AI **无需读任何 SOP 文件**——指令已内嵌 overnight_campaign_policy 全部执行规则；SOP 为法律真源，不一致时以 SOP 为准并回报。
> 版本：v1.2.0 两改（Owner 裁定）：①任务目标固定=端到端打通全部流程、全部运行完成，不逐次改写；②交付=直接汇报状态，禁另建「交付表」等临时交付文档（与临时文件清理冲突，已废）；并补齐 v1.1.0 缺失的指令正文。v1.1.0 改为通用自然语言版（弃填空槽样式）。

## 指令全文（一键复制区）

```
【任务目标】端到端完成本任务——全部流程打通、全部运行完成、产物全部经 GitCommitGateway 落地。判定标准=链路真实跑通（端到端实测打穿），不是"代码写完/文档写完"。

【任务范围】<当次任务一句话：动哪些域、禁碰哪些>

【执行规则】
1. 骨架先行：先挖环节骨架产出总簿环节全景，环节清单封矿前不进任何单环节深挖。
2. 挖干判据：每环节六向台账填全+挖后自审闸三态裁定（施工/挂起/封矿）后才准施工。
3. 并行流水：线内先挖后干；线间谁挖干谁先开工，不等批复。子代理并发 2-3，超量波次派发；多会话并发写同一目录期间禁止 rm 清理。
4. 自裁栈：第一性原理→专业机构实践→社区惯例→开源先例→登记+跳过；通宵令有效期内不提问、不停等批复、不中断。
5. 循环检查：全部完工后重查修复，连续两轮问题=0 才算通过；红蓝对抗（red-blue-validator+互审）测出即修。
6. 端到端实测：实测点必须真实打穿，禁模拟桩自证。
7. 收尾：全部产出走 GitCommitGateway 落地（改前 claim、毕后 release）；清理 .runtime/tmp 本战役产物与中间脚本；骨架/台账状态回写。
8. 交付=直接汇报状态：按【起床报告】格式在对话内汇报终态并写 docs/_working/<campaign>/90_report.md；禁另建「交付表」等临时交付文档（与临时文件清理冲突，已废）。
9. 红线：宪法十二硬规则全程适用；交付报告禁止虚报，做不到的如实写「未达成+原因」，宁实勿华。

【起床报告】醒来看到：各环节状态+证据 commit hash／红蓝与循环两轮归零证据／端到端实测记录（含失败重试）／遗留=0 声明（非零逐条案由）／待裁定清单（附五级分析）／临时文件清理确认。
```
