# 交易决策地图逐层讨论 SOP——防撞车·防越级·防枝末先行

> **定位**：交易决策地图（69 号设计备忘录）血肉填充阶段的逐层讨论标准流程。
> **诞生背景**（2026-09-05 撞车事故）：情绪六段列轴与项目已有情绪周期五态（10 号 spec §3.3）撞车——根因是**讨论前未盘点项目已有资产**。本 SOP 把教训固化为流程，适用于地图所有后续环节（板块层/个股层/买卖点层/持仓流/离场流/组合流/币圈）的讨论。
> **核心原则**（Owner 2026-09-05 裁定）：先结构后填装；先主干后枝末；**裁定按第一性原理选效果最好的方案，不以推翻成本为由迁就**（尚未施工的部分，现在就是未来的地基）。

## 1. 三个反模式（本 SOP 防什么）

| 反模式 | 事故实例 | 后果 |
|---|---|---|
| **撞车**：讨论前不盘点项目已有资产 | 情绪六段 vs 已有情绪周期五态（10 号 spec）词汇撞车 | 第二真源/返工/词汇分裂 |
| **越级**：下层未定先讨论上层依赖它的内容 | 六段没定就讨论矩阵格子的策略挂载 | 上层一改，下层全部重写 |
| **枝末先行**：主干未清就讨论枝丫细节 | 大盘层没定就讨论"选股里怎么区分中军/龙头"（个股层内的枝末） | 枝末失去依附的主干，讨论结果悬空 |

## 2. 六步流程（每层/每个环节讨论 MUST 依序执行）

### Step 1 · 已有资产盘点清单（防撞车，MUST 第一个做）

讨论任何环节前，MUST 先全项目搜索并罗列**该环节相关的所有已有内容**，逐项标注处置：

| 搜索范围 | 搜什么 |
|---|---|
| 设计备忘录（07 域 design_memos/） | 相关 spec/工程计划（如 regime→10 号、板块→22 号、策略→24-28 号） |
| 作战地图三表（battle_map_steps） | 相关环节及其锚点（BM-BUY-02-A 等） |
| 注册表（REG-STR-001/REG-FCT-001/REG-DATAFLOW-001） | 相关策略/因子/数据条目 |
| 代码（src/zephyr 对应域） | 已实现模块（如 regime_detector.py） |
| 其他地图（frontend_map/预案引擎/触发注册表） | 相邻系统的重叠功能 |

每项标注五选一：**引用**（挂 module_ref/data_refs，不重建）/ **融合**（词汇合并，映射表记录）/ **扩展**（已有条目的细分升级，需回写原 spec）/ **废弃**（过时，走三步审判）/ **无冲突**（新建合法）。

**通过判据**：清单落盘到讨论备忘录 + 每项有处置标注 + 真源唯一自查（本层不产生第二状态/词汇真源）。

### Step 2 · 四路外部调研（Owner 裁定：AI 先查再问，不许让 Owner 凭空发明）

| 路 | 查什么 | 来源 |
|---|---|---|
| 学术前沿 | 最新论文/arXiv/算法（近 12 个月优先） | WebSearch |
| 机构实践 | 顶级机构公开方法论/产品文档 | WebSearch |
| 量化社区 | 开源实现/实证框架/卖方研报 | WebSearch |
| 实战社区 | A股实战体系（与本层相关时） | WebSearch |

**通过判据**：调研结论附来源+新旧对照；与 Step 1 已有资产做"谁更优"的第一性原理对比（效果优先，非成本优先）。
**禁止**：不调研就让 Owner 答结构问题（Owner 提供的是实战纠偏，不是算法发明）。

### Step 3 · 上层完整性检查（防越级，顺序依赖铁律）

讨论第 N 层前，MUST 确认**第 N-1 层（及所有更上游层）已定稿**：

```
主干链顺序（已定稿标 ✅）：
L1 大盘总闸 ✅（六段+灰度+仲裁+预算带，D7-D13）
  → ①E-L2 板块层（待讨论）
    → ②E-L3 个股层（依赖①的候选板块池）
      → ③E-L4 买卖点层（依赖②的个股池）
横向：P 流（依赖 L4 产出的持仓）/ X 流（依赖 P 流的持仓）/ F-C1（依赖 L1+全流）/ C2/C3（依赖 C1）
```

**检查动作**：对照地图 YAML 的 edges，本层所有 `from_node` 上游环节是否"定稿"（定稿=该层讨论备忘录+YAML 内容+置信度标注齐备）。
**不通过处置**：上游未定稿 → **禁止讨论本层**，回退上游（哪怕 Owner 想跳，也 MUST 先补上游）。
**通过判据**：上游依赖链逐项列出+定稿状态确认，记录在讨论备忘录。

### Step 4 · 枝干分级检查（防枝末先行）

讨论议题前判定它在树上的位置：

| 级别 | 判定 | 前置要求 |
|---|---|---|
| **主树干** | 地图 flow 层级节点（L/P/S/F/C 各层 gate/stage） | 其上游主干全部清晰 |
| **树枝** | 主干节点内部的子结构（如 L3 内 5 策略各自的选股链） | 本主干节点定稿+同层兄弟树枝定稿或明确挂起 |
| **枝末** | 树枝内的操作细节（如"个股怎么区分中军/龙头"——L3 选股树枝内的细节） | **整条主干链+本树枝全清晰**；枝末结论必须能回答"它挂在哪个树枝上" |

**判定工具**：地图 YAML 的 edges 依赖链——从议题节点向上回溯到根，路径上任何未定稿节点=禁止讨论。
**通过判据**：议题的树上位置声明（挂哪个节点下）+ 回溯路径全绿。

### Step 5 · 讨论与裁定（AI 查证打底 + Owner 实战纠偏）

1. AI 按 Step 1/2 产出"已有资产×外部调研"对比矩阵
2. Owner 以实战经验纠偏/拍板（AI 禁止替 Owner 编决策规则）
3. 裁定按第一性原理记录：判据+论证+放弃方案及理由（效果优先，成本让位）
4. 裁定编号顺延（D-NN），同步更新讨论备忘录

### Step 6 · 落盘与校验

1. YAML 更新（config/trading_decision_map.yaml）——只存稳定标识符引用（STR-*/FCT-*/DS-*/MOD-*/path），禁复制内容
2. 新增/变化因子缺口显性化（factor_refs 留空=缺口节点）
3. 69 号设计备忘录升版（新增 §小节记录裁定）
4. 讨论备忘录补轮次记录（D-NN+落地内容）
5. 循环验收：`pytest tests/trading/test_decision_map.py tests/governance/test_alignment_gates_red_blue.py`（真源回归锚必须全绿）
6. GitCommitGateway 提交（capability lookup 先行；禁 --no-verify）
