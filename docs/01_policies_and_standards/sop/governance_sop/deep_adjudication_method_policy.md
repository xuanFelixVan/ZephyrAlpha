# 深度裁定方法论——战场划分 × 穷举扫描（真源）

> **一句话**：深度裁定班的活不是"检查有没有做对"，是**裁定该不该做、算得对不对、这话能不能信**。机械复验归弱模型/夜间任务档；最强模型配额只花在"弱模型干不了、且干错了自己发现不了"的判断上。

## 1. 深度裁定法

### 1.1 只给最强模型原则

1. **筛选判据（贯穿全战役）**：*这件事的结论如果错了，弱模型有没有能力自己发现？* 发现不了的——**数学、口径、外推合法性、全局一致性、该不该做**——才归最强模型。
2. **token 经济学三事实**（分派判据的物理基础）：
   - 模型不生成 token 时不计费——**等待≈免费，碎问式轮询才贵**（每次轮询重发整个上下文）；
   - 分派判据＝**token 花在搬运与生成上，不是花在第几小时上**：全量测试套、几百文件批量读写、全仓漂移扫描是"token 体积活"，交弱模型/夜间任务；"跑一个回测"是时间活不烧 token，归强模型自己起后台；
   - "这件事要跑回测才知道结果"绝不是把它推给别人的理由——按 §1.3 自己起、自己等、自己读。
3. **终点三样，不是报告堆**：①一页页**裁定书草案**（Owner 签名即生效；Owner 终局只做输入与拍板两类事，产出要长成"可直接签字"的形状）；②**被推翻的结论清单**——凡"已被验收但其实错"的，点名+举证+改对（弱模型只会确认，不会推翻，这是本战役存在的理由）；③**当场改好的尺子与钱闸代码**（按三问边界，边查边修，不攒批）。对既有基线数字的动作＝**复算并裁定这笔账成不成立，不是重做它**。

**执行序**（先例）：S1 → S2 → S13 → S3 → S4 → S5 → S15 → S6 → S7 → S8 → S14 → S11 → S9 → S10 → S12 → 收官。

划分纪律：
- **执行序＝按依赖不按难度**：钱闸与战役存亡最先（决定后面一切战场是否白做），可信度地基次之（尺子没定，后面全是裸奔），赚钱真相再次，收口最后。
- **开班第一小时＝播种（不许跳过）**：先把所有"要跑回测/重考/聚合才能判读"的实验写成工单并后台启动（按 §1.3 四步），播完立刻转纯判断类战场；回测小时级，晚一小时播种就少一轮迭代。
- **每档收尾即落盘+提交**：别把整班赌在一次连续输出上——上下文压缩或断线时，已落盘的才是你的。
- **断线保底**：若配额或时间中途见底，预先指定的"最小交付集"（约 30% 配额）必须已经完成——每件独立成立，**不许为了"审得全"而调整它们的顺序**（先例＝S1 钱闸 + S2 战役存亡 + S13 切换判据 + S5 定尺四件）。

### 1.3 十五战场详案（v1.1 问句全录，问句即方法）

- **S1 钱闸数学**：逐对象给"对/错/待证"三态结论，错的当场改。先例可复用探针：Wilson 边界与单双侧、FDR 的 m 取法、DSR 的 num_trials 台账真实性、ANOVA 前提检验缺失、binomial 退化分支。不变式**本身对不对、覆盖够不够**强模型判；补写实现转弱模型档（写进 S12 规格）。
- **S2 战役可行性裁定（最高杠杆，先做）**。必答四问：①组合空间多大？穷举下多重检验惩罚把及格线推到什么位置——**这条战役数学上能不能出正结论**？②若能出，预注册窄化到什么程度（假设数上限/批次冻结纪律）才保功效？③既有证伪结论对新矩阵是否仍成立——**先坐实依据**："这条结论站在哪份证据上"（裁定号核验见 §2.4，悬空引用直接动摇立项）；④裁定：**继续 / 改设计（附具体改法） / 砍（附替代方案）**。这场战役的算力与车道时间常是项目能省下的最大一笔钱——**判它死刑也是贡献**。
- **S3 裁定书工厂**：清单由 §2 穷举扫描法预备（强模型**不必再自己扫全仓**——穷举由主力会话完成，不占判断配额）；逐条预消化，每页一条 Owner 签名即生效的裁定书草案；扫表发现的新待裁项**追加进清单**（清单即 S3 进度真源，裁完一条回填处置列）。最高价值入口＝扫描件违规发现区（§2.5）。格式与入册纪律见 §2.5。
- **S13 策略切换统计判据（整装策略承重墙）**。"什么时候允许从 A 切到 B"不定，整装策略就只是一句口号。必答六问：①切换信号用什么统计量、滞后几根 bar（滞后的代价 vs 抖动代价怎么算）；②**切换本身的成本要不要计入考核**（不计＝纸面最优、实盘来回打脸）；③状态判定如何防抖（闩锁/最短驻留/确认窗）；④多状态并存怎么仲裁（优先级 or 权重）；⑤多选一的显著性怎么校正（同时比 N 条、最优者胜出＝多重比较陷阱）；⑥切换规则本身怎么预注册冻结，防"看了 OOS 再改规则"。产出＝规则定稿（写进标准库/真源）+ **翻转清单**（新规则下哪些既有组合装配结论改变）。
- **S4 审"审校器"本身**：审**判定机制**，不是业务代码。审面：own_scope 标记真实性、内容扫描型闸的差分口径、reconciler 是否真事件触发（禁 cron/Timer/sleep-loop）、commit-queue serializer 环境 fail-open、integrity 重登记时序竞态、**判通过的测试能否被证明能红**。每条发现都问：**如果这一层静默失效，全仓哪些"已通过"结论同时失去意义**——这个连锁半径就是严重级。
- **S5 定尺子**：尺子是 **Owner 决策代理**——写错一次，以后每次自动放行都在替他犯错。逐条裁定：统计功效够不够、各条件是否同时可满足（过严 or 池子质量与标称不符，**两个方向都要给结论**）、组合门与单策略门的层级关系、缺不缺第三条腿（容量/相关性/换手）。**改尺子的硬纪律**：必须列**翻转清单**（哪些已入库结论在新尺下翻转），用重考历史工具出证。
- **S15 测试有效性审计（假绿清单）**：三类假绿必查——①**断言空转**（只跑不判/断言恒真）；②**mock 掉被测对象自身**（加固逻辑被自己的桩替掉，须配"不 mock 自身"的钉）；③**异常吞没**（宽 except 把失败变绿）。方法：逐条问"**我改坏被测代码，这个测试会红吗**"——不会红就是假绿；能当场构造变异验证的自己构造（几十行内），不能的写进 S12 规格。**这条决定夜间批量跑出来的绿底有多少含金量**，排在它前面做。
- **S6 经济解释强制审查**：在册策略逐条答"**谁在付我们钱、这个优势为什么持续、什么时候会消失**"。答不出＝统计幻觉嫌疑，进死刑名单（附复算依据）。他人/分包结论各自**复算+给经济解释**，不接受纯数字结论。
- **S7 成本/容量/账实恒等真实性**：成本模型逐环裁定（分层标定样本与真实成交一致性/冲击模型在盘口深度上是否乐观/地板佣金在小额多笔下如何咬合/结构性缺口对可得性影响）——**乐观的成本模型＝全套"能赚钱"结论自欺**。并案账实恒等：期初+现金流=期末、持仓×价=市值、成交笔数与 fill 表对账、多币种折算链闭合——**恒等式在哪一环断开，收益数字就是虚构的**。
- **S8 数据外推合法性**："可得≠可用"从个案升级成全仓体检。对每条已交付结论问：**这份数据能不能推出这个结论**，推不出的点名（含产物文件与口径出处）。
- **S14 前视偏差专项（lookahead，量化最贵的单类型错误）**：核心问句只有一个——"**下单那一刻，这个数看得到吗？**"这是语义判断，门禁和弱模型都看不见。覆盖面：快照/复权因子/停牌与退市/指数成分变更的**时点**处理、财务数据发布日 vs 报告期末、决策价与成交价错配、当日收盘价回灌当日信号。方法：对每条在册策略的信号取数路径回溯到"数据落地时刻"，与下单时刻比较；对时点敏感件逐个取证。产出：时点违规清单（file:line）+ **能变红的前视探针测试**（当场写，可直改类）。
- **S9-S12 收口档**：S9 跨层接口契约定稿（归属划清）；S10 架构减法裁定（建/合/废/挂）；S11 同族错误**抽样**定性（非全量）；S12 自证实验设计（不变式集+注入样本+历史极端日反证场景规格，自跑或转弱模型档）。

### 1.4 模型分派纪律：三问边界 + 回测四步

**三问边界（发现问题时依次自问）**：

1. **纯技术判据能定吗？**（数学错/口径错/断链/文档漂移/尺子实现失真）→ **直接改**，改完跑相关单测，按战场粒度提交。绝不攒施工单——重建上下文才是贵的，当场修命中缓存≈白送。
2. **验证它要不要跑任务？** → **要跑就自己跑**：按四步标准动作后台启动+机读判据+检查点回读，不因此推迟结论。只有当"为了让它可验需要写的施工代码量大"（几十上百行的搬运活）时，才把那段工程写成**带判据的交接包**给弱模型档——判的是 token 体积，不是时间长短。
3. **要不要花真钱、改 Owner 门位、砍/合并战役、删资产、净删注册表？** → **不改**。写成一页式裁定书（§2.5 格式）等 Owner 签。

三问之外一律直改（算法口径、成本模型参数、阈值实现、门禁逻辑、登记与蓝图同步）。**P0 钱闸/资金路径/破坏性数据操作的修复照做**，但收官报告单列"P0 修复待复核"，逐条给 commit 号，Owner 亲自复核。

**回测四步标准动作（缺一即变成烧配额）**：

1. **写成工单**：实验脚本+期望产物路径+**机读判据**（阈值/反例/什么算红）+预计耗时。判据必须在启动前写死——它同时也是"我下班后别人怎么替我判"的东西。
2. **分离启动**（不前台阻塞、不管道等待）：`nohup python <脚本> > .runtime/tmp/exp/<id>.log 2>&1 &`；把脚本关键词登记进 `data/runtime/process_reaper_keep.txt`（**不登记会被 reaper 误杀**）；产物完成写哨兵 `.runtime/tmp/exp/<id>.done`。
3. **立刻转下一个不依赖它的战场**——绝不问"跑完了吗"。
4. **检查点一次回读**：每完成一个战场，扫一次自己的实验台账（一次读操作，不是循环），`.done` 存在的读产物判读、推进结论；不存在的继续放着。

**实验台账必建**（一行一实验：id/启动时刻/命令/日志/产物/判据/状态/结论；**每启动一个当场写一行，不要攒**）——上下文会被压缩，压缩后只能靠它记起自己埋了什么。

禁：轮询式碎问；`tail -f`/sleep 循环盯盘；结果留在只有自己记得的位置；为"今天有结论"用估算替代回测却不声明（估算就明写估算+误差带）。

**P0 双角色加试**：高两档（一档二档）每个"已定级"结论，自己切"复算反驳者"给最强三条反驳再定级（花 2×token，只在高两档做）。

### 1.5 红线

1. **禁的是"把 token 花在等和搬上"，不是"跑回测"**：长任务按四步走；全量测试套与批量文件读写才交弱模型档。token 只该花在：读关键代码、复核数学、做裁定、写窄范围修复与探针测试。
2. **禁顺手重构系统**——产出是裁定不是施工；重构需求写进减法表或裁定书。
3. **禁编造锚点**——每条发现给 file:line + 复现路径 + 严重级 P0-P3；抽查复核制，**一处编造＝全案可信度归零**。
4. **P0 双角色加试**（高两档强制）。
5. **文档矛盾＝事故**：引用数字前先核实当前 HEAD，别信任何未复核的汇报口径。

### 1.6 产出与收官（三条全局规则，凌驾于所有战场）

1. **结论入真源，不入报告**。之后接手的是弱模型和门禁，它们不会翻 `docs/_working/` 报告。每个裁定必须落到耐久真源：`config/standards.yaml`（尺子）、`review_sop/defect_pattern_checklist.md`（新缺陷模式带 commit 锚点）、尺子与钱闸的代码与注释、`backtest_backlog.yaml`（可执行条目）、蓝图 `[INVARIANTS]` 头。报告只承载证据与翻案过程。
2. **凡移交必带机读判据**。任何交给弱模型、夜间任务或明天自己的条目，必须写死 pass/fail 阈值+反例样本+"什么算红"——**判据写不出来的条目＝还没想清楚的条目，退回重想**。
3. **断线保底**（见 §1.2 划分纪律末条）。

**收官报告七件套**：①被推翻的结论清单（本案成绩单）②已直改清单（含 commit 号）③P0 修复待复核清单 ④待签裁定书索引 ⑤转弱模型的规格与挂单 ⑥误报档案（判为误报的记档，长期修正审查策略）⑦给 Owner 的三句话总评+最危险的三个洞。

**循环检查**：全部落盘后跑两轮自检（结论有无锚点/改动有无测试/提交有无落地/挂单有无归属），**连续两轮零问题**才算完。收尾：`.runtime/tmp/` 清空、项目根目录零临时文件、release 全部自己 acquire 的锁。

**提交纪律**：冷启动与提交正门按宪法 §0/§2 执行（Python 3.12 PATH 修正、reaper 存活检查、claim → GitCommitGateway/git_commit.py → release、禁裸 git commit）。本战役追加两条纪律：**一个战场一批提交**（不是每改一行一提，更不是最后一次性大提交——几百文件大提交必然撞跨域/超范围门禁，且事后无法单独撤销某个修复）；提交后 `git log -1 --name-only` 核实真实归属（暂存区可能吸收他会话内容）。开工先 `git log --since=<上次落库点> --oneline` 自同步最新落库面，不按旧快照干活。

## 2. 全仓待裁穷举扫描法

### 2.1 分工原则

穷举扫描由主力会话（非强模型配额）完成，强模型只做逐条预消化——**扫描是 token 体积活，预消化是判断活**，与 §1.1 分派判据同源。扫描产物＝一张带锚点的待裁清单（先例 v1.0：净 96 条/八类/含 12 个批量合并项折算 ≈190 个决策点 + 违规与矛盾 8 条 + 低置信 14 条），**该清单即裁定战场的进度真源**。

### 2.2 五分区并行穷举

分区清单（先例划分；新战役按仓型增删，但**必须先声明分区清单再开扫**）：**策略回测 / 治理门禁 / 数据层 / 模块蓝图与减法 / 配置与管线**。

先例分区命中统计（自证口径）：策略区 43 + 治理区 45 + 数据区 25 + 模块区 18 行（折算 114）+ 管线区 6 = **137 行 / ≈190 决策点**。

### 2.3 标记词全量 grep 清单

先例 16 词（四主词+12 次级词），主词命中面：`待裁` 135 文件、`需 Owner` 170 文件、`挂单` 139 文件、`HELD` 95 文件、另 12 词（先例战役件未逐词展开，原样保留于归档件头部注记）。

**本册纪律（对先例的补强）**：执行本扫描法的战役件必须**显式登记全词表**（词+命中文件数），清单必须可复现；只报"另 N 词"视同扫描留痕不全。次级词按战役性质自选（方向提示，非先例原文：待定/暂缓/pending/draft/待批/去留/立项/点头一类悬决语族），但选定了就必须逐词列全。

### 2.4 逐行核实与入表闸（六步）

1. **命中的每条逐行 Read 核实后才入表**——grep 命中≠待裁（可能是已决、纯施工或引用性提及）。
2. **去重归并在入表时做**：同一决策跨多文档**只留一行、锚点全列**；每条登记四元组——编号 / 要拍的板（一句话问句）/ 锚点（file:line，多锚点全列）/ 来源（原始分区编号，供回溯）。先例去重口径：合并跨区重复 8 组（冻结区挂单三处重复、EXP 复评两处、破坏性清理批两处、收敛残余两处、一次性任务三处、消费方切换两处、成本模型启用两处、口径认可两处）+ 剔除已决/纯施工 ≈30 条，明细留分区报告可回溯。
3. **裁定号核验**：凡条目引用裁定#NNN，逐一比对 `ruling_registry.yaml`（先例口径：在册 121 条、最大号 #303；四区共 120+ 个编号逐一比对）。**"引用了编号但登记表查无此条"是稀缺信号，单列违规与矛盾发现区**（先例战果：V-01 悬空 #304、V-02 #293 内容不符，均由此法捕获）。机器核验必须兼容 `ruling_id` 带引号/不带引号两种写法——先例实测不兼容会产生 6 条假阴性。
4. **锚点双程抽检**：先脚本核"文件存在 + 行号在范围内"，再抽承重锚点比对行内关键词（先例抽 21 个：命中 17、修准 3 处行号漂移、1 处关键词在相邻行而锚点准确）。以 `…` 缩写的长路径未逐个复检的，必须在可信度声明中披露，引用前展开核实。
5. **低置信单列**：无法核实或存疑的条目进低置信区（先例 14 条），消费者裁前自判是否升格，**禁混入正表冒充实测**。
6. **可信度声明随表发布**：锚点全部实测命中 ≠"未被后续文档推翻"——推翻与否仅按新鲜度推断，**消费者裁前必须复核当前 HEAD**（宪法：文档矛盾=事故）。

### 2.5 分类、打包与消费纪律

- **八类分类**（先例；新战役按内容重配，但必须保留"为什么这个序"栏）：**A** 资金动作·仓位·花钱闸（16，直接关系真钱与实盘敞口，不裁=降级运行或悬空）｜**B** 尺子·阈值·统计口径（19，与定尺战场同源，一次裁定批量解锁下游）｜**C** 战役存亡·删资产·破坏性清理（18，不裁=继续烧算力与存储）｜**D** 注册表·flag·错误码门位（14，口径不统一导致反复踩同一道闸）｜**E** 晋升·冻结区解锁（9，多为一次性批文）｜**F** 数据可得性与外推授权（12，与外推/前视战场同源）｜**G** 方法论选型·该不该做（5，纯判断最需要强模型）｜**H** 治理机制与常设门位澄清（3，需先定"什么算门位"）。
- **首批必做选择原则**：卡 Owner 带宽最狠、且一次裁定连带解锁最多的条目先行（先例 12 条）。
- **分布即裁定素材**：先例——A+C+G 共 39 条属"该不该做/花不花钱"，B+D+E 共 42 条属"尺子与门位"，F 12 条属"数据能不能推"；Owner 拍板带宽**按条消耗需 96 次，按族打包只需 ≈14 次批文**。打包裁定是本法的核心产出形状（先例：门位口径一条规则消掉 12 个决策点）。
- **违规与矛盾发现区＝最高价值区**（先例 V-01~V-07 八条形态）：悬空裁定号 / 引用内容不符 / 待裁项与已生效裁定冲突 / 文档自相矛盾 / 已决未回写（虚增待裁面）/ 实质裁定只写"用户裁定/待定"不编号使 RULE-RULING 失能 / 蓝图 frontmatter 与正文自相矛盾 / 门禁"门还在、牙没了"（拦新增放原犯）。此类条目常直接决定战役存亡类战场的立项依据。**V 类发现必须回写 `review_sop/defect_pattern_checklist.md`**（带 commit 锚点）。
- **消费纪律五条**：①不许直接替 Owner 拍——A/C/E 类与全部 V 类产出**一页式裁定书草案**，一份一条；②与定尺战场同源的条目（B 类等）等尺子定稿后回头批量重写，**别裁两遍**；③门位口径统一类优先（杠杆最大）；④V 类必须先处理；⑤每条裁完在清单回填处置列（草案已出/已直改/作废/仍挂）——**清单即进度真源**。
- **裁定书格式（每页一条）**：现状（含证据锚点）/ 选项（≥2，含最坏情形）/ 数学或专业依据 / 风险 / 建议+置信度 / **若不同意建议应看什么数据**。
- **入册纪律**：真裁定须经 `ruling_registry.yaml` 登记（RULE-RULING）；强模型/扫描会话**只产草案+登记建议**，登记动作留 Owner 或按 §1.4 三问处理。
