# 裁定路由政策（真源）

> **一句话**：裁定是一条机械流水线——先判这事是不是问题（三轴价值主张），再判现有资产能否承接（内收），再拿证据（四层阶梯），再按十年量尺选方案，最后按八类路由处置留痕；Owner 只保留不可逆外部面六类（业务资产退役在内），其余 AI 照章自裁+署名+季度抽查。
> **定位**：governance_sop 族——[deep_adjudication_method_policy.md](deep_adjudication_method_policy.md) 管"怎么组织一场裁定战役"，本册管"一个待裁事项是什么类型→过哪几道门→谁拍板"。两册互挂不复制；裁定登记语义归 RULE-RULING+`ruling_registry.yaml`；人机门位查表归 `risk_tier_registry.yaml`（宪法 §5 修订版）。

## 1. 裁定哲学三公理（底座，v1 承接不变）

1. **可逆性不对称**：两个选项等权时，永远偏向可逆方向——恢复优先于删除、停用优先于判死、追加优先于覆盖、登记优先于销毁。不可逆动作必须多付一道证据税（授权链+墓碑+复活条件）。
2. **概念与实现分离**：行业共识概念永不被概念级判死——不合格的只能是我们的实现，标签只能是"算法待优化"。自研/非共识/野想法才允许判死归档。
3. **证据先于裁定**：裁定必须锚定机械判据；机械判定禁止凭记忆；无判据可依时，先立判据再裁，不凭直觉拍。

## 2. 五门流水线（v2 主干：每个待裁事项依序过门，每门有机械判据）

### 2.0 Gate 0 · 问题成立性（价值主张门）

**判定问句**："这是存量还是增量？增量：三轴上能不能说出一条可测的 Δ？存量：零触发零消费之外，还有没有价值主张？"

| 判据 | 内容 |
|---|---|
| G0-1 对象分野 | 存量（已存在资产）走判退轨；增量（拟建工程）走判立轨。禁跨用——新工程建成前消费者必为零，禁用存量判据否决增量。 |
| G0-2 存量判退 | 零触发零消费 **AND** 提不出价值主张 **AND** 无重启条件挂靠 → 退役轨（D1）。零触发零消费是联言条件之一，**永不做单判**。 |
| G0-3 增量判立 | 三轴（附表 A）至少一轴有可测 Δ，且三件套齐：基线→目标→验收判据（含测量方法与窗口）。任何一轴都提不出可测 Δ＝过度工程，否决。 |
| G0-4 主轴指定 | 多轴收益必须指定主轴（验收按主轴计），辅轴只做约束。 |
| G0-5 不劣化约束 | 价值主张必须声明其余两轴"不劣化"（提速不得增幻觉/漂移；算法改进不得绕门禁）。验收同验主轴 Δ 与辅轴不劣化。 |
| G0-6 等待痛感证据 | 速度轴主张必须附痛感读数：队列积压／滞留时长／绕路工单数／死信率／人肉等待记录。"感觉慢"不是证据。 |
| G0-7 证伪回路 | 落地后按验收窗（默认 30 天）对拍。达标＝价值主张兑现入册；**未达标＝价值主张证伪→自动转 D1 退役评估**，禁不了了之。 |
| G0-8 基线冷启动 | 无基线领域：先立测量（一次只读普查产出基线快照）再立主张。禁"无基线即免验"。基线带时间戳+环境戳，环境变更后重立。 |

**失效对策**：低目标保过→Owner 季度抽样 10 条复核；多轴骑墙→强制主轴。

### 2.1 Gate 1 · 内收承接（禁另造门）

**判定问句**："现有资产能不能交付同样的 Δ？"

| 判据 | 内容 |
|---|---|
| G1-1 四判据机械跑 | 同真源可派生→必并｜同域重复簇→收敛唯一｜跨域不同对象→不并另立｜零触发零消费→转 G0-2 存量轨。 |
| G1-2 内收豁免 | 承接方自身在退役/重构/deprecated 名单上→豁免内收走新建（并入将死者＝制造新孤儿）。 |
| G1-3 复杂度上界 | 并入后承接方超 high_complexity_gate 阈值（圈复杂度>15）→先拆分再并，或不并。 |
| G1-4 派生成本 | 派生一次成本（含十年维护差）>新建一次→不并，但登记映射关系防后人重复考古。 |
| G1-5 净零申报 | 走新建必须声明"为何无既有资产可承接"（引用本门判据编号）。 |

### 2.3 Gate 3 · 方案选型（十年量尺门）

| 判据 | 内容 |
|---|---|
| G3-1 当场治本 | 判据**当场冻结**；执行可以排队——**有排期+有判据＝排队（合法）；无排期＝搁置（违本册）**。需停机窗/静窗的治本属排队不属搁置。 |
| G3-2 长期主义选型 | 标准协议＞社区主流＞最小自研面。选型时做生态健康度检查（维护活跃度/发布频率/替代面），入年度依赖健康复检清单。 |
| G3-3 自研保护区 | 判据机器／考试体系／registry_ledger 账本／门禁核心／资金面＝自研不可替代（项目主权面）；其余优先社区。 |
| G3-4 流程也是治本对象 | 根因在纪律/流程/并发行为时，治本形态＝门禁化/宪法化（把人的纪律变机器判据），不是只改代码。 |
| G3-5 临时方案 | 必须带报废判据+期限。禁无期限"先凑合以后重构"。 |
| G3-6 当场执行优先（反拖延判据·Owner 2026-10-10 直令） | 凡拟裁定"等待/延后/换窗"，必须先过**现在性检验**三步：①列名全部阻塞门；②逐门三问——有无合法绕行/放行通道（含：该门实际开关位置是否已实测核实，"报备放行未生效"常因开关不在想当然处）？有无替代路径/资源？是硬阻塞还是仅不便？③全门硬阻塞才准裁"等"，且等待裁定必须写明四件：阻塞门清单＋各自硬因＋等待结束触发器＋**等待成本账**（等待期间什么在出血、什么链被堵）。缺任一项＝把搁置包装成排队，按搁置违规处置。依据＝**拖延不对称**：等待成本常不可见（出血时钟/依赖链堵塞/会话活性衰减/占用 Owner 注意力），执行成本常被高估——默认＝现在执行，"等"是必须自证合法的例外。判例：2026-10-09/10 图书馆 14:35 案（"等"被推翻后零冲突改道通道即现）、st-dexp 日班案（熔断真源开关挖出后放行即通）。 |

八类路由总表见 §3；两轨制见 §4.1。本门增补：

### 2.5 Gate A · 算法域自动裁定快道（Owner 2026-10-10 直令）

判定问句："这事是不是为了提高夏普族指标、且可回测、可补救、可对打、预算在册？"
五判据全真 ⇒ 本事项 AI 自动裁定（登记+adjudicator 署名，不呈 Owner）：
A1 目标轴：主轴=Δ算法质量（夏普族），预注册卡在册且门柱看数前冻结（时间戳可验）；
A2 可回测：考试执行器可在历史数据执行，窗口/牛熊段随卡冻结；数据断供先回补（D7）；
A3 可补救：产物只落考试面（分数册/TrialLedger），不触 production、无删除动作；
    fail=不迁移+如实入册（G0-7 负结果自动转退役评估）；
A4 可对打：新 vs 基线同窗双打（IS+OOS+牛熊段），门柱含 OOS 非劣；试次计入试次池，
    报告按试次总数打折（多重检验校正）；
A5 预算在册：计算预算预声明，fire_grid fail-closed 在守；不新增花钱面。
任一假 ⇒ 出本通道，按五门流水线正常走。
边界：目标是夏普≠手段豁免——手段触碰 Owner 保留面七条任一（实盘资金参数/业务资产轨 B
退役/花钱/对外发布/宪法/法律/物理不可逆删除）⇒该子项仍呈 Owner。判例=裁定#505 同日
X-R1-03（目标可为夏普，参数挂 position/core 实盘面→Owner 批文在案）。
机检化路线：登记工具先以字段校验实现（预注册卡冻结时间戳/试次池计数/产物去向断言），
成熟后并入裁定引擎决策表（§5 L3）。

## 4. 处置路径库（逐类细化，增量丰富区）

### 4.1 生死处置两轨制【v1 全文承接，裁定#490 首例】

**判定问句**："它是全行业都在用的概念，还是我们自己发明的？"

- **轨 A｜实现级停用 `deprecated`（算法待优化）**——适用＝行业共识/经典。必填三件事：①下岗原因（哪次考试哪条判据没过，证据锚点到考册）②职责承载者（功能现在由谁顶岗）③重启条件（写死门槛防无限重试）。
- **轨 B｜概念级判死 `retired`**——适用＝自研/非共识/野想法。必填：判死证据（考试读数）+复活条件（新假设新条目重来）。
- **共同底线（v2 修订）**：注册册条目身份在墓碑与复活窗内零消失（G4-1）；物理清账走季度打包（G4-2）。原 v1"永不物理删除"表述由墓碑制+季度打包承接。

### 4.1.5 资产分域与业务资产保护【Owner 2026-10-09 补批】

**资产分域表**：

| 域 | 范例 | 判退自主权 | 删除自主权 |
|---|---|---|---|
| **业务资产** | 数据表/数据源/因子/策略/指标/实验产物（GPU 考试产物、回测成绩单） | 轨 A"待重新优化算法"＝AI；**轨 B 退役＝Owner** | 主库删除＝Owner；**数据表安全删除（下方判据）＝AI** |
| **治理资产** | 脚本/文档/配置/注册表条目/工棚/临时件 | deprecated/retired＝AI（墓碑制） | 墓碑+季度打包＝AI 自裁+Owner 打包批 |

**数据表安全删除机械判据（三者全真才可 AI 删）**：
1. 真重复：同内容真身表在库（行数相等＋主键指纹抽样相等）＋ #311 隔离 7 天期满；
2. 空表：0 行 AND 写者不在 tasks.yaml AND 消费者 E1 全查零命中；
3. 驻留守恒：删除后该数据仍满足"主库或冷库"其一（真身在库即满足；空表无数据即满足）。

**数据驻留公理**：业务数据任意时刻 ∈ {主库, 冷库}。降采样/覆盖/窗口淘汰/格式转换中丢弃原粒度＝删除类动作，同规则：**先冷库留档（dump/parquet 双证）再动主库**；不可再生数据（已断供源的 tick/历史粒度）另加 Owner 知会。

**季度打包对业务资产**：轨 B 退役可随季度打包呈批但**逐项列示**（禁混入治理资产打包计数）；打包件必须机生摘要＋复活窗内引用自动剔除。

## 5. 自治分级 L1-L3（升降级机械化）

- **L1（现行）**：五门流水线＝AI 代裁依据；medium/low 行照表代裁+署名留痕；保留面呈 Owner（呈批件长成"可直接签字"形状——deep_adjudication §1.1）。
- **L2（丰富期）**：先例回流——Owner 实裁后校验路由命中；不命中＝表缺口补节。
- **L3（自动化）**：流水线＝裁定引擎决策表输入；挂钩 `ai_autonomy_authority_registry`＋per_agent_gate。每次代裁产出＝裁定书草案+证据锚点，Owner 只审保留面。
- **升级判据**：路由命中率>90% ＋ 代裁推翻率<5% ＋ 连续 50 条无路由缺口 → 自动呈批升一级。
- **降级判据**：推翻率>10% 或发生包装绕门位/净删事故 → 降一级并复查最近 N 条。
- **Owner 季度抽样**：每季抽 10 条 AI 代裁，复核价值主张达标质量+证据链完整性（信任但验证）。
