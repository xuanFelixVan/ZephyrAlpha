# 文档治理流程 v1.0

> **文档版本**: v1.0
> **创建日期**: 2026-04-03
> **目的**: 防止新增文档引入重复和职责不清

---

## 1. 概述

### 1.1 治理目标

- 防止内容重复
- 确保职责边界清晰
- 维护Layer定位一致性
- 保证接口契约规范

### 1.2 适用范围

- 新增技术规格文档
- 修改现有文档
- 文档归档和废弃

### 2.2 审查要点

#### 2.2.1 职责边界审查

| 检查项 | 检查内容 | 通过标准 |
|--------|----------|----------|
| 单一职责 | 是否只负责一种核心功能 | 是 |
| 职责声明 | 是否明确声明负责和不负责 | 完整声明 |
| 边界清晰 | 是否与现有模块职责重叠 | 无重叠 |

#### 2.2.2 重复内容检测

| 检查项 | 检查内容 | 通过标准 |
|--------|----------|----------|
| 功能重复 | 是否与现有模块功能重复 | 相似度 < 30% |
| 接口重复 | 是否定义了已存在的接口 | 无重复接口 |
| 代码重复 | 是否复制了其他模块的代码 | 无复制代码 |

#### 2.2.3 Layer定位检查

| 检查项 | 检查内容 | 通过标准 |
|--------|----------|----------|
| Layer归属 | 是否符合架构定义 | 符合 |
| 上下层关系 | 是否正确声明依赖 | 正确 |
| 跨层调用 | 是否存在不当跨层调用 | 无 |

## 4. 职责边界审查清单

### 4.1 新增模块检查

- [ ] 模块ID是否唯一
- [ ] 模块名称是否清晰
- [ ] Layer定位是否正确
- [ ] 核心职责是否明确
- [ ] 不负责内容是否声明
- [ ] 依赖模块是否正确
- [ ] 接口契约是否定义
- [ ] 是否与现有模块职责重叠

### 4.2 修改模块检查

- [ ] 修改是否影响其他模块
- [ ] 接口是否向后兼容
- [ ] 依赖模块是否需要更新
- [ ] 文档版本是否更新
- [ ] 变更记录是否添加

---

## 5. 重复内容检测规则

### 5.1 检测方法

| 方法 | 说明 | 阈值 |
|------|------|------|
| 关键词匹配 | 检测相同功能关键词 | > 50% 重合 |
| 接口签名匹配 | 检测相同接口定义 | > 80% 相似 |
| 代码块匹配 | 检测相同代码实现 | > 70% 相似 |

### 5.2 处理规则

| 检测结果 | 处理方式 |
|----------|----------|
| 相似度 < 30% | 通过 |
| 相似度 30%-70% | 需说明差异 |
| 相似度 > 70% | 驳回，需重构 |

## 6. 文档归档流程

### 6.1 归档条件

- 模块已废弃
- 功能已迁移到其他模块
- 文档已过时

### 6.2 归档步骤

1. 标记文档状态为 `Deprecated`
2. 添加废弃说明和替代模块
3. 移动到归档目录
4. 更新模块注册中心

## 7. 定期审计

### 7.1 审计周期

| 审计类型 | 周期 | 范围 |
|----------|------|------|
| 快速审计 | 每周 | 新增/修改文档 |
| 标准审计 | 每月 | 全部活跃文档 |
| 深度审计 | 每季度 | 全部文档含归档 |

### 7.2 审计指标

| 指标 | 目标值 |
|------|--------|
| 内容重复率 | < 5% |
| 职责清晰度 | > 95% |
| Layer一致性 | 100% |
| 接口规范性 | > 90% |
