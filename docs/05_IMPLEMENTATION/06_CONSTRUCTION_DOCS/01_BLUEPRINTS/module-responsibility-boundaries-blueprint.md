### 2.1 情景分析器（ScenarioAnalyzer）与压力测试报告器（StressTestReporter）



#### 对比摘要



| 维度 | ScenarioAnalyzer | StressTestReporter |

|------|------------------|-------------------|

| **核心职责** | 历史/假设情景定义与回放 | 压力情景执行与报告产出 |

| **主要输出** | 情景分析报告、冲击结果 | 压力测试报告、监管口径材料 |

| **典型节奏** | 按需 / 周度 | 月度 / 季度 |

| **典型场景** | 危机回放、参数敏感性 | 统一压力模板、限额联动 |



#### ScenarioAnalyzer 职责范围



**包含**：情景库与模板管理；资产在给定情景下的损益与风险指标；情景分析报告。



**不包含**：以监管报送为目的的定型压力测试流水线（与 StressTestReporter 的边界在集成设计中另行约定）。



#### StressTestReporter 职责范围



**包含**：压力测试任务编排、极值与生存能力类指标、合规报送格式报告。



**不包含**：一般性的策略级情景探索（偏研究向时由 ScenarioAnalyzer 侧重承担）。

## 三、模块间接口定义



### 3.1 标准接口格式



```python

class IReportModule(ABC):

    """报告模块标准接口"""

    

    @abstractmethod

    def generate_report(self, input_data: Dict) -> Report:

        """生成报告"""

        pass

    

    @abstractmethod

    def get_module_info(self) -> ModuleInfo:

        """获取模块信息"""

        pass

```



### 3.2 模块间通信协议



**同步调用**：适用于实时性要求高的场景。



```python

report = reporter.generate_report(input_data)

```



**异步调用**：适用于耗时较长的场景。



```python

task_id = reporter.submit_report_task(input_data)

report = reporter.get_report_result(task_id)

```

## 接口与契约（蓝图终稿）



- **契约真源**：`API_Contract.md`

- **对外接口边界**：本模块定义“跨模块职责边界与接口归属”的治理口径与检查项；不替代各具体模块蓝图中的接口明细，也不直接定义业务 API 细节。



## 验收标准（可检查）



- 对至少 1 组相邻模块（例如策略 ↔ 执行、数据 ↔ 风控）能够明确给出“负责/不负责”边界与接口归属判定，并能据此识别出职责重叠或缺口（可形成清单）。
