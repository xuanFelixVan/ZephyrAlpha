## 2. 文档治理工作流（详细）

### 2.1 孤儿文档检测与处理

**目标**：识别零入链文档，判断是否应保留、归档或删除。

**工作流程**：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  步骤 1        步骤 2        步骤 3        步骤 4        步骤 5              │
│  扫描孤儿  →  语义搜索  →  结构分析  →  关联记录  →  提交决策              │
│  (脚本)       (Qdrant)     (Sequential)  (KG)         (GitHub)             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**详细步骤**：

| 步骤 | 动作 | 工具/插件 | 输入 | 输出 | 防幻觉检查 |
|------|------|-----------|------|------|------------|
| 1 | 扫描零入链 | `scan_index_health.py` | `docs/` 目录 | `INDEX_HEALTH_ORPHAN_*.md` | 报表路径可追溯 |
| 2 | 语义搜索 | **Qdrant** | 文档内容片段 | 相关模块列表 | 返回结果有路径 |
| 3 | 结构分析 | **SequentialThinking** | 文档内容 + 相关模块 | 保留/归档/删除建议 | 5 步思考过程可追溯 |
| 4 | 关联记录 | **Knowledge Graph** | 决策结果 | 知识图谱节点 | 存储路径可验证 |
| 5 | 提交决策 | **GitHub** | 变更文件 | commit hash | `git show` 可验证 |

**插件调用示例**：

```
步骤 2 - Qdrant 调用：
输入："搜索与 DATA_SOURCE_MANAGEMENT_BLUEPRINT 相关的模块"
输出：返回相关蓝图路径列表，如：
  - docs/05_IMPLEMENTATION/06_CONSTRUCTION_DOCS/01_BLUEPRINTS/DATA_SOURCE_MANAGEMENT_BLUEPRINT.md
  - docs/01_FRAMEWORK/DATA_SOURCE_LAYER_BLUEPRINT.md

步骤 3 - SequentialThinking 调用：
输入："分析文档 docs/09_AUDIT/REPORTS/xxx.md 是否应保留，依据：
       1. 文档内容摘要
       2. 相关模块列表
       3. 当前目录职责"
输出：5 步结构化思考 + 最终建议（保留/归档/删除）
```

**工作流程**：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  步骤 1        步骤 2        步骤 3        步骤 4        步骤 5              │
│  扫描重复  →  语义分析  →  合并设计  →  关联更新  →  提交合并              │
│  (脚本)       (Qdrant)     (Sequential)  (KG)         (GitHub)             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**C1 类（字节级相同）详细步骤**：

| 步骤 | 动作 | 工具/插件 | 输入 | 输出 | 防幻觉检查 |
|------|------|-----------|------|------|------------|
| 1 | 扫描内容重复 | `scan_duplicate_file_content.py --ext md` | Git 已跟踪文件 | `DUPLICATE_CONTENT_BY_HASH_*.md` | hash 可验证 |
| 2 | 语义确认 | **Qdrant** | 文档路径 | 语义相似度 | 返回结果有路径 |
| 3 | 选择 canonical | **SequentialThinking** | 候选路径列表 | canonical 路径 + 理由 | 思考过程可追溯 |
| 4 | 更新关联 | **Knowledge Graph** | canonical 路径 | 图谱节点更新 | 存储路径可验证 |
| 5 | 提交合并 | **GitHub** | 变更文件 | commit hash | `git show` 可验证 |

**D 类（功能重复）详细步骤**：

| 步骤 | 动作 | 工具/插件 | 输入 | 输出 | 防幻觉检查 |
|------|------|-----------|------|------|------------|
| 1 | 扫描 D 类候选 | `scan_blueprint_d_overlap_candidates.py` | 蓝图目录 | `BLUEPRINT_D_OVERLAP_CANDIDATES_*.md` | 报表路径可追溯 |
| 2 | 置信度分析 | **SequentialThinking** | 候选对内容 | L0～L3 置信度 | 思考过程可追溯 |
| 3 | 合并方案 | **SequentialThinking** | 高置信候选对 | 合并大纲 | 方案可追溯 |
| 4 | 低置信登记 | - | 低置信候选 | D 类合稿待审登记 | 登记表可追溯 |
| 5 | 提交合并 | **GitHub** | 变更文件 | commit hash | `git show` 可验证 |

**D 类置信度判定标准**（与 D 类 Playbook **§2.5** 对齐）：

| 置信度 | 判定标准 | 处理方式 |
|--------|----------|----------|
| **L3（高置信）** | 主题完全一致、内容高度重叠、无冲突 | 直接合并 |
| **L2（中置信）** | 主题一致、内容部分重叠、需整合 | 设计合并方案后合并 |
| **L1（低置信）** | 主题相关、内容差异大、需裁决 | 登记待审，Owner 裁决 |
| **L0（无置信）** | 仅关键词相似、无实际关联 | 不处理 |

```

蓝图主题：[从蓝图标题提取]
相关契约：[Qdrant 搜索结果]
```

## 6. 插件使用最佳实践

### 6.1 效率提升技巧

| 技巧 | 说明 | 示例 |
|------|------|------|
| **批量预处理** | 先用脚本扫描，再用插件分析 | 先跑 `scan_index_health.py`，再用 Qdrant 分析孤儿文档 |
| **并行调用** | 多个独立插件可并行调用 | Qdrant 搜索 + File System 列目录可同时进行 |
| **结果缓存** | 重复查询使用缓存结果 | 同一文档的 Qdrant 搜索结果可复用 |
| **增量更新** | 只处理变更部分 | 搬迁目录后只验证受影响的链接 |

### 6.2 精准度提升技巧

| 技巧 | 说明 | 示例 |
|------|------|------|
| **交叉验证** | 多插件结果交叉验证 | Qdrant 搜索结果 + Knowledge Graph 关联关系 |
| **证据追溯** | 所有决策有证据路径 | SequentialThinking 思考过程 + 脚本报表 |
| **门禁检查** | 关键步骤有门禁 | L1 扫描无效链 = 0 |
| **人工复核** | 高风险操作人工复核 | D 类低置信合稿须 Owner 裁决 |

### 6.3 防止 AI 幻觉

| 场景 | 防幻觉措施 | 验证方法 |
|------|-----------|----------|
| **文档路径** | 插件返回结果必须有完整路径 | `git show` 或文件系统验证 |
| **内容引用** | 引用内容必须有原文出处 | grep 或 Read 工具验证 |
| **决策建议** | SequentialThinking 必须输出思考过程 | 检查 5 步结构化输出 |
| **关联关系** | Knowledge Graph 必须有存储路径 | 检查 `memory_graph.json` |

## 7. 插件调用快速参考

### 7.1 Qdrant（语义搜索）

```
用途：语义搜索文档和代码
调用时机：
  - 搜索相关蓝图
  - 定位文档归属
  - 查找 API 契约
输入：自然语言查询
输出：相关文档路径列表
防幻觉：返回结果必须有完整路径
```

### 7.2 SequentialThinking（结构化思考）

```
用途：复杂问题分析和决策
调用时机：
  - 分析文档是否保留
  - 设计合并方案
  - 设计门禁三段
输入：问题描述 + 相关上下文
输出：5 步结构化思考 + 最终建议
防幻觉：思考过程必须可追溯
```

### 7.3 Knowledge Graph Memory（知识图谱）

```
用途：记录和查询文档关联关系
调用时机：
  - 记录蓝图依赖
  - 可视化模块关系
  - 追溯决策历史
输入：实体和关系定义
输出：知识图谱节点和边
防幻觉：存储路径必须可验证（memory_graph.json）
```

### 7.4 File System（文件操作）

```
用途：文件和目录操作
调用时机：
  - 列出目录结构
  - 读取文件内容
  - 验证文件存在
输入：文件或目录路径
输出：文件列表或内容
防幻觉：路径必须存在
```

### 7.5 GitHub（版本控制）

```
用途：Git 操作和 PR 管理
调用时机：
  - 提交变更
  - 创建 PR
  - 查询提交历史
输入：文件路径和 commit 信息
输出：commit hash 或 PR URL
防幻觉：`git show` 可验证
```
