## 一、文档治理五大原则最佳实践

### 1.1 职责驱动原则 (SoC)

**原则定义**: 每个文档只承担一种核心职责

**最佳实践**:

| 实践编号 | 实践名称 | 实践描述 | 示例 |
|---------|---------|---------|------|
| **BP-001** | 单一职责检查 | 每个文档必须有明确的核心职责 | BLUEPRINT_INDEX.md只负责蓝图索引 |
| **BP-002** | 职责边界声明 | 在文档开头明确职责边界 | 添加"负责"和"不负责"章节 |
| **BP-003** | 职责重叠检测 | 定期检查文档间职责重叠 | 使用审计工具检测职责重叠 |
| **BP-004** | 职责命名规范 | 文档命名反映核心职责 | RISK_BUDGETING_FRAMEWORK.md |

**典型案例**:

**案例1: BLUEPRINT_INDEX.md职责明确**
```markdown
## 📋 文档职责说明

### 核心职责
本文档是Layer 11战略决策层的蓝图索引导航文档，负责：
- 提供完整的蓝图清单和快速导航
- 说明蓝图之间的依赖关系
- 提供实施优先级参考

### 职责边界
**负责**：
- ✅ 提供蓝图清单和导航链接
- ✅ 说明蓝图依赖关系

**不负责**：
- ❌ 详细的模块状态（由COMPLETE_BLUEPRINT_OVERVIEW.md负责）
- ❌ 缺失模块清单（由COMPLETE_BLUEPRINT_OVERVIEW.md负责）
```

### 1.2 索引完备性原则

**原则定义**: 所有活跃文档必须被索引，归档文档必须可追溯

**最佳实践**:

| 实践编号 | 实践名称 | 实践描述 | 示例 |
|---------|---------|---------|------|
| **BP-005** | 100%索引覆盖 | 所有活跃文档必须被索引 | INDEX.md列出所有活跃文档 |
| **BP-006** | 索引链接验证 | 定期验证索引链接有效性 | 使用链接检查工具 |
| **BP-007** | 索引层级清晰 | 建立清晰的索引层级体系 | 根索引 → 层级索引 → 子目录索引 |
| **BP-008** | 索引更新及时 | 文档变更时立即更新索引 | 文档变更 → 更新索引 |

**典型案例**:

**案例2: 索引层级体系**
```
docs/INDEX.md (根索引)
├── docs/11_STRATEGIC_DECISION/INDEX.md (层级索引)
│   ├── docs/11_STRATEGIC_DECISION/BLUEPRINT_INDEX.md (专项索引)
│   └── docs/11_STRATEGIC_DECISION/COMPLETE_BLUEPRINT_OVERVIEW.md (状态清单)
└── docs/System_Manifest.md (系统清单)
```

### 1.3 版本隔离原则

**原则定义**: 同一内容只保留最新版本，历史版本统一归档

**最佳实践**:

| 实践编号 | 实践名称 | 实践描述 | 示例 |
|---------|---------|---------|------|
| **BP-009** | 重复文档检测 | 定期检测重复文档 | 使用内容比对工具 |
| **BP-010** | 历史版本归档 | 历史版本移至archive目录 | docs/06_ARCHIVE/ |
| **BP-011** | 版本标识清晰 | 文档内版本号与文件名一致 | v1.0.0 |
| **BP-012** | 变更记录完整 | 文档包含变更历史记录 | 更新日志章节 |

**典型案例**:

**案例3: 历史版本归档**
```
docs/11_STRATEGIC_DECISION/ (活跃目录)
├── BLUEPRINT.md (最新版本)
└── ...

docs/06_ARCHIVE/ (归档目录)
├── 2026-03/
│   ├── BLUEPRINT_v1.0.md (历史版本)
│   └── ...
└── ...
```

### 1.4 文档代码对应原则

**原则定义**: 文档必须反映实际代码状态

**最佳实践**:

| 实践编号 | 实践名称 | 实践描述 | 示例 |
|---------|---------|---------|------|
| **BP-013** | 文档代码同步 | 文档与代码保持同步 | 代码变更 → 更新文档 |
| **BP-014** | 接口一致性 | 文档接口与代码实现一致 | API文档与API代码一致 |
| **BP-015** | 定期验证 | 定期验证文档与代码一致性 | 每周验证一次 |
| **BP-016** | 变更通知 | 代码变更时通知文档维护者 | Git hooks通知 |

**典型案例**:

**案例4: 文档代码同步验证**
```markdown
## 代码一致性验证

**验证时间**: 2026-04-07
**验证结果**: ⚠️ 文档超前于代码
**发现**: Layer 11蓝图文档完整，但代码实现缺失
**建议**: 立即开始代码实现
```

### 1.5 命名规范原则

**原则定义**: 使用标准化的命名体系，命名反映内容和职责

**最佳实践**:

| 实践编号 | 实践名称 | 实践描述 | 示例 |
|---------|---------|---------|------|
| **BP-017** | 命名反映职责 | 文档命名反映核心职责 | RISK_BUDGETING_FRAMEWORK.md |
| **BP-018** | 命名风格统一 | 同类文档命名风格一致 | 蓝图文档统一使用大写 |
| **BP-019** | 避免特殊字符 | 文件名不包含空格、中文等 | 使用下划线代替空格 |
| **BP-020** | 版本号规范 | 版本号符合语义化版本规范 | v1.0.0 |

**典型案例**:

**案例5: 命名规范示例**
```
✅ 正确命名:
- RISK_BUDGETING_FRAMEWORK.md
- STRATEGY_SELECTION_FRAMEWORK.md
- BLUEPRINT_INDEX.md

❌ 错误命名:
- 风险预算框架.md (包含中文)
- risk budgeting framework.md (包含空格)
- blueprint-index.md (风格不一致)
```

## 二、常见问题与解决方案

### 2.1 职责重叠问题

**问题描述**: 多个文档承担相同职责

**典型表现**:
- INDEX.md和System_Manifest.md都包含架构说明
- BLUEPRINT_INDEX.md和COMPLETE_BLUEPRINT_OVERVIEW.md都包含蓝图清单

**解决方案**:
1. 明确每个文档的核心职责
2. 添加职责边界声明
3. 删除重叠内容
4. 建立交叉引用

**案例**:
```markdown
**问题**: BLUEPRINT_INDEX.md和COMPLETE_BLUEPRINT_OVERVIEW.md职责重叠

**解决**:
- BLUEPRINT_INDEX.md: 负责蓝图导航和依赖关系
- COMPLETE_BLUEPRINT_OVERVIEW.md: 负责模块状态和缺失识别
- 添加职责边界声明
- 添加交叉引用
```

### 2.2 索引不完整问题

**问题描述**: 部分文档未被索引

**典型表现**:
- 新增文档未添加到索引
- 索引链接失效
- 索引层级不清晰

**解决方案**:
1. 建立索引更新机制
2. 定期验证索引完整性
3. 使用自动化工具检查链接
4. 建立索引规范

**案例**:
```markdown
**问题**: BLUEPRINT_INDEX.md中存在死链接

**解决**:
- 删除死链接
- 添加"待创建"说明
- 更新完成统计
- 创建缺失文档后更新索引
```

### 2.3 版本混乱问题

**问题描述**: 同一内容存在多个版本

**典型表现**:
- 重复文档
- 历史版本未归档
- 版本标识不一致

**解决方案**:
1. 检测重复文档
2. 归档历史版本
3. 统一版本标识
4. 建立版本管理规范

**案例**:
```markdown
**问题**: Layer 11存在重复的蓝图文档

**解决**:
- 识别重复文档（中英文版本）
- 保留英文版本（符合命名规范）
- 归档中文版本
- 更新索引引用
```

### 2.4 文档代码不一致问题

**问题描述**: 文档描述与代码实现不符

**典型表现**:
- 文档超前于代码
- 文档滞后于代码
- 接口描述不一致

**解决方案**:
1. 定期验证文档代码一致性
2. 建立同步机制
3. 使用自动化工具
4. 建立变更通知机制

**案例**:
```markdown
**问题**: Layer 11蓝图文档完整，但代码实现缺失

**解决**:
- 验证文档与代码一致性
- 识别实施差距
- 制定实施计划
- 开始代码实现
```

    │

    │
    ▼

    │
    ▼

    │

    │
    ▼

    │
    ▼

    │
