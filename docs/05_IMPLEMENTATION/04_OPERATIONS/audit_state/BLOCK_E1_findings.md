## 🔍 详细问题记录

### P1: 测试覆盖不完整

**问题 E1-P1-001**: 模块测试覆盖不足  
**严重性**: 🟠 P1  
**发现位置**: `tests/unit/` 目录  
**问题描述**: 现有测试仅覆盖 `core/` 与 `modules/` 部分模块，缺失对 `utils/` 及规划中模块的测试。基于System_Manifest.md模块映射表，当前测试覆盖率约25%。

**影响范围**:
- 代码质量保障不足，重构风险增加
- 新模块开发缺乏测试范例参考
- 持续集成流程测试环节薄弱

**修复建议**:
1. **短期措施** (1周内):
   - 补充 `utils/` 模块基础测试
   - 为 `factor_calculator.py` 添加因子计算边界测试
   - 为 `risk_manager.py` 添加风控规则测试
2. **中期规划** (1个月内):
   - 建立测试框架规范文档
   - 实现核心模块100%测试覆盖
   - 添加集成测试示例
3. **长期目标**:
   - 实施测试驱动开发(TDD)流程
   - 集成覆盖率报告工具

### P1: Notebooks 文档化不足

**问题 E1-P1-002**: 研发笔记缺乏规范  
**严重性**: 🟠 P1  
**发现位置**: `notebooks/` 目录  
**问题描述**: 目录仅有 `.gitkeep` 占位文件，缺乏研发过程记录与规范。研究过程不可追溯，知识沉淀不足。

**影响范围**:
- 研究过程不可追溯，实验可重复性差
- 研究成果难以转化为系统文档
- 团队协作缺乏共享研究平台

**修复建议**:
1. **建立 notebooks 模板**:
   ```markdown
   # 研究笔记标题
   
   ## 研究目标
   - 目标1: ...
   - 目标2: ...
   
   ## 数据准备
   - 数据源: ...
   - 预处理: ...
   
   ## 实验过程
   - 方法1: ...
   - 方法2: ...
   
   ## 结果分析
   - 指标对比: ...
   - 可视化: ...
   
   ## 结论与后续
   - 主要发现: ...
   - 系统集成建议: ...
   ```
2. **目录结构规划**:
   ```
   notebooks/
   ├── 01_exploratory/      # 探索性分析
   ├── 02_factor_research/  # 因子研究
   ├── 03_strategy_dev/     # 策略开发
   ├── 04_backtest_analysis/# 回测分析
   └── templates/           # 模板文件
   ```
3. **集成研究流程**:
   - 将重要研究发现提炼至 `docs/07_RESEARCH/`
   - 定期归档成熟研究笔记至 `docs/06_ARCHIVE/research/`

### P2: 测试目录结构可优化

**问题 E1-P2-001**: 测试目录层级过深  
**严重性**: 🟡 P2  
**发现位置**: `tests/unit/`, `tests/integration/`, `tests/fixtures/`  
**问题描述**: 测试目录结构层级较多，可能增加测试运行路径复杂度。当前结构为3级深度(`tests/unit/test_core.py`)。

**影响范围**:
- 测试导入语句较长: `from tests.unit.test_core import ...`
- 测试发现路径配置稍复杂
- 新人学习曲线略陡

**修复建议**:
1. **评估方案A (扁平化)**:
   ```
   tests/
   ├── test_core.py
   ├── test_factor_calculator.py
   ├── test_risk_manager.py
   ├── fixtures/           # 保留夹具目录
   └── conftest.py
   ```
   - **优点**: 导入简化，结构清晰
   - **缺点**: 文件数量增多时可能混乱
2. **评估方案B (保持现状)**:
   - 添加 `tests/__init__.py` 优化导入
   - 完善测试运行配置文档
3. **推荐方案**: 保持当前结构，但优化导入方式，待测试文件超过20个时重新评估。
