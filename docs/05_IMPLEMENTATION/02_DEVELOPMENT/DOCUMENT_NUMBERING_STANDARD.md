# 文档编号体系标准

> 清风量化系统个人开发版文档编号规范
>
> **设计原则**: 简洁实用、个人友好、适度结构化、不增加额外维护负担
> **适用范围**: 核心模块技术文档、因子库文档、风险因子文档等需要长期维护的文档
> **灵活原则**: 非核心文档可免编号，以降低维护复杂度

## 🎯 编号体系设计目标

### 1.1 核心目标
- **快速定位**: 通过编号快速识别文档所属层级和模块
- **版本无关**: 编号与文档版本解耦，避免频繁更新
- **适度结构化**: 提供必要组织结构，不过度工程化
- **个人友好**: 适合个人开发者维护，不增加额外负担

### 1.2 适用场景
| 文档类型 | 是否需要编号 | 理由 |
|----------|--------------|------|
| **核心模块技术文档** | ✅ 需要 | 长期维护，需要清晰分类 |
| **因子库文档** | ✅ 需要 | 因子数量多，需要编号管理 |
| **风险因子文档** | ✅ 需要 | 分类管理，便于查找 |
| **策略文档** | ⚠️ 可选 | 策略数量有限，可描述性命名 |
| **教程/指南文档** | ❌ 不需要 | 一次性阅读，无需编号 |
| **审计报告** | ❌ 不需要 | 按日期标识更合适 |
| **临时文档** | ❌ 不需要 | 短期使用，无需编号 |

## 📋 编号格式规范

### 2.1 标准编号格式
```
T.XX.YYY###.descriptive_name.md
```
**各字段说明**:
| 字段 | 说明 | 示例 |
|------|------|------|
| **T** | 文档类型前缀 (Technical) | 固定为 `T` |
| **XX** | 层级编号 (2位数字) | `01`=数据层, `02`=因子层, `03`=风险层 |
| **YYY** | 模块类型代码 (3位字母) | `RF`=风险因子, `DS`=数据源, `RM`=风险管理 |
| **###** | 序列号 (3位数字) | `001`, `002`, `003`... |
| **descriptive_name** | 描述性名称 (小写下划线) | `barra_style_factors` |

### 2.2 层级编号映射表 (XX字段)
| 编号 | 层级名称 | 包含模块 |
|------|----------|----------|
| **01** | 数据层 (Data Layer) | 数据源、数据清洗、数据存储 |
| **02** | 因子层 (Factor Layer) | Alpha因子、风险因子、因子计算 |
| **03** | 风险层 (Risk Layer) | 风险管理、风险因子、风险报告 |
| **04** | 策略层 (Strategy Layer) | 策略引擎、策略池、策略回测 |
| **05** | 执行层 (Execution Layer) | 交易执行、订单管理、执行算法 |
| **06** | 监控层 (Monitoring Layer) | 监控系统、告警管理、性能监控 |
| **07** | AI层 (AI Layer) | AI研究、机器学习、深度学习 |
| **08** | 架构层 (Architecture Layer) | 系统架构、设计文档、蓝图 |
| **09** | 工具层 (Tool Layer) | 开发工具、脚本、实用程序 |

### 2.3 模块类型代码表 (YYY字段)
| 代码 | 模块类型 | 说明 |
|------|----------|------|
| **RF** | Risk Factors | 风险因子 |
| **DS** | Data Sources | 数据源 |
| **RM** | Risk Management | 风险管理 |
| **FE** | Factor Engineering | 因子工程 |
| **SE** | Strategy Engine | 策略引擎 |
| **TE** | Trade Execution | 交易执行 |
| **AI** | AI Research | AI研究 |
| **AR** | Architecture | 架构设计 |
| **UT** | Utilities | 工具函数 |

## 🛠️ 实施指南

### 3.1 新文档编号分配
**分配流程**:
```
1. 确定文档层级 (参考2.2表)
2. 确定模块类型 (参考2.3表)
3. 检查现有编号，分配下一个可用序列号
4. 创建文件: T.XX.YYY###.descriptive_name.md
```

**示例: 创建新的数据源文档**
```bash
# 检查现有数据源文档编号
ls docs/02_FACTOR_LIBRARY/04_DATA_SOURCE/T.01.DS*.md

# 现有: T.01.DS001.free_data_sources.md
# 新文档编号: T.01.DS002.ifind_integration.md

# 创建文件
touch docs/02_FACTOR_LIBRARY/04_DATA_SOURCE/T.01.DS002.ifind_integration.md
```

### 3.2 现有文档迁移指南
**迁移优先级**:
1. **P1优先级**: 核心模块文档、因子库文档
2. **P2优先级**: 次要技术文档
3. **P3优先级**: 非技术文档（无需迁移）

**迁移步骤**:
```bash
# 示例: 迁移中文或无编号文档
# 原文件: docs/02_FACTOR_LIBRARY/03_RISK_FACTORS/Barra优化器.md
# 目标文件: docs/02_FACTOR_LIBRARY/03_RISK_FACTORS/T.03.RM003.barra_optimizer.md

# 1. 确定编号
#   层级: 03 (风险层)
#   模块类型: RM (风险管理)
#   序列号: 检查现有RM文档，分配003

# 2. 重命名文件
mv docs/02_FACTOR_LIBRARY/03_RISK_FACTORS/Barra优化器.md \
   docs/02_FACTOR_LIBRARY/03_RISK_FACTORS/T.03.RM003.barra_optimizer.md

# 3. 更新引用
#   搜索并更新所有引用此文件的地方
```

### 3.3 编号维护规则
**序列号分配规则**:
- **连续分配**: 同一模块内序列号连续分配
- **预留间隔**: 可预留间隔 (如001, 005, 010) 以备未来扩展
- **不重复**: 确保同一模块内编号唯一

**变更管理**:
- **编号不变**: 文档内容更新时，编号保持不变
- **层级变更**: 如文档层级变化，可更新编号 (但需谨慎)
- **模块重组**: 模块重组时，可重新分配编号

## 📊 合规性检查

### 4.1 检查清单
| 检查项 | 标准 | 工具/方法 |
|--------|------|----------|
| **编号格式正确** | 符合 `T.XX.YYY###.name.md` 格式 | 正则表达式匹配 |
| **层级编号有效** | XX在01-09范围内 | 查表验证 |
| **模块代码有效** | YYY在预定义代码表中 | 查表验证 |
| **序列号唯一** | 同一模块内序列号不重复 | 目录扫描 |
| **描述名称规范** | 小写下划线，无中文 | 命名规范检查 |

### 4.2 自动化检查脚本
```python
# 示例检查脚本 (可集成到现有工具)
def check_document_numbering(file_path: str) -> bool:
    """检查文档编号合规性"""
    import re
    
    pattern = r'^T\.(\d{2})\.([A-Z]{2,3})(\d{3})\.([a-z0-9_]+)\.md$'
    match = re.match(pattern, os.path.basename(file_path))
    
    if not match:
        return False
    
    layer = match.group(1)  # 层级
    module_type = match.group(2)  # 模块类型
    sequence = match.group(3)  # 序列号
    name = match.group(4)  # 描述名称
    
    # 验证层级有效性
    valid_layers = ['01', '02', '03', '04', '05', '06', '07', '08', '09']
    if layer not in valid_layers:
        return False
    
    # 验证模块类型有效性
    valid_modules = ['RF', 'DS', 'RM', 'FE', 'SE', 'TE', 'AI', 'AR', 'UT']
    if module_type not in valid_modules:
        return False
    
    return True
```

## 🔄 版本管理与编号解耦

### 5.1 编号与版本分离原则
**核心原则**:
- **编号标识内容分类**: 编号表示文档在系统中的位置和类型
- **版本标识内容演进**: 版本表示文档内容的更新状态
- **两者独立**: 内容更新时版本变化，编号不变

**示例**:
```
文件: T.03.RF001.barra_style_factors.md
元数据: version: 1.0.0 → 1.1.0 → 2.0.0
编号: T.03.RF001 (始终不变)
```

### 5.2 个人开发优化建议
**简化策略**:
1. **核心文档编号**: 只对需要长期维护的核心文档编号
2. **非核心文档免编号**: 教程、指南、临时文档使用描述性命名
3. **渐进实施**: 逐步迁移，不要求一次性完成
4. **工具辅助**: 使用现有工具 (blueprint_validator.py) 检查合规性

**豁免清单**:
- `README.md` 文件
- `INDEX.md`, `SITEMAP.md` 导航文件
- `CHANGELOG.md` 变更日志
- `FAQ.md` 常见问题
- 教程、快速入门指南
- 审计报告、临时分析报告
