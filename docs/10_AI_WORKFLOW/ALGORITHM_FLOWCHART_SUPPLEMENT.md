## 一、合规监控模块算法流程图

### 1.1 交易合规检查算法流程

```mermaid
graph TD
    A[接收订单] --> B{订单格式验证}
    B -->|格式错误| C[返回格式错误]
    B -->|格式正确| D{交易量检查}
    D -->|超过限制| E[记录违规: 交易量超限]
    D -->|未超限| F{交易价格检查}
    F -->|价格异常| G[记录违规: 价格异常]
    F -->|价格正常| H{交易时间检查}
    H -->|非交易时间| I[记录违规: 非交易时间]
    H -->|交易时间| J{黑名单检查}
    J -->|在黑名单| K[记录违规: 黑名单股票]
    J -->|不在黑名单| L[检查通过]
    E --> M[汇总违规项]
    G --> M
    I --> M
    K --> M
    M --> N{是否有违规}
    N -->|是| O[拦截订单]
    N -->|否| P[批准订单]
    O --> Q[发送告警]
    P --> R[记录审计追踪]
    Q --> R
    R --> S[返回检查结果]
```

**算法说明**:
1. **订单格式验证**: 检查订单字段是否完整、数据类型是否正确
2. **交易量检查**: 验证交易量是否超过预设限额（默认100000股）
3. **交易价格检查**: 验证价格是否在合理范围内（涨跌停板限制）
4. **交易时间检查**: 验证是否在交易时间内（9:30-11:30, 13:00-15:00）
5. **黑名单检查**: 验证股票是否在黑名单中
6. **决策逻辑**: 如果有任何违规项，拦截订单并发送告警；否则批准订单

**复杂度分析**:
- 时间复杂度: O(n)，n为检查规则数量
- 空间复杂度: O(1)

### 1.2 风控合规检查算法流程

```mermaid
graph TD
    A[接收持仓数据] --> B[计算持仓市值]
    B --> C{持仓限额检查}
    C -->|超过限额| D[记录违规: 持仓超限]
    C -->|未超限| E[计算未实现盈亏]
    E --> F{损失限额检查}
    F -->|超过限额| G[记录违规: 损失超限]
    F -->|未超限| H[计算VaR值]
    H --> I{VaR限额检查}
    I -->|超过限额| J[记录违规: VaR超限]
    I -->|未超限| K[计算使用率]
    D --> L[汇总违规项]
    G --> L
    J --> L
    L --> M{是否有违规}
    M -->|是| N[标记状态: breach]
    M -->|否| O{使用率检查}
    O -->|>90%| P[标记状态: warning]
    O -->|≤90%| Q[标记状态: normal]
    N --> R[发送告警]
    P --> S[发送预警]
    Q --> T[记录审计追踪]
    R --> T
    S --> T
    T --> U[返回检查结果]
```

**算法说明**:
1. **持仓限额检查**: 验证持仓市值是否超过预设限额
2. **损失限额检查**: 验证未实现盈亏是否超过损失限额
3. **VaR限额检查**: 验证VaR值是否超过风险限额
4. **使用率计算**: 计算当前使用率（持仓市值/限额）
5. **状态判定**: 根据违规项和使用率判定风险状态

**复杂度分析**:
- 时间复杂度: O(1)
- 空间复杂度: O(1)

### 1.3 监管报告生成算法流程

```mermaid
graph TD
    A[接收报告请求] --> B{报告类型判断}
    B -->|daily_report| C[查询当日合规检查记录]
    B -->|weekly_report| D[查询本周合规检查记录]
    B -->|monthly_report| E[查询本月合规检查记录]

    D --> F
    E --> F
    F --> G[计算合规率]
    G --> H[生成违规明细]

    I --> J[组装报告内容]
    J --> K[生成Markdown格式]
    K --> L[保存报告记录]

```

**算法说明**:
1. **数据查询**: 根据报告类型查询相应时间范围的合规检查记录
2. **统计计算**: 统计违规次数、计算合规率
3. **明细生成**: 生成违规明细列表
4. **建议生成**: 根据违规类型生成改进建议
5. **报告组装**: 将所有内容组装成Markdown格式报告

**复杂度分析**:
- 时间复杂度: O(n)，n为合规检查记录数量
- 空间复杂度: O(n)

## 二、实盘监控模块算法流程图

### 2.1 实时交易监控算法流程

```mermaid
graph TD
    A[启动监控线程] --> B[设置监控间隔: 1秒]
    B --> C[循环监控]
    C --> D[采集交易数据]
    D --> E{订单频率检查}
    E -->|>100/min| F[记录异常: 高频交易]
    E -->|≤100/min| G{交易量检查}
    G -->|>500000股/h| H[记录异常: 大额交易]
    G -->|≤500000股/h| I{成交金额检查}
    I -->|>10000000元/h| J[记录异常: 大额资金]
    I -->|≤10000000元/h| K[状态正常]
    F --> L[汇总异常]
    H --> L
    J --> L
    L --> M{是否有异常}
    M -->|是| N[发送告警]
    M -->|否| O[记录监控数据]
    N --> O
    O --> P{是否继续监控}
    P -->|是| C
    P -->|否| Q[停止监控]
```

**算法说明**:
1. **数据采集**: 每秒采集一次交易数据
2. **频率检查**: 验证订单频率是否超过阈值
3. **交易量检查**: 验证交易量是否超过阈值
4. **金额检查**: 验证成交金额是否超过阈值
5. **异常处理**: 发现异常立即发送告警

**复杂度分析**:
- 时间复杂度: O(1)（每次监控）
- 空间复杂度: O(1)

### 2.2 异常交易检测算法流程

```mermaid
graph TD
    A[接收交易模式] --> B[计算订单金额]
    B --> C{订单金额检查}
    C -->|>1000000元| D[记录异常: 大额订单]
    C -->|≤1000000元| E[计算订单频率]
    E --> F{订单频率检查}
    F -->|>50/min| G[记录异常: 高频订单]
    F -->|≤50/min| H[计算价格偏离度]
    H --> I{价格偏离检查}
    I -->|>5%| J[记录异常: 价格偏离]
    I -->|≤5%| K[计算成交量偏离度]
    K --> L{成交量偏离检查}
    L -->|>10%| M[记录异常: 成交量偏离]
    L -->|≤10%| N[无异常]
    D --> O[汇总异常]
    G --> O
    J --> O
    M --> O
    O --> P{是否有异常}
    P -->|是| Q[发送告警]
    P -->|否| R[返回正常]
    Q --> S[返回异常检测结果]
```

**算法说明**:
1. **订单金额检查**: 验证单笔订单金额是否异常大
2. **订单频率检查**: 验证订单频率是否异常高
3. **价格偏离检查**: 验证价格偏离度是否超过阈值
4. **成交量偏离检查**: 验证成交量偏离度是否超过阈值
5. **异常汇总**: 汇总所有异常项并判定严重程度

**复杂度分析**:
- 时间复杂度: O(1)
- 空间复杂度: O(1)

### 2.3 持仓风险监控算法流程

```mermaid
graph TD
    A[接收持仓数据] --> B[计算持仓市值]
    B --> C[获取市场数据]
    C --> D[计算未实现盈亏]
    D --> E[计算风险敞口]
    E --> F[计算VaR值]
    F --> G{风险敞口检查}
    G -->|>0.10| H[记录风险: 高风险敞口]
    G -->|≤0.10| I{VaR检查}
    I -->|<-50000| J[记录风险: 高VaR值]
    I -->|≥-50000| K[风险正常]
    H --> L[汇总风险]
    J --> L
    L --> M{是否有风险}
    M -->|是| N[发送风险告警]
    M -->|否| O[记录风险数据]
    N --> O
    O --> P[返回风险状态]
```

**算法说明**:
1. **市值计算**: 计算当前持仓市值
2. **盈亏计算**: 计算未实现盈亏
3. **风险敞口计算**: 计算风险敞口（未实现盈亏/持仓市值）
4. **VaR计算**: 使用历史模拟法计算VaR值
5. **风险判定**: 根据风险敞口和VaR值判定风险状态

**复杂度分析**:
- 时间复杂度: O(n)，n为历史数据数量（VaR计算）
- 空间复杂度: O(n)

## 三、性能分析模块算法流程图

### 3.1 性能指标采集算法流程

```mermaid
graph TD
    A[接收模块名称] --> B[初始化采集器]
    B --> C[采集CPU使用率]
    C --> D[采集内存使用率]
    D --> E[采集I/O等待时间]
    E --> F[采集网络延迟]
    F --> G[组装指标数据]
    G --> H[保存到数据库]
    H --> I[返回指标数据]
```

**算法说明**:
1. **CPU采集**: 使用psutil.cpu_percent()采集CPU使用率
2. **内存采集**: 使用psutil.virtual_memory().percent采集内存使用率
3. **I/O采集**: 使用psutil.cpu_times_percent().iowait采集I/O等待时间
4. **网络采集**: 使用ping命令采集网络延迟
5. **数据组装**: 将所有指标组装成字典格式

**复杂度分析**:
- 时间复杂度: O(1)
- 空间复杂度: O(1)

### 3.2 性能瓶颈识别算法流程

```mermaid
graph TD
    A[接收性能指标] --> B{CPU使用率检查}
    B -->|>90%| C[记录瓶颈: CPU严重瓶颈]
    B -->|80%-90%| D[记录瓶颈: CPU瓶颈]
    B -->|≤80%| E{内存使用率检查}
    E -->|>90%| F[记录瓶颈: 内存严重瓶颈]
    E -->|80%-90%| G[记录瓶颈: 内存瓶颈]
    E -->|≤80%| H{I/O等待检查}
    H -->|>30%| I[记录瓶颈: I/O瓶颈]
    H -->|≤30%| J{网络延迟检查}
    J -->|>100ms| K[记录瓶颈: 网络瓶颈]
    J -->|≤100ms| L[无瓶颈]
    C --> M[汇总瓶颈]
    D --> M
    F --> M
    G --> M
    I --> M
    K --> M
    M --> N[计算影响分数]
    N --> O[判定严重程度]
    O --> P[返回瓶颈列表]
```

**算法说明**:
1. **CPU检查**: 根据CPU使用率判定瓶颈严重程度
2. **内存检查**: 根据内存使用率判定瓶颈严重程度
3. **I/O检查**: 根据I/O等待时间判定瓶颈
4. **网络检查**: 根据网络延迟判定瓶颈
5. **影响分数计算**: 根据使用率计算影响分数

**复杂度分析**:
- 时间复杂度: O(1)
- 空间复杂度: O(1)

### 3.3 性能趋势分析算法流程

```mermaid
graph TD
    A[接收历史指标] --> B[计算平均CPU使用率]
    B --> C[计算平均内存使用率]
    C --> D[计算CPU趋势]
    D --> E[计算内存趋势]
    E --> F{趋势判定}
    F -->|上升趋势| G[预测未来使用率]
    F -->|稳定趋势| H[保持当前使用率]
    F -->|下降趋势| I[预测降低使用率]
    G --> J[计算预测值]
    H --> J
    I --> J
    J --> K{预测值检查}
    K -->|>85%| L[生成预警]
    K -->|≤85%| M[状态正常]
    L --> N[返回趋势分析结果]
    M --> N
```

**算法说明**:
1. **平均值计算**: 计算历史指标的平均值
2. **趋势计算**: 使用线性回归计算趋势
3. **趋势判定**: 判定趋势类型（上升/稳定/下降）
4. **预测计算**: 根据趋势预测未来使用率
5. **预警生成**: 如果预测值超过阈值，生成预警

**复杂度分析**:
- 时间复杂度: O(n)，n为历史数据数量
- 空间复杂度: O(n)
