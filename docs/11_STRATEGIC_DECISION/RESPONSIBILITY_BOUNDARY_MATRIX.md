## 二、职责重叠处理规则

### 2.1 职责重叠识别

**重叠类型**：
1. **完全重叠**：两个模块承担相同职责
2. **部分重叠**：两个模块职责有交集
3. **边界模糊**：模块间职责边界不清晰

### 2.2 职责重叠处理原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **单一职责原则** | 每个职责只能由一个模块承担 | 资产配置决策只能由战略资产配置模块承担 |
| **主次分明原则** | 明确主要职责和次要职责 | 再平衡决策中，再平衡触发是主要职责，成本优化是次要职责 |
| **接口清晰原则** | 模块间通过明确接口交互 | 战略资产配置通过接口向风险预算分配传递配置决策 |
| **数据流向原则** | 明确数据流向，避免循环依赖 | 数据流向：Layer 10 → Layer 11 → Layer 6-7 |

### 2.3 职责重叠处理方法

#### 方法1：职责拆分

**适用场景**：两个模块承担相同职责

**处理方法**：
1. 识别重叠职责
2. 将职责拆分为子职责
3. 将子职责分配给不同模块

**示例**：
```
重叠职责：风险分析
├── 拆分为：
│   ├── 风险预算分配（负责：风险预算分配模块）
│   ├── 风险评估（负责：Layer 7风险管理层）
│   └── 风险监控（负责：Layer 10质量保证层）
```

#### 方法2：主次划分

**适用场景**：两个模块职责有交集

**处理方法**：
1. 识别主要职责和次要职责
2. 主要职责由核心模块承担
3. 次要职责由支持模块承担

**示例**：
```
重叠职责：再平衡
├── 主要职责：再平衡决策（负责：再平衡决策模块）
└── 次要职责：再平衡执行（负责：Layer 6组合优化层）
```

#### 方法3：接口定义

**适用场景**：模块间职责边界不清晰

**处理方法**：
1. 定义明确的接口规范
2. 通过接口传递数据
3. 避免直接访问内部数据

**示例**：
```
接口定义：
战略资产配置模块 → 风险预算分配模块
├── 输入：配置决策数据
├── 输出：风险预算数据
└── 接口：RiskBudgetInterface
```
