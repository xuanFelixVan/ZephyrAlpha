## 附录 A：专业机构在做什么（给非技术读者）

可以把整件事想成 **「盖楼前的联合审图」**，和写代码不是一回事；代码是 **按图施工** 阶段的事。

| 步骤 | 机构里叫什么 | 你要做的事（白话） |
|------|----------------|-------------------|
| 1 | **立项 / 范围** | 定下来：这次只审哪几层楼（哪些目录），**不审**什么；多久做完。 |
| 2 | **冻结权威** | 定「听谁的」：一般以 **总架构** 为第一权威，其它文档不能和它打架。 |
| 3 | **对照审（只读）** | 像对表格：总架构里列了哪些模块，边界文档里有没有、写得一不一样。**先只记问题，不大改。** |
| 4 | **缺陷登记** | 每条问题贴标签：**缺了**、**两处重复**、**互相矛盾**、**蓝图没挂到总图**、**缺接口说明**（对应 G1～G5）。 |
| 5 | **分级** | **P0** = 不做会误导施工或堵死主路径；**P1/P2** 可后补。 |
| 6 | **补缺** | 先改 **总纲、边界、互链**，再写长蓝图；每改一批用 **链接扫描** 防止改坏导航。 |
| 7 | **留痕** | 登记表 + 变更记录（谁、何时、改了哪条结论），方便以后审计翻旧账。 |

**和你刚做完的「文档审计」区别**：上一轮主要管 **链接通不通、格式乱不乱**；这一轮管 **意思对不对、模块归谁、和总架构是否一致**。
