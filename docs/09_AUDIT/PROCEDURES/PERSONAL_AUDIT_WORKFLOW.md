# 个人审计工作流程

> 清风量化系统 v5.3 个人开发者快速审计流程
>
> **核心价值**: 5分钟内完成关键路径审查，防止系统质量退化
> **设计理念**: 极简高效、聚焦核心、立即反馈
> **使用场景**: 日常开发后、小变更后、蓝图设计阶段


## 🎯 快速选择你的审计场景

### 🔸 场景1: 日常开发后（推荐）
**目标**: 防止文件漂移、目录混乱  
**时间**: 3-5分钟  
**检查项**: 5个核心检查项

**适用时机**:
- 编写代码后
- 创建新文件后  
- 修改目录结构后

### 🔸 场景2: 小变更后
**目标**: 验证变更影响范围  
**时间**: 5-8分钟  
**检查项**: 8个针对性检查项

**适用时机**:
- 修改配置文件后
- 更新文档后
- 添加新依赖后

### 🔸 场景3: 蓝图设计阶段
**目标**: 确保设计文档结构健康  
**时间**: 8-12分钟  
**检查项**: 10个文档专项检查项

**适用时机**:
- 创建新蓝图文档后
- 修改系统架构后
- AI讨论新内容后


## ⚡ 5分钟快速审计流程

### 第1步: 确定审计范围（30秒）
**问自己**: "我刚才修改了什么？"
- 修改了代码？→ 检查 `src/` 相关目录
- 修改了文档？→ 检查 `docs/` 相关目录  
- 修改了配置？→ 检查 `config/` 相关目录
- 都不确定？→ 检查最近1小时修改的文件

**快速命令**:
```bash
# 查看最近1小时修改的文件
git status
# 或
find . -type f -mmin -60
```

### 第2步: 执行核心检查（3分钟）

#### 检查1: 文件漂移检查（60秒）
**目标**: 确保文件在正确目录

**检查方法**:
```python
# 心理检查清单
- src/ 目录只有代码文件吗？
- docs/ 目录只有文档文件吗？
- config/ 目录只有配置文件吗？
- tests/ 目录只有测试文件吗？
```

**常见问题**:
- 文档出现在 `src/` 目录 ❌
- 代码出现在 `docs/` 目录 ❌
- 配置文件出现在其他目录 ❌

#### 检查2: 目录健康度检查（60秒）
**目标**: 防止目录嵌套过深

**检查方法**:
- 打开修改文件所在目录
- 数一下目录深度：`项目根目录/一级/二级/三级/文件`
- 深度 ≤ 4 ✅  | 深度 > 4 ⚠️

**处理原则**:
- 深度=4: 可以接受
- 深度=5: 考虑重构
- 深度≥6: 必须重构

#### 检查3: 版本一致性检查（60秒）
**目标**: 防止版本混用

**检查方法**:
1. 查看 `config/system.yaml` 中的版本号
2. 查看修改文件的版本标识（如果有）
3. 确保一致: 都应该是 `v5.3` 相关版本

**关键文件**:
- `config/system.yaml` - 应该为 `version: "5.1.0"`
- `docs/System_Manifest.md` - 应该为 `version: 5.1`

### 第3步: 记录与反馈（1.5分钟）

#### 发现问题时:
1. **立即记录** (30秒)
   - 问题描述: 一句话说清楚
   - 位置: 具体文件路径
   - 严重性: 🔴严重/🟡中等/🟢轻微

2. **立即修复** (60秒)
   - 简单问题: 立即修复
   - 复杂问题: 创建TODO并计划修复时间

#### 无问题时:
- **记录**: "✅ 快速审计通过，无核心问题"
- **时间戳**: 记录审计时间
- **信心值**: 系统健康度评估（高/中/低）


## 📋 个人审计检查清单

### 快速检查清单（5项核心）

**每次审计必检查**:
- [ ] **文件位置正确**: 文件在正确目录（src/docs/config/tests）
- [ ] **目录深度合理**: 目录嵌套 ≤ 4层
- [ ] **版本标识一致**: 修改文件版本与系统版本一致
- [ ] **关键引用完整**: 修改文件在System_Manifest中有记录
- [ ] **命名规范符合**: 文件名符合命名规范

### 扩展检查清单（8项标准）

**小变更后检查**:
- [ ] **配置文件完整**: 新增配置有默认值
- [ ] **环境变量安全**: 无硬编码密钥
- [ ] **依赖关系正确**: 新增依赖已记录
- [ ] **接口兼容性**: 修改不影响现有接口

### 深度检查清单（10项完整）

**蓝图设计阶段检查**:
- [ ] **文档引用完整**: 新文档有正确引用
- [ ] **索引更新**: INDEX.md/SITEMAP.md已更新
- [ ] **职责清晰**: 新文档职责明确
- [ ] **路径简化**: 引用路径无冗余 `../`
- [ ] **版本管理**: 文档有版本标识


## 🔧 审计工具快速使用

### 自动化脚本使用

**文件系统健康扫描**:
```bash

```

**输出示例**:
```

📊 统计信息:
  - 总文件数: 156
  - 目录深度: 平均3.2层 (最大5层)
  - 文件漂移: 0个
  - 孤儿文件: 2个 (1.3%)
🔍 建议: 检查孤儿文件并注册到System_Manifest
```

### 手动检查快捷命令

**检查文件漂移**:
```bash
# 检查src/目录中的非代码文件
find src/ -type f ! -name "*.py" ! -name "*.pyx" ! -name "*.so" ! -name "__init__.py"

# 检查docs/目录中的非文档文件  
find docs/ -type f ! -name "*.md" ! -name "*.yaml" ! -name "*.yml" ! -name "*.json"
```

**检查目录深度**:
```bash
# 查找深度>4的目录
find . -type d | awk -F'/' '{print NF-1 " " $0}' | sort -nr | head -10
```

**检查版本标识**:
```bash
# 查找版本标识
grep -r "version:" config/ docs/ --include="*.yaml" --include="*.yml" --include="*.md"
```

## 🚨 常见问题快速处理

### 问题1: 发现文件漂移

**症状**: 代码文件出现在 `docs/` 目录
**快速处理**:
1. 确认文件类型（代码/文档/配置）
2. 移动到正确目录
3. 更新所有引用该文件的路径
4. 运行快速审计验证

**预计时间**: 2-3分钟

### 问题2: 目录嵌套过深

**症状**: 路径如 `src/modules/submodule/deep/more/deeper/file.py`
**快速处理**:
1. 评估是否真的需要这么深
2. 考虑扁平化重构
3. 创建重构计划（如果不是紧急）
4. 记录为技术债务

**预计时间**: 评估1分钟，重构5-30分钟

### 问题3: 版本不一致

**症状**: 不同文件显示不同系统版本
**快速处理**:
1. 确定正确版本（查看system.yaml）
2. 更新不一致的文件版本标识
3. 检查版本引用一致性
4. 运行版本一致性检查

**预计时间**: 1-2分钟

### 问题4: 孤儿文件

**症状**: 文件未在System_Manifest.md中记录
**快速处理**:
1. 判断文件是否重要
2. 重要: 添加到System_Manifest
3. 不重要: 考虑删除或归档
4. 更新相关引用

**预计时间**: 1-2分钟


## 📈 审计效率提升技巧

### 技巧1: 批量处理类似问题

**场景**: 发现多个类似规范问题
**方法**: 创建批量修复脚本
**示例**:
```bash
# 批量重命名文件
for file in *.md; do mv "$file" "${file// /_}"; done
```

### 技巧2: 设置审计提醒

**场景**: 容易忘记执行审计
**方法**: 在开发流程中嵌入审计
**示例**:
```bash
# 在git pre-commit钩子中添加审计
#!/bin/bash
python scripts/audit_filesystem.py --quick
if [ $? -ne 0 ]; then
  echo "审计失败，请修复问题后再提交"
  exit 1
fi
```

### 技巧3: 建立个人审计习惯

**最佳实践**:
1. **开发后立即审计** - 趁热打铁
2. **小步多次审计** - 每次修改都审计
3. **记录审计历史** - 跟踪系统健康度趋势
4. **定期回顾** - 每月回顾审计记录

### 技巧4: 使用审计模板

**节省时间**:
- 复制审计记录模板
- 使用自动化脚本
- 建立个人快捷命令库
- 创建常见问题处理指南
