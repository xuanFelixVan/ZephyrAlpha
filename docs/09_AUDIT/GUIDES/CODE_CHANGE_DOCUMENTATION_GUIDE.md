## 1. 概述

### 1.1 指南目的

本指南为开发人员提供代码变更时的文档更新操作指南，确保代码和文档保持同步。

### 1.2 适用范围

本指南适用于所有代码变更场景，包括新功能开发、Bug修复、性能优化、架构调整等。

### 1.3 核心原则

**代码变更 = 文档变更**

每次代码变更都应该考虑是否需要更新文档。

## 3. 文档更新操作流程

### 3.1 代码变更前

**步骤1: 评估文档影响**

```bash
# 查看本次变更的文件
git status

# 查看变更内容
git diff

# 评估是否需要文档更新
# 问自己：用户、运维、其他开发人员需要知道这个变更吗？
```

**步骤2: 确定需要更新的文档**

根据代码变更类型，参考第2节的文档更新要求，确定需要更新的文档列表。

**步骤3: 创建文档更新任务**

在项目管理工具中创建文档更新任务，关联到代码变更任务。

### 3.2 文档更新中

**步骤1: 使用文档模板**

```bash
# 使用标准文档模板创建新文档
cp docs/09_AUDIT/TEMPLATES/DOCUMENT_TEMPLATE.md docs/XX_CATEGORY/NEW_DOCUMENT.md
```

**步骤2: 填写元数据**

确保填写所有必需的元数据字段：

```yaml
---
standard_type: 技术文档
applicable_scope: 全系统
compliance_level: 初始标准
parent_document: ../INDEX.md
implementation_status: 已完成
owner: 文档所有者
version: 1.0.0
module_id: MODULE_ID
created_date: 2026-04-02
last_updated: 2026-04-02
---
```

**步骤3: 编写文档内容**

按照文档模板的结构编写内容，确保：
- 内容完整，无占位符
- 语言清晰，易于理解
- 示例代码可运行
- 链接有效

**步骤4: 更新相关索引**

如果创建了新文档，需要更新相关索引文件：

```bash
# 更新目录索引
vim docs/XX_CATEGORY/INDEX.md

# 更新系统清单
vim docs/System_Manifest.md
```

### 3.3 文档更新后

**步骤1: 运行质量检查**

```bash
# 检查文档链接
python scripts/document_auditor.py --check-links

# 检查元数据完整性
python scripts/metadata_enhancer.py --scan

# 检查文档分类
python scripts/document_classifier.py --scan
```

**步骤2: 提交文档变更**

```bash
# 添加文档变更
git add docs/

# 提交文档变更
git commit -m "docs: 更新XX文档以反映YY变更"

# 推送到远程仓库
git push origin feature-branch
```

**步骤3: 代码合并前检查**

确保所有文档更新都已完成，并且通过了质量检查。

## 5. 文档更新最佳实践

### 5.1 及时性原则

- **代码合并前**: 更新用户可见的文档
- **代码合并后**: 更新内部技术文档
- **不超过3天**: 所有文档更新应在代码合并后3天内完成

### 5.2 完整性原则

- **内容完整**: 无占位符、无TODO标记
- **元数据完整**: 所有必需字段都已填写
- **索引完整**: 新文档已添加到相关索引

### 5.3 准确性原则

- **代码对应**: 文档描述与实际代码一致
- **示例可运行**: 代码示例可以实际运行
- **链接有效**: 所有链接都指向有效文档

### 5.4 可维护性原则

- **结构清晰**: 使用标准文档模板
- **命名规范**: 使用标准命名格式
- **分类正确**: 文档位于正确的目录

## 6. 文档更新检查工具

### 6.1 自动化检查脚本

```bash
#!/bin/bash
# 文档更新检查脚本

echo "开始文档更新检查..."

# 1. 检查是否有代码变更
CODE_CHANGED=$(git diff --name-only HEAD~1 | grep -E '\.(py|js|ts)$' | wc -l)

if [ $CODE_CHANGED -gt 0 ]; then
    echo "检测到代码变更，检查文档更新..."
    
    # 2. 检查是否有文档变更
    DOC_CHANGED=$(git diff --name-only HEAD~1 | grep -E '\.md$' | wc -l)
    
    if [ $DOC_CHANGED -eq 0 ]; then
        echo "⚠️  警告: 代码变更但未检测到文档更新"
        echo "请确认是否需要更新文档"
    else
        echo "✅ 检测到文档更新"
    fi
fi

# 3. 运行文档质量检查
python scripts/document_auditor.py --quick

echo "文档更新检查完成"
```

### 6.2 Git Hook配置

在`.git/hooks/pre-commit`中添加：

```bash
#!/bin/bash
# 代码提交前文档检查

# 检查文档链接
python scripts/document_auditor.py --check-links
if [ $? -ne 0 ]; then
    echo "❌ 文档链接检查失败，请修复后再提交"
    exit 1
fi

# 检查元数据完整性
python scripts/metadata_enhancer.py --scan
if [ $? -ne 0 ]; then
    echo "❌ 元数据完整性检查失败，请修复后再提交"
    exit 1
fi

echo "✅ 文档检查通过"
exit 0
```

## 7. 常见问题

### Q1: 代码变更很小，需要更新文档吗？

**A**: 取决于变更的影响范围。如果变更对用户、运维或其他开发人员有影响，就需要更新文档。

### Q2: 文档更新太耗时，怎么办？

**A**: 
1. 使用文档模板，减少编写时间
2. 只更新必要的文档
3. 利用自动化工具检查质量
4. 将文档更新纳入开发流程，养成习惯

### Q3: 忘记更新文档怎么办？

**A**: 
1. 设置Git Hook，在代码提交前提醒
2. 定期运行文档审计，发现不一致
3. 建立文档更新检查清单

### Q4: 文档和代码不一致怎么办？

**A**: 
1. 立即更新文档，使其与代码一致
2. 在文档中标注更新时间和版本
3. 通知相关人员文档已更新
