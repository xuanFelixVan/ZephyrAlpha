# 文档治理定期检查计划

> **核心职责**: 定义文档治理的定期检查机制
> **职责边界**: 
> - [OK] 本文档负责：检查计划、检查频率、检查内容
> - [NO] 本文档不负责：具体检查执行、问题修复

**计划范围**: 全系统文档

**计划状态**: 已建立

## 检查内容

### 1. 元数据完整性检查

**检查项**:
- [ ] 是否有YAML元数据块
- [ ] 是否包含所有必需字段
- [ ] 字段值是否符合规范
- [ ] 版本号格式是否正确
- [ ] 日期格式是否正确

**检查脚本**: `scripts/check_metadata_completeness.py`

**质量目标**:
- 元数据符合率 ≥ 95%
- 必需字段完整率 100%

---

### 2. 引用链接检查

**检查项**:
- [ ] 链接是否有效
- [ ] 链接路径是否正确
- [ ] 是否存在死链接
- [ ] 是否存在循环引用

**检查脚本**: `scripts/check_links.py`

**质量目标**:
- 链接有效率 ≥ 99.9%
- 死链接数量 = 0

---

### 3. 职责描述检查

**检查项**:
- [ ] 是否有职责描述
- [ ] 职责描述是否清晰
- [ ] 职责边界是否明确
- [ ] 是否符合职责驱动原则

**检查脚本**: `scripts/check_responsibility.py`

**质量目标**:
- 职责符合率 ≥ 95%
- 职责描述清晰度 ≥ 90%

---

### 4. 质量指标监控

**检查项**:
- [ ] 文档指标（总文件数、元数据符合率、职责符合率）
- [ ] 引用指标（总链接数、有效链接、无效链接、有效率）
- [ ] 结构指标（最大深度、平均深度、深层文件数）
- [ ] 合规指标（合规分数、合规等级）

**检查脚本**: `scripts/quality_metrics_monitoring.py`

**质量目标**:
- 合规分数 ≥ 80/100
- 合规等级 ≥ 合格

## 检查流程

### 自动检查流程

```
1. 执行检查脚本
   ↓
2. 生成检查报告
   ↓
3. 识别问题文档
   ↓
4. 生成问题清单
   ↓
5. 通知负责人
```

### 人工审核流程

```
1. 审查检查报告
   ↓
2. 分析问题原因
   ↓
3. 制定修复方案
   ↓
4. 执行修复操作
   ↓
5. 验证修复效果
```

## 检查报告

### 报告格式

所有检查报告应包含以下内容：

1. **检查概要**: 检查时间、范围、方法、结论
2. **检查统计**: 检查项数量、通过率、问题数量
3. **问题详情**: 具体问题描述、位置、影响
4. **改进建议**: 立即行动、持续改进、长期优化

### 报告存储

- **存储位置**: `docs/09_AUDIT/STATE/`
- **命名格式**: `[检查类型]_REPORT_[时间戳].md`
- **保留期限**: 永久保留
