#### 职责边界定义

| 层级 | 职责范围 | 时间框架 | 关键指标 | 输出 |
|------|---------|---------|---------|------|
| **宏观层** | 经济周期识别 | 季度/年度 | GDP、CPI、PMI、利率 | 经济范式标签 |
| **中观层** | 市场状态识别 | 周/月 | 趋势、波动率、成交量 | 市场状态标签 |
| **微观层** | 实时状态感知 | 分钟/小时 | 订单流、价差、深度 | 实时状态信号 |

#### 职责冲突解决

**问题**: 多个文档涉及市场状态识别，职责边界模糊

**解决方案**:
1. 明确层级定位：每个文档只负责一个层级的市场状态识别
2. 统一命名规范：使用层级前缀区分（MACRO_/MESO_/MICRO_）
3. 建立调用关系：宏观层 → 中观层 → 微观层

## 📊 职责边界管理机制

### 1. 职责注册机制

每个文档必须在YAML头部明确声明其职责边界：

```yaml
---
module_id: EXAMPLE_MODULE_001
version: 1.0.0
responsibility_boundary:
  layer: "中观策略层"
  scope: "市场状态识别"
  time_frame: "周/月"
  input: ["价格数据", "成交量数据"]
  output: ["市场状态标签", "置信度"]
  excludes: ["宏观经济分析", "日内交易信号"]
---
```

### 2. 职责冲突检测

定期运行职责冲突检测脚本：

```powershell
# 检测职责重叠
$keywords = @("市场状态识别", "风险预算", "数据质量")
foreach ($keyword in $keywords) {
    $files = Get-ChildItem -Path "docs" -Recurse -Filter "*.md" |
             Where-Object { $_.FullName -notlike "*audit_state*" -and
                           $_.FullName -notlike "*archive*" }

    $matches = @()
    foreach ($file in $files) {
        $content = Get-Content $file.FullName -Raw
        if ($content -match $keyword) {
            $matches += $file.FullName
        }
    }

    if ($matches.Count -gt 10) {
        Write-Host "警告: '$keyword' 涉及 $($matches.Count) 个文件，可能存在职责重叠" -ForegroundColor Yellow
    }
}
```

### 3. 职责边界审查流程

1. **新增文档审查**: 检查是否与现有文档职责冲突
2. **定期审查**: 每月审查职责边界是否清晰
3. **冲突解决**: 发现冲突后立即协调解决
4. **文档更新**: 更新职责边界地图
