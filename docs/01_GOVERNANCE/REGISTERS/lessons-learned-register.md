# 教训记录册 (Lessons Learned Register)

> **用途**：记录项目历史中的关键失误、事故和教训，防止重蹈覆辙。
> AI 进入项目前应读取本文件，了解已知的系统性风险。

---

## LL-001：正则双重转义导致的扫描死循环（2026-04）

| 字段 | 内容 |
|------|------|
| **事件** | `VALID_VERSION_PATTERN` 被定义为 `r"^\\d+\\.\\d+\\.\\d+$"` 而非正确的 `r"^\d+\.\d+\.\d+$"`，导致扫描器误报 3587 个文件版本格式错误，AI 陷入修复死循环 |
| **影响** | 数百次无效修复操作，浪费大量计算资源；多个文件被错误修改 |
| **根因** | 未在修改正则前在 Python REPL 中验证；无修改后立即测试的强制机制 |
| **防护措施** | 禁止修改 `scripts/governance/constants.py` 中任何正则表达式，除非先验证；修改后必须运行 `python scripts/tests/test_constants.py` |
| **规则已更新** | `.cursor/rules/audit-system.mdc` — 死循环防护章节 |

## LL-002：双编辑器（Cursor + Trae）导致编码损坏（2026-04）

| 字段 | 内容 |
|------|------|
| **事件** | Cursor 和 Trae 交替编辑同一文件，导致多个治理核心文件编码损坏（出现阿拉伯文乱码） |
| **已知受损文件** | `docs/08_KNOWLEDGE/INDEX.md`、`docs/00_OVERVIEW/data-flow.md`、`onboarding-guide.md`、`ARCHIVED.md` |
| **根因** | Trae 默认编码与 Cursor 不一致；未设置 `files.autoGuessEncoding: false` |
| **防护措施** | 切换编辑器前后运行编码检查脚本；禁止 PowerShell `Out-File` 默认写文件 |

---

## LL-003：.cursor/rules 路径体系与实际仓库脱节（2026-04）

| 字段 | 内容 |
|------|------|
| **事件** | `.cursor/rules/` 定义了一套"理想目录结构"，但对应目录从未在磁盘上创建，导致 AI 每次会话都在尝试读取不存在的文件 |
| **影响** | 至少 25 处幻影引用；新 AI 无法正确执行"会话启动强制协议" |
| **根因** | 规则在设计阶段编写，但未与实际迁移工作同步执行 |
| **修复** | 2026-04-16 创建缺失目录和文件；更新规则路径 |

---

## LL-004：蓝图归档无价值提取（2026-04）

| 字段 | 内容 |
|------|------|
| **事件** | 265 个蓝图被批量归档，无结构化元数据、无价值提取，信息大量流失 |
| **影响** | 知识库仅剩 ~10 篇实质内容；已归档蓝图的设计决策无法追溯 |
| **根因** | 无正式的蓝图退役流程；"归档"被简单理解为物理搬运 |
| **防护** | Phase B 建立 `blueprint-lifecycle-standard.md`，退役时强制触发价值提取 Checklist |

---

## LL-005：重复子系统静默增殖（2026-04）

| 字段 | 内容 |
|------|------|
| **事件** | 仓库中形成 12 对功能重复的子系统/目录，总计约 1400+ 文件分散存储 |
| **根因** | 无子系统注册表；每次重构只创建新目录，不清理旧目录 |
| **防护** | Phase 0 创建 `subsystem-registry.yaml`；Phase E 创建 pre-commit hook 阻止无登记的新目录 |

---

## LL-006：舆情层五轮迭代文档膨胀（2026-04）

| 字段 | 内容 |
|------|------|
| **事件** | 舆情分析层（Layer 10）在设计阶段产生 5 轮迭代文档（补充模块蓝图、完整性评估报告、专业差距分析），合计约 18 个文件。由于每轮都生成全量文件而非增量 diff，文档总量膨胀至无法维护 |
| **影响** | 18 个过程文档全部编码损坏（GBK vs UTF-8 冲突），无法提取内容；关键设计决策（模型选型、数据源选择）被埋入无法读取的迭代报告中 |
| **根因** | 迭代过程中未强制使用"增量记录"模式；每轮"补充报告"都完整复制上一轮内容并追加变更，导致冗余比率 >90% |
| **防护** | 蓝图设计遵循：一个模块 = 一个蓝图文件（持续更新版本号），禁止为每轮修改创建新的"补充"文件；关键决策即时录入 `TECH_DECISION_RECORDS.md` |

---

## LL-007：大规模物理归档导致信息不可达（2026-04）

| 字段 | 内容 |
|------|------|
| **事件** | `06_ARCHIVE/blueprints/` 积累 223 个文件，其中最大文件达 335KB（`qingfeng-v4-draft.md`）。文件全部采用 GBK 编码写入，在 UTF-8 环境下完全不可读 |
| **影响** | 这批文件代表项目早期的核心架构设计，但因编码损坏已永久丢失（2026-04-16 统一删除） |
| **根因** | 编辑器默认 GBK 编码；无编码一致性检查；退役时直接"搬入归档区"而非提取知识 |
| **防护** | 写入文件必须显式 `encoding='utf-8'`；价值提取协议要求：退役 = 提取 + 删除，禁止直接搬入归档区 |
