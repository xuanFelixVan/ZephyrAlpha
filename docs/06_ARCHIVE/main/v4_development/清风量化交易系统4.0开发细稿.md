## 系统模块结构清单

### 1. 系统概述

#### 1.1 系统定位
一个**完全由AI驱动的个人量化交易平台**，具备自主学习进化能力，集成先进AI智能体框架，**聚焦国内市场**，深度支持A股、国金证券QMT等国内交易市场和平台，让非技术用户也能构建专业交易系统。

**核心价值主张**：让完全不懂编程的个人投资者，通过最自然的方式(输入文字内容、画线、上传文件)就能获得一个持续进化、专业级的个人量化交易系统，真正实现"你的交易思维，AI来编程"。

#### 1.2 核心架构
采用**三大阶段、九大核心平台**的业务与技术混合架构，形成从研究到实盘再到迭代的完整闭环：

##### 1.2.1 三大阶段
- **研究域（策略实验室）**：将投资思想转化为经过严格验证的、可部署的策略代码
  - 核心功能：数据研究、因子开发、策略设计、回测验证
  - 目标：高效验证投资策略，确保策略的科学性和有效性

- **交易域（生产车间）**：将验证通过的策略安全、可靠、高效地投入实盘交易
  - 核心功能：订单管理、风险控制、智能路由、实盘执行
  - 目标：保障策略的安全执行，优化交易成本，提高执行效率

- **运营域（指挥与保障中心）**：保障系统7x24稳定运行，监控业绩，处理日常运营，并驱动系统持续进化
  - 核心功能：系统监控、绩效分析、风险管理、运维保障
  - 目标：确保系统稳定运行，提供决策支持，实现系统持续优化

##### 1.2.2 九大核心平台

| 平台名称 | 所属阶段 | 核心功能 | 主要模块映射 |
|---------|---------|---------|-------------|
| **数据平台** | 研究域 | 多源数据采集、处理、存储和服务 | 数据管理系统 |
| **因子研究与策略开发平台** | 研究域 | 因子库管理、策略IDE与研究环境、回测引擎和策略分析 | 研究阶段系统、策略开发框架 |
| **模拟交易平台** | 研究域 | 仿真交易环境，验证策略实盘表现 | 模拟交易系统 |
| **统一交互入口** | 研究域 | 研究域的总控台，集成策略IDE、数据看板、实验追踪和监控视图 | 统一交互入口模块 |
| **AI增强研究工具** | 研究域 | 因子挖掘、参数优化、报告解读等AI辅助功能 | AI智能体框架 |
| **实时风控中心** | 交易域 | 事前、事中、事后的全方位风险控制 | 风险管理系统 |
| **订单执行与路由系统** | 交易域 | 订单管理、智能路由和交易所网关 | 实盘交易系统 |
| **监控与运维平台** | 运营域 | 保障系统稳定运行，监控系统和业务状态 | 监控与评估系统、核心基础设施 |
| **实盘绩效与会计平台** | 运营域 | 实盘归因分析、会计清算和投资者报告 | 监控与评估系统 |

#### 1.3 核心目标
- 构建**AI驱动的高性能、高可用**量化交易平台
- 实现**AI智能体自主决策**的交易系统，具备自主学习进化能力
- **聚焦国内市场**，深度支持A股、国金证券QMT等国内交易市场和平台
- 集成**vnpy.alpha**增强国内市场因子研究能力，提供专业的多因子机器学习框架
- 提供**完整的回测、模拟交易和实盘交易**功能
- 建立**AI增强的全面风险管理体系**
- 实现系统的**可观测性、可维护性和可扩展性**
- 设计**模块化、低耦合**的扩展架构
- 提供**友好的可视化交互界面**，保留五区域布局和NozyIO可视化编辑系统
- 形成**研究-实盘-分析**的完整数据流闭环

#### 1.4 核心设计原则
- **模块独立性**：每个模块可独立开发、测试和部署，降低耦合度
- **可测试性**：所有功能均设计为可测试的单元，确保系统质量
- **可复用性**：核心功能和组件设计为可复用的模块，提高开发效率
- **优先级驱动**：按照模块重要性和依赖关系分阶段开发，确保核心功能优先实现
- **开源优先**：优先使用成熟的开源框架，减少定制开发，提高系统可靠性
- **AI友好**：模块接口清晰标准化，支持AI智能体自主调用，实现AI与系统的深度融合
- **渐进式增强**：基础功能先行，高级功能后续，确保系统的稳定性和可用性
- **数据驱动**：基于数据进行决策，确保策略的科学性和有效性
- **安全可靠**：采取多层次安全措施，确保系统和数据的安全

#### 1.5 开发优先级

| 优先级 | 模块类别 | 具体模块 |
|-------|---------|---------|
| **高优先级** | 核心基础设施 | 核心基础设施、统一交互入口 |
| **高优先级** | 研究域核心 | 数据管理系统、研究阶段系统、策略开发框架、回测系统、模拟交易系统 |
| **高优先级** | AI核心 | AI智能体框架 |
| **高优先级** | 交易域核心 | 实盘交易系统、风险管理系统、交易所适配器（A股、国金证券QMT） |
| **高优先级** | 可视化编辑 | NozyIO可视化编辑系统 |
| **中优先级** | 运营域核心 | 监控与评估系统 |
| **中优先级** | AI增强 | AI学习模块 |
| **低优先级** | 扩展功能 | 高级可视化功能、语音交互功能、第三方系统集成

#### 1.6 开发阶段划分
1. **模块级分析阶段**：分析现有模块结构，识别边界和关系，明确模块间的依赖关系
2. **核心基础设施开发**：构建系统的基础框架，包括API网关、认证授权、消息队列等
3. **研究域模块开发**：开发数据管理、因子研究、策略开发、回测验证等核心研究功能
4. **交易域模块开发**：开发订单管理、风险控制、实盘执行等核心交易功能
5. **运营域模块开发**：开发监控系统、绩效分析、运维保障等核心运营功能
6. **AI增强功能开发**：集成AI智能体框架，开发AI辅助研究、AI风控等增强功能
7. **系统整合与测试**：进行模块间集成测试和系统级测试，确保系统的稳定性和可用性
8. **部署与试运行**：系统部署到生产环境，进行试运行和性能优化
9. **迭代优化**：根据用户反馈和运行数据，持续优化系统功能和性能

### 2.13 Docker容器化环境选择

#### 2.13.1 Docker Desktop是否是最佳选择？

**Docker Desktop的优势**：
- **跨平台支持**：同时支持Windows、macOS和Linux（部分发行版）
- **用户友好的图形界面**：提供直观的容器管理界面，便于可视化操作
- **内置Kubernetes支持**：简化Kubernetes集群的搭建和管理
- **WSL 2集成**：在Windows上提供接近原生Linux的性能
- **自动更新**：确保使用最新的Docker版本和安全补丁
- **与Docker Hub深度集成**：方便获取和管理容器镜像
- **丰富的插件生态**：支持多种扩展功能

**Docker Desktop的局限性**：
- **商业使用许可**：对于大型企业（250人以上或年收入超过1000万美元）需要购买商业许可证
- **资源消耗较大**：在开发环境中可能占用较多CPU和内存资源
- **Linux平台支持有限**：在某些Linux发行版上不如直接使用Docker Engine高效
- **网络配置复杂**：跨平台网络配置可能存在一定复杂性

**针对量化交易系统的最佳实践**：
- **开发环境**：推荐使用Docker Desktop，提供良好的开发体验和跨平台支持
- **测试环境**：可以使用Docker Desktop或Docker Engine，根据团队熟悉程度选择
- **生产环境**：推荐直接使用Docker Engine（Linux），提供更高的性能和更低的资源消耗

**替代方案**：
- **Docker Engine**：直接安装在Linux系统上，性能优异，资源消耗低
- **Podman**：无守护进程的Docker替代方案，与Docker API兼容
- **LXD**：Linux容器管理器，提供更完整的系统容器支持
- **containerd**：底层容器运行时，适合高性能场景

**结论**：对于清风量化交易系统4.0的开发和测试环境，Docker Desktop是一个优秀的选择，提供了良好的用户体验和跨平台支持。对于生产环境，建议使用直接安装在Linux系统上的Docker Engine，以获得更高的性能和更低的资源消耗。

#### 2.10 风险管理系统

##### 2.10.1 风险指标计算

**市场风险指标**：
- **VaR（在险价值）**：使用历史模拟法、方差-协方差法、蒙特卡洛模拟法计算
- **CVaR（条件在险价值）**：评估极端情况下的潜在损失
- **波动率**：计算日/周/月收益率标准差
- **最大回撤**：评估策略的最大损失幅度
- **夏普比率**：风险调整后收益指标
- **索提诺比率**：下行风险调整收益指标
- **卡尔玛比率**：收益率与最大回撤的比值

**信用风险指标**：
- **违约概率（PD）**：使用机器学习模型预测交易对手违约概率
- **违约损失率（LGD）**：评估违约情况下的损失比例
- **信用利差**：计算债券收益率与无风险利率的差值
- **Z-score**：评估企业财务健康状况

**流动性风险指标**：
- **成交量**：评估资产的交易活跃度
- **换手率**：计算资产的交易频率
- **买卖价差**：评估资产的买卖成本
- **市场深度**：评估市场的流动性提供能力
- **Amihud流动性比率**：衡量价格对交易量的敏感度

### 3. AI能力实现方案

#### 3.1 AI模型选择

##### 3.1.1 核心AI模型
- **首选方案**：使用云API大模型作为主要AI驱动
  - **GPT-4o**：用于复杂交易决策、自然语言理解和生成
  - **Claude 3**：用于长文本处理、金融分析报告生成
- **备用方案**：本地大模型作为备份和补充
  - **DeepSeek-R1**：中文金融领域表现优秀，支持本地部署
  - **Qwen-DeepResearch**：支持多模态输入，适合复杂交易场景
- **模型选择原则**：
  - 优先使用云API模型，保证模型性能和更新速度
  - 本地模型作为备份，确保系统在网络中断时仍能运行
  - 根据任务复杂度自动选择合适的模型

##### 3.1.2 AI框架集成
- **核心框架**：LangChain+LangGraph
  - 提供强大的AI自主决策和工具调用能力
  - 支持复杂工作流编排
- **多智能体协作**：
  - AutoGen：用于对话式多智能体协作
  - CrewAI：用于组建分工明确的AI团队

#### 3.2 训练数据管理

##### 3.2.1 数据来源
- **市场数据**：A股、期货等历史行情数据
- **交易数据**：策略回测数据、模拟交易数据、实盘交易数据
- **用户交互数据**：用户输入的交易思维、画图标注、反馈数据
- **外部数据**：研究报告、新闻事件、宏观经济数据
- **AI生成数据**：AI智能体生成的模拟交易数据、优化后的策略参数组合

##### 3.2.2 数据处理流程
1. **数据采集**：自动采集多源数据，支持定时更新和事件触发更新
2. **数据清洗**：去除异常值、填补缺失值、数据标准化，使用离群值检测算法（如Isolation Forest）
3. **特征工程**：
   - 技术特征：均线、MACD、RSI等传统指标
   - 基本面特征：财务报表数据、估值指标
   - 情绪特征：新闻情感分析、社交媒体情绪
   - 另类特征：订单簿数据、成交量分布
   - 支持AI自动特征发现（使用AutoML工具如TPOT、AutoKeras）
4. **数据存储**：
   - 热数据（最近1-3个月）：Redis缓存，快速访问
   - 温数据（3个月-1年）：InfluxDB，时序数据优化
   - 冷数据（1年以上）：PostgreSQL+压缩，长期存储
5. **数据安全**：
   - 端到端加密，数据传输和存储全程加密
   - 基于角色的访问控制（RBAC）
   - 数据脱敏处理
   - 符合金融行业合规要求（如等保2.0）

##### 3.2.3 AI数据标注与增强
- **半监督学习**：结合少量人工标注数据和大量未标注数据
- **数据增强技术**：
  - 时间序列增强：滑动窗口、旋转、缩放
  - 合成数据生成：使用GAN生成仿真市场数据
  - 样本均衡：解决类别不平衡问题
- **主动学习**：AI智能体自动识别需要人工标注的数据点
