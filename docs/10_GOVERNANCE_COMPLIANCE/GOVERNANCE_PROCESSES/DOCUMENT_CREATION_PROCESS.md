# 文档创建流程

> **核心职责**: 文档内容说明
> **职责边界**: 
> - ✅ 本文档负责：文档内容说明相关内容
> - ❌ 本文档不负责：其他模块内容


> **版本**: v1.0.0

> **适用范围**: 全系统文档创建流程
> **合规级别**: 专业标准

---

## 📋 一、流程概述

### 1.1 流程目标

本文档规定文档创建的标准流程，确保：
- ✅ 文档创建过程规范化
- ✅ 文档质量符合专业标准
- ✅ 文档职责描述清晰明确
- ✅ 文档索引完备准确

### 1.2 适用范围

本流程适用于：
- 蓝图文档创建
- 技术规格书创建
- 实施指南创建
- 治理文档创建
- 所有需要纳入文档治理体系的文档

### 1.3 流程原则

**原则1: 标准化**
- 使用标准文档模板
- 遵循命名规范
- 符合结构标准

**原则2: 质量优先**
- 确保文档质量
- 避免职责重叠
- 保持索引完备

**原则3: 可追溯**
- 记录创建过程
- 保留审批记录
- 维护版本历史

## 🔍 二、创建前准备阶段

### 2.1 需求确认

**步骤1: 明确文档需求**
```
□ 确定文档类型（蓝图/技术规格/实施指南/治理文档）
□ 确定文档目标（解决什么问题）
□ 确定目标读者（谁会阅读）
□ 确定文档范围（包含哪些内容）
```

**步骤2: 评估必要性**
```
□ 是否已有类似文档？
□ 是否可以复用现有文档？
□ 是否真的需要新建文档？
□ 文档的长期价值如何？
```

**步骤3: 确认资源**
```
□ 是否有足够的技术资料？
□ 是否有足够的时间？
□ 是否有合适的编写人员？
□ 是否有审批人员？
```

## ✍️ 三、文档创建阶段

### 3.1 编写YAML头部

**必需字段**:
```yaml
---
module_id: [模块ID]           # 必需：唯一标识符
version: 1.0.0               # 必需：版本号
status: Active               # 必需：状态
created_date: 2026-04-07    # 必需：创建日期
last_updated: 2026-04-07    # 必需：最后更新日期
owner: [负责人]              # 必需：负责人
layer: [层级]                # 必需：层级
standard_type: [标准类型]    # 必需：标准类型
applicable_scope: [适用范围] # 必需：适用范围
compliance_level: 专业标准   # 必需：合规级别
---
```

**字段说明**:
- `module_id`: 格式为 `[模块名]_[文档类型]_001`
- `version`: 使用语义化版本 `主版本.次版本.修订版本`
- `status`: Active（活跃）/ Archived（归档）/ Draft（草稿）
- `layer`: Layer 1-10，根据文档类型确定
- `standard_type`: 专业量化机构文档/技术规格/实施指南等

### 3.2 编写职责描述

**步骤1: 使用自动生成工具**
```bash
# 使用职责描述自动生成工具
python scripts/responsibility_description_generator.py --file [文件路径]
```

**步骤2: 参考最佳实践**
```
参考 docs/10_GOVERNANCE_COMPLIANCE/KNOWLEDGE_BASE/RESPONSIBILITY_DESCRIPTION_BEST_PRACTICES.md
中的最佳实践案例
```

**步骤3: 遵循标准结构**
```
[模块名称]，负责[核心功能]，包括[具体功能1]、[具体功能2]、[具体功能3]等
```

**质量要求**:
- 长度: 50-200字
- 包含关键动词: 负责、支持、提供、实现、包括
- 包含具体功能点: 3-5个
- 使用专业术语

### 3.3 编写文档内容

**步骤1: 编写核心定位章节**
```markdown
## 核心定位

[模块名称]，负责[核心功能]，包括[具体功能1]、[具体功能2]、[具体功能3]等
```

**步骤2: 编写主体内容**
```
□ 按章节结构组织内容
□ 使用清晰的章节编号
□ 添加必要的图表和示例
□ 确保内容完整准确
```

**步骤3: 编写文档尾部**
```markdown
---

**文档版本**: v1.0.0
**创建日期**: 2026-04-07
**维护者**: [负责人]
**状态**: Active
```

### 3.4 质量自检

```

□ 文档结构是否清晰？
□ 内容是否完整准确？
□ 是否使用了专业术语？
□ 是否添加了必要的图表？
□ 文档尾部是否完整？
```

## 🔎 四、创建后检查阶段

### 4.1 自动化检查

**检查1: 编码格式检查**
```bash
# 检查文件编码
python scripts/check_encoding_issues.py
```

**检查2: 职责相似度检查**
```bash
# 检查职责相似度
python scripts/responsibility_similarity_checker.py --threshold 0.8
```

**检查3: 职责冲突检测**
```bash
# 检测职责冲突
python scripts/responsibility_conflict_detector.py --threshold 0.8
```

**检查4: 文档结构检查**
```bash
# 检查文档结构
python scripts/document_structure_checker.py
```

**检查5: 链接有效性检查**
```bash
# 检查链接有效性
python scripts/validate_index_links.py
```

### 4.2 手动检查

**检查1: 内容质量**
```
□ 内容是否准确？
□ 逻辑是否清晰？
□ 表达是否专业？
□ 是否易于理解？
```

**检查2: 格式规范**
```
□ 标题层级是否正确？
□ 列表格式是否统一？
□ 代码块是否正确？
□ 表格是否规范？
```

**检查3: 专业性**
```
□ 是否使用了专业术语？
□ 是否符合行业标准？
□ 是否体现了技术深度？
□ 是否有参考价值？
```

### 4.3 问题修复

**发现问题后**:
```
1. 记录问题描述
2. 分析问题原因
3. 制定修复方案
4. 实施修复
5. 验证修复效果
```

**常见问题及解决方案**:
- 职责相似度过高 → 重新编写职责描述
- 编码格式错误 → 转换为UTF-8编码
- 链接无效 → 更新链接路径
- 结构不规范 → 调整文档结构

## ✅ 五、审批发布阶段

### 5.1 提交审批

**步骤1: 准备审批材料**
```
□ 文档正文
□ 检查报告
□ 创建说明
□ 相关资料
```

**步骤2: 提交审批申请**
```
审批申请模板:

文档名称: [文档名称]
文档类型: [文档类型]
创建原因: [创建原因]
目标读者: [目标读者]
主要内容: [主要内容概要]
质量检查: [检查结果摘要]
```

### 5.2 审批流程

**审批人员**:
- 技术负责人：技术内容审核
- 文档架构师：格式规范审核
- 项目经理：必要性审核

**审批标准**:
```
□ 文档是否必要？
□ 内容是否准确？
□ 格式是否规范？
□ 职责是否清晰？
□ 质量是否达标？
```

**审批结果**:
- ✅ 通过：进入发布流程
- ⚠️ 需修改：返回修改后重新审批
- ❌ 不通过：说明原因，终止创建

### 5.3 发布流程

**步骤1: 更新索引**
```
□ 在INDEX.md中添加文档索引
□ 在System_Manifest.md中添加文档记录
□ 更新相关文档的引用
```

**步骤2: Git提交**
```bash
# 提交文档
git add [文档路径]
git commit -m "创建文档: [文档名称]"
git push
```

**步骤3: 通知相关人员**
```
□ 通知文档使用者
□ 通知相关开发人员
□ 更新项目文档清单
```
