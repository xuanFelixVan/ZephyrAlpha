## 两个新脚本详解

### 1. validate_lifecycle_refs.py（LRC 合规门禁）

| 属性 | 值 |
|------|-----|
| 维度 | D5 |
| 优先级 | P1 |
| 消耗时间 | 30s |
| 入口 | `python scripts/governance/d5_architecture/validate_lifecycle_refs.py` |

**检测逻辑**：
1. 扫描 `docs/` 下所有 `.md` 文件，解析 frontmatter
2. 构建 `module_id → 文件路径` 索引
3. 遍历所有 `status: active` 文件，检查每个 `depends_on` 目标
4. 如果目标文件的 `status == draft` → **LRC-001 MEDIUM Finding**
5. 统计每个 draft 文件被多少个 active 文件引用——超过 3 个 → **LRC-004 MEDIUM Finding**（"实质活跃应升格"）

**参数**：
- `--warn-only`：exit 0（CI 非阻断模式）
- `--scope policies`：仅扫描 `docs/01_policies_and_standards/`；默认 `docs`（全量）

### 2. validate_three_way_consistency.py（三方对账门禁）

| 属性 | 值 |
|------|-----|
| 维度 | D5 |
| 优先级 | P1 |
| 消耗时间 | 30s |
| 入口 | `python scripts/governance/d5_architecture/validate_three_way_consistency.py` |

**检测逻辑**（仅扫描 `docs/01_policies_and_standards/`）：
1. 读取文件 frontmatter（`status`, `version`）
2. 匹配正文 blockquote（支持 `> **module_id**: XXX | **version**: X.Y.Z | **status**: active` 和 `> module_id: XXX | version: X.Y.Z | status: active | layer: L1` 两种格式）
3. 读取 `document-metadata-index.yaml` 中的注册条目
4. **三向对比**：
   - frontmatter.status ≠ blockquote.status → MEDIUM
   - frontmatter.version ≠ blockquote.version → MEDIUM
   - frontmatter.status ≠ registry.status → MEDIUM
   - frontmatter.version ≠ registry.version → **HIGH**（最严重——registry 是机器消费的真源）
   - blockquote.version ≠ registry.version → MEDIUM

**严重度区分逻辑**：
- `status` 不一致 = MEDIUM（可能只是同步滞后）
- `version` 不一致且涉及 registry = **HIGH**（registry 是脚本消费的权威数据，版本错=下游全错）

## 钻机经验教训（Owner 必备）

### 1. SearchReplace 对 `|` 字符行有 bug

`governance/index.md` 第 27 行 `> **module_id**: GOV-IDX-001 | **version**: 1.0.0 | **status**: active`

这个行的替换**在 4 个 session 中反复失败**——SearchReplace 工具报"修改成功"但磁盘文件没变。

> **大白话**：遇到含竖线 `|` 的行需要修改时，不要用 SearchReplace。改用 Python 临时脚本直接写文件（read → replace → write）。今后如果发现"明明修好了下次又坏了"的现象，先怀疑是不是这行含 `|`。

### 2. "规则的最后一公里"——写规则同时写检查器

metadata-registry.md §4.1.1 的 LRC-001~005 规则写了 3 个 session 了——但直到本 session 创建 `validate_lifecycle_refs.py` 之前，这些规则**从未被机器执行过**。

> **对标**：Kubernetes 不会说"alpha API 不应该被 stable API 依赖，但我不检查"——Admission Controller 强制全检查。
>
> **大白话**：以后定新规则时，同时问一句"谁来检查这个规则？"——如果答案是"靠 AI 自觉"，那这条规则形同虚设（对标 AGENTS.md §6.5 v2.0 的理念：行为触发 > 语义分类）。
