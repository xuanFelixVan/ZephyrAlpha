# D-022-01 三级升级策略实现

> task_id: TASK-INF-0220002 | source: MOD-INF-022 §2.1-§2.3 + D-022-01 | priority: P0

## 目标

实现升级协议的核心判定引擎和规则集。决策 D-022-01 定义了三级升级策略（autonomous / auto_guard / blocked），取消人工审批层，升级双向可逆。escalation_engine.py 作为判定引擎，escalation_rules.yaml 作为规则 SSoT（Single Source of Truth）。

关键约束：
- 引擎默认行为 deny_by_default（未匹配规则 → blocked）
- 多规则冲突：priority 最高者胜出（highest-wins）
- 时间窗口聚合：window_sec 内的重复触发合并
- 规则 YAML 对 AI 为只读——运行时锁定 + Hash 校验

## 触发条件

- TASK-INF-0220001（模块骨架搭建）已完成——98个空壳文件已创建

## 执行步骤

### 读
- 蓝图 §2.1-§2.3: 三级升级定义 + 规则引擎结构 + 冲突解决机制
- 蓝图 决策 D-022-01: 三级升级与权限对齐
- __init__.py: 包结构理解

### 做
1. 定义 escalation_rules.yaml——包含:
   - rules 区段: ESC-001~008 blocked 规则(文件删除/配置文件修改/规则修改/密钥暴露等)
   - auto_guard 规则: 敏感操作但可自动验证
   - autonomous 规则: 安全操作白名单
   - 每条规则含: id, priority, condition, escalate_to, action, window_sec
   - metadata 区段: version, created, hash
2. 实现 escalation_engine.py:
   - RuleLoader: 从 YAML 加载规则 + Hash 校验
   - RuleEvaluator: evaluate(operation)→判定结果
   - ConflictResolver: priority + highest-wins 冲突解决
   - TimeWindowAggregator: window_sec 内的重复触发合并
   - DefaultResolver: deny_by_default 未匹配规则处理

### 产
- `escalation_rules.yaml` — 完整规则 SSoT
- `escalation_engine.py` — 升级判定引擎
- `test_escalation_engine.py` — 单元测试
