## 施工步骤

### Step 1: R1 stdio 阻塞缓解
- 重构 `_base_server.py` run() 方法：`asyncio.run(_async_run())`
- `_async_run()` 中用 `asyncio.to_thread(stdin.readline)` 或 aiofiles 异步读
- 产出：`_base_server.py` async 版本
- 检查：同时发 2 个 tools/call —— 目目不互相阻塞

### Step 2: R2 safety_level 强制执行
- 在 `_handle_tools_call` 入口检查 tool.safety_level：
  - L → 直接执行
  - M → 返回确认提示（confirmation_required: true）
  - H → 返回 approval_required + 暂停等待 Owner
- 产出：`_base_server.py` `_handle_tools_call` 含 safety_level 检查
- 检查：调 H 级 tool → 返回 approval_required 错误（非直接执行）

### Step 3: R3 契约漂移缓解
- 在 `.pre-commit-config.yaml` 新增 hook：
  - `python scripts/governance/validate_tool_contracts_consistency.py`
  - 对比 tool_contracts.yaml 中 tool.input_schema ↔ 代码中 handler 实际参数
- 产出：pre-commit hook + validate_tool_contracts_consistency.py
- 检查：修改 handler 参数但不更新 YAML → pre-commit 失败

### Step 4: R6 超时机制
- 在 `_handle_tools_call` 中使用 `asyncio.wait_for(coro, timeout=tool.timeout_ms)`
- 默认 timeout=30000ms（30s），可在 tool_contracts.yaml 中 per-tool 配置
- 超时后返回 ERR_TOOL_EXECUTION(-32002) + "Tool execution timed out"
- 产出：`_base_server.py` 超时逻辑
- 检查：调 sleep(60) 的 tool → 30s 后返回 timeout error

### Step 5: R8 幂等性实现
- 在 task_manager_server.py create_task handler 开头检查 idempotency：
  - 计算 `hashlib.sha256(json.dumps(arguments, sort_keys=True)).hexdigest()`
  - 查 MemoryCache 或 SQLite 是否有相同 hash → 有则直接返回已创建结果
- 产出：task_manager_server.py 幂等检查

### Step 6: R9/R10 Observer 告警 + CI 测试执行
- R9: 每个 Server 暴露 healthz tool（返回 {status, uptime, backend_status}）
- R9: 在 _base_server.py 中接入 `shared/metrics.py`——emit `mcp_server_started` / `tool_call_completed` metrics
- R10: 修改 `.github/workflows/governance.yml`——`pytest tests/ -x --timeout=120`（不再 --collect-only）
- 产出：healthz tool + metrics 接入 + CI 更新

## 验收条件
