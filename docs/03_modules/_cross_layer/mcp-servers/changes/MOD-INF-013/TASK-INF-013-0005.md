# TASK-INF-013-0005: Phase 5——MCP Gateway 集中式治理节点实现

## 任务描述

根据蓝图 §12（MCP Gateway 架构）+ §4 Phase 5，实现 MCP Gateway 作为集中式治理节点，Integrated Auth/ACL + RateLimit + Route + Audit + Degrade 五大职能，对标 IBM ContextForge Gateway 模式。

## 施工步骤

### Step 1: 路由分发模块
- 读取 `config/mcp.json`（待新建作为 SSoT）
- 实现 Route 模块：根据 tools/call 的 tool name（格式 `{server_id}.{action}`）自动路由
- 配置表：每个 server_id → 对应 Server 的 stdio 连接
- 产出：`src/zephyr/mcp/gateway_server.py`——含 Route 路由逻辑
- 检查：`gateway.route("task_manager.decompose_blueprint")` → task_manager Server；未匹配 → ERR_TOOL_NOT_FOUND

### Step 2: Auth/ACL 模块
- 与 MOD-INF-018 RBAC 对齐：初始化时检查调用者 session identity → role → 过滤可见工具
- 产出：`gateway_server.py` 中 AuthMiddleware + ACL filter
- 检查：受限 session 调用 H 级 tool → RBAC_DENIED(-32004)

### Step 3: RateLimit 模块
- 集成 `shared/limiter.py` TokenBucketLimiter
- 默认值：10 req/s per client（可配置）
- 按 tool_name 粒度创建独立 bucket（对标 R98）
- 产出：`gateway_server.py` 中 RateLimitMiddleware
- 检查：10s 内发 200 请求 → 第 101+ 返回 429 RATE_LIMITED + Retry-After

### Step 4: Audit 模块
- 全量 tools/call 审计：timestamp + client_session_id + tool_name + arguments_hash + result_status + duration_ms
- 使用 ZephyrLogger 写入审计日志（对标 R81）
- 产出：`src/zephyr/mcp/audit_logger.py` + gateway 集成
- 检查：每次 tools/call 后 audit log 写入

### Step 5: Degrade 模块 + Circuit Breaker
- Circuit Breaker 三态：CLOSED → OPEN（N 次失败后）→ HALF_OPEN（试探恢复）
- 降级策略：单 Server 不可用 → 自动从 tools/list 移除该 Server 的 tool + 标记 `unavailable`
- 产出：`gateway_server.py` 中 CircuitBreaker 类 + degrade 逻辑
- 检查：手动 kill knowledge_base → tools/list 不含 knowledge_base tool → tools/call 返回降级提示

### Step 6: tools/list 聚合
- Gateway 自身暴露 tools/list：一次调用返回所有已就绪 Server 的全量 tool 目录
- 产出：`gateway_server.py` 中 `_handle_tools_list` 聚合逻辑
- 检查：`gateway.tools/list` → 返回 7 Server × 4+ tool 的完整列表

## 验收条件
1. Gateway 五模块全部实现并通过单元测试
2. 外部连接 Gateway → 自动路由到目标 Server
3. RateLimit 限流生效（10QPS per client）
4. 全量审计日志写入 ZephyrLogger
5. Circuit Breaker 三态切换正常——单 Server 不可用不影响其他 Server
6. 所有相关盲点关闭：B1/B7/B8/B9/B10/B16
