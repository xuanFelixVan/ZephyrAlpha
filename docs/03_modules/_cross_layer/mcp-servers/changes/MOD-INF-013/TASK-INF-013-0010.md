## 施工步骤（关键项目，完整列表见蓝图 §9 R11-R65）

### Step 1: 观测性基础设施（R11/R52/R63/R97/R173）
- `_base_server.py` 接入 `trace_context`：tools/call 时提取 trace_id → 传播 → 完成时 emit span
- 接入 `metrics_registry`：每个 tools/call 成功/失败后 emit `tool_call_completed` metric
- MCP Server 暴露 stats tool：复用 `agent_health_monitor.py` 返回 uptime/error_rate/p50/p99
- 产出：`_base_server.py` 观测性集成

### Step 2: SLO/SLA 定义（R63-R64）
- 新建 `config/capacity/mcp_slo.yaml`：每个 Server avail_latency_slo + error_budget + burn_rate
- tool_contracts.yaml 每个 tool 新增 `latency_budget_ms: {p50, p95, p99}`
- 产出：mcp_slo.yaml + tool_contracts.yaml SLO 字段

### Step 3: 运维工具（R54/R56/R75/R83/R84/R85）
- `scripts/mcp/doctor.py`：7 项检查（Python / mcp / ChromaDB / SQLite / Server import / disk / memory）
- `scripts/mcp/generate_docs.py`：tool_contracts.yaml → Markdown/HTML
- `scripts/mcp/launcher.py`：b_mcp.yaml 拓扑排序 → 并行/串行启动
- pyproject.toml [project.scripts]：7 Server CLI entry points
- Dockerfile.mcp + docker-compose.yml MCP 服务编排

### Step 4: AI 集成测试（R68/R73）
- `tests/ai_integration/test_mcp_with_ai_agent.py`：LiteLLM → 真实模型 → AI 自主选 tool → 验证调用
- `tests/ai_integration/test_mcp_cross_model.py`：DeepSeek/Claude/GPT × 同一 task → diff 比较

### Step 5: 配置管理（R59/R60/R72/R80）
- `config/mcp/mcp_config.yaml` SSoT → 生成 tool_contracts 引用
- `_base_server.py` validate_config() 钩子 → 启动时校验后端可达性
- file watcher 监听 tool_contracts.yaml mtime → 变更时 notifications/tools_changed

### Step 6: 执行质量（R53/R86/R88/R91/R92/R98/R99/R100/R101）
- 结果截断：max_result_size 检查 → `_truncated: true`
- 模糊匹配：Levenshtein 距离 ≤3 → "did you mean create_task?"
- 响应元数据：`_meta: {server_id, timestamp, request_id, duration_ms}`
- Git 上下文感知：`_git_context()` 获取 branch + diff-stat
- 参数智能默认值：`defaults_from_context: {$session.id, $workspace.root}`
- RateLimit 执行（R98）：TokenBucketLimiter 实际拦截
- 工具链式编排（R99）：`tools/chain_call` 自动 output→input 流转
- 超时 + 大小治理（R100/R101）
