# TASK-INF-013-0014: §12-§14——Gateway 架构 + 安全机制 + Server 依赖 DAG 编排实现

## 任务描述

根据蓝图 §12（MCP Gateway 架构）、§13（安全机制）、§14（Server 依赖 DAG），完成 Gateway 五模块实现、安全四层机制落地、以及按 DAG 拓扑排序的自动启动编排。

## 蓝图覆盖范围

| 蓝图节 | 内容 | 映射到本任务卡 |
|--------|------|:---:|
| §12 | MCP Gateway 架构——ASCII 架构图 + 五模块 | ✅ |
| §13.1 | OS 级进程隔离——独立 Python 进程 + stdio 管道 | ✅ |
| §13.2 | Gate 级别硬合规——G4/G5/G6 三 Gate 校验 | ✅ |
| §13.3 | 工具级 safety_level——L/M/H 三级控制 | ✅ |
| §13.4 | 健康检查——healthz + readyz | ✅ |
| §14 | Server 依赖 DAG——ASCII DAG + 启动顺序 | ✅ |

## 施工步骤

### Step 1: Gateway 架构实现（§12，与 TASK-INF-013-0005 协同）
- Auth/ACL Module：session identity extraction + role-based tool filtering
- RateLimit Module：TokenBucket 10 QPS per client
- Route Module：tool name → server_id 解析 → 对应 Server 转发
- Audit Module：全量 tools/call → ZephyrLogger 审计
- Degrade Module：CircuitBreaker 三态 + Server 健康感知

### Step 2: 安全机制实现（§13）
- §13.1 进程隔离：每个 Server `multiprocessing.Process(target=server.run)` + stdio 单独
- §13.2 Gate 硬合规：G4(output JSON Schema)/G5(lint+typecheck pass)/G6(blueprint lookup) handler 实现
- §13.3 safety_level：`_handle_tools_call` → L=直行 / M=requireConfirmation / H=requireApproval
- §13.4 健康检查：healthz tool → 返回 {pid, uptime, chromadb_ok, sqlite_ok, ollama_ok} + readyz → handler registry 就绪状态

### Step 3: 依赖 DAG 编排（§14）
- 读取 `architecture-model/layers/b_mcp.yaml` 获取依赖声明
- 新建 `scripts/mcp/launcher.py`：
  - 解析 b_mcp.yaml → 构建 DAG → 拓扑排序
  - 按层级并行启动（ChromaDB/SQLite → kb/gate/blueprint_search(并行) → task_manager → session_handoff → intent_router）
  - 每个 Server 等待 healthz 就绪后再启动下一层
- 产出：launcher.py + DAG 编排逻辑
- 检查：launcher.py 执行 → 7 Server 按 DAG 顺序全部就绪

## 验收条件
1. Gateway 五模块全部实现并可通过单元测试
2. 安全四层（进程隔离/Gate/ safety_level /健康检查）100% 生效
3. launcher.py 按拓扑排序正确启动 7 Server
4. DAG 中任一 Server 启动失败 → 下一层不启动 → 报错退出
