# TASK-INF-009-0015: dry_run 模式实现

## 背景

从蓝图 §15 提取：dry_run 模式允许在不实际调用 AI 模型的情况下预演 Pipeline 的路由决策和 Affinity 校验结果。用于：
1. 新路由策略上线前的回归预演
2. Pipeline 配置变更时的安全校验
3. Owner 手动验证"这个任务会被路由到哪个模型"

## 实现内容

### 1. dispatch 扩展

```python
def dispatch(self, task_card: TaskCard, dry_run: bool = False) -> PipelineResult:
    route = resolve_route(task_card)
    
    if dry_run:
        return PipelineResult(
            task_id=task_card.task_id,
            pipeline=route.node_id[:1],  # A/B from node prefix
            modules_executed=[],         # 无实际执行
            overall_status=PipelineStatus.SUCCESS,
            ct_pipe_route=route,
            is_dry_run=True,
            cost_total_usd=0.0,
            cost_records=[],
        )
    
    # ... 正常dispatch流程
```

### 2. dry_run 产出的关键信息

- `ct_pipe_route.rationale` —— 路由决策依据
- `ct_pipe_route.execution_model` —— 预计使用的模型
- `affinity_violations` —— 预演发现的冲突（如有）

## 验收标准

1. dry_run=True 不调用任何 AI API
2. PipelineResult 包含 route 决策但不含 module 执行结果
3. is_dry_run=True 可区分
4. cost_total_usd=0.0

## 回滚说明

移除 dry_run 参数。所有 dispatch 调用恢复为实际执行模式。
