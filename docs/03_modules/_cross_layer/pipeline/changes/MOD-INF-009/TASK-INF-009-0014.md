# TASK-INF-009-0014: 双盲审查实现

## 背景

从蓝图 §14 提取：双盲审查是 Pipeline 的质量核心——M3(DeepSeek)生成代码/文档，M7(GLM)独立审查。两者的模型必须不同（§2.5 hard antiAffinity），否则"双盲"退化到"单盲"（一个模型既当运动员又当裁判）。

## 实现内容

### 1. BlindReviewResult

```python
class BlindReviewResult(BaseModel):
    generator_output: ModuleResult   # M3生成结果
    reviewer_output: ModuleResult    # M7审查结果
    consensus: bool                  # True=一致通过, False=存在分歧
    disagreement_points: list[str]   # 分歧点摘要
    consensus_details: dict          # 共识详情
```

### 2. 并行执行流程

```
dispatch(task) → resolve_route → M3+M7 并行:
   M3(deepseek)→_call_model→生成代码→ModuleResult[generator]
   M7(glm)→_call_model→深度审查→ModuleResult[reviewer]

→ blind_review_consensus:
   if generator.status==SUCCESS and reviewer finds no blocking issues:
       consensus = True
   else:
       consensus = False → escalate to M11 G5/G6 裁决
```

### 3. Anti-Affinity 校验

```python
if M3_model == M7_model:
    raise AffinityViolation("M3和M7必须使用不同模型——双盲审查不可同模")
```

### 4. Claude 仲裁（Backlog v0.10.0 B207）

当 `consensus=False` → 可选触发 Claude 仲裁（更昂贵的模型进行独立判断）。

## 验收标准

1. M3+M7并行执行
2. M3/M7 模型不同（antiAffinity hard）
3. Consensus=True 时产出 BlindReviewResult
4. Consensus=False 时产出分歧报告

## 回滚说明

回退双盲逻辑→Pipeline执行M3后串行M7。失去并行优化和双盲独立性。
